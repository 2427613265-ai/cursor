# 质检总控（顶层：只挂二级总控）

## 适用场景

- 用户说「质检」「审核」「检查」权利要求书、某一条权利要求或说明书；
- 独权/从权定稿后、说明书撰写前后，需要做正式质检；
- 需要统一从顶层入口进入，再由二级总控调度具体质检 skill。

**硬性规则：本 skill 是质检顶层总入口。凡用户意图是质检/审核/检查申请文件，应先触发本 skill，再分流至二级总控；本 skill 不直接调用具体质检 skill。**

**不适用：** 撰写过程中的边写边自查（仍由各撰写 skill 挂接的规范就地自查）；审查意见答复中的创造性论证（改用 `意见陈述书撰写`）。

---

## 本 skill 管什么

本 skill **只做三件事**：

1. **识别质检大类**（权利要求 / 说明书 / 全案）；
2. **分流至二级总控**（`权利要求质检总控` / `说明书质检总控`）；
3. **全案时收口**：权要结果 + 说明书结果 + 权要↔说明书待同步事项。

具体判型（整份/单条）、执行顺序、检查细则由二级总控及其挂接的具体质检 skill 负责。

---

## 一、挂接清单（仅二级总控）

| 二级总控 | 管什么 | 何时分流 |
|----------|--------|----------|
| `权利要求质检总控` | 权利要求书相关质检的判型、编排与收口；其下再挂具体权要质检 skill | 整份权要、单条权要、全案中的权要阶段 |
| `说明书质检总控` | 说明书相关质检的判型、编排与收口；其下再挂具体说明书质检 skill | 说明书质检、全案中的说明书阶段 |

本 skill **不** 直接挂接：`权利要求书质检`、`单条权利要求审查`、`权利要求引用结构检查`、`说明书具体实施方式清楚性与逻辑一致性规范` 等具体 skill。

---

## 二、先识别质检大类

| 类型 | 典型用户说法 | 下一步调用 |
|------|--------------|------------|
| A. 权利要求（含整份或单条） | 「质检权利要求书」「检查权2」「审核整份权要」 | **必须** `权利要求质检总控` |
| B. 说明书 | 「质检说明书」「检查具体实施方式」「审核实施例」 | **必须** `说明书质检总控` |
| C. 全案（权要+说明书） | 「质检全案」「权要和说明书一起审」 | 先 `权利要求质检总控`，再 `说明书质检总控`，最后由本 skill 汇总 |
| D. 对象不明 | 只说「质检」且上下文无材料 | 先确认大类；若会话中仅有权要则按 A，仅有说明书则按 B |

**选用硬规则：**

- 整份权要 vs 单条权要的细分，由 `权利要求质检总控` 完成，本 skill 不越级判型；
- 说明书内部具体挂接哪些检查，由 `说明书质检总控` 完成；
- 全案建议先权要后说明书；用户只要其一，只跑对应二级总控。

---

## 三、调用顺序

### 链路 A：仅权利要求

```text
质检总控（本 skill）
  → 权利要求质检总控
       →（由其再挂具体权要质检 skill）
```

### 链路 B：仅说明书

```text
质检总控（本 skill）
  → 说明书质检总控
       →（由其再挂具体说明书质检 skill）
```

### 链路 C：全案

```text
质检总控（本 skill）
  → 权利要求质检总控
  → 说明书质检总控
  → 汇总：权要问题 | 说明书问题 | 权要↔说明书待同步事项
```

---

## 四、最低交付要求

- **仅权要 / 仅说明书**：以对应二级总控的收口格式为准，本 skill 不另定细则。
- **全案**：在两段二级总控结果之后，增加一节「权要↔说明书一致性/待同步」收口。

---

## 五、与二级总控、具体 skill 的关系（收口）

| 角色 | skill |
|------|--------|
| **顶层总控** | 本 skill（`质检总控`） |
| **二级总控** | `权利要求质检总控`、`说明书质检总控` |
| **具体质检** | 分别挂在上述二级总控之下（本 skill 不直挂） |

检查清单：

- [ ] 是否已先触发本顶层总控
- [ ] 大类分型（A～D）是否正确
- [ ] 是否只分流至二级总控，而未直接散跑具体质检 skill
- [ ] 全案是否先权要后说明书，并做待同步收口
- [ ] 是否避免只说「注意质检」却不打开二级总控
