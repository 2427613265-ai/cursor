# 质检总控（先分型，再调用具体质检 skill）

## 适用场景

- 用户说「质检」「审核」「检查」权利要求书、某一条权利要求或说明书；
- 独权/从权定稿后、说明书撰写前后，需要做正式质检；
- 需要统一调度多个具体质检 skill，而不是直接散跑某一条规范。

**硬性规则：本 skill 是质检总入口。凡用户意图是质检/审核/检查申请文件，应先触发本 skill，再由本 skill 分流调用具体质检 skill。**

**不适用：** 撰写过程中的边写边自查（仍由各撰写 skill 挂接的规范就地自查）；审查意见答复中的创造性论证（改用 `意见陈述书撰写`）。

---

## 本 skill 管什么

本 skill **不直接替代**各具体质检细则，只做三件事：

1. **识别质检对象**（整份权要 / 单条权要 / 说明书 / 全案）；
2. **分流并编排**要调用的具体质检 skill 及执行顺序；
3. **收口输出格式**（先硬伤、后实质；单条与说明书的待同步事项单独列表）。

## 一、挂接清单（完整版）

### A. 具体质检 skill（本分支主挂接）

| 具体 skill | 管什么 | 何时分流 |
|------------|--------|----------|
| `权利要求书质检` | 整份权利要求书的实质与布局（独权范围/创造性、从权梯度、依附编号、清楚性、按需表达） | 整份权要质检；全案质检的权要阶段 |
| `单条权利要求审查` | 单条权利要求的六维审查（逻辑、表达、格式、说明书支持、现有技术区分、布局策略） | 用户指定权1/权2/权利要求N |
| `权利要求引用结构检查` | 独立改进平行引用、依赖改进串联、组合多项引用 | 整份权要质检必读；形式合规之后 |
| `说明书具体实施方式清楚性与逻辑一致性规范` | 说明书具体实施方式的孤岛、自定义术语、模糊语、歧义反例、常识/矛盾 | 说明书质检；全案质检的说明书阶段 |

### B. 撰写规范类（由具体质检 skill 再挂接；总控只编排，不重复展开）

整份权要质检时，由 `权利要求书质检` 按「必读/按需」加载，例如：

- 必读：`权利要求形式合规性规范`
- 按需：`权利要求清楚性与逻辑一致性规范`、`独立权利要求必要技术特征检查`、`自定义名词就地定义`、`预设值与参数来源检查`、`交底口语名改写为自明结构名规范`、`方位与场景限定上位规范`、`结构类权利要求撰写`、`功能性限定使用边界规范`、`条件判断语句规范`、`权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范` 等

总控 **不** 直接替代上述规范的读取与核对；命中条件时确保对应具体质检 skill 已按其分级表加载即可。

## 二、先识别质检对象

| 类型 | 典型用户说法 | 下一步调用 |
|------|--------------|------------|
| A. 整份权利要求书 | 「质检权利要求书」「审核整份权要」「质检一下」且上下文是权要 | **必须**走「整份权要质检链路」 |
| B. 单条权利要求 | 「检查权2」「审阅权利要求3」「改一下权1」且聚焦单条 | **必须** `单条权利要求审查` |
| C. 说明书（具体实施方式） | 「质检说明书」「检查具体实施方式」「审核实施例」 | **必须** `说明书具体实施方式清楚性与逻辑一致性规范` |
| D. 全案（权要+说明书） | 「质检全案」「权要和说明书一起审」 | 先整份权要链路，再说明书具体 skill |
| E. 对象不明 | 只说「质检」且上下文无材料 | 先确认对象；若会话中仅有权要则按 A，仅有说明书则按 C |

**选用硬规则：**

- 用户点名某一条权利要求 → 只能走 B，不得直接展开整份四维度；
- 单条审查后若发现编号重排/引用关系变化可能影响全文 → 末尾提醒升格为 A；
- 说明书质检建议在权要稳定后进行；若用户只要说明书，仍可只跑 C。

## 三、调用顺序

### 链路 A：整份权要质检

```text
质检总控（本 skill）
  → 1. 权利要求形式合规性规范          （必读，硬伤优先）
  → 2. 权利要求引用结构检查            （必读，平行/串联）
  → 3. 权利要求书质检                  （实质四维度 + 按需规范）
  → 4. 按总控收口格式汇总输出
```

执行原则：

1. **先硬伤、后实质**：形式违规、依附编号错误、引用结构不当优先列出；
2. 实质问题（范围/创造性/梯度）放在硬伤之后；
3. 按需规范由 `权利要求书质检` 按案件类型再加载，总控不越级展开全文。

### 链路 B：单条权利要求审查

```text
质检总控（本 skill）
  → 单条权利要求审查
  → 若末尾提示影响全文编号/引用 → 建议用户再跑链路 A
```

### 链路 C：说明书质检

```text
质检总控（本 skill）
  → 说明书具体实施方式清楚性与逻辑一致性规范
```

### 链路 D：全案质检

```text
质检总控（本 skill）
  → 链路 A（整份权要）
  → 链路 C（说明书具体实施方式）
  → 汇总：权要问题 | 说明书问题 | 权要↔说明书待同步事项
```

> 说明：并非每次质检都四条链路全跑；由本总控判型后只跑命中链路。

## 四、最低交付要求

### 整份权要 / 全案中的权要阶段

必须按下列顺序输出（与 `权利要求书质检` 对齐）：

1. 形式合规性硬伤  
2. 引用结构问题  
3. 依附编号错误  
4. 实质重复问题  
5. 独权范围与创造性观察  
6. 从权梯度布局观察  
7. 表达清楚性核对（如有）

每条问题写清：位置 → 问题 → 修改建议。

### 单条审查

按 `单条权利要求审查` 六维输出；「待同步说明书事项」单独列表，不计入缺陷。

### 说明书

按 `说明书具体实施方式清楚性与逻辑一致性规范` 的检查清单输出；发现孤岛等勿擅自删除，说明疏漏或不必写入后交用户决定。

### 全案

在权要与说明书分块结果之后，增加一节「权要↔说明书一致性/待同步」收口。

## 五、与具体 skill 的关系（收口）

| 角色 | skill |
|------|--------|
| **总控 / 分流入口** | 本 skill（`质检总控`） |
| 整份权要实质与布局 | `权利要求书质检` |
| 单条六维审查 | `单条权利要求审查` |
| 引用平行/串联 | `权利要求引用结构检查` |
| 说明书实施方式清楚性 | `说明书具体实施方式清楚性与逻辑一致性规范` |
| 形式硬伤等撰写规范 | 由上述具体质检 skill 再挂接，不由总控直接替代 |

检查清单：

- [ ] 是否已先触发本总控（未直接散跑某一具体质检 skill 充当入口）
- [ ] 质检对象分型（A～E）是否正确
- [ ] 命中链路是否已 Read 并遵循对应具体质检 skill
- [ ] 整份权要是否遵守「形式 → 引用结构 → 实质」顺序
- [ ] 输出是否按总控收口格式（先硬伤后实质）
- [ ] 是否避免只说「注意质检」却不打开具体 skill
