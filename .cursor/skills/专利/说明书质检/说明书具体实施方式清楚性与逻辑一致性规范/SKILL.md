# 说明书具体实施方式清楚性与逻辑一致性规范

## 适用场景

- 由 `具体实施例质检总控` 在撰写规范核对之后调用（全套必含）。
- 撰写具体实施方式时可边写边自查。
- **不是**质检总入口；用户说质检应先 `质检总控` → `说明书质检总控` → `具体实施例质检总控`。

**执行时必须先 Read** `清楚性与逻辑一致性共用内核`，检查对象 = **说明书具体实施方式叙述**（详细技术叙述，非精炼法律文本）。本文件只补说明书侧差异。

## 说明书侧差异（相对内核）

### 规则一补充：附图标记与跨文件呼应

孤岛判定时，对带附图标记或专门命名的部件/参数重点排查；若在附图说明或权利要求书已有完整呼应，可不判孤岛。

### 规则二补充：公开充分

人为定义词在说明书中突然使用却无定义/计算方式 → 可构成公开不充分或含义不清（权要侧另有就地定义要求）。

### 规则六补充：与权利要求一致

前后矛盾包括：说明书不同段落之间，以及**说明书与权利要求书**相应表述互相排斥（如背景指摘固定连接之缺陷，实施例却写成完全等价固定连接且无改进点）。

### 名词释义顺序（说明书专有）

某条权利要求涉及的新定义名词，须在对应实施例**之前**先解释清楚——见 `具体实施方式名词先释义后展开`。

## 说明书检查清单

先勾共用内核清单，再补：

- [ ] 带标记/专名的部件参数后文有呼应，或属公知/暗含例外？
- [ ] 新定义名词是否在对应实施例之前已释义？

## 应用范围

适用于说明书「具体实施方式」的撰写与质检；与权要清楚性检查配合：建议先跑权要链路再检说明书是否清楚支持权利要求。
