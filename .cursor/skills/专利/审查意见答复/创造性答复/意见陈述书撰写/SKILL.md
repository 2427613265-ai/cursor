# 创造性答复意见陈述书撰写规范

本 skill 用于**分步**撰写（或按用户反馈逐步修订）针对创造性缺陷的意见陈述书。最终目标是完整可提交正文，但**禁止在同一次回复中一次性写出全文**；其中**第1步不得夹带修改策略分层与 plan**（二者合并为第1步之后的同一步交付，不得塞回第1步，也不得再拆成两步）；**2.2 非显而易见性**还须再拆为「逐条针对性答复，每条一步」+「体系化归纳，单独一步」，**禁止在同一次回复中一次性输出整节 2.2**（含多条“第一/第二/第三”与“首先/其次/再次/最后”同批交付）。

**加粗展示与纯文本分离（硬性）**：
1. **对话展示必须加粗**：交付修改说明、2.1/2.2/2.3、二通第一部分、其他权利要求抗辩、组装全文时，在对话回复中对每步最关键的 1～3 处表述使用 Markdown `**……**` 加粗，使用户在界面中直接看到粗体（实际技术问题句、发明构思命名、无技术启示结论句、法条收束句等）。不得整段加粗。
2. **可复制纯文本不得含星号**：同一答复正文须同时给出（或写入工作稿）一份去掉全部 `*` 的纯文字版，供粘贴进意见陈述书；纯文本版与展示版仅差加粗标记，文意相同。交付前对纯文本版搜索 `*`，有则删除。
3. **禁止**文末另列「建议手动加粗：……」段（加粗已在对话展示版中完成）。
4. 第1步材料核对/手法表、第2步修改策略/plan 等过程性交付：不加粗、不插 `*`。

结构来源与分工（提取模版，勿原案照抄）：

| 来源 | 角色 |
|------|------|
| 岩芯批量校正意见陈述书 | **一通**骨架：常规三段论 2.1→2.2→2.3；审查员观点在需要处嵌入 2.2 |
| 路面深层病害 OA2 意见陈述书 | **二通**骨架：先针对审查员核心观点逐条作答，再收束权利要求创造性 |
| 不合理审查逻辑及应对 | **手法库与组合逻辑**：如何拆上位、破事后分析、建鸿沟/失败预期、讲结合障碍与整体协同 |

## 通知书次数分支（硬性；先判一通/二通）

第1步必须先判明本次是**一通**还是**二通及以后**，再选正文重心。二者不是同一套篇幅分配。

### 一通｜以常规三段论为基础（岩芯模版）

正文重心 = **创造性三段论**；审查员结论性观点在需要直接交锋时**引述后嵌入**非显而易见性论证。

```text
一、修改说明 / 坚持原权利要求
二、修改后的（或本申请）权利要求1具备创造性
    2.1 区别技术特征 → 实际技术问题 → 与审查员概括对比
    2.2 非显而易见性（内嵌：引述审查员结论性观点 + 其一/其二拆解；
         并以 2.1 问题为锚完成技术启示否定；首先/其次/再次/最后）
    2.3 显著的技术进步（镜像 2.1 技术问题）
三、第二项独权 3.1/3.2/3.3（若有）
四、其他权利要求
```

要求：

1. **骨架不可改**：2.1 / 2.2 / 2.3 标题与顺序固定。
2. **引述嵌入 2.2**：凡审查员作出“有动机 / 有启示 / 作用相同 / 常规手段 / 简单叠加”等结论性论断，在 2.2 中按“针对审查意见指出的：……对此，申请人答复如下：”拆解；不另设与三段论并列的大节抢戏。
3. **手法服务三段论**：选法后按逻辑递进写入 2.2，最终落回“针对如 2.1 所述技术问题无技术启示”。

### 二通及以后｜以针对审查员观点作答为主（路面 OA2 模版）

一通已用三段论完整论证过一次；二通正文重心 = **针对本次通知书核心观点的逐条答复**，三段论节用于收束与固化修改后方案，避免再写一篇等长的“教科书式三段论复读”。

```text
一、针对第【N】次审查意见的核心观点作答如下：
    第一、针对审查意见指出的：【引述/概括】→ 对此答复（其一/其二…递进）
    第二、……
    第三、……
二、修改后的（或本申请）权利要求1具备创造性
    2.1 区别技术特征 → 实际技术问题 → 与审查员概括对比（仍须完整）
    2.2/2.3 可相对一通压缩：非显而易见性要点已在「一」展开的，
         用“如本意见第一部分针对审查意见第×点所述……”回引，
         补足尚未覆盖的启示否定与技术进步镜像即可
三、第二项独权（若有；同样“针对性为主 + 三段论收束”）
四、其他权利要求
```

要求：

1. **第一部分是主战场**：按审查员本次核心观点逐条交锋；每条内部手法递进（见下文“手法组合”），不得只堆并列口号。
2. **仍须有 2.1**：区别特征与实际技术问题（含与审查员概括对比）不可省——这是三步法第二步，也是后文启示锚点。
3. **禁止二通再写一通同构长文**：若「一」已充分完成启示/动机/鸿沟论证，2.2 作体系化收束即可；2.3 仍单独写技术进步并镜像 2.1 问题。
4. **二通新争点优先**：审查员新的概括、新的组合方式、对新修改特征的“常规手段”认定，必须在第一部分正面拆解。

### 逻辑递进与衔接（一通、二通共用，硬性）

无论一通还是二通，单条答复与全文均须**递进**，不得平铺。下列是**可选进阶层级**（按本案成立与否取舍），不是必须写满的清单：

```text
纠错问题界定/扳倒上位（若审查员问题上位）
  → 对比文件客观教导与本申请的真实差异（作用是否真相同）
  → 针对如 2.1 所述技术问题有无技术启示 / 有无结合动机
  →（仅当事实支持时）退一步：即便存在框架思想，从思想到本案具体方案仍有鸿沟
  →（仅当事实支持时）再退一步：结合后冲突无规则 / 违背对比文件初衷 / 失败预期
  →（仅当特征间确有前提/输入/约束关系时）整体性与协同：不可暴力拆分后拼贴
```

**取舍标准**：每一层必须能回答“删去本层，上一层结论是否仍缺一块关键论证”。若某层只是换说法重复、或靠夸张才能成立，删除该层。衔接检查：删去上一层后，下一层是否失去前提？若会，说明递进成立；若各层可任意调序，说明仍是并列堆砌，必须重排或删层。

## 核心结构（独权三段论组件；一通全量展开，二通收束复用）

独权创造性论述的固定三节（标题与顺序不可改）：

1. **2.1、**申请人认为，权利要求1与最接近的现有技术对比文件1相比，至少具有以下区别技术特征：
2. **2.2、**权利要求1所保护的技术方案是非显而易见的。
3. **2.3** 修改后的（或本申请）权利要求1的技术方案具有显著的技术进步

- **一通**：上述三节为正文主体；审查员观点的逐条答复**归入 2.2**。
- **二通**：上述三节为第二部分收束；审查员观点的逐条答复**前置为第一部分主战场**，2.2 回引第一部分并补漏。
- **其他独权、从属权利要求** + 开场/结尾。

**有益效果归属（硬性）**：凡 2.2 针对性答复中本来会写的“本申请能够……效果”“取得预料不到的技术效果”等，**一律放到对应独权的技术进步一节**（第一项独权为 2.3，第二项独权为 3.3）集中论述，不在逐条答复的“其一/其二/其三”里做效果收束。

**技术问题只在区别特征节展开（硬性）**：实际技术问题的界定、展开，以及与审查员问题概括的对比，**只在 2.1（或第二项独权的 3.1）完整论述一次**。进入 2.2/3.2 后，不得再次整段复述申请人的技术问题或再次展开与审查员概括的对比；若审查结论本身就是问题界定类，仅用一句“如 2.1 所述……”指向前文，随即转入动机、启示、常规手段等非显而易见性论证。

**“不重复”≠“不衔接”（硬性）**：禁止在 2.2/3.2 **重写**技术问题整段，但**必须把 2.1/3.1 已界定的实际技术问题当作非显而易见性与技术启示论证的锚点**。凡写“有无技术启示 / 有无结合动机 / 是否常规手段”，一律回答：现有技术是否给出了将区别特征（N）用于最接近现有技术、**以解决如 2.1（或 3.1）所述实际技术问题**的教导。禁止只写“对比文件未公开某特征”就停笔，也禁止脱离该技术问题空谈“无启示”。

### 技术问题 → 技术启示衔接（硬性；三步法第三步）

创造性三步法第三步的判断对象不是抽象的“特征是否已知”，而是：在已确定区别特征与实际技术问题后，现有技术整体上是否给出将所述区别特征应用到最接近现有技术以解决**该**实际技术问题的**技术启示**。本 skill 要求：

1. **2.1/3.1 产出可被引用的问题表述**：技术问题须以**问题要素**具体到可由区别特征（N）解决的层面，避免宽泛到任何改进都能对上，也**禁止把技术方案手段写入问题句**；写完后应能用一短句回指（如“如 2.1 所述，实际要解决的是……”）。
2. **2.2/3.2 必须专设技术启示论证**：体系化归纳中，“首先/其次/再次”每一层都要落到“针对如 2.1 所述技术问题，该文件/该组合是否给出采用区别特征（N）的启示”；不得用“未公开”替代“无启示”。
3. **技术启示的标准问句**（每项独权至少完整回答一遍）：
   - 对比文件自身要解决的技术问题/技术目的是什么？与 2.1 所述实际技术问题是否相同或足够接近？
   - 对比文件客观教导的技术手段与作用是什么？是否指向采用区别特征（N）这一手段？
   - 即使公开了相似部件/步骤名称，其在该文件中的作用、前提、数据关系是否与解决 2.1 所述问题所需的作用相同？
   - 审查员主张的“作用相同 / 有动机结合 / 常规技术手段”，是否建立在其上位概括的技术问题上，而非建立在 2.1 所述具体技术问题上？
4. **衔接用语（推荐，可替换同义表述）**：
   - `针对如 2.1 所述实际技术问题，对比文件【X】……并未给出采用上述区别特征（N）的技术启示。`
   - `对比文件【X】所要解决的是……问题，与如 2.1 所述……问题并不相同；其教导停留在……，本领域技术人员据此不会为解决如 2.1 所述问题而……。`
   - `审查意见所谓“有技术启示”，是以其概括的“……”问题为前提；在如 2.1 所述更具体的技术问题之下，该前提不成立。`
5. **有益效果仍归 2.3**：2.2 论证“无启示”时，可点明“因此不能显而易见地获得本申请方案”，但具体技术效果展开仍放 2.3，并与 2.1 技术问题镜像对应。

### 两项或多项独立权利要求的处理（硬性）

若权利要求书包含两项独立权利要求（常见为“方法独权 + 系统/装置独权”），不得只完整论证第一项独权，再用一句“另一独权与其对应，故也具备创造性”带过。应当：

1. **逐项识别创造性基础**：分别确定每项独权的最接近现有技术、区别技术特征、实际技术问题及审查员对该项独权的评述。两项独权共用同一对比文件时也要分别核对其公开内容。
2. **逐项设置论证，结构二选一（据发明构思关系择一，均须每项都有区别特征/充分非显而易见性/单独深入技术进步）**：
   - **构思相异 → 分章**：第一项独权写“2.1 / 2.2 / 2.3”，第二项独权另设下一大节写“3.1 / 3.2 / 3.3”（后续从权章节顺延）。
   - **共用同一发明构思与同一对比文件 → 共享 2.1/2.2/2.3 内部并列**（范文范式）：2.1 内并列列"区别特征（1）=第一独权""区别特征（2）=第二独权"，2.2 内以"第一/第二"分别针对各独权评述作答，2.3 内并列分述各独权效果。此法省重复、更清晰，但**并列不等于合并**——每项独权的区别特征、启示否定、技术进步仍须各自写足，不得共用一段带过。
3. **系统独权不得只作形式映射**：若第二项独权是与方法独权对应的系统/装置，须逐一说明其模块/单元如何对应实施方法步骤，并核对系统独权是否还包含独有的结构、连接、数据流或协同关系；对这些独有特征单独论证。可引用前文已充分论证的共同发明构思，但必须补足系统实现层面的差异，不能只有“同理可得”。
4. **独立发明构思分别论证**：若两项独权解决不同技术问题或采用不同核心手段，不得合并论述；分别建立完整创造性逻辑链。
5. **plan 按独权拆项**：每项独权的 2.1/2.2/2.3（或 3.1/3.2/3.3）各列为独立待办，逐项交付、逐项确认。

### 审查意见引述规则（短文照录，长文概括）

写“针对审查意见指出的：”之后：

1. **篇幅适中或较短**：完整照录该条审查意见原文，不得歪曲。
2. **原文非常长**：改为**忠实概括**，保留其结论链条中的关键认定（如公开了什么、作用是否相同、给出何种启示、有何种结合动机、认定是否常规等），用一两段浓缩表述对准靶子；**不得删掉关键结论点，也不得改成对自己有利的弱化版**。
3. 概括后仍须让读者一看就知道在反驳哪一条审查逻辑；必要时可在概括句中用引号保留审查员的关键原词（如“作用相同”“有动机结合”“常规技术手段”）。
4. 判断“非常长”的实务标准：单条连续论述明显超过半页、或包含多段重复铺陈时，优先概括；一两句到一小段的结论仍宜照录。

```text
第【序】、针对审查意见指出的：【短文照录原文；过长则忠实概括其结论链】

其一、【就该条审查结论拆解：可指向 2.1 已列区别特征（N）、指出对比文件未公开等；若涉问题界定，仅一句“如 2.1 所述……”指向，不重写技术问题】
```

### 独权创造性三节模板（2.1 → 2.2 → 2.3）

**2.1 区别技术特征（编号 + 权利要求原文）+ 实际技术问题 + 与审查员概括对比**

> 2.1、申请人认为，权利要求1与最接近的现有技术对比文件1相比，至少具有以下区别技术特征：
>

>
> 区别特征（1）：【权利要求原文，不得自行概括压缩】
>
> 区别特征（2）：【权利要求原文】
>
> ……
>
> 【简要说明对比文件1已公开何处、未公开上述哪一项】
>
> 基于上述区别技术特征，并结合本申请的背景技术，申请人认为，修改后的权利要求1实际要解决的技术问题应当为：
> 【申请人界定的具体技术问题——只写问题要素，不写实现手段；见下文「技术问题须问题要素导向」】
>
> 具体而言，【此处才写：区别特征（N）分别针对哪一问题要素、如何达成——手段只放在本句，不放进上一句问题界定】。
>
> 审查员将实际解决的技术问题概括为“【审查员原概括用语】”，该概括未能具体反映【……问题要素】。相较而言，上述技术问题更能客观体现修改后的权利要求1相对于最接近现有技术所实现的技术改进。

**2.1 撰写增补规则（范文提炼，硬性）：**

1. **区别特征立体化**：把并入的**每一处**限定都以权利要求原文列入区别特征，成组呈现"完整逻辑链条"，不选择性只摘一个最亮点。区分面越立体，审查员越难用"仅是设置位置/仅是常规元件"一句上位掉（范文将"结构一致+倾斜插装+锐角+端面延伸路径"成组列入区别特征（1））。
2. **"具体而言"首句 = 发明构思命名句**：具体而言的第一句先抛出发明构思的名称（如"独立工装壳体替换原装壳体"），后文 2.2/2.3 一律回指该名，形成统一话语。
3. **问题要素与特征一一对应**：有几组可区分特征就提炼几个问题要素；并入新特征后回查问题句是否漏掉对应要素（范文因并入"多点+三角解算"，就在技术问题里补出"消除转子偏摆耦合误差"这一独立要素）。
4. **问题句方向性可留、具体手段下沉**：问题句保留"如何在……前提下，获得/确定……"的方向性骨架即可；具体器件名、试验方法名、结构名（如"力锤""传递函数""外置工装"）尽量下沉到"具体而言"。**判据：删去问题句中的具体器件/步骤名后，是否仍能看清要解决什么缺陷；能，则合格。**（本条为对旧"零手段植入"规则的放宽，兼顾实务习惯与要素导向。）
5. **审查员概括对比清单化**：不要只说"审查员概括过于上位"，要用"未能具体反映……①……②……③……"逐条点名它漏掉的每个问题要素/效果。
6. **允许 2.1 末尾一段"本质定性埋点"**：区别特征列完后，可用 **1–2 句**宣示两类方案的范式级差异（如"实验力学标定 vs 理论建模属不同范式"）作为后文锚点；**只定性、不展开完整启示否定**（完整论证留 2.2，避免与 2.2 重复）。
7. **多独权结构二选一**：
   - 两独权**发明构思相异** → 仍用 2.x / 3.x **分章**（第一独权 2.1/2.2/2.3，第二独权 3.1/3.2/3.3）。
   - 两独权**共用同一发明构思与同一对比文件** → 允许**共享 2.1/2.2/2.3、内部并列**（2.1 内并列列"区别特征（1）=权1""区别特征（2）=方法独权"；2.2 内"第一/第二"分别答；2.3 并列写效果）。本案属后者，更省重复、更清晰。

**2.2 非显而易见性（四层递进，必须充分；逐条答复 + 技术问题锚定的技术启示）**

> 2.2、权利要求1所保护的技术方案是非显而易见的。
>
> 首先，……（对比文件1单独：其技术目的/教导为何不能针对如 2.1 所述技术问题给出采用区别特征（N）的启示）
> 其次，……（其他对比文件分别：各自要解决的问题、客观教导与作用；为何不能弥补对比文件1以解决如 2.1 所述问题）
> 再次，……（组合后仍无针对如 2.1 所述问题的技术启示；连续改造清单；禁止事后拼贴）
> 最后，……（适用时反驳“常规步骤/公知常识”——即使手段名称已知，也不构成解决如 2.1 所述具体问题的启示）

凡在针对性答复中已充分展开的点，此处做**体系化归纳**并可用“如本意见前文针对审查意见第×点所述……”指引，避免逐字重复；但 **2.2 标题与四层骨架必须保留**，且每层须显式回扣 2.1 技术问题 + 区别特征（N）+ 有无技术启示。

**2.2 的内部次序与分步交付（硬性）：**

1. **先逐条、后归纳，分步交付**：先按审查意见核心结论逐条写“引述（短文照录 / 长文概括）+ 对此答复”，分别击破结合动机、技术启示、公知常识、特征抽取等；每条至少有一句把反驳锚定到“如 2.1 所述实际技术问题”。**每条答复独占一步交付**；全部逐条答复确认后，**另起一步**再写“首先/其次/再次/最后”体系化归纳。**禁止**同批交付多条逐条答复，**禁止**同批交付逐条答复与归纳。
2. **每步只写一条**：2.2-① 写标题 + 第一条；2.2-② 起只写后续各条（不写重复标题）。**不得**在同一步内写“第一、第二、第三……”多个段落。
3. **体系化归纳单独一步**：归纳步只写“首先/其次/再次/最后”；可用“如本意见前文针对审查意见第×点所述……”回引，**不得**重复粘贴已确认逐条答复全文。
4. 2.2 只论证“为什么不能显而易见地得到”，不在本节集中展开有益效果，也**不再整段复述 2.1 的技术问题界定**；但**必须完成以该技术问题为锚点的技术启示否定论证**（归纳步须写足）。
5. **对话加粗 + 纯文本分离（硬性）**：2.2、3.2 及二通第一部分在对话中对关键结论句 `**加粗**` 展示；另附/写入工作稿的纯文本版不得含 `*`；禁止「建议手动加粗」段；其一/其二等结构序号仍用汉字。

**充分论证的最低要求：**

1. **对比文件1单独**：不仅写“未公开”，还要说明其技术目的、工作原理、完整方案及客观教导停留在何处；逐项对应区别特征（N）；明确其自身要解决的问题与如 2.1 所述实际技术问题的差异，以及为何不能单独给出采用区别特征（N）以解决该问题的启示。
2. **其他对比文件分别审查**：逐篇说明其技术场景、必要前提、数据/结构来源、实际实施方式、自身技术问题/目的，以及为何不能弥补对比文件1以解决如 2.1 所述问题。对比文件较多时不得合并成一句“其他文件均未公开”。
3. **技术启示专项（必写，不得省略）**：用上文“技术启示的标准问句”逐项作答；结论句须形如“针对如 2.1 所述实际技术问题，……未给出采用区别特征（N）的技术启示”。审查意见已主张“有启示/作用相同/有动机”时，必须正面拆解其启示链条，不能只重复“未公开”。
4. **组合推理闭合**：分别回答“为什么会为解决如 2.1 所述问题去找该文件”“为什么会抽取该特征”“为什么会按权利要求顺序/关系组合”“组合后为什么能够正常工作并解决该问题”。审查意见缺少其中任一环，应明确指出。
5. **连续改造清单**：列出从对比文件组合到本申请仍需完成的具体改造，并说明这些改造不是彼此独立的常规替换，而受如 2.1 所述同一技术问题和数据/结构关系约束。
6. **整体性与协同关系**：说明区别特征之间如何互相提供前提、输入、约束或反馈，为什么不能拆成若干孤立常规手段逐项评价。
7. **公知常识/常规手段须有依据**：审查员仅作结论时，指出其未证明该手段在本案具体技术场景、具体关系和**如 2.1 所述具体技术问题**下属于公知常识；不能只争论手段名称是否已知。
8. **结论必须落回权利要求整体**：最终明确，本领域技术人员在申请日前没有合理成功预期，不能在不付出创造性劳动的情况下为解决如 2.1 所述问题而得到该项独权的整体方案。

**2.2 递进三层模板（范文提炼；每个独权、每条审查结论内部按此排）：**

```text
首先——破上位概括（过度概括 / 事后分析 / 归谬）
        抽掉对比文件关键限定后只剩上位表述的，逐一还原被抽掉的限定；
        可用归谬：若"有共同上位概念即有启示"成立，则几乎任何同类元件方案都显而易见，有悖启示认定标准。

        即便产生上位念头，从该念头到本案具体方案仍缺哪几环教导；
```

层与层须删上则下失前提，是真递进不是并列；每层结论都回扣"针对如 2.1 所述实际技术问题有无采用区别特征（N）的技术启示"。

**组合难度升级为"拆核心 + 造新系统"框架（替代/强化"连续改造清单"）：**

明确列出得到本申请须完成的无教导"跳跃"——(1) 须放弃对比文件1的核心发明构思？(2) 须放弃对比文件2的核心发明构思？(3) 须新发明哪一整套系统？"拆掉两个对比文件各自的核心、再发明一套新系统"显然不是正向启示，而是以本申请为蓝本的事后拼凑。比单纯罗列改造步骤更有冲击力。

**表达增强手法子库（新增；让答复"表达清楚、重点突出"）：**

> 硬性护栏：以下手法**必须以已验真的事实论证为前提，只作论证的表达外壳，不得替代论证**。每个金句/比喻/场景后必须紧跟其事实依据（对比文件段号 / 区别特征编号）；数量服从递进，不堆砌；写完删掉任何只靠修辞才成立的句子。

1. **金句化降维**：把核心区别压成一句直觉性对比（范文："本质差异不是'用了什么传感器'，而是'传感器在谁的上面'"）。
2. **工程场景叙事对比**：分步骤讲"对比文件的场景 vs 本申请的场景"，让审查员"看见"差异，而非只读术语。
3. **比喻锚定**：用一个形象（"围墙 / 翻墙"）把整段论证钉进记忆。
4. **方法论范式对比框**：一对标签把复杂技术差异结构化（"自下而上·理论建模 vs 自上而下·黑箱频响"）。
5. **单点爆破**：锁定一个对方完全没有的关键环节（"力锤标定"）打聚光灯，逐一说明对方各步骤为何都不对应。
6. **归谬法 / "有规则 vs 无规则"反衬**：把对方逻辑推到荒谬极端；用本申请"有解"反衬结合方案"无解"。
7. **"常规设计"物理关联反驳**：用具体物理结构/受力路径的关联性（如 MAX(|F1|,|F2|) 对应油膜受力方向可变），打掉审查员的"常规设计"标签。

**2.3 显著的技术进步（单独成节；有益效果统一写在这里；必须深入）**

> 2.3 修改后的权利要求1的技术方案具有显著的技术进步
>
> 【以说明书实施例/工作流程的自然叙述开篇：燃料/物料如何进入、风如何走、各区如何配合——先讲清楚方案怎么跑起来，再顺势带出解决了什么问题、比现有技术好在哪】
> 【每一个效果须能追溯到区别特征（N），并与 2.1 的实际技术问题相呼应；但不要用“机制/直接效果/逐点对比”等标签把段落切成填表腔】
> 【与对比文件的差异在叙述中穿插说明，而非每段机械罗列 D1/D2/D3】
>
> 因此，修改后的权利要求1相对于现有技术具有显著的技术进步。
>
> 综上所述，修改后的权利要求1具有突出的实质性特点和显著的进步，具备创造性，符合专利法第二十二条第三款的规定。

**深入论述须覆盖的实质层次（写法可灵活，层次不可缺）：**

1. **区别特征到运行机制**：按权利要求的数据流、控制流或结构配合顺序，说明方案实际如何工作，不得只复述权利要求原文。
2. **运行机制到直接效果**：写清特征→中间状态/过程→技术效果之间的因果，避免从特征直接跳到“提高准确性/效率/可靠性”等空泛形容词。
3. **特征协同到整体效果**：说明各区别特征如何配合，缺少任一特征会出什么问题；整体效果不是各已知手段的简单叠加。
4. **与 2.1 技术问题呼应**：2.1 各问题要素在本节均须有对应回应（可自然融入叙述，**不必**再列“①②③镜像表”或“以下三个方面”式提纲）。
5. **相对现有技术的进步**：结合对比文件1及审查员组合方案说明本申请多实现了什么、避免了什么；对比写入行文，不套“D1如何、D2如何、D3如何”的固定排比。
6. **显著性表述审慎**：有说明书/实施例支持时方可使用较强措辞；无依据不用“预料不到”“唯一”“质变”等营销化或 AI 常用强化词。
7. **证据与支持**：优先引用说明书实施例、附图关系或已记载机理；无数据不编造定量幅度。

**2.3 行文风格（反 AI 腔；硬性）：**

交付正文须读起来像代理人撰写的意见陈述书，而不是自动生成的结构化报告。具体要求：

1. **禁止填表式标签**：不得出现“机制：”“直接效果：”“逐点对比：”“场景价值：”“第一、……（效果命名）”下再套完全同构的四段式。效果用连贯段落叙述即可。
2. **禁止套路起句**：慎用或不用“与对比文件相比，本申请至少在以下 N 个方面产生了……所不能实现的技术效果”“本申请实现了从……到……的质变”等明显的生成式套话。
3. **禁止过度对称**：不要强行拆成三点、五点且每点字数、句式、结构完全一致；2～3 个问题要素可用 1～2 段长文呼应，必要时一段专讲协同、一段专讲与 D1 的差异，结构服从案情。
4. **叙述优先于命名**：少用自造效果小标题（如“零改装测试”“分区梯级送风效果”等口号式命名）；直接写技术事实与因果，效果从事实中自然得出。
5. **对比文件穿插写法**：需要对比时，用“相较对比文件1……，本申请……”“对比文件2虽……，但未……”等嵌入句，避免每条效果末尾都机械追加“对比文件1……对比文件2……对比文件3……”三连排比。
6. **场景价值从简**：工程场景一句带过即可（如“适用于连续进料的生物质燃烧炉运行”），不写商业策划式铺陈；无说明书依据不拓展市场、产业链表述。
7. **对话加粗 + 纯文本分离**：同加粗展示与纯文本分离规则；禁止填表标签与套路起句。
8. **收束句保留**：节末“因此……具有显著的技术进步”及法22.3符合性收束可保留，这是实务惯例，不算 AI 腔。

**推荐写法（叙述式；优先采用）：**

```text
2.3 修改后的权利要求1的技术方案具有显著的技术进步

【1～2段：按工作流程讲方案如何运行——参照说明书实施例的叙述节奏，如进料→落料区→鼓风→风箱→各送风孔→各区燃烧→排渣；段内自然点到关键区别特征】

【1～2段：在上述运行过程中，针对如2.1所述问题分别产生了何种改善——厚料层充分燃烧、外围不过吹、灰渣外移减结焦等，因果写清楚；与对比文件1的分隔双室炉排吹送、对比文件2的平顶均布孔等差异在叙述中带出，不单独开“对比小节”】

【可选0～1段：各特征协同——若协同关系是效果来源，用一段话说明，不拆成标签列表】

因此，修改后的权利要求1相对于现有技术具有显著的技术进步。
综上所述，……（法22.3收束）
```

**禁止浅表写法：**

- 仅把区别特征换一种说法复述后直接写“因此效果更好”；
- 只列“提高精度、降低成本、提升效率”三个结果而不解释技术因果；
- 两项独权共用一段效果文字、不区分方法执行机制与系统结构协同；
- 把针对性答复中尚未由独权特征支撑的效果搬入 2.3；
- 使用填表式标签（机制/直接效果/逐点对比/场景价值）或高度对称的“第一/第二/第三”四点式；
- 每条效果末尾机械堆砌 D1、D2、D3 三连对比。

**三点式表达骨架（已降级为备选；默认不采用）：**

仅当用户明确要求“分点列效果”或案情效果要素多、叙述式易遗漏时，方可酌情用分点写法——且**不得**使用“机制/直接效果/逐点对比/场景价值”标签，每点用**一整段自然段落**完成，各段句式须有变化。默认优先用上文「叙述式」写法。

若采用分点，须满足：
1. **镜像自检**：效果覆盖 ≥ 2.1 问题要素数，缺一即补。
2. **场景一句即可**：不展开商业策划式铺陈。
3. **两独权分别写效果**：方法独权不得机械复制装置独权效果。

### 区别技术特征列举硬性要求

- 用**权利要求原文**列出，不得压缩成自己的概括句。
- 用**编号**列出：`区别特征（1）：……` `区别特征（2）：……`；2.1 一次性列出全部；针对性答复与 2.2/2.3 引用时写“上述区别特征（N）”。

### 技术问题以问题要素为主、方向性可留、具体手段下沉（硬性；仅在 2.1 / 3.1 的问题句）

重新界定实际技术问题（含纠正审查员上位概括）时，**问题句以问题要素为主，可保留最小方向性限定，但具体器件/步骤/参数须下沉到"具体而言"**。

1. **问题要素**：从背景技术/区别特征所暴露的不足中提炼“缺什么、坏在哪、风险是什么”（如排泄不畅、失稳后直冲行车道、暴露致强度衰减），可并列 2～3 个相互独立的问题要素。
2. **可留方向性、禁止堆砌具体手段**：问题句可保留"如何在……前提下，获得/确定……"的方向性骨架（范文即用"如何在不改装内部承载件、不干扰进风工况的前提下，获得可推算轴向载荷的位移信息"）；但**不得把权利要求中的具体结构、步骤、参数、施工时序、器件选型堆进问题句**。反例：“如何通过竖向锚杆基础实现不挖地基的坡脚支挡并与墙—坡面分层排水相协同……”——把整套方案写进了问题。
3. **手段归“具体而言”**：区别特征如何针对各问题要素起作用、用了什么具体器件/试验/结构，只在紧随的“具体而言，……”中展开；问题句本身保持要素导向。
4. **与“足够具体”的关系 + 判据**：“具体”指问题要素相对审查员万能上位（提高精度/效率/可靠性等）足够可区分，**不是**把独权手段清单塞进问题句。**自检：删去问题句中的具体器件/步骤/参数名词后，是否仍能看清要解决什么缺陷；能，则合格（方向性限定可保留）；若删后只剩空泛愿望或根本读不懂，则须重写。**
5. **对抗审查员上位时同样遵守**：指出审查员概括“未能具体反映……问题要素”，对比用语也用问题要素，避免用“未能反映××结构/××步骤带来的效果”把手段又写回问题对比句（效果镜像留给 2.3）。

### 技术问题界定后必须对比审查员概括（仅在 2.1 / 3.1）

1. 先写申请人界定的实际技术问题（**问题要素为主、方向性可留、具体手段下沉**）。
2. “具体而言，……”简要展开（**此处才对应区别特征与具体手段，首句宜为发明构思命名句**）。
3. **紧跟**：`审查员将实际解决的技术问题概括为“【审查员用语】”，该概括未能具体反映【①…②…③…】。相较而言，上述技术问题更能客观体现……`（**对比清单化，逐条点名审查员漏掉的问题要素/效果**）
4. 不得只写自己的问题而不点出审查员概括何处不当。
5. **只在区别特征分析节（2.1 / 3.1）完成上述“界定 + 对比”整段**；后续非显而易见性节不得整段重复该界定。
6. **为 2.2/3.2 预留可回扣的问题锚点**：问题表述应以问题要素写清、可被短句引用；写完 2.1 后自检——若删去该技术问题，后文“无启示”是否会失去判断对象；若会，说明衔接设计正确。另自检手段是否误入问题句（见上节）。

## 情形分支：修改与否 × 一通/二通

先判**通知书次数**（上文），再判是否修改：

- **情形一｜修改了权利要求**：写「修改说明」——将拟补充内容**接到原独立权利要求末尾**（并入来源 + 完整新增原文；法33条 + 细则第57条第3款在删权/适应性修改条之后**合并声明一次**）。并入哪一条/哪些权利要求须遵守下文「修改策略」（**以一次答复争取授权为默认目标：核心区别特征成组并入 + 平衡保护范围不过窄 + 梯度防御靠保留从权**）。
  - 一通：修改说明 → 三段论（2.1→2.2→2.3，2.2 内嵌审查员观点）。
  - 二通：修改说明可并入开场后；**先**「针对第N次审查意见核心观点作答」，**再**创造性收束（含 2.1）。
- **情形二｜未修改**：开头“申请人坚持原权利要求”。
  - 一通：坚持原权 → 三段论全文。
  - 二通：坚持原权 → **先**核心观点逐条作答 → **再**创造性收束。

## 修改策略（硬性；一通尤其适用；单独成步交付）

**默认目标：以一次答复争取授权，同时保护范围不过窄**——把**能立住创造性所必需**的核心区别技术特征成组并入独权，**不为"留后手"而故意把核心点保留给二通**；但**一次授权 ≠ 凡有区分度的特征都并进独权**。并入以"**够用能立住创造性**"为度：构成完整逻辑链条、足以拆掉本轮审查逻辑即可，**禁止**为"更稳妥"把次要结构、可选实施方式、纯参数等一股脑堆进独权，以致保护范围过窄。梯度防御靠**其余**有价值从权在末节作"退一步·独立防线"，而非靠对独权藏招，也非靠无节制加限定。

> 这与老师范文（PA23-1239 案）实际做法一致：把从权 3 + 说明书 [0065] 的核心区别并入装置独权、把从权 7/8 + 说明书多段并入方法独权以争取一次授权，同时**仍保留权 7、8 为独立从权**，在"三、其他权利要求"用"退一步"作独立防线——核心并入、非核心保留，而不是把核心留到二通，也不是把能并的都并完。

### 核心原则

1. **并入对象=能立住创造性的核心区别特征（宜精选）**：从现有从权、以及**说明书已记载且符合法33条、可改写成权利要求的技术内容**中，选出直接支撑申请人界定的实际技术问题、相对最接近现有技术**区分度最高、审查员最难用"常规手段/简单叠加"一笔带过**的特征并入独权。**并入来源必须同时考虑从权与说明书，不得只搬从权。** 同一发明构思下构成完整逻辑链条的必要特征应成组并入（避免只摘孤点导致说不圆），但链条外的增强/优选特征默认留从权。
2. **并入充分度：以"够用一次立住"为标尺，反对少并也反对滥并**：须使 2.1 技术问题具体、2.2 启示否定站得住、2.3 效果闭环；**不要**因怕缩范围而只并入孤零零一处、创造性说不圆。同时**不要**因追求"一次授权更稳"而把权2至权N或说明书可选细节全部并入——那是过窄，不是平衡。
3. **范围平衡（硬性；双向自检）**：
   - **够不够**：删去核心并入层中任一特征后，本轮创造性是否说不圆？若说不圆，该特征应留在独权（成组必要）。
   - **窄不窄**：对每一处拟并入限定另问——删去它，本轮创造性是否**仍成立**？若仍成立且它明显缩小范围（次要结构细化、可选驱动方式之一、纯尺寸/数量/材料等），则**不并入**、下放/保留为从权。
   - **禁止两极**：禁止"几乎不改独权、全靠争辩"；也禁止"能并尽并、独权写成实施例清单"。
4. **梯度防御靠"保留从权 + 精选展开"实现，而非靠对独权藏招或滥并**：核心并入后，其余有价值从权保留；在其他权利要求节**仅挑选 1～2 项**作"退一步·独立防线"，其余一句依附概括。
5. **确有多轮预期时的例外**：仅当案情复杂、争点多、预判一次难以说服时，才可有意识保留个别专克潜在下一轮争点的从权；默认不这样做。
6. **用户已指定并入方案时**：以用户方案为准，但修改策略步仍须标明哪些属"核心并入"、哪些属"保留作独立防线"；若用户方案并入不足（创造性说不圆）或并入过度（范围过窄），须提示风险，确认后再执行。

### 修改策略步必做：权利要求修改分层清单（情形一时；禁止并入第1步）

本清单在**第2步（与 plan 同批）**输出，**不得**与第1步的材料核对/手法组合同批交付。输出一张表（交用户确认）；默认只给**一套平衡主方案**（够用立住 + 不过窄），不要并列"少并/多并"菜单除非用户索要备选。

| 层级 | 权利要求编号（或说明书可支持改写来源） | 为何并入/保留 | 建议处置 |
|------|--------------------------------------|------------------|----------|
| **核心并入独权（争取一次授权；够用即可）** | 如原从权 X + 说明书第[..]段 | 区分度最高 / 问题锚点 / 构成完整逻辑链条所必需 / 对抗本轮审查逻辑 | 成组接到独权末尾 |
| **保留作独立防线（不并入）** | 如原从权 Y、Z | 有价值但对独权创造性非必需；并入会不必要缩窄范围；末节**择 1～2 项**作退一步独立抗辩 | 保持从权；标明"精选展开"候选 |
| **仅论证引用、不修改** | 说明书段落… | 支持效果/机理 | 不写入独权 |

自检（须同时满足）：

- **并入是否够立住创造性**：假设只保留"核心并入"层，2.1 是否具体、2.2 启示否定是否站得住、2.3 是否闭环？若否，上调并入。
- **范围是否被不必要缩窄**："核心并入"层里是否有删去后创造性仍成立、却明显缩小范围的限定？若有，下放为从权。**若几乎把全部从权都列入核心并入，应视为过窄警报，重新精选。**
- **多独权是否都已处理**：装置独权与方法/系统独权若都被评述，是否都做了核心并入（见修改说明步"多独权分别写"）。

### 与答复正文的衔接

- **2.1** 围绕**已并入（或坚持）的独权**成组列区别特征与技术问题；两独权共用同一发明构思时可在 2.1 内并列列"区别特征（1）/（2）"（见 2.1"多独权结构二选一"）。
- **2.2/第一部分** 论述整体性时可提及并入特征之间的协同；保留作独立防线的从权特征不得暗示已是独权一部分。
- **其他权利要求节** 把"保留作独立防线"的从权中**精选 1～2 项**兑现为"退一步·独立防线"论证，其余从权仅依附概括，形成"修改策略平衡并入 → 修改说明落地 → 末节精选抗辩"的闭环。

## 答复要点：核心必达 + 视情选用

**A. 核心必达**

1. **区别技术特征**（落在 2.1，编号 + 原文）
2. **实际解决的技术问题** + **与审查员概括对比**（落在 2.1；只在此完整论述；**问题要素为主、方向性可留、具体手段下沉；对比清单化**）
3. **非显而易见性 + 技术启示否定**（一通：落在 2.2；二通：主战场在第一部分，2.2 回引补漏）：以 2.1/3.1 所述实际技术问题为锚点；不得用“未公开”代替“无启示”；按"首先破上位→其次破方向动机→再次破鸿沟"递进；可用表达增强手法（工具箱 I）
4. **有益效果 / 显著的技术进步**（落在 2.3/3.3；呼应 2.1 技术问题；**叙述式、反 AI 腔**；不在逐条答复里做效果收束）
5. **引述审查员结论性观点**（一通嵌入 2.2；二通作为第一部分标题靶子）
6. **修改说明**（仅情形一）+ **权利要求修改分层**（核心区别特征成组并入争取一次授权 / 保留从权作独立防线 / 仅论证引用；平衡保护范围不过窄）

**B. 视情况选用**（按案情组合，服务于递进链条，不必全覆盖）

- 过度概括、事后分析、正常研发路径、相反教导/互斥、变好变差分类、技术鸿沟、失败预期、结合冲突、结合障碍、领域可迁移、退一步/再退一步、整体协同等——第1步选出后**排成递进序**再写。

## 硬性流程规则（最高优先级）

1. **禁止一次生成答复全文**；**禁止一次生成整节 2.2**（含多项“第【序】、针对审查意见指出的”与“首先/其次/再次/最后”同批输出）。2.2 必须按「逐条答复子步 × N + 体系化归纳子步 × 1」拆分，每子步只交付一条答复或仅归纳段。
2. **第1步不得夹带修改策略与 plan（硬性）**：第1步只交付材料核对、一通/二通判定、结论清单、变好/变差预分类、手法组合、独权清点、是否倾向修改的一句判断及篇幅分配提示。**权利要求修改分层清单**与**plan 待办清单**合并为第1步之后的**同一步**交付（先分层、后 plan，同一回复内完成），**禁止**塞回第1步，也**禁止**再拆成两个独立步骤；用户确认该合并步后，再进入修改说明/正文。
3. **先判一通/二通，再分析选法**：摘出审查员结论性论断；为每条挑选 2–4 种**本案事实真正撑得住**的手法，并给出**递进顺序**（为何先写 A 再写 B）；**并非每种都用**；选法与组合方案须先交用户确认。工具箱只收通用手法，案情特有表述不得默认选用。
4. **内在合理性优先于套模板（硬性）**：骨架（一通三段论 / 二通观点作答、2.1→2.2→2.3、引述后拆解）必须遵守；**手法层数、退一步措辞、失败预期、互斥、听谁的、违背初衷等不是填空题**。落笔前对拟用的每一环自问：对比文件客观教导是否支持该论断？本领域人员申请日前会否认同？若只能靠夸大、臆测或套话才能写下去，**弃用该环**，宁可链条短而真，不可为凑“其一/其二/其三”或五层框架强行说理。第1步选法表须标注每环的**事实支点**；支点不足的手法不得进入正文。
5. **用 plan/待办清单驱动全过程**：plan 在**与修改策略合并的那一步**建立（不得塞进第1步，也不再单列 plan 步）；一通按三段论步骤拆，且**2.2 须按审查结论条数再拆为 N+1 个子步**（N 条逐条答复 + 1 步体系化归纳）；二通按“核心观点①②③…（每条一步）+ 2.1 + 收束”拆；逐步更新状态，始终只有一个“进行中”。
6. **一步只做一个交付物**；须等用户确认再进入下一步；按用户提示推进。**2.2 的一个交付物 = 一条逐条答复，或 = 体系化归纳段，不得合并。**修改策略与 plan 合并为一步交付物，不得并回第1步，也不得再拆成两步。
7. 用户要求“一口气写完”时仍分步；修订也按步。**用户要求“一次性写完 2.2”时，仍须按 2.2 子步逐条交付，不得合并。**
8. **对话展示加粗（硬性）**：修改说明、2.1、2.2/3.2、2.3/3.3、二通第一部分、其他权利要求、组装全文在对话中必须对 1～3 处关键句 `**加粗**`，保证用户看得见粗体。
9. **纯文本版零星号（硬性）**：工作稿或明确标为“可复制纯文本”的正文不得含 `*`；与展示版仅差加粗标记。**禁止**文末「建议手动加粗」。第1/2步过程性交付不加粗。

若有两项独权，plan 中的“三节各一步”适用于**每一项独权**：权利要求1的 2.1/2.2（含全部子步）/2.3 完成并确认后，再依次撰写第二项独权的 3.1/3.2（含全部子步）/3.3；不得一轮同时交付两项独权的全部创造性正文。**第二项独权的 3.2 适用与 2.2 相同的分步规则。**

每步输出格式：`【第X步 / 共N步】步骤名称` + 对话展示版正文（关键句已 `**加粗**`）+ 可复制纯文本版（无 `*`，可与展示版同文去标记后写入工作稿）+ 请用户确认 + 预告下一步。**不得**只给纯文本却无加粗展示；**不得**输出「建议手动加粗」段。

## 适用场景

- 审查意见指出不符合专利法第22条第3款（创造性）需书面答复。
- 第N次通知书；**次数、发文日、申请号按用户材料填写**。
- 不区分结构类/方法类/算法类。

不适用：仅新颖性、超范围、不清楚、得不到说明书支持、单一性等且不夹带创造性评述。

## AI 能力边界

- 不得编造对比文件未记载内容、段落号、效果或公知常识出处。
- 不得把本申请特征事后拆开贴回对比文件当作“启示”。
- 信息不足时只论证已能支撑的部分，并列出待核引用。

## 分步流程（必须按序执行）

**一通流程：**

```text
第1步 材料核对 + 判明一通 + 结论清单 + 手法组合（含递进序）+ 独权清点
     （禁止输出修改分层清单；禁止输出完整 plan）
  ↓
第2步 修改策略建议 / 权利要求修改分层清单 + 建立 plan 清单（同一步；够用立住 + 不过窄）
  ↓
第3步 修改说明 / 坚持原权
  ↓
第4步 2.1 区别特征 + 技术问题 + 与审查员概括对比
  ↓
第5步 2.2-① 标题 + 第1条逐条答复（仅一条“针对审查意见指出的”）
  ↓
第6步 2.2-② 第2条逐条答复（仅一条，不写重复标题）
  ↓
……（审查结论有几条拆几条，每条独占一步；无新结论的可合并入相关条，但一步仍只交付一条）
  ↓
第(4+N)步 2.2-末 体系化归纳（仅“首先/其次/再次/最后”；禁止重复粘贴各逐条答复）
  ↓
第(5+N)步 2.3 显著技术进步（镜像 2.1）
  ↓
第(6+N)步 第二项独权 3.1/3.2-①…/3.2-末/3.3（若有；3.2 同 2.2 分步）
  ↓
第(7+N)步 其他权利要求 → 组装
```

> **总步数 N_total**：在原有正文步之外，固定多出「修改策略+plan」合并步一步。情形一且有修改说明时，前端为第1～3步（材料 / 修改策略+plan / 修改说明），其后 2.1 起算；K = 2.2 逐条答复条数。该合并步须算出 K 并列出逐步名称。

**二通及以后流程：**

```text
第1步 材料核对 + 判明二通 + 结论清单 + 手法组合（含递进序）+ 独权清点
     （禁止输出修改分层清单；禁止输出完整 plan）
  ↓
第2步 修改策略建议 / 权利要求修改分层清单 + 建立 plan 清单（若需修改；同一步）
  ↓
第3步 修改说明 / 坚持原权（若有）
  ↓
第4步-①/②/③… 「针对第N次审查意见核心观点」逐条作答（主战场；递进拆解）
  ↓
第5步 2.1 区别特征 + 技术问题 + 与审查员概括对比
  ↓
第6步 2.2 收束（回引第4步已论证要点；补足启示否定；单独一步）
  ↓
第7步 2.3 显著技术进步（镜像 2.1；单独一步）
  ↓
第8步 第二项独权（若有；同样“观点作答为主 + 三段论收束”）
  ↓
第9步 其他权利要求 → 第10步 组装
```

### 第1步：材料核对 + 一通/二通 + 结论清单 + 手法组合 + 独权清点（必做交付物）

**必收材料**：通知书（含次数）、对比文件要点、当前权利要求书、拟修改方案或坚持不改；二通时尽量附一通答复要点，避免复读。

**本步交付物（仅此范围；多交即违规）：**

1. 材料齐备情况表；**明确本次为一通或二通及以后**。
2. 审查意见结论清单（结合动机型 / 问题界定上位型 / 常规公知型 / 特征抽取拼贴型 / 教导忽略型）。
3. **变好/变差预分类（推荐）**：假设将本申请手段植入对比文件1，对比文件1会变好还是变差/互斥？据此选择主攻链条（见工具箱 F）。
4. **逐条手法组合（不是清单堆砌）**：每条挑 2–4 种手法（可更少），写明**递进顺序**、理由，以及每环的**事实支点**（对比文件哪一公开 / 本申请哪一区别特征能撑住该论断）；支点写不出的手法直接剔除。输出对照表（审查结论 / 类型 / 手法组合及顺序 / 事实支点 / 对应区别特征编号 / 落点）。**不是每种都用**；目标是组成**最有说服力且说得圆的一条链**。
5. **独权清点（硬性）**：独立权利要求数量、编号、主题、是否方法/系统对应保护。
6. 一句判断是否倾向修改，并说明**一通/二通**下的篇幅分配（一通：三段论为主；二通：观点作答为主）。**不在本步展开并入哪些从权/说明书段落，不输出分层表，不建立 plan。**

**本步明确禁止：**

- 输出「权利要求修改分层清单」或具体并入方案（含少并/多并菜单）；
- 输出完整 plan / 待办逐步名称表。

本步末尾预告：下一步为**修改策略建议 + plan（同一步；够用立住 + 保护范围不过窄）**。

### 第2步：修改策略建议 + plan 清单（同一步；禁止拆开，也禁止并回第1步）

**本步交付物（同一回复内按下列顺序输出，不得拆成两次回复）：**

**A. 修改策略 / 权利要求修改分层清单**  
按上文「修改策略」输出分层清单（核心并入 / 保留防线 / 仅论证引用），默认**一套平衡主方案**；标注末节拟精选展开的 1～2 项从权；完成“够不够 / 窄不窄”双向自检。情形二（坚持不改）时改为列出“若审查员坚持则必要时可并入的核心特征候选（仍按够用不过窄口径）”。

**B. plan 清单**  
紧接 A 之后，按一通或二通流程列完整待办；二通须把“核心观点①②③”列为独立待办。**一通时须把 2.2 拆为独立待办**：`2.2-① 第1条答复`、`2.2-② 第2条答复`……`2.2-末 体系化归纳`，**每条审查结论性论断对应一个待办，不得合并为“写 2.2”一项**。写明 K（逐条答复条数）与总步数；固化“修改说明 / 坚持原权”之后的正文路径。

**禁止：** 与第1步手法表同批；把 A、B 拆成两个独立步骤分两次交付；默认把几乎全部从权堆进独权。

本步末尾预告：下一步为**修改说明 / 坚持原权**。

### 第3步：修改说明 / 坚持原权

**情形一**：把修改策略步确认的**核心区别特征**（来源=从权 ∪ 说明书已记载内容）**接到对应独立权利要求末尾**。修改说明须**逐条编号、逆向选特征、可溯源**，遵守以下 7 条规范：

1. **逐条编号，体例固定**：一条修改一个条目。第1条（及多独权时的后续并入条）固定四拍：①单独一句“申请人对原独立权利要求X进行了修改。”→ ②“根据原权利要求……的附加技术特征，以及原说明书第[…]段的记载，在原独立权利要求X的末尾增加以下内容：”→ ③引号照录新增原文 → ④“从而形成新的权利要求X。”**法条声明不写在本条末尾**，统一放到删权/适应性修改条之后（见第6点）。
2. **依据多源、精确到段**：并入来源同时考虑从属权利要求与说明书；凡以说明书为据，必须写明精确段号（如“以及原说明书第[0033]、[0034]、[0035]段的记载”），为法33条超范围抗辩预埋证据。**不得只搬从权而漏掉说明书里能拉开区分度的支持性记载。**
3. **多独权分别写**：装置独权与方法独权同被评述时，**各写一条独立修改说明**（各自的并入依据与新增原文），不得只实质补强一个、另一个仅调引用带过。多独权时法条合并声明仍只在全部并入条与删权条写完后出现一次。
4. **逆向选特征**：先想清 2.1 要立的区别、2.2 要破的启示、2.3 要挂的效果，再回头决定并入哪些特征；修改说明服务于后文论证，不是孤立形式段。
5. **适应性调整从简表述（硬性）**：删从权、重编号、调引用等适应性调整**必须做**，但在修改说明正文中**只用一条概括句带过**，不得逐条列出“原权利要求X→新权利要求Y”对照表，不得展开各从权引用关系调整明细。写法示例见下文模板第2条。
6. **法条合并声明（硬性；一次收束）**：在删权/适应性修改条之后，用**一段**收束声明，固定句式：“上述修改是针对第【N】次审查意见通知书指出的创造性缺陷作出的，未超出原说明书和权利要求书记载的范围，符合专利法第33条以及专利法实施细则第57条第3款的规定。”**禁止**在每条并入说明末尾分别再写一遍法33/细则；**禁止**仍写旧细则第51条（现行答复性修改对应细则第57条第3款）。
7. **防重复并入自检**：并入某从权的特征后，该从权应删除；若仅并入其部分特征、保留其余作独立防线，须明确界定"哪部分已并入、哪部分保留"，杜绝"同一特征既并入独权又作为从权保留"的编号/逻辑冲突（老师范文里"原权8 特征既并入方法独权又作新权7"即此类需警惕的隐患）。

> 1、申请人对原独立权利要求1进行了修改。
> 根据原权利要求【X】、原权利要求【Y】的附加技术特征，以及原说明书第【a】、【b】段的记载，在原独立权利要求1的末尾增加以下内容：
> “【接在原独权末尾的完整新增文字，通常以「其中，……」或直接续写部件限定起句；成组并入时逐项照录】”
> 从而形成新的权利要求1。
>
> 2、鉴于原权利要求【X、Y、Z（已并入者）】的相应附加技术特征已并入新的权利要求1，申请人删除了原权利要求【X、Y、Z】，并对其余权利要求的编号及引用关系进行了适应性修改。
> 上述修改是针对第一次审查意见通知书指出的创造性缺陷作出的，未超出原说明书和权利要求书记载的范围，符合专利法第33条以及专利法实施细则第57条第3款的规定。
>
> **第2条写法要求**：删权句一句概括即可；**禁止**另附表格或逐条写明“原权利要求4→新权利要求2”等编号映射；删了哪些从权可点名，其余用“适应性修改”收束。法条声明紧接本条之后，不另起“3、”纯法条条。
>
> （若有第二项独权需并入特征，编号顺延，例如：）
> 2、申请人对原独立权利要求【方法/系统独权编号】进行了修改。
> 根据原权利要求【Y、Z】的附加技术特征，以及原说明书第【…】段的记载，在原独立权利要求【编号】的末尾增加以下内容：
> “……”
> 从而形成新的权利要求【编号】。
>
> 3、鉴于原权利要求【凡已并入者】的相应附加技术特征已并入新的权利要求【…】，申请人删除了原权利要求【…】，并对其余权利要求的编号及引用关系进行了适应性修改。
> 上述修改是针对第一次审查意见通知书指出的创造性缺陷作出的，未超出原说明书和权利要求书记载的范围，符合专利法第33条以及专利法实施细则第57条第3款的规定。
>
> （仅一项独权修改时：删权条为第2条，法条声明紧接第2条之后，不另起纯法条编号条。）

**情形二**：仅一句坚持原权利要求。若一通选择不改（较少见，因默认导向一次授权），修改策略步仍可列出"必要时可并入的核心特征候选"，供后续使用。

严格按上文「2.1 模板」输出；顺序为编号原文特征 → 未公开说明 → 实际技术问题 → 具体而言 → **与审查员概括对比**。标题用：

> 2.1、申请人认为，权利要求1与最接近的现有技术对比文件1相比，至少具有以下区别技术特征：

本步结束前自检：技术问题是否以**问题要素**写清（未植入结构/步骤/时序等手段）、是否足够具体以区别于审查员万能上位，能否用“如 2.1 所述实际技术问题”一句回扣并作为技术启示判断的对象；手段是否仅出现在“具体而言”而不在问题句。

### 一通·第5步起：2.2 非显而易见性（**必须拆为多子步，禁止整节一次输出**）

2.2 整体严格按上文「2.2 模板」「技术问题 → 技术启示衔接」及“充分论证的最低要求”撰写，但**交付时必须拆步**：

#### 2.2-①（一通第5步）：标题 + 第1条逐条答复

- **本步只交付**：2.2 标题 + **一个**“第【一】、针对审查意见指出的：……对此，申请人答复如下：其一……（其二/其三视需要）”段落。
- 标题用：

> 2.2、权利要求1所保护的技术方案是非显而易见的。

- “针对审查意见指出的：”后短文照录/长文概括**本条**审查结论；
- 按第1步为本条选定的**递进序**展开；凡涉结合/启示/常规，须写明针对如 2.1 所述实际技术问题无采用区别特征（N）的技术启示；
- 不整段重复技术问题；禁止效果收束；**本步不得写“第二/第三”条答复，不得写“首先/其次/再次/最后”。**
- **本步对话展示须对 1～2 处关键结论句加粗**；工作稿/纯文本版去 `*`；禁止文末「建议手动加粗」段。

#### 2.2-②…（一通第6步起）：后续逐条答复

- **每步只交付一个**“第【序】、针对审查意见指出的：……”段落；**不写** 2.2 重复标题，**不写**其他条答复，**不写**体系化归纳。
- **对话展示加粗关键句**；纯文本版零星号；禁止「建议手动加粗」段。
- 条数 = 第1步结论清单中拟正面交锋的审查结论数（通常 2–5 条；从属权利要求可并入其引用独权所对应的答复条，不必机械一条从权一步）。

#### 2.2-末：体系化归纳（单独一步）

- **本步只交付**“在此基础上，申请人进一步归纳如下：”及 **首先/其次/再次/最后** 四层归纳；
- 用“如本意见前文针对审查意见第×点所述……”回引已确认逐条答复，**禁止**重复粘贴各条全文；
- 每层须回扣 2.1 技术问题 + 区别特征（N）+ 有无技术启示；
- **本步不得新写“第【序】、针对审查意见指出的”逐条答复。**
- “首先/其次/再次/最后”用纯文字序号；对话展示对归纳结论句加粗；纯文本版零星号；禁止「建议手动加粗」段。

#### 2.2 分步硬性禁令（复述）

| 禁止 | 正确做法 |
|------|----------|
| 一次输出“第一、第二、第三、第四”全部逐条答复 | 每条答复独占一步，用户确认后再写下一条 |
| 逐条答复与“首先/其次/再次/最后”同批输出 | 全部逐条答复确认后，单独一步写归纳 |
| 为凑步数把同一审查结论拆成多个碎段 | 一条审查结论 = 一步；过碎则合并，但一步仍只交付一条 |
| 用户说“继续/下一步”时跳过尚未写的答复条 | 按 plan 顺序依次交付，不得跳步 |
| 对话展示版未对关键句加粗，用户看不见重点 | 展示版必须 `**加粗**` 1～3 处 |
| 纯文本/工作稿残留 `*` | 纯文本版删除全部 `*` |
| 文末另列「建议手动加粗」 | 取消；加粗已在展示版完成 |
| 给第1步/第2步过程性内容加粗 | 仅答复正文展示版加粗 |

### 二通·第4步起：针对第N次审查意见核心观点逐条作答（主战场；**每条一步**）

- 大标题建议：`一、针对第【N】次审查意见的核心观点作答如下：`（在首条子步与第一条一并写出）
- **每个子步只交付一个** `第【序】、针对审查意见指出的：` + 引述/概括 + `对此，申请人答复如下：` + 按递进序拆解；**禁止**同批输出多个“第【序】”；
- **对话展示加粗**（规则同 2.2）；纯文本版零星号；禁止「建议手动加粗」段。
- 技术问题若尚未写 2.1，可先用临时锚点句“本申请实际要解决的是……”，并在后续 2.1 固化同一表述；若 2.1 已写，则用“如 2.1 所述……”；
- **禁止**把二通写成与一通同构的超长三段论复读；本步写透审查员观点；
- 禁止在本步做有益效果大段收束（留 2.3）。

### 二通·第6步：2.2 收束（单独一步）

- 2.2：回引第一部分已论证的启示/动机/鸿沟要点，补足尚未覆盖的 D1/Dx 分析与技术启示锚点句；**本步只写 2.2 收束归纳，不写 2.3**。

### 二通·第7步 / 一通·第(5+N)步：2.3 显著的技术进步（有益效果统一在此；**单独一步**）

本节必须**单独成节并深入论述**，严格按上文「2.3 模板」「深入论述须覆盖的实质层次」及「行文风格（反 AI 腔）」输出。标题用：

> 2.3 修改后的权利要求1的技术方案具有显著的技术进步

- 效果挂在区别特征（N）上，与 2.1 技术问题呼应（**叙述中自然覆盖，不强制列镜像提纲**）。
- 写入 2.2 各子步针对性答复时**刻意留到本步**的全部有益效果要点。
- 优先用**工作流程叙述式**（1～3个连贯段落 + 收束句），**默认不用**填表式三点四段式。
- 不用“机制/直接效果/逐点对比/场景价值”等标签；对话展示对核心效果/法22.3收束句加粗；纯文本版零星号；禁止「建议手动加粗」段。
- 以创造性符合法22.3的收束句结束本节。

### 第二项独立权利要求（存在时，拆为三个子步骤）

若本案有第二项独权，对其分别撰写：

- **3.1 区别技术特征 + 实际技术问题 + 与审查员概括对比**（技术问题仅在此完整论述）；
- **3.2 非显而易见性**：充分程度不低于第一项独权；**分步规则同 2.2**（逐条答复每步一条 + 归纳单独一步）；共同论点可准确引用 2.2，但须补充第二项独权特有的结构/模块/数据流与现有技术差异；**不整段重复 3.1 已写的技术问题**，但必须完成以 3.1 所述技术问题为锚点的技术启示否定论证；
- **3.3 显著的技术进步**：单独成节，写清第二项独权自身“特征 → 机制 → 效果”链，并与 3.1 技术问题呼应；**行文风格同 2.3（叙述式、反 AI 腔）**。方法独权的效果不能机械复制为系统独权效果。

若两项独权分别为方法与系统，3.2/3.3 至少核对：

1. 系统模块是否只是功能名称，还是限定了特定连接/数据流/协同；
2. 模块组合如何实际承载方法中的关键步骤；
3. 系统独有结构是否产生额外技术作用；
4. 对比文件是否真正公开相同模块关系，而非仅公开相似功能；
5. 即使共同发明构思已在 2.2 论证，系统化实现是否仍需无启示的结构改造。

不存在第二项独权时，在 plan 中将本步标记为“不适用”，不得虚构。

### 其他权利要求（梯度防御 / 退一步·独立防线；**精选 1～2 项展开**）

本节分两层：**全体从权**作简短依附概括；**仅 1～2 项**重点从权作"退一步·独立防线"深入论证。**禁止**对每一项从权都按"小独权"标准逐条展开——篇幅过长、重复 2.2/2.3 已论证内容，且显模板化。

#### 精选哪 1～2 项（修改策略步应预先选定）

从"保留作独立防线"的从权中，按下列优先级择 **1～2 项**（通常不超过 2 项；仅 1 项亦足）：

| 优先级 | 选取标准 | 示例 |
|--------|----------|------|
| 1 | 审查意见**单独点名**或重点评述的从权 | 审查员专段论述的权4、权9 |
| 2 | 与对比文件差异**最立体**、最难被"常规选择"一笔带过的从权 | 进料引导至主燃区、特殊判据/结构关系 |
| 3 | 对独权创造性**形成有效补强**、且未在 2.2/2.3 充分展开的特征 | 独权未并入但说明书有明确机理支持的从权 |
| 低 | 纯参数范围、纯数量、纯角度等常规优选 | 孔径 3–25mm、坡角 0°–45° 等——**默认不选**，除非审查员专评且该案仅此争点 |

**不选**：与已并入独权的特征实质重复者；与 2.2 已充分反驳的审查逻辑完全同构者；仅为"凑齐从权都写了"而选的弱从权。

修改策略步分层清单中须写明：`其他权利要求节精选展开：新权X、新权Y（理由：……）`；用户另有指定时从其指定。

#### 正文结构

**第一层（必写，简短）：依附概括**

> 新的权利要求【2】至新的权利要求【N】直接或间接引用新的权利要求1。在新的权利要求1具备创造性的前提下，上述从属权利要求亦具备创造性，符合专利法第22条第3款的规定。

一句即可覆盖**全部**未单独展开的从权；**不得**对每一项从权再写"权利要求X具备创造性，因为……"的重复段落。

**第二层（可选，仅 1～2 项）：退一步·独立防线**

仅对 7.1 精选的从权，用统一起句（写一次即可）：

> 退一步而言，即使审查员对独立权利要求1的创造性持保留意见，以下从属权利要求的附加技术特征同样构成相对于对比文件1、对比文件2及其结合的实质区别：

然后**每项精选从权各写一段**（不是四段式小论文），包含：
- 该从权附加特征的技术含义（1～2 句）；
- 对比文件未公开或未教导之处（穿插对比，不机械 D1/D2/D3 三连）；
- 落回"该从权具备创造性"（1 句）。

**精选 2 项时**：两项合起来通常 **2～4 个自然段**（含起句），不宜更长。

#### 护栏

1. **数量硬性**：深入论证的从权 **≤ 2 项**；用户明确要求展开更多项时最多 3 项，须说明理由。
2. **其余从权**：只靠第一层依附概括带过，**不点名、不逐条论证**。
3. **事实为据**：精选从权的独立抗辩仍须以对比文件事实为据，不得为凑防线强行说理。
4. **对话加粗 + 纯文本分离**：同加粗展示与纯文本分离规则。
5. **不重复 2.2/2.3**：已在前文充分论述的效果或区别，从权抗辩只补**该从权附加限定**带来的增量区别，不整段复读独权创造性。
6. **禁止「建议手动加粗」段**：文末不再另列提醒。

仅当前述各步均确认后拼接。按情形及独权数量使用下文骨架。附检查清单自检。

## 反驳手法工具箱（第1步据此选法并组合；一通写入 2.2，二通写入第一部分）

**备选清单而非必用清单**。只收可跨案件复用的通用手法。目标不是“用得越多越好”，而是**组出一条最有说服力的递进链**。

> 个别案件审查意见里的特有表述（例如“对比文件没有排除某手段，故有动机……”）属**案情特例**，不是通用手法，不得收入工具箱、更不得默认选用；仅当本案确有同类表述时，可按事后分析（第1项）等通用逻辑就事论事反驳。

### A. 结合动机 / 显而易见

1. **反对事后分析（事后诸葛）**：申请日前看对比文件，不会反向抽取本申请框架再投射回去
2. **正常研发路径叙事**：先发现具体问题再设计手段；反对“忽略问题发现难度、拆解手段再宣称容易想到”
3. **根本差异 → 相反教导 / 互斥方案（teaching away）**
4. **自洽闭环、缺失动机与核心功能**：对比文件1已能独立完成其目标时，无引入额外环节的动机

### B. 技术问题界定

5. **纠正技术问题过度上位**：扳倒“提高准确性/效率”等万能问题；回到区别特征对应的**具体问题要素**（与 2.1 呼应）；纠上位时仍禁止把独权手段写进问题句

### C. 简单迁移 / 常规调整

6. **反对过度概括对比文件**：反对抽掉前提条件与整体方案后的“上位思想 + 特征抽取”
7. **相反方向 / 无逆向动机**

### D. 公知常识 / 跨领域

8. **领域可迁移性反驳**：场景前提不同则不可当作通用手段直接迁移

### E. 递进退让

9. **退一步：从思想到方案的鸿沟**
10. **再退一步：结合后冲突无规则**（两套逻辑听谁的？）
11. **结合障碍：违背对比文件初衷**（成本/效率/复杂度与 D1 发明目的冲突）

### F. 植入后“变好 / 变差”预分类（选主攻链用）

先问：若对比文件1采用本申请手段，会变好还是变差/互斥？

| 类型 | 典型信号 | 主攻递进链（示例；须逐环验真） |
|------|----------|-------------------|
| **变差/互斥** | 改变 D1 原理、破坏其必要条件、增加无谓复杂 | 仅当互斥/无动机**事实成立**时用 3/4 → 5 纠上位 → 6 过度概括 → 针对 2.1 问题无启示 →（成立时）11 违背初衷 |
| **看似变好** | 提高稳定/排水等普遍动机说得通，具体方案对不上 | **主链宜短而真**：6 客观教导差异（作用并非审查员所说的相同）→ 针对 2.1 问题无启示 →（成立时）9 从普遍动机到本案具体方案仍有鸿沟。**不要默认写失败预期、听谁的、违背初衷**——边坡支挡排水类案件里“结合会注定失败”往往说不圆，硬写即强行说理 |

“看似变好”常用要点（按事实取舍，不必写满）：

1. 承认加强稳定/改善排水等普遍动机说得通，但普遍动机不等于教导采用**本申请这一具体手段组合**；
2. 紧扣对比文件客观公开：部件位置、连接关系、施工对象与区别特征（N）是否同一，作用是否针对如 2.1 所述问题要素；
3. 若存在真实缺口，再写从“想改进”到“得到区别特征（N）”缺哪一步教导；**仅当本领域人员确会预见失败或方案互斥时**，才写失败预期/反向教导；
4. 问题发现难度、整体协同：仅当对1未暗示如 2.1 问题要素、或特征间确有不可拆的前提关系时使用。

### G. 针对“上位思想 + 常规细节”的递进（可选用，仍须逐层验真）

审查员逻辑常为：把问题/效果上位成常规 → 再称区别特征常规或容易想到。可选用层次如下，**每一层用前先验本案是否成立**：

1. 指出对对比文件的上位化概括脱离实际教导；
2. 即便存在框架思想，从框架到本案具体方案仍有鸿沟（须能指出缺哪一环教导）；
3. 对比文件1整体教导是否真的阻碍“引入某改进”（不成立则整层删除，勿硬写“绝无动机”）；
4. 事后诸葛亮——宜点到为止，勿替代特征比对；
5. 整体性与协同（仅当特征间有真实耦合时）。

### H. 逻辑手法增补（范文提炼；仍须逐环验真）

12. **归谬法**：把审查员逻辑推到荒谬极端——若"有共同上位概念即有启示"成立，则几乎任何使用同类功能元件的方案都显而易见，有悖创造性中技术启示的认定标准。
13. **多篇对比文件"合力反转"**：证明多篇对比文件在关键问题上指向**共同路径**（如 D1、D2 都"改装被测件"），再把这股合力反转为对本申请的更强反向阻却（"它们共同构成一道围墙，本申请恰是翻墙"）。比孤立的相反教导更有力。
14. **问题发现难度专项**：指出审查员忽略了"问题本身的发现难度"——对比文件根本没意识到本案要解决的那个特定问题（如"进风通道内布传感器不阻气流"），谈何给出解决它的启示。
15. **"有规则 vs 无规则"反衬**：结合后若出现冲突（两模型结果不一致、方向不确定等），对比文件无任何判定/换算规则，而本申请恰给出明确工程准则——用本申请"有解"反衬结合方案"无解"。
16. **"拆核心 + 造新系统"组合难度**：量化得到本申请须完成几个无教导跳跃——放弃对方几个核心发明构思 + 新发明几套系统；"拆掉各自核心再造新系统"显非正向启示，而是以本申请为蓝本的事后拼凑。

### I. 表达增强手法子库（让答复"表达清楚、重点突出"；须以已验真事实为前提，只作论证外壳）

> 硬性护栏：金句 / 比喻 / 场景叙事等**不得替代论证**；每个金句/比喻后必须紧跟其事实依据（对比文件段号 / 区别特征编号）；数量服从递进、不堆砌。

17. **金句化降维**：把核心区别压成一句直觉对比（"传感器在谁的上面"）。
18. **工程场景叙事对比**：分步骤讲"对比文件的场景 vs 本申请的场景"，让审查员"看见"差异。
19. **比喻锚定**：用一个形象（"围墙 / 翻墙"）把整段论证钉进记忆。
20. **方法论范式对比框**：一对标签结构化差异（"自下而上·理论建模 vs 自上而下·黑箱频响"）。
21. **单点爆破**：锁定一个对方完全没有的关键环节（"力锤标定"）集中打。
22. **"常规设计"物理关联反驳**：用具体物理结构/受力路径的关联性打掉"常规设计"标签。
23. **结构化排比对比**：如"目的不同、判据不同、处理动作不同"，用于从权/细节对比，清晰有节奏。

> 组合规则：先 F 定主攻类型 → 再从 A–E/G/H 取**经事实验真**的 2–4 环（可更少）排成递进序（推荐范文的三层：首先破上位概括 → 其次破方向动机含合力反转 → 再次破从思想到方案的鸿沟含无规则反衬）→ 每环回扣“如 2.1 所述技术问题有无技术启示”→ 视需要用 I 的表达手法为关键环节加"外壳"。一通把该链写入 2.2；二通把该链写入第一部分，2.2 只收束。不要用效果收束代替非显而易见论证，也不要用“未公开”代替“无启示”。**禁止为凑满示例链或“其一其二其三”而写本案撑不住的论断；表达手法不得替代事实论证。**
