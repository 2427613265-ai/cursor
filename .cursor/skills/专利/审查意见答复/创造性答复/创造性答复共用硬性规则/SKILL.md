# 创造性答复共用硬性规则

本 skill 汇集创造性答复**跨步骤共用**的硬性规则。由 `创造性答复总控` 在相关步骤要求 Read；**本文件为上述规则的权威出处**。

## 何时必读

- 撰写修改说明、2.1/2.2/2.3、二通第一部分、其他权利要求、组装等**任一答复正文步**之前
- 第1步选法时：至少遵循「内在合理性优先于套模板」「选法须有事实支点」与下文「命题权属与一次展开」

## 命题权属与一次展开（硬性；充分且不重复）

**充分** = 每个拟交锋争点的推理链闭合，且下表各命题在全篇**写透一次**。不是每一子步、每一层骨架都重写一遍，也不是用条数/层数/段数填满来冒充充分。

**同一事实支点只展开一次**：同一对比文件段号 + 同一作用/教导认定，或同一区别特征编号的同一层含义，全篇只展开一次。后文只准回引「如 2.1 所述」「如本意见前文针对审查意见第×点所述」「上述区别特征（N）」，**不准**换「首先/其次」或「其一/其二」骨架重述同一命题。

| 命题 | 独占位置 | 后文只准 |
|------|----------|----------|
| 区别特征原文、问题要素、与审查员概括对比 | 2.1 / 3.1 | 短回扣「如 2.1 所述……」 |
| 发明构思命名、范式级定性（一两句点名） | 2.1 / 3.1 | 2.2/2.3 使用该名称，不再解释「何谓不同范式」 |
| 审查员某一句为何错（教导、作用、动机、常规） | 对应那一条 2.2 逐条（二通：第一部分对应条） | 归纳/收束一句回引 |
| 三步法第三步闭合：组合四问、改造清单或「拆核心+造新系统」、公知常识总评、落回权要整体 | **仅** 2.2 归纳（二通：2.2 收束） | 2.3 不写 |
| 评价上不能把区别特征拆成孤立常规手段 | **仅** 2.2 归纳 | 2.3 不重复「不能拆开评」 |
| 方案如何运行、中间状态、问题要素→直接效果、缺一退化的效果落差 | **仅** 2.3 / 3.3 | 2.2 不写「从而提高了」 |
| 第二独权模块/连接/数据流及独有结构 | **仅** 3.1/3.2/3.3 增量 | 禁止重放 2.x 已展开的事实段 |
| 从权附加特征自己的未公开 + 未教导 | **仅** 其他权利要求精选段 | 禁止把该从权再塞进 2.2 凑 K |

第1步须产出「对比文件卡 + 争点账本」（过程性，不进答复正文；栏位见 `创造性答复总控`）。后文撰写前先查账本：本步独占哪一命题、哪些只准回引。

## 2.2 与 2.3 语言分轨（硬性）

- **2.2 / 3.2 / 二通第一部分**：只写目的、教导、作用是否相同、有无动机、能否结合、是否常规、有无针对如 2.1 所述问题采用区别特征（N）的启示。禁止效果形容词与「显著进步」「从而提高了……」。
- **2.3 / 3.3**：只写运行中间量、因果、缺一之后效果停在现有技术哪一步、相对现有多实现了什么 / 避免了什么。禁止「技术启示」「结合动机」「非显而易见」「不是显而易见地得到」。
- 2.3「穿插对比文件得不到该效果」= 只对比**运行停点与直接效果差**，禁止把 2.2 的启示/动机链再叙述一遍。

## 两种协同（硬性；只写一次、各写各的）

「协同」不是第三处必写的递进层。事实支持时按下表劈开，写一处即勾选，禁止 2.2 与 2.3 互抄：

| 类型 | 独占 | 写什么 | 不写什么 |
|------|------|--------|----------|
| 评价协同 | 仅 2.2 归纳 | 区别特征互相提供前提/输入/约束，**评价上**不能拆成孤立常规手段逐项评 | 缺一之后效果变差的故事 |
| 效果协同 | 仅 2.3 | 物理/控制上少一块会停在现有技术**哪一停点**；整体效果不是已知手段叠加 | 「不能拆开评价」「无技术启示」 |

总控「逻辑递进」末层的整体协同 = 上表评价协同，不在 2.3 再写一遍，也不在逐条里预写归纳才该写的不可拆评价。

## 加粗星号标记规则（硬性）

1. **只交一份答复正文**：修改说明、2.1/2.2/2.3、二通第一部分、其他权利要求抗辩、组装全文，只输出一份正文（对话与工作稿相同），**不要**再拆“展示版/纯文本版”两套。
2. **用一对星号标出加粗位置**：对每步最关键的 1～3 处表述，在正文中直接用 `**……**` 包住（如实际技术问题句、发明构思命名、无技术启示结论句、法条收束句）。用户粘贴后按星号位置在文书中加粗，再自行删掉星号。不得整段包星号。
3. **禁止**文末另列「建议手动加粗：……」段；星号本身即提示。
4. 第1步对比文件卡/争点账本、第2步修改策略/plan 等过程性交付：不插 `**……**`。

## 有益效果归属与技术问题展开边界（硬性）

**有益效果归属（硬性）**：凡 2.2 针对性答复中本来会写的“本申请能够……效果”“取得预料不到的技术效果”等，**一律放到对应独权的技术进步一节**（第一项独权为 2.3，第二项独权为 3.3）集中论述，不在逐条答复的“其一/其二/其三”里做效果收束。**归入 2.3 不等于可以短收束**：2.3 须按 `创造性答复显著技术进步撰写` 以**因果单元**写满（运行中间状态 + 每个 2.1 问题要素一处「特征→中间过程→直接效果」+ 效果协同/缺一退化）；禁止「作业过程两段 + 因此句」收工。段数是结果不是尺：通常 4～7 段，问题要素仅 1 个时不得注水凑段。

**技术问题只在区别特征节展开（硬性）**：实际技术问题的界定、展开，以及与审查员问题概括的对比，**只在 2.1（或第二项独权的 3.1）完整论述一次**。进入 2.2/3.2 后，不得再次整段复述申请人的技术问题或再次展开与审查员概括的对比；若审查结论本身就是问题界定类，仅用一句“如 2.1 所述……”指向前文，随即转入动机、启示、常规手段等非显而易见性论证。

**“不重复”≠“不衔接”（硬性）**：禁止在 2.2/3.2 **重写**技术问题整段，但**必须把 2.1/3.1 已界定的实际技术问题当作非显而易见性与技术启示论证的锚点**。凡写“有无技术启示 / 有无结合动机 / 是否常规手段”，一律回答：现有技术是否给出了将区别特征（N）用于最接近现有技术、**以解决如 2.1（或 3.1）所述实际技术问题**的教导。禁止只写“对比文件未公开某特征”就停笔，也禁止脱离该技术问题空谈“无启示”。

### 技术问题 → 技术启示衔接（硬性；三步法第三步）

创造性三步法第三步的判断对象不是抽象的“特征是否已知”，而是：在已确定区别特征与实际技术问题后，现有技术整体上是否给出将所述区别特征应用到最接近现有技术以解决**该**实际技术问题的**技术启示**。本 skill 要求：

1. **2.1/3.1 产出可被引用的问题表述**：技术问题须以**问题要素**具体到可由区别特征（N）解决的层面，避免宽泛到任何改进都能对上，也**禁止把技术方案手段写入问题句**；写完后应能用一短句回指（如“如 2.1 所述，实际要解决的是……”）。
2. **2.2/3.2 必须完成技术启示论证**：针对如 2.1 所述问题有无采用区别特征（N）的启示，须在**整节 2.2**闭合一次。逐条负责打掉本条审查员逻辑；归纳只填逐条未覆盖的缺口（组合四问、改造清单、评价协同、公知常识总评、落回整体），**禁止**为凑「首先/其次/再次/最后」把已写透的层再写一遍。已覆盖的层：归纳一句回引 + 启示锚点句即可。不得用“未公开”替代“无启示”。
3. **技术启示的标准问句**（每项独权整节至少完整回答一遍；可分摊在对应逐条与归纳，禁止每条逐条都把四问重答一遍）：
   - 对比文件自身要解决的技术问题/技术目的是什么？与 2.1 所述实际技术问题是否相同或足够接近？
   - 对比文件客观教导的技术手段与作用是什么？是否指向采用区别特征（N）这一手段？
   - 即使公开了相似部件/步骤名称，其在该文件中的作用、前提、数据关系是否与解决 2.1 所述问题所需的作用相同？
   - 审查员主张的“作用相同 / 有动机结合 / 常规技术手段”，是否建立在其上位概括的技术问题上，而非建立在 2.1 所述具体技术问题上？
4. **衔接用语（推荐，可替换同义表述）**：
   - `针对如 2.1 所述实际技术问题，对比文件【X】……并未给出采用上述区别特征（N）的技术启示。`
   - `对比文件【X】所要解决的是……问题，与如 2.1 所述……问题并不相同；其教导停留在……，本领域技术人员据此不会为解决如 2.1 所述问题而……。`
   - `审查意见所谓“有技术启示”，是以其概括的“……”问题为前提；在如 2.1 所述更具体的技术问题之下，该前提不成立。`
5. **有益效果仍归 2.3**：2.2 论证“无启示”时，可点明“因此不能显而易见地获得本申请方案”，但具体技术效果展开仍放 2.3，并与 2.1 技术问题镜像对应。

### 两项或多项独立权利要求的处理（硬性）

若权利要求书包含两项独立权利要求（常见为“方法独权 + 系统/装置独权”），不得只完整论证第一项独权，再用一句“另一独权与其对应，故也具备创造性”带过。应当：

1. **逐项识别创造性基础**：分别确定每项独权的最接近现有技术、区别技术特征、实际技术问题及审查员对该项独权的评述。两项独权共用同一对比文件时也要分别核对其公开内容。
2. **逐项设置论证，结构二选一（据发明构思关系择一，均须每项都有区别特征/充分非显而易见性/单独深入技术进步）**：
   - **构思相异 → 分章**：第一项独权写“2.1 / 2.2 / 2.3”，第二项独权另设下一大节写“3.1 / 3.2 / 3.3”（后续从权章节顺延）。
   - **共用同一发明构思与同一对比文件 → 共享 2.1/2.2/2.3 内部并列**（范文范式）：2.1 内并列列"区别特征（1）=第一独权""区别特征（2）=第二独权"，2.2 内以"第一/第二"分别针对各独权评述作答，2.3 内并列分述各独权效果。此法省重复、更清晰，但**并列不等于合并**——每项独权的区别特征、启示否定、技术进步仍须各自写足，不得共用一段带过。
3. **系统独权不得只作形式映射（增量模板；权威出处在本条）**：若第二项独权是与方法独权对应的系统/装置：
   - 共同发明构思、已在 2.1/2.2/2.3 展开的对比文件教导与启示否定，**一律回引**，禁止重放事实段；
   - 本步只允许写增量：模块是否对应实施方法步骤、连接/数据流/协同是否独有、独有结构的启示否定与效果；
   - 「不得同理带过」= 必须有增量事实，**不是**必须有与 2.x 同等篇幅。3.2 各条篇幅以增量写清为度，原则上不超过对应 2.2 条的一半；3.3 不得写成 2.3 的一句改写，也不得整节克隆 2.3。
4. **独立发明构思分别论证**：若两项独权解决不同技术问题或采用不同核心手段，不得合并论述；分别建立完整创造性逻辑链（此时 3.x 不是增量而是完整链，仍遵守命题权属，不得与 2.x 互抄同一事实支点的展开）。
5. **plan 按独权拆项**：每项独权的 2.1/2.2/2.3（或 3.1/3.2/3.3）各列为独立待办，逐项交付、逐项确认。3.1/3.2/3.3 的分步规则与 2.x 相同；写法细则见对应撰写 skill，增量边界以本条为准。

## 硬性流程规则（最高优先级）

1. **禁止一次生成答复全文**；**禁止一次生成整节 2.2**（含多项“第【序】、针对审查意见指出的”与归纳段同批输出）。2.2 必须按「逐条答复子步 × N + 体系化归纳子步 × 1」拆分（**N 必须为 3～5**），每子步只交付一条答复或仅归纳段。归纳步按「缺口填写」交付，见 `创造性答复非显而易见性撰写`。
2. **第1步不得夹带修改策略与 plan（硬性）**：第1步只交付**对比文件卡 + 争点账本**（栏位见总控）、一通/二通判定、结论清单、变好/变差预分类、手法组合、独权清点、是否倾向修改的一句判断及篇幅分配提示。**权利要求修改分层清单**与**plan 待办清单**合并为第1步之后的**同一步**交付（先分层、后 plan，同一回复内完成），**禁止**塞回第1步，也**禁止**再拆成两个独立步骤；用户确认该合并步后，再进入修改说明/正文。
3. **先判一通/二通，再分析选法**：摘出审查员结论性论断；**拟正面交锋并写入 2.2（二通写入第一部分）的条数必须为 3～5**，禁止默认只打「D1单独＋Dx结合」两条。选条规则（硬性）：
   - 独权评述中**彼此独立**的结论须分条；一条审查意见里的连环认定（未公开 / 作用相同 / 有启示）在**同一条**的其一/其二/其三里打完，**禁止**拆成多条凑 K。
   - 独权独立结论已 ≥3 条时，**禁止**再抽从权凑数。
   - 不足 3 条时，仅当某从权评述与独权发明构思相关、且 2.2 不写就缺一块启示链时，才补入事实支点最强者；补入的权号记入争点账本，**自动排除**出其他权利要求精选池。
   - 至多 5 条；纯参数/数量/角度从权默认不进 2.2。
   为每条挑选 2–4 种**本案事实真正撑得住**的手法，并给出**递进顺序**（为何先写 A 再写 B）；**并非每种都用**；选法与组合方案须先交用户确认。工具箱只收通用手法，案情特有表述不得默认选用。I 类金句/比喻第1步选定后，指定**只在一条逐条或只在归纳出现一次**；2.3 禁止再套同一比喻。
4. **内在合理性优先于套模板（硬性）**：骨架（一通三段论 / 二通观点作答、2.1→2.2→2.3、引述后拆解）必须遵守；**手法层数、退一步措辞、失败预期、互斥、听谁的、违背初衷、归纳四层标题、2.3 段数等不是填空题**。落笔前对拟用的每一环自问：对比文件客观教导是否支持该论断？本领域人员申请日前会否认同？若只能靠夸大、臆测或套话才能写下去，**弃用该环**，宁可链条短而真，不可为凑“其一/其二/其三”或五层框架强行说理。充分看争点因果是否闭合，不看层数是否写满。第1步争点账本须标注每环的**事实支点**；支点不足的手法不得进入正文。
5. **用 plan/待办清单驱动全过程**：plan 在**与修改策略合并的那一步**建立（不得塞进第1步，也不再单列 plan 步）；一通按三段论步骤拆，且**2.2 须按审查结论条数再拆为 N+1 个子步**（N 条逐条答复 + 1 步体系化归纳；**N 必须为 3～5**）；归纳子步在 plan 中写明「缺口：……（或：逐条已覆盖，短收束）」；二通按“核心观点①②③…（每条一步，3～5 条）+ 2.1 + 收束（只填第一部分未覆盖缺口）”拆；逐步更新状态，始终只有一个“进行中”。
6. **一步只做一个交付物**；须等用户确认再进入下一步；按用户提示推进。**2.2 的一个交付物 = 一条逐条答复，或 = 体系化归纳段，不得合并。**修改策略与 plan 合并为一步交付物，不得并回第1步，也不得再拆成两步。
7. 用户要求“一口气写完”时仍分步；修订也按步。**用户要求“一次性写完 2.2”时，仍须按 2.2 子步逐条交付，不得合并。**
8. **正文内星号标加粗（硬性）**：修改说明、2.1、2.2/3.2、2.3/3.3、二通第一部分、其他权利要求、组装全文只交一份，对 1～3 处关键句用 `**……**` 标出加粗位置。
9. **禁止两套正文、禁止文末加粗清单**：**禁止**再拆展示版/纯文本版；**禁止**「建议手动加粗」。第1/2步过程性交付不插星号标记。

若有两项独权，plan 中的“三节各一步”适用于**每一项独权**：权利要求1的 2.1/2.2（含全部子步）/2.3 完成并确认后，再依次撰写第二项独权的 3.1/3.2（含全部子步）/3.3；不得一轮同时交付两项独权的全部创造性正文。**第二项独权的 3.2 适用与 2.2 相同的分步规则与缺口归纳；内容遵守上文增量模板。**

每步输出格式：`【第X步 / 共N步】步骤名称` + 一份答复正文（关键句已用 `**……**` 标出）+ 请用户确认 + 预告下一步。**不得**输出两套正文；**不得**输出「建议手动加粗」段。
