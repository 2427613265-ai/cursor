# 创造性答复非显而易见性撰写

本 skill 为 2.2 / 3.2 / 二通第一部分 的撰写细则。撰写本步前须同时 Read `创造性答复共用硬性规则`（命题权属、语言分轨、选条规则以此为准）。

适用：一通 2.2（及 3.2）；二通第一部分核心观点逐条作答 + 2.2 收束。选法见 `创造性答复反驳手法工具箱`。第1步争点账本已标「本条独占命题」的，本步不得越权展开留给归纳或 2.3 的命题。

**逐条条数（硬性；K＝3～5）：** 「第【序】、针对审查意见指出的」必须写满 **3～5 条**，不得以「对比文件1单独＋对比文件X结合」两条收工。第1步争点账本即按此圈定拟正面交锋条数；plan 的 2.2 子步数＝K＋1（含归纳）。选条（与共用硬性规则一致）：

- 先拆独权评述中彼此独立的结论（D1未公开/无启示、常规手段/公知常识、Dx结合有启示等**分条**，不得把不同独立结论合成一条）。
- 一条审查意见里的连环认定（未公开 / 作用相同 / 有启示）在**同一条**的其一/其二/其三里打完，禁止拆成多条凑 K。
- 独权独立结论已 ≥3 条时，禁止再抽从权凑数。
- 不足 3 条时，仅当从权评述与独权发明构思相关、且 2.2 不写就缺一块启示链时，才补入事实支点最强者；该权号记入账本并排除出其他权利要求精选池。
- 至多 5 条；纯参数/数量/角度从权默认不进 2.2。禁止把同一结论拆碎凑满 3 条。

### 审查意见引述规则（短文照录，长文概括）

写“针对审查意见指出的：”之后：

1. **篇幅适中或较短**：完整照录该条审查意见原文，不得歪曲。
2. **原文非常长**：改为**忠实概括**，保留其结论链条中的关键认定（如公开了什么、作用是否相同、给出何种启示、有何种结合动机、认定是否常规等），用一两段浓缩表述对准靶子；**不得删掉关键结论点，也不得改成对自己有利的弱化版**。
3. 概括后仍须让读者一看就知道在反驳哪一条审查逻辑；必要时可在概括句中用引号保留审查员的关键原词（如“作用相同”“有动机结合”“常规技术手段”）。
4. 判断“非常长”的实务标准：单条连续论述明显超过半页、或包含多段重复铺陈时，优先概括；一两句到一小段的结论仍宜照录。

### 2.2 内的针对性答复段模板（不含有益效果；不重写技术问题，但必须衔接到启示）

```text
第【序】、针对审查意见指出的：【短文照录原文；过长则忠实概括其结论链】
对此，申请人答复如下：
其一、【就该条审查结论拆解：可指向 2.1 已列区别特征（N）、指出对比文件未公开等；若涉问题界定，仅一句“如 2.1 所述……”指向，不重写技术问题】
其二、【技术启示/结合动机核心句：针对如 2.1 所述实际技术问题，对比文件【X】……未给出将区别特征（N）应用于对比文件1的技术启示；可接无动机 / 相反教导 / 过度概括 / 退一步…——用第1步为本条选定的手法】
（视需要再写其三；**仅当上一层仍留缺口且下一层事实成立时**，才用“退一步来讲……”设防；不成立则停，勿硬凑）
【此处不要写有益效果；效果统一写入后文 2.3】
【此处不要重写 2.1 已论述的实际技术问题整段；但“无启示”必须回扣该问题】
【禁止套话堆砌：每句须能指回对比文件具体公开或区别特征（N）；写完后删掉任何只靠修辞成立的句子】
【本条只打争点账本标明的独占命题；组合四问、改造清单、评价协同留给归纳，除非本条审查员逻辑本身就是组合/常规总评且账本已把该命题分给本条】
```

## 独权创造性三节中的 2.2 模板与充分论证要求

**2.2 非显而易见性（逐条打审查员逻辑 + 归纳填缺口；语言分轨见共用硬性规则）**

> 2.2、权利要求1所保护的技术方案是非显而易见的。
>
> （逐条：第【序】针对审查意见……）
>
> 在此基础上，申请人进一步归纳如下：
> 【仅展开逐条尚未覆盖的缺口。已覆盖的层用「如本意见前文针对审查意见第×点所述……」一句回引，可保留启示锚点句。】

**覆盖检查表（全节 2.2 勾选一次；不是归纳必须再写的正文大纲）：**

| 层 | 典型内容 | 默认归属 |
|----|----------|----------|
| 对比文件1单独 | 目的/教导停留何处；为何不能针对如 2.1 所述问题给出采用区别特征（N）的启示 | 评 D1 的那一条逐条 |
| 其他对比文件分别 | 各篇场景、前提、自身问题；为何不能弥补 D1 以解决如 2.1 所述问题 | 评 Dx 的对应逐条 |
| 组合后仍无启示 | 组合四问；改造清单或「拆核心+造新系统」 | **仅归纳**（除非某条审查结论本身就是「结合有启示」且账本把组合四问分给该条——该条写组合反驳，归纳只回引并补未问之问） |
| 常规/公知常识 | 名称已知 ≠ 解决如 2.1 所述具体问题的启示 | 评「常规手段」的那一条；若无该条则归纳补一句 |

凡在针对性答复中已充分展开的点，归纳**只回引编号**，禁止换骨架重述。四层标题「首先/其次/再次/最后」**仅用于仍有缺口的层**；四层在逐条中均已闭合时，归纳改为短收束（回引 + 落回权要整体 + 启示锚点句），**不必**为凑四层再写四段。

**2.2 的内部次序与分步交付（硬性）：**

1. **先逐条、后归纳，分步交付**：先按审查意见核心结论逐条写“引述（短文照录 / 长文概括）+ 对此答复”；每条至少有一句把反驳锚定到“如 2.1 所述实际技术问题”。**每条答复独占一步交付**；全部逐条答复确认后，**另起一步**写归纳。**禁止**同批交付多条逐条答复，**禁止**同批交付逐条答复与归纳。
2. **每步只写一条**：2.2-① 写标题 + 第一条；2.2-② 起只写后续各条（不写重复标题）。**不得**在同一步内写“第一、第二、第三……”多个段落。
3. **体系化归纳单独一步（缺口填写）**：先对照覆盖检查表列出「已覆盖 / 本步补写」；只写未覆盖项。可用“如本意见前文针对审查意见第×点所述……”回引，**不得**重复粘贴已确认逐条答复全文，也不得把已写透的 D1/Dx 教导再叙述一遍。
4. 2.2 只论证“为什么不能显而易见地得到”，不在本节集中展开有益效果，也**不再整段复述 2.1 的技术问题界定**；但**必须完成以该技术问题为锚点的技术启示否定论证**（可分摊在逐条与归纳，全节闭合一次即可）。禁止出现「从而提高了」「显著进步」。
5. **正文内星号标加粗（硬性）**：2.2、3.2 及二通第一部分只交一份正文，对关键结论句用 `**……**` 标出；禁止「建议手动加粗」段；禁止两套正文；其一/其二等结构序号仍用汉字。

**充分论证的最低要求（全节覆盖一次；括号内为默认归属）：**

1. **对比文件1单独**（评 D1 的逐条）：不仅写“未公开”，还要说明其技术目的、工作原理、完整方案及客观教导停留在何处；逐项对应区别特征（N）；明确其自身要解决的问题与如 2.1 所述实际技术问题的差异，以及为何不能单独给出采用区别特征（N）以解决该问题的启示。
2. **其他对比文件分别审查**（评 Dx 的对应逐条）：逐篇说明其技术场景、必要前提、数据/结构来源、实际实施方式、自身技术问题/目的，以及为何不能弥补对比文件1以解决如 2.1 所述问题。对比文件较多时不得合并成一句“其他文件均未公开”。
3. **技术启示专项**（逐条打本条审查员主张的启示链；标准问句未答完的部分由归纳补足）：结论句须形如“针对如 2.1 所述实际技术问题，……未给出采用区别特征（N）的技术启示”。审查意见已主张“有启示/作用相同/有动机”时，必须正面拆解其启示链条，不能只重复“未公开”。标准问句每项独权整节答一遍，禁止每条逐条把四问重答一遍。
4. **组合推理闭合**（默认仅归纳）：分别回答“为什么会为解决如 2.1 所述问题去找该文件”“为什么会抽取该特征”“为什么会按权利要求顺序/关系组合”“组合后为什么能够正常工作并解决该问题”。审查意见缺少其中任一环，应明确指出。
5. **连续改造清单或「拆核心+造新系统」**（默认仅归纳；二者写一即可，勿两套并列）：列出从对比文件组合到本申请仍需完成的无教导跳跃，并说明这些改造不是彼此独立的常规替换，而受如 2.1 所述同一技术问题和数据/结构关系约束。
6. **评价协同**（默认仅归纳；见共用硬性规则「两种协同」）：说明区别特征之间如何互相提供前提、输入、约束或反馈，为什么**评价上**不能拆成若干孤立常规手段逐项评价。禁止在此写缺一之后的效果故事（留给 2.3）。
7. **公知常识/常规手段须有依据**（评「常规」的逐条；无该条则归纳补）：审查员仅作结论时，指出其未证明该手段在本案具体技术场景、具体关系和**如 2.1 所述具体技术问题**下属于公知常识；不能只争论手段名称是否已知。
8. **结论必须落回权利要求整体**（归纳收束句）：最终明确，本领域技术人员在申请日前没有合理成功预期，不能在不付出创造性劳动的情况下为解决如 2.1 所述问题而得到该项独权的整体方案。

**2.2 逐条内部递进（范文提炼；按第1步为本条选定的手法取舍，不是每条都写满三层，更不是归纳再抄一遍）：**

```text
首先——破上位概括（过度概括 / 事后分析 / 归谬）
        抽掉对比文件关键限定后只剩上位表述的，逐一还原被抽掉的限定；
        可用归谬：若"有共同上位概念即有启示"成立，则几乎任何同类元件方案都显而易见，有悖启示认定标准。
其次——破方向与动机（相反教导；善用"多篇合力反转"）
        证明对比文件在关键问题上指向共同路径，再把这股合力反转为对本申请的反向阻却
        （范文："D1+D2 共同教导'传感器必须内置'，构成一道围墙，本申请的贡献恰是翻出这道墙"）。
再次——破"从上位到具体"的鸿沟（退一步；含组合后冲突无规则）
        即便产生上位念头，从该念头到本案具体方案仍缺哪几环教导；
        结合后若出现冲突（如两模型结果不一致以何为准），指出对比文件无任何判定规则，
        而本申请恰给出明确准则（有规则 vs 无规则反衬）。
```

层与层须删上则下失前提，是真递进不是并列；每层结论都回扣"针对如 2.1 所述实际技术问题有无采用区别特征（N）的技术启示"。撑不住的层整层删除。本三层属于逐条内部手法，归纳不得再按此三层重写。

**组合难度升级为"拆核心 + 造新系统"框架（默认仅归纳；与「连续改造清单」二选一）：**

明确列出得到本申请须完成的无教导"跳跃"——(1) 须放弃对比文件1的核心发明构思？(2) 须放弃对比文件2的核心发明构思？(3) 须新发明哪一整套系统？"拆掉两个对比文件各自的核心、再发明一套新系统"显然不是正向启示，而是以本申请为蓝本的事后拼凑。比单纯罗列改造步骤更有冲击力。

**表达增强手法子库（新增；让答复"表达清楚、重点突出"）：**

> 硬性护栏：以下手法**必须以已验真的事实论证为前提，只作论证的表达外壳，不得替代论证**。每个金句/比喻/场景后必须紧跟其事实依据（对比文件段号 / 区别特征编号）；第1步争点账本指定出现位置后，**全篇只用一次**（一条逐条或归纳，不得两处都用）；2.3 禁止再套同一比喻。数量服从递进，不堆砌；写完删掉任何只靠修辞才成立的句子。

1. **金句化降维**：把核心区别压成一句直觉性对比（范文："本质差异不是'用了什么传感器'，而是'传感器在谁的上面'"）。
2. **工程场景叙事对比**：分步骤讲"对比文件的场景 vs 本申请的场景"，让审查员"看见"差异，而非只读术语。
3. **比喻锚定**：用一个形象（"围墙 / 翻墙"）把整段论证钉进记忆。
4. **方法论范式对比框**：一对标签把复杂技术差异结构化（"自下而上·理论建模 vs 自上而下·黑箱频响"）。
5. **单点爆破**：锁定一个对方完全没有的关键环节（"力锤标定"）打聚光灯，逐一说明对方各步骤为何都不对应。
6. **归谬法 / "有规则 vs 无规则"反衬**：把对方逻辑推到荒谬极端；用本申请"有解"反衬结合方案"无解"。
7. **"常规设计"物理关联反驳**：用具体物理结构/受力路径的关联性（如 MAX(|F1|,|F2|) 对应油膜受力方向可变），打掉审查员的"常规设计"标签。

### 一通·第5步起：2.2 非显而易见性（**必须拆为多子步，禁止整节一次输出**）

2.2 整体严格按上文覆盖检查表、充分论证最低要求及 `创造性答复共用硬性规则`「技术问题 → 技术启示衔接」撰写，但**交付时必须拆步**：

#### 2.2-①（一通第5步）：标题 + 第1条逐条答复

- **本步只交付**：2.2 标题 + **一个**“第【一】、针对审查意见指出的：……对此，申请人答复如下：其一……（其二/其三视需要）”段落。
- 标题用：

> 2.2、权利要求1所保护的技术方案是非显而易见的。

- “针对审查意见指出的：”后短文照录/长文概括**本条**审查结论；
- 按第1步为本条选定的**递进序**展开；凡涉结合/启示/常规，须写明针对如 2.1 所述实际技术问题无采用区别特征（N）的技术启示；
- 不整段重复技术问题；禁止效果收束；**本步不得写“第二/第三”条答复，不得写“首先/其次/再次/最后”。**
- **本步正文对 1～2 处关键结论句用 `**……**` 标出**；只交一份正文；禁止文末「建议手动加粗」段。

#### 2.2-②…（一通第6步起）：后续逐条答复

- **每步只交付一个**“第【序】、针对审查意见指出的：……”段落；**不写** 2.2 重复标题，**不写**其他条答复，**不写**体系化归纳。
- **正文用 `**……**` 标出关键句**；只交一份；禁止「建议手动加粗」段。
- 条数 K＝第1步拟正面交锋的审查结论数，**必须为 3～5**（见上文「逐条条数」）；从权评述仅在硬规则允许时补入，且该权号排除出末节精选池。

#### 2.2-末：体系化归纳（单独一步；缺口填写）

- **本步先列出覆盖检查表**（过程性可极简：已覆盖①② / 本步补③④），再交付归纳正文。
- 已覆盖的层：一句回引 + 必要时一句启示锚点；**禁止**重述该层事实。
- 未覆盖的层：按「充分论证最低要求」归属展开（默认补：组合四问、改造清单或拆核心、评价协同、公知常识总评若无对应逐条、落回权要整体）。
- 四层均已闭合：短收束即可，不必出现「首先/其次/再次/最后」。
- 仍有 ≥2 个缺口层时，可用「首先/其次/……」只给**缺口层**编号，跳过已覆盖层。
- 用“如本意见前文针对审查意见第×点所述……”回引；**禁止**重复粘贴各条全文。
- **本步不得新写“第【序】、针对审查意见指出的”逐条答复。**
- 归纳结论句用 `**……**` 标出；只交一份；禁止「建议手动加粗」段；禁止效果用语。

#### 2.2 分步硬性禁令（复述）

| 禁止 | 正确做法 |
|------|----------|
| 一次输出“第一、第二、第三、第四”全部逐条答复 | 每条答复独占一步，用户确认后再写下一条 |

### 二通·第4步起：针对第N次审查意见核心观点逐条作答（主战场；**每条一步**）

- 大标题建议：`一、针对第【N】次审查意见的核心观点作答如下：`（在首条子步与第一条一并写出）
- **每个子步只交付一个** `第【序】、针对审查意见指出的：` + 引述/概括 + `对此，申请人答复如下：` + 按递进序拆解；**禁止**同批输出多个“第【序】”；核心观点条数同样 **K＝3～5**，不得只打两条；

- 禁止在本步做有益效果大段收束（留 2.3）；禁止启示论证与效果因果混写。
