# 权利要求质检总控（二级总控：挂具体权要质检 skill）

## 适用场景

- 由顶层 `质检总控` 判定为权利要求质检或全案中的权要阶段后调用；
- 用户明确只要质检/审核权利要求书或某一条权利要求时，经顶层总控分流至此。

**硬性规则：本 skill 是权利要求质检的二级入口。具体检查由本 skill 分流调用下属具体质检 skill；不直接替代其细则。顶层入口仍是 `质检总控`，本 skill 不越级充当专利质检总入口。**

---

## 本 skill 管什么

1. **识别权要质检对象**（整份权要 / 单条权要）；
2. **分流并编排**下属具体质检 skill 及执行顺序；
3. **收口输出格式**（先硬伤、后实质；单条的待同步说明书事项单独列表）。

---

## 一、挂接清单（具体质检 skill）

| 具体 skill | 管什么 | 何时分流 |
|------------|--------|----------|
| `权利要求书质检` | 整份权利要求书的实质与布局（独权范围/创造性、从权梯度、依附编号、清楚性、按需表达） | 整份权要质检 |
| `单条权利要求审查` | 单条权利要求的六维审查（逻辑、表达、格式、说明书支持、现有技术区分、布局策略） | 用户指定权1/权2/权利要求N |
| `权利要求引用结构检查` | 独立改进平行引用、依赖改进串联、组合多项引用 | 整份权要质检必读；形式合规之后 |

### 撰写规范类（由具体质检 skill 再挂接；本总控只编排）

整份权要质检时，由 `权利要求书质检` 按「必读/按需」加载，例如：

- 必读：`权利要求形式合规性规范`
- 按需：`权利要求清楚性与逻辑一致性规范`、`独立权利要求必要技术特征检查`、`自定义名词就地定义`、`预设值与参数来源检查`、`交底口语名改写为自明结构名规范`、`方位与场景限定上位规范`、`结构类权利要求撰写`、`功能性限定使用边界规范`、`条件判断语句规范`、`权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范` 等

本总控 **不** 直接替代上述规范的读取与核对。

## 二、先识别权要质检对象

| 类型 | 典型用户说法 | 下一步调用 |
|------|--------------|------------|
| A. 整份权利要求书 | 「质检权利要求书」「审核整份权要」 | **必须**走「整份权要质检链路」 |
| B. 单条权利要求 | 「检查权2」「审阅权利要求3」「改一下权1」且聚焦单条 | **必须** `单条权利要求审查` |
| C. 对象不明（已进入本总控） | 上下文仅有权要全文 | 默认按 A |

**选用硬规则：**

- 用户点名某一条权利要求 → 只能走 B，不得直接展开整份四维度；
- 单条审查后若发现编号重排/引用关系变化可能影响全文 → 末尾提醒升格为 A。

## 三、调用顺序

### 链路 A：整份权要质检

```text
权利要求质检总控（本 skill）
  → 1. 权利要求形式合规性规范          （必读，硬伤优先）
  → 2. 权利要求引用结构检查            （必读，平行/串联）
  → 3. 权利要求书质检                  （实质四维度 + 按需规范）
  → 4. 按本总控收口格式汇总输出
```

执行原则：

1. **先硬伤、后实质**：形式违规、依附编号错误、引用结构不当优先列出；
2. 实质问题（范围/创造性/梯度）放在硬伤之后；
3. 按需规范由 `权利要求书质检` 按案件类型再加载，本总控不越级展开全文。

### 链路 B：单条权利要求审查

```text
权利要求质检总控（本 skill）
  → 单条权利要求审查
  → 若末尾提示影响全文编号/引用 → 建议用户再跑链路 A
```

## 四、最低交付要求

### 整份权要

必须按下列顺序输出（与 `权利要求书质检` 对齐）：

1. 形式合规性硬伤  
2. 引用结构问题  
3. 依附编号错误  
4. 实质重复问题  
5. 独权范围与创造性观察  
6. 从权梯度布局观察  
7. 表达清楚性核对（如有）

每条问题写清：位置 → 问题 → 修改建议。

### 单条审查

按 `单条权利要求审查` 六维输出；「待同步说明书事项」单独列表，不计入缺陷。
