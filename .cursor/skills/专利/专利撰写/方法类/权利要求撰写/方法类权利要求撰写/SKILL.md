# 方法类权利要求撰写（I/O 流水线 · 不变量 · 扩围）

## 适用场景

- 撰写「一种××方法」类**方法独立权利要求**（含明显的算法/数据处理流程型方法）。
- 撰写方法从权中进一步限定某步骤的内部实现、参数、分支细判据时（用于判断哪些内容不宜提前塞进独权）。
- 审核方法独权是否过窄（钉死实现）、过空（假宽）、或步骤 I/O 接不上。
- **不替代** `独权撰写` 的三版递进策略；**不替代** `结构类权利要求撰写`（结构铺陈规则不适用于步骤流）。

**典型触发：** 「写方法独权」「方法权怎么扩围」「这一步是不是写太细」「按输入输出重写步骤」。

---

## 保护客体（先定准）

方法发明保护的是：**为解决技术问题而采用的、可实施的操作流程/处理步骤及其逻辑关系**。

- 侵权视角：他人是否实质实施了与独权相同的 **输入—变换—输出** 流水线。
- 独权应描写这条流水线的**对外契约**与**必要不变量**，不是某次编码/某篇实施例的全部内部细节。
- 须落成技术方案（技术问题、手段、效果），不能停在纯数学兴趣或空洞「优化/智能处理」。

---

## 核心规则

### 规则一：算法思维——逐步写成函数接口

把每个主步骤写成：

```text
步骤名（输入）→ 输出
```

撰写时对每一步追问：

1. **输入**从哪来（上一步输出 / 获取步骤 / 预设）？
2. **输出**交给谁用？
3. 从输入到输出，独权里是否只需保留**必要变换准则**，而非完整实现路径？

**优先保留：** 步骤顺序、数据血统、解决问题所必需的准则与控制流。  
**默认下放从权/说明书：** 具体模型结构、相似度公式、聚类算法名、软件工具名、超参与魔法数、实施例采样细节。

### 规则二：三层分离（扩围与保质的总开关）

| 层 | 写什么 | 默认位置 |
|----|--------|----------|
| **I/O 层** | 输入、输出、步骤衔接 | **独权主体** |
| **不变量层** | 删掉后技术问题无解的变换准则、关键控制流 | **独权必须保留** |
| **实现层** | 可替换的具体算法、工具、参数、实施例数值 | **从权 / 说明书** |

- **扩围** = 压缩实现层（去钉死）。  
- **保质** = 守住不变量层 + 权利要求清楚完整。  
- **禁止**为扩围删掉不变量，也禁止用「进行优化/智能选点」等假宽空词冒充 I/O。

### 规则三：核心关键步骤才展开「怎么变」

- **要展开：** 不写清准则则方案不完整或失去区别（例如必须「在信息盲区内选」且「按定位误差减少量选」）。展开的是**准则/约束**，不是源码。  
- **不展开：** 仅为复现实施例、或众多等价实现之一的细节。  
- **「其中」句：** 定义自定义名词的**语义边界**；避免在「其中」里塞完整伪代码级实现。

### 规则四：控制流接口化

条件分支使用 `条件判断语句规范` 的句式。独权只保留对保护必要的分支（如切换搜索域、终止循环）；具体阈值、系数名、魔法数进从权，独权可写「预设的××条件/终止条件」。

### 规则五：数据血统闭合（机器人视角）

配合 `预设值与参数来源检查`：

- 使用的数据必须先获取、算得或标明预设；  
- 上一步输出名称与下一步输入对齐；  
- 集合可空等入口要在叙述上接得住（若交底支持从零实施）。

### 规则六：扩围手法清单（方法独权常用）

| 手法 | 典型动作 | 边界 |
|------|----------|------|
| 去模型钉死 | 具体网络名 → 上位为能完成该 I/O 的模型类名 | 说明书宜有多种模型支持或可扩展披露 |
| 去算法钉死 | 谱聚类/余弦等 → 聚类 / 特征相似度 | 不得变成不可实施的空步骤 |
| 去工具钉死 | 某仿真软件名 → 管网水力模型等 | 实施例保留专名 |
| 去参数钉死 | 具体阈值/维数/层号 → 预设条件或删层号 | 预设须标明来源 |
| 去场景钉死 | 城市级、某工程专名等非必要场景语 | 与 `方位与场景限定上位规范` 精神一致 |
| 术语与问题同级 | 问题已上位则题名、步骤用词同步上位 | 避免问题宽、独权窄 |
| 成组下放 | 实现细节按组进从权作退路 | **禁止**把最小创造性骨架整组下放 |

### 规则七：假宽与过削自检

交稿前五问：

1. 每步能否说清输入/输出？  
2. 留下的准则是否正是解决当前锚定技术问题所必需？  
3. 钉死的实现换掉后是否仍想卡住对方？想 → 独权不应钉死。  
4. 自定义词能否仅靠「其中」读懂（不靠说明书）？  
5. 是否存在「优化/处理/智能」等无可核对动作的假宽词？

## 与独权三版策略的配合

由 `独权撰写` 挂接本 skill，建议力度：

| 版本 | 本 skill 用法 |
|------|----------------|
| **第一版** | 按交底忠实写全流程；允许暂留实现层；仍尽量步骤有序、I/O 可追踪 |
| **第二版** | 对准重新界定问题；用三层分离删非必要实现；保留不变量；并行 `独立权利要求必要技术特征检查` |
| **第三版** | 在第二版骨架上最大化去钉死 + 术语上位；跑扩围手法清单与五问；不得抽空区别骨架 |

命名对照表、部件/术语命名仍先走 `部件命名优化总控`（方法案中的关键术语同理入表）。

## 配套调用（横切，不在本文重写）

| 需求 | 调用 |
|------|------|
| 条件句句式 | `条件判断语句规范` |
| 参数/阈值来源 | `预设值与参数来源检查` |
| 自定义名词 | `自定义名词就地定义` |
| 主谓宾/指代 | `权利要求主谓宾结构规范` / `权利要求指代与参照清晰性规范` |
| 是否非必要 | `独立权利要求必要技术特征检查` |
| 术语命名扩围 | `部件命名优化总控` → 具体命名 skill |
| 三版策略/变劣 | `独权撰写` |

## 正确 / 错误示范（示意）

**偏向实现层（独权过窄，宜下放）：**

```text
提取全节点TCN最后一个卷积层输出的128维向量，采用余弦相似度构建矩阵并做谱聚类……
```

**I/O + 不变量（独权宜留）：**

```text
提取全节点基准定位模型输出的各管网节点的节点特征；根据所述节点特征之间的特征相似度进行聚类，得到特征簇；……在信息盲区内按定位误差减少量选择监测点加入集合；每加入后重新训练漏损定位模型并更新定位误差减少量……
```

**假宽（禁止）：**

```text
对管网数据进行智能分析并优化监测点布设。
```

## 最低交付要求（撰写方法独权时）

1. 主步骤可列出「输入 → 输出」对照（可在代理人笔记中，或口头可复述）。  
2. 已区分并守住不变量；实现层已尽量不进独权（第一版可暂留，第二/三版须清理）。  
3. 自定义词已「其中」定义语义。  
4. 条件与预设参数符合配套 skill。  
5. 扩围后仍可实施，且最小区别骨架仍在。

## 检查清单

- [ ] 是否认准方法保护客体为处理流程，而非产品结构或纯公式？  
- [ ] 各主步骤是否具备可追踪的输入与输出？  
- [ ] 是否用三层分离区分 I/O、不变量、实现？实现层是否默认下放？  
- [ ] 独权是否保留解决问题所必需的变换准则/控制流，而非假宽空词？  
- [ ] 模型/算法/工具/参数/场景钉死语是否已按版本目标清理？  
- [ ] 「其中」是否只定义语义、未塞完整实现？  
- [ ] 数据血统与预设参数来源是否闭合？  
- [ ] 成组下放是否避开了最小创造性骨架？  
- [ ] 方法类案是否已由 `独权撰写` 挂接本 skill，而非误用结构类「先总列后展开」？
