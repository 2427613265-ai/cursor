# 方法类权利要求撰写（分步 I/O · 衔接闭合 · 路径下放 · 扩围）

## 适用场景

- 撰写「一种××方法」类**方法独立权利要求**（含算法/数据处理流程型）。
- 审核方法独权是否：步骤切分不清、I/O 不明、步内输入空挂、步间接不上、中间路径过细或假宽。
- 判断某段「输入→输出」的具体计算路径应留独权还是下从权。
- **不替代** `独权撰写`；**不替代** `结构类权利要求撰写`。

**与 `独权撰写` 的挂接时机（硬性，内容不降级）：**

- 本 skill 由 `独权撰写` 在方法/算法/调控案**各版独权**的 **「b. 方法优化段」** 挂接并执行核心规则（拆步、I/O、用尽/咬合、路径/不变量三问、可实施下限、调控中间量、从权按步映射等，**不得删减**）。各版正文**暂按轨A**落笔。  
- **轨 A / 轨 B（规则 4.2）正式择一** 已从各版方法优化中**拆出**，改由 `独权撰写` **第8步**（第三版之后、可选变劣之前）统一出示对照并请用户择一；**禁止**在各版策略段（命名/问题锚定）、各版 b 段或各版正文段正式逼选双轨。b 段仅可**预列**双轨示意。  
- **禁止**本 skill 充当独权总控：不写三版 plan、不重新界定技术问题、不递交变劣、不替代命名总控、不独自完成末尾择轨调度（择轨调度属独权第8步）。  
- 用户仅点名「按 I/O 重写 / 路径是否过细」等、未走三版策略时，可单独用本 skill 做方法质检；一旦处于 `独权撰写` 流水线，必须服从其各版 **a→b→正文** 三截顺序，以及末尾第8步择轨。

**典型触发：** 「写方法独权」「按输入输出重写步骤」「这一步是不是写太细」「步骤衔接不紧」；或由 `独权撰写` 第2/4/7 步的 b 段、第8步（择轨）调度。

## 保护客体（为何这样写）

方法发明保护的是：**为解决技术问题而采用的操作流程/处理步骤及其逻辑关系**。

- 侵权比对：是否实质实施同一条 **输入 →（必要变换）→ 输出** 流水线。
- 独权对准**分步流程契约**，不是某次实现的全部中间工序。
- **省去步内中间路径**（下从权）：避免把客体收成「一种具体算法实现」、换等价实现即规避；与扩围一致。
- **不能省的**：删掉后技术问题无解或失去区别的变换准则（不变量）。

须落成技术方案；禁止纯数学兴趣或「智能优化」类空词。

## 高质量方法独权总纲（硬性）

> **先把方案清楚拆成若干步；每步明确抽象出输入与输出；步内输入用尽、步间输出咬合；输入到输出的具体路径默认进从权。**

## 核心规则

### 规则一：先拆步（粒度），再写每步 I/O

#### 1.1 怎么拆

1. **按处理目标 / 产物拆步**，不按代码行、仿真次数或「加第 1 个点、加第 2 个点」拆。  
   - 宜（数据处理）：得到节点特征 → 得到候选监测点集合 → 得到优化后的监测点集合 → 输出布设方案。  
   - 宜（调控闭环）：感知状态量 →（可选）建立作用场/判定工况 → **得到中间调控量** → 按偏差执行调整（见规则八）。  
   - 不宜：生成工况、训练模型、抽特征拆成三个独权主步骤（三者多为同一步的路径/概括层，见规则四）。  
2. **独权主步骤数量**：一般 **3～7 步**。过碎易把实现路径抬进独权；过粗（1～2 步包打天下）易假宽、I/O 无法核对。  
3. **循环 / 迭代**：默认写成**一步**（如「盲区约束的增量选点」），用控制流写切换/终止；不要按迭代轮次拆成多个主步骤。闭环调控若「算调控量→执行→再观测」属同一控制周期，可合并或按产物拆成相邻两步，勿按采样时刻拆碎。  
4. **获取类动作**：与「第一次使用该数据的处理」合并，或单独成步但须满足规则二（本步输出必须用到该获取）；禁止只获取、本步无产出。

#### 1.2 每步 I/O 契约

每一步写成可核对契约：

```text
本步（输入）→ 输出
```

常用句式方向：`获取…` / `基于…` / `根据…` → `得到…`（或训练/识别/输出等可核对动词）。

#### 1.3 I/O 对照表门禁（方法案）

写方法/算法流程型独权正文前，须交付下表，标注「**待确认：方法独权 I/O 对照表**」。在 `独权撰写` 流水线中，本表属 **b. 方法优化段** 交付（命名对照表属 a 段，**宜分截确认**；单独使用本 skill 做质检时仍可与命名表同批）。

| 步骤 | 输入（操作数） | 输出 | 本步不变量（若有） | 拟下放路径（成组） |
|------|----------------|------|--------------------|--------------------|
| S1 | … | … | … / 无 | … |
| … | | | | |

**力度：**

| 版本 | 要求 |
|------|------|
| **第一版** | **建议**交付；用户未反对可先表后文 |
| **第二版、第三版** | **硬性**：用户确认（或改表）前**不得**输出该版独权全文 |

表内须已做规则二用尽自检与规则四初步归类（不变量列 / 拟下放路径列）。确认后写正文时不得偷偷加回空挂输入或未归类的实现路径。表内步骤号须与正文 **S1、S2…** 一致（见 1.4）。

#### 1.4 步骤编号形式（硬性）

方法独权与从权正文中的步骤标号按下列规则书写（亦约束从权撰写）：

| 位置 | 编号 | 含义 |
|------|------|------|
| **独权**主步骤 | **S1、S2、S3…**（一位序号，按执行顺序） | 独权流程骨架；I/O 对照表步骤列与正文一致 |
| **从权**中、对独权**某一主步骤**的细化/优化子步骤 | **Sij**：**i** = 所挂靠的独权步号，**j** = 该从权内子步序 | 如扩 S1 → **S11、S12、S13…**；扩 S2 → **S21、S22、S23…**；扩 S3 → **S31…** |
| **从权**中、**不挂靠**独权某一步、而是对**整方案新增**的步骤 | **不加** S11/S12/S21 这类挂靠编号 | 用「还包括…」「进一步地，在…之后还进行…」等表述列出；勿写成 S11 以免被读成「只优化 S1」 |

**硬性约束：**

1. 独权正文每个主步骤必须以 `S1、` `S2、` … 开头（中文顿号或全角逗号体例与案件全文统一即可，但 **S + 序号** 不可省）。  
2. 从权若展开的是「独权 Si 怎么做」，子步骤必须用 **Si1、Si2…**，使读者一眼看出挂靠关系；与规则九「按独权步骤成组」同构。  
3. 从权若增加的是贯穿整法的新步骤（如预处理总入口、总输出校验、与各 Si 平级的新环节），**禁止**误用 S11/S21 等挂靠号。  
4. 禁止独权使用 S11 这类两位号；禁止从权细化 S2 时误标成 S11。

示意：

```text
【独权】S1、…；S2、…；S3、…；
【从权·扩S1】进一步地，所述S1包括：S11、…；S12、…；
【从权·扩S2】进一步地，所述S2包括：S21、…；S22、…；
【从权·整方案新增】进一步地，在所述S1之前，还对…进行…；（不加S11）
```

### 规则二：步内衔接——输入用尽（禁止空挂）

#### 2.1 基本原则

本步**为得到本步输出而写明的操作数（输入）**，都必须参与得到**本步输出**。

| 不合格 | 合格处置 |
|--------|----------|
| 「获取 A 和 B」，其后运算只用 A，B 留到后续步骤才用 | 将 B 的获取**挪到真正使用它的步骤**；禁止为「用尽」而虚构本步输出硬塞 B |
| 本步输出与所获取输入对不上 | 重定本步 I/O，使「基于这些输入得到该输出」成立 |

**禁止**为凑「获取」清单而空挂输入（典型：与本步抽特征无关的「当前监测点集合」与水力模型捆在同一获取句）。

#### 2.2 「用尽」适用范围与例外（防机械套用）

| 类型 | 是否要求本步用尽 | 说明 |
|------|------------------|------|
| **本步操作数** | **是** | 为本步产出而获取/引入的数据、集合、模型、特征等 |
| **仅下一步才用的对象** | 不适用「本步用尽」 | **应挪步**，不要留在本步获取句里 |
| **循环状态量** | 在含该循环的那一步内用尽 | 如「当前布设集合」在增量选点步中作为起点并被更新 |
| **全文统一的执行主体** | 不视为须「用尽」的输入 | 如「计算机」「控制器」作主语，不计入操作数清单 |
| **预设条件 / 预设阈值** | 在使用它的判断句所在步用尽 | 配合 `预设值与参数来源检查`；标明「预设」即可 |

**禁止反向操作：** 发现空挂后，不得编造「本步也输出对 B 的评估」等交底未支撑的产出只为通过用尽检查；要么挪步，要么交底确有该产出再写入。

#### 2.3 入口集合与「可空」

交底支持从零布设时：当前监测点集合可在**增量选点步**作为起点引入；说明书/从权可说明初始可为空。  
独权**勿**写「允许为空」类注释句；也**勿**因可空而把该集合提前塞进无关步骤。

### 规则三：步间衔接——输出咬合输入

- 上一步输出名称与下一步输入对齐（数据血统闭合）。  
- 配合 `预设值与参数来源检查`：参数先获取/算得/标明预设再使用。  
- 跨步传递的集合/模型/特征：在**引入步**满足用尽，在**使用步**作为输入再次出现并参与该步产出。

### 规则四：路径 / 不变量二分（硬判问 · 先判再放）

对拟写入独权的每一段「中间处理」，先三分，再决定去留。**禁止**未经二分就把整段训练/仿真细节塞进独权，也禁止为扩围删到无法实施。

#### 4.1 三问硬判（按序；命中即归类）

| 顺序 | 判问 | 若「是」→ 归类 | 独权处置 |
|------|------|----------------|----------|
| ① | 换成另一种本领域常见等价实现后，**本步声明的输入与输出是否仍成立**？ | **路径（实现层）** | **默认下从权/说明书**；独权不写该具体实现 |
| ② | 不写清该段，本领域技术人员能否仍由本步输入**得到**本步输出（可实施）？ | 若「否」→ 尚不够抽象 | 独权至少保留**概括层**手段（见 4.2）；细节仍从权 |
| ③ | 该段是否正是区别于现有技术、解决锚定技术问题所靠的**变换准则/控制逻辑**？ | **不变量** | **必须留独权**；不得当路径删掉 |

说明：①与③可同时观察——「用余弦」常为路径，「按特征相似度聚类」「在盲区内按误差减少量选」常为不变量。②是扩围刹车，但**不强制**独权必须写「通过××方式」；见 4.2 双轨。

#### 4.2 可实施下限与概括层双轨（保留版 / 下放版）

独权每步在压缩**细节路径**后，仍须使本领域技术人员**能够实现**该步 I/O。可实施可靠：独权概括层、**中间产物 I/O**、`其中` 语义定义、从权展开、说明书实施例——**不要求**独权堆「通过何种方式」句。

对「方式类」表述（仿真怎么做、如何训练、用什么算法得到中间模型等），交付时在下列**两轨中择一**（须在 I/O 对照表或交付说明中标注采用哪一轨）；**两轨均合法**。

**调度位置（与 `独权撰写` 对齐，规则本身不删减）：**

1. **各版 b 段**：先完成规则四三分与 I/O 表（含不变量列、拟下放路径列）；可在表注中**预列**轨 A/B 两种落笔示意，但**不要求、不允许**用户在各版内正式择轨。  
2. **各版正文**：默认**暂按轨 A（保留版）**落笔，并标注「暂定轨A，第8步统一择轨」。  
3. **`独权撰写` 第8步（三版之后、变劣之前）：正式出示双轨对照并请用户择一**；按所选轨改写定稿独权；未择轨不得进入变劣/收束。  
4. 禁止在命名/策略段（a）或未完成二分前，用「先选轨」替代路径/不变量判断；禁止在第2/4/7步内正式逼选双轨。

| 轨 | 独权怎么写 | 从权/说明书 | 适用 |
|----|------------|-------------|------|
| **A. 概括层保留** | 可写不钉死工具/参数的方式概括，如「通过多漏损工况仿真与定位模型训练，得到…并提取节点特征」 | 软件名、层号、维数、损失、具体算法进从权 | 担心「基于 A 得到 B」假宽、或审查/交底要求独权可见手段轮廓 |
| **B. 概括层下放** | 独权只写 **基于什么 → 得到什么**（可含中间产物，如「基于水力模型，得到全节点基准定位模型，并提取…节点特征」）；**不写**「通过仿真/训练/某算法」 | 「通过何种方式」整段进从权（`S11、S12…`）；可实施主要靠从权+说明书+`其中` | 用户要最大范围、或明确「方式进从权」 |

**共用硬性：**

- **细节层**（EPANET、漏损面积范围、TCN、最后一卷积层、128 维、余弦、谱聚类、学习率等）→ **两轨都进从权**，不得进独权。  
- **禁止**把③类不变量当路径下放。  
- **禁止**假宽空词（「智能分析并优化」等）；轨 B 若删到连中间产物/`其中` 都没有、且后文无法锚定可实施，须补中间产物或改回轨 A，不得硬留空壳。  
- 轨 B 的「基于 A 得到 B」**不等于**不合格；仅当可实施无所依托时才不合格（修正原「凡基于 A 得到 B 即过薄」的过严示例）。

#### 4.3 与三层分离的对应

| 层 | 内容 | 位置 |
|----|------|------|
| **I/O 层** | 分步、输入、输出、步内用尽、步间咬合 | **独权**（两轨都要） |
| **不变量层** | 判问③为是的准则/控制流 | **独权必须保留** |
| **实现层（路径）** | 判问①为是的算法/工具/参数等 | **从权/说明书** |
| **概括层（方式轮廓）** | 不钉死的手段概括（「通过仿真与训练」类） | **轨 A：可留独权；轨 B：下从权** |

客体理由：独权锁流程契约与必要准则；具体路径写下独权则范围缩成该实现；方式概括是否留独权由轨 A/B 显式选择，避免暗中把「通过××」当成唯一合法独权写法。

**不变量如何写进独权：** 只展开判为③的准则（如「在信息盲区内选」「按定位误差减少量选」「加点后重评」），不写源码路径。自定义概念优先在名称出现前白话写清或改自明名；「其中」仅兜底，不塞伪代码（见 `自定义名词就地定义`）。

### 规则五：控制流接口化

条件句用 `条件判断语句规范`。独权只留必要分支（切换域、终止等）；细阈值进从权，写「预设的××条件」即可。

### 规则六：扩围手法（去钉死；须先完成规则四）

先规则四二分，再对本步留下的表述去钉死：

| 手法 | 动作 | 边界 |
|------|------|------|
| 去模型/算法/工具/参数/场景钉死 | 上位为完成该 I/O 的类名或预设条件 | 不得跌破 4.2 可实施下限 |
| 术语与问题同级 | 问题已上位则题名与步骤用词同步 | 避免问题宽、独权窄 |
| 成组下放路径 | ①类实现细节**按独权步骤成组**进从权 | **禁止**把③类不变量整组下放 |
| **和/或执行手段** | 同一不变量下多种可选执行器/调节量，独权用「和/或」并列 | 细则与优先序进从权；旋钮本身若是不变量则不得冲掉（见规则八.2） |

### 规则七：执行主体（主语）

方法步骤须有明确执行者，或全文统一隐含同一执行主体（如「一种由计算机执行的…方法」）。禁止因省略主语导致「谁获取/谁训练/谁选点」不清。细则见 `权利要求主谓宾结构规范`（方法案必查主语）。

因果动词链宜清楚：`获取…` → `确定/计算…` → `根据…调整/输出…`，使每步产物可核对、步间可咬合。  
步内可用「以…」接**本步直接技术效果**（如「以产生定向扰动水流」「以控制热交换速率」）；禁止「以…」写成空泛有益效果宣传（提高效率、更加智能等）。

### 规则八：调控闭环型方法（感知 → 作用/判定 → 调控量 → 执行）

交底为**测控/调节/闭环控制**（非纯离线算法）时，在规则一～四之外适用本规则。数据处理型案可不套本模板。

#### 8.1 推荐产物链

| 典型步 | 产物 | 说明 |
|--------|------|------|
| 感知 | 初始/实时状态量 | 如厚度、温度剖面、压力等；可与首次使用合并 |
| 作用/判定（可合并或分步） | 已建立的作用场，和/或工况判定结果 | 如驱动形成定向流、判定「暖水层」；视案情可「作用先于精细观测」（先建扰动场，再算通量） |
| **调控量（控制量中置）** | **中间控制量**（须成步输出） | 如实际/目标热通量及其偏差、误差减少量；**禁止**跳过本步直接写「根据状态调执行器」导致因果断链 |
| 执行（偏差驱动） | 对执行器/操作量的调整结果 | 独权写「根据所述偏差调节…」；阈值与公式进从权；多执行器见 8.2 |

**中间控制量**与最终执行量不是同一产物：前者回答「调多少/朝哪边」；后者回答「动哪个旋钮」。独权宜让调控量在表中单独占「输出」列，再由执行步消费。

#### 8.2 「和/或」执行（同一不变量下的等价旋钮）

当交底给出**两种以上可独立或联合使用的执行手段**，且换成任一种（或组合）后「按调控量完成调节」的 I/O 仍成立时：

- 独权执行步可用 **「和/或」** 并列（如调整 A 和/或 B），作为**概括层**，勿只钉死一种旋钮（亦见规则六）。  
- 各旋钮的具体公式、阈值、优先顺序 → **从权路径组**（按执行步成组）。  
- 若某一旋钮本身是区别不变量（删掉则问题无解），不得用「和/或」冲掉，须保留。

#### 8.3 与规则四的衔接

- 「如何算调控量的具体公式/系数」→ 常为①路径。  
- 「先算调控量再按偏差调节」「按某判定区间才调」→ 常为③不变量。  
- 独权至少保留：作用/判定概括 + 调控量作为中间输出 + **根据偏差（或等价准则）调节**；公式与阈值细节进从权。

#### 8.4 闭环回馈放哪里

返回重测/重算调控量、气象补偿、终止条件、多周期迭代等，**默认进从权或独权末步一句概括**，避免独权按采样轮次臃肿；独权须保留的是闭环不变量（如「根据偏差调节」），不是每一次反馈的实现细节。

### 规则九：从权按独权步骤成组映射（硬性提醒）

I/O 对照表「拟下放路径」列与从权盘点须**按独权步骤编号成组**（S1 一组、S2 一组…），禁止打成与步骤无关的杂烩清单。从权 = **逐步显微镜**：每条核心从权应能标明扩的是独权哪一步的路径/分支。

| 独权步 | 从权宜接什么 |
|--------|----------------|
| 感知/获取 | 测点布置、采样方式、预处理 |
| 作用/判定 | 驱动方式、判据细化、阈值、子区间 |
| 调控量 | 计算公式、系数、滤波 |
| 执行 | 各执行器细节、「和/或」之一的专条、联合策略 |
| 闭环回馈 | 返回条件、补偿项、终止条件（见 8.4） |
| 数据/模型步 | 模型结构、相似度、聚类等实现层 |

布局时优先：**每条核心从权能指回某一独权步**；细化该步时正文用 **Si1、Si2…** 编号（规则 1.4）；并行改进点可平行引用权1（见 `从权撰写` / `权利要求引用结构检查`）。整方案新增步骤不加挂靠编号。

方法+装置/系统双独权（可选薄提）：产业上常另写「执行该方法的系统/装置」独权并与方法步骤模块对应；**方法轨按本 skill，系统/装置轨归产品结构规范**，由 `独权撰写` 按客体分写，本 skill 不展开系统独权句式。

### 规则十：交稿自检

1. 是否按产物拆步（约 3～7）？循环/闭环是否未按轮次拆碎？每步 I/O 能否一句话说清？独权是否以 S1、S2… 开头？  
2. 操作数是否用尽、无空挂？有无为用尽虚构产出？步间是否咬合？  
3. 是否已规则四三问？路径/不变量/概括层归类是否正确？  
4. 调控类是否写出**中间调控量**？是否偏差驱动执行？闭环回馈是否未把独权撑臃肿？多执行器「和/或」与按步下放是否齐备？  
5. 换等价实现是否仍想卡住？有无跌破可实施下限或假宽空词？  
6. 主语与因果动词链是否清楚？「以…」是否接本步直接效果而非空泛宣传？  
7. 拟下放路径是否已按独权步骤成组（规则九，逐步显微镜）？从权编号是否符合规则 1.4（Sij / 整案新增不加挂靠号）？

## 最低交付

1. **第二/三版：** 已确认的 I/O 对照表（步骤|输入|输出|不变量|拟下放路径）；第一版建议有表。步内无空挂、步间咬合；主语清楚；独权步骤以 **S1、S2…** 开头（规则 1.4）。  
2. 规则四归类与表内「拟下放路径」列一致，且**按独权步骤成组**（规则九）；供从权盘点。概括层轨 A/B：**各版 b 段**可预列示意；**正式择一并在定稿中标明**由 `独权撰写` 第8步完成（见 4.2）；不得以未择轨摘要替代双轨规则条文。  
3. 调控类：中间调控量为表内独立输出；偏差驱动执行；多执行器「和/或」已处理；闭环回馈位置已按 8.4 处理（规则八）。  
4. 自定义概念已按 `自定义名词就地定义` 说清（优先前置白话，少堆「其中」）；「以…」接本步直接效果；条件与预设符合配套 skill。  
5. 扩围后仍可实施，最小区别骨架仍在。
