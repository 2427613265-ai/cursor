# 方法类权利要求撰写（分步 I/O · 衔接闭合 · 路径下放 · 扩围）

## 适用场景

- 撰写「一种××方法」类**方法独立权利要求**（含算法/数据处理流程型）。
- 审核方法独权是否：步骤切分不清、I/O 不明、步内输入空挂、步间接不上、中间路径过细或假宽。
- 判断某段「输入→输出」的具体计算路径应留独权还是下从权。
- **不替代** `独权撰写`；**不替代** `结构类权利要求撰写`。

**典型触发：** 「写方法独权」「按输入输出重写步骤」「这一步是不是写太细」「步骤衔接不紧」。

---

## 保护客体（为何这样写）

方法发明保护的是：**为解决技术问题而采用的操作流程/处理步骤及其逻辑关系**。

- 侵权比对：是否实质实施同一条 **输入 →（必要变换）→ 输出** 流水线。
- 独权对准**分步流程契约**，不是某次实现的全部中间工序。
- **省去步内中间路径**（下从权）：避免把客体收成「一种具体算法实现」、换等价实现即规避；与扩围一致。
- **不能省的**：删掉后技术问题无解或失去区别的变换准则（不变量）。

须落成技术方案；禁止纯数学兴趣或「智能优化」类空词。

---

## 高质量方法独权总纲（硬性）

> **先把方案清楚拆成若干步；每步明确抽象出输入与输出；步内输入用尽、步间输出咬合；输入到输出的具体路径默认进从权。**

---

## 核心规则

### 规则一：先拆步（粒度），再写每步 I/O

#### 1.1 怎么拆

1. **按处理目标 / 产物拆步**，不按代码行、仿真次数或「加第 1 个点、加第 2 个点」拆。  
   - 宜：得到节点特征 → 得到候选监测点集合 → 得到优化后的监测点集合 → 输出布设方案。  
   - 不宜：生成工况、训练模型、抽特征拆成三个独权主步骤（三者多为同一步的路径/概括层，见规则四）。  
2. **独权主步骤数量**：一般 **3～7 步**。过碎易把实现路径抬进独权；过粗（1～2 步包打天下）易假宽、I/O 无法核对。  
3. **循环 / 迭代**：默认写成**一步**（如「盲区约束的增量选点」），用控制流写切换/终止；不要按迭代轮次拆成多个主步骤。  
4. **获取类动作**：与「第一次使用该数据的处理」合并，或单独成步但须满足规则二（本步输出必须用到该获取）；禁止只获取、本步无产出。

#### 1.2 每步 I/O 契约

每一步写成可核对契约：

```text
本步（输入）→ 输出
```

常用句式方向：`获取…` / `基于…` / `根据…` → `得到…`（或训练/识别/输出等可核对动词）。

#### 1.3 I/O 对照表门禁（方法案）

写方法/算法流程型独权正文前，须交付下表（可与命名对照表**同批**），标注「**待确认：方法独权 I/O 对照表**」：

| 步骤 | 输入（操作数） | 输出 | 本步不变量（若有） | 拟下放路径（成组） |
|------|----------------|------|--------------------|--------------------|
| S1 | … | … | … / 无 | … |
| … | | | | |

**力度：**

| 版本 | 要求 |
|------|------|
| **第一版** | **建议**交付；用户未反对可先表后文 |
| **第二版、第三版** | **硬性**：用户确认（或改表）前**不得**输出该版独权全文 |

表内须已做规则二用尽自检与规则四初步归类（不变量列 / 拟下放路径列）。确认后写正文时不得偷偷加回空挂输入或未归类的实现路径。

### 规则二：步内衔接——输入用尽（禁止空挂）

#### 2.1 基本原则

本步**为得到本步输出而写明的操作数（输入）**，都必须参与得到**本步输出**。

| 不合格 | 合格处置 |
|--------|----------|
| 「获取 A 和 B」，其后运算只用 A，B 留到后续步骤才用 | 将 B 的获取**挪到真正使用它的步骤**；禁止为「用尽」而虚构本步输出硬塞 B |
| 本步输出与所获取输入对不上 | 重定本步 I/O，使「基于这些输入得到该输出」成立 |

**禁止**为凑「获取」清单而空挂输入（典型：与本步抽特征无关的「当前监测点集合」与水力模型捆在同一获取句）。

#### 2.2 「用尽」适用范围与例外（防机械套用）

| 类型 | 是否要求本步用尽 | 说明 |
|------|------------------|------|
| **本步操作数** | **是** | 为本步产出而获取/引入的数据、集合、模型、特征等 |
| **仅下一步才用的对象** | 不适用「本步用尽」 | **应挪步**，不要留在本步获取句里 |
| **循环状态量** | 在含该循环的那一步内用尽 | 如「当前布设集合」在增量选点步中作为起点并被更新 |
| **全文统一的执行主体** | 不视为须「用尽」的输入 | 如「计算机」「控制器」作主语，不计入操作数清单 |
| **预设条件 / 预设阈值** | 在使用它的判断句所在步用尽 | 配合 `预设值与参数来源检查`；标明「预设」即可 |

**禁止反向操作：** 发现空挂后，不得编造「本步也输出对 B 的评估」等交底未支撑的产出只为通过用尽检查；要么挪步，要么交底确有该产出再写入。

#### 2.3 入口集合与「可空」

交底支持从零布设时：当前监测点集合可在**增量选点步**作为起点引入；说明书/从权可说明初始可为空。  
独权**勿**写「允许为空」类注释句；也**勿**因可空而把该集合提前塞进无关步骤。

### 规则三：步间衔接——输出咬合输入

- 上一步输出名称与下一步输入对齐（数据血统闭合）。  
- 配合 `预设值与参数来源检查`：参数先获取/算得/标明预设再使用。  
- 跨步传递的集合/模型/特征：在**引入步**满足用尽，在**使用步**作为输入再次出现并参与该步产出。

### 规则四：路径 / 不变量二分（硬判问 · 先判再放）

对拟写入独权的每一段「中间处理」，先三分，再决定去留。**禁止**未经二分就把整段训练/仿真细节塞进独权，也禁止为扩围删到无法实施。

#### 4.1 三问硬判（按序；命中即归类）

| 顺序 | 判问 | 若「是」→ 归类 | 独权处置 |
|------|------|----------------|----------|
| ① | 换成另一种本领域常见等价实现后，**本步声明的输入与输出是否仍成立**？ | **路径（实现层）** | **默认下从权/说明书**；独权不写该具体实现 |
| ② | 不写清该段，本领域技术人员能否仍由本步输入**得到**本步输出（可实施）？ | 若「否」→ 尚不够抽象 | 独权至少保留**概括层**手段（见 4.2）；细节仍从权 |
| ③ | 该段是否正是区别于现有技术、解决锚定技术问题所靠的**变换准则/控制逻辑**？ | **不变量** | **必须留独权**；不得当路径删掉 |

说明：①与③可同时观察——「用余弦」常为路径，「按特征相似度聚类」「在盲区内按误差减少量选」常为不变量。②是扩围刹车：①判为路径后，若独权只剩「基于 A 得到 B」而无人能实施，必须加概括层，不能删光。

#### 4.2 可实施下限（与扩围的平衡）

- 独权每步在压缩路径后，仍须使本领域技术人员**能够实现**该步 I/O。  
- **概括层示例（可留独权）：**「通过仿真得到训练数据并训练得到定位模型，再提取节点特征」——不钉死软件名、层号、维数、损失。  
- **细节层示例（进从权）：** EPANET、漏损面积范围、TCN、最后一卷积层、128 维、余弦、谱聚类、学习率。  
- **禁止：** 为扩围写成无可核对手段的「基于 A 得到 B」空壳；**禁止**把③类不变量误判为路径下放。

#### 4.3 与三层分离的对应

| 层 | 内容 | 位置 |
|----|------|------|
| **I/O 层** | 分步、输入、输出、步内用尽、步间咬合 | **独权** |
| **不变量层** | 判问③为是的准则/控制流 | **独权必须保留** |
| **实现层（路径）** | 判问①为是的算法/工具/参数等 | **从权/说明书** |
| **概括层（若需要）** | 判问②要求的、不钉死实现的必要手段概括 | **独权可保留** |

客体理由：独权锁流程契约与必要准则；具体路径写下独权则范围缩成该实现。

**不变量如何写进独权：** 只展开判为③的准则（如「在信息盲区内选」「按定位误差减少量选」「加点后重评」），不写源码路径。自定义名词用「其中」定义**语义**，不塞伪代码（见 `自定义名词就地定义`）。

### 规则五：控制流接口化

条件句用 `条件判断语句规范`。独权只留必要分支（切换域、终止等）；细阈值进从权，写「预设的××条件」即可。

### 规则六：扩围手法（去钉死；须先完成规则四）

先规则四二分，再对本步留下的表述去钉死：

| 手法 | 动作 | 边界 |
|------|------|------|
| 去模型/算法/工具/参数/场景钉死 | 上位为完成该 I/O 的类名或预设条件 | 不得跌破 4.2 可实施下限 |
| 术语与问题同级 | 问题已上位则题名与步骤用词同步 | 避免问题宽、独权窄 |
| 成组下放路径 | ①类实现细节**按独权步骤成组**进从权 | **禁止**把③类不变量整组下放 |

### 规则七：执行主体（主语）

方法步骤须有明确执行者，或全文统一隐含同一执行主体（如「一种由计算机执行的…方法」）。禁止因省略主语导致「谁获取/谁训练/谁选点」不清。细则见 `权利要求主谓宾结构规范`（方法案必查主语）。

### 规则八：交稿自检

1. 是否按产物拆步（约 3～7）？循环是否整步？每步 I/O 能否一句话说清？  
2. 操作数是否用尽、无空挂？有无为用尽虚构产出？步间是否咬合？  
3. 是否已规则四三问？路径/不变量/概括层归类是否正确？  
4. 换等价实现是否仍想卡住？有无跌破可实施下限或假宽空词？  
5. 主语是否清楚？自定义词能否仅靠「其中」读懂？

## 执行顺序与相邻 skill 接口（硬性）

写/改方法独权时按下列顺序，**禁止颠倒成先砍必要特征、后补 I/O**：

```text
① 本 skill：拆步 → 填 I/O 对照表（第二/三版须确认）→ 用尽/咬合 → 规则四路径·不变量二分（含概括层）
        ↓
② 部件命名优化总控（命名表确认；可与 I/O 表同批）
        ↓
③ 独立权利要求必要技术特征检查（相对锚定技术问题再筛；对象主要是已留在独权的不变量/概括层，不是把①类路径重新堆回独权）
        ↓
④ 条件判断 / 预设值来源 / 主谓宾·指代 / 其中定义（横切随写随查）
        ↓
⑤ 从权撰写：承接①成组下放的路径（按独权步骤成组；不得把③类不变量丢进从权）
```

| 接口 | 本 skill 负责 | 对方负责 |
|------|----------------|----------|
| vs `独立权利要求必要技术特征检查` | I/O 闭合、路径/不变量二分 | 相对技术问题「能否删除/概括」；方法案以本 skill 二分结果为输入 |
| vs `从权撰写` | 标出拟下放路径组（按步） | 布局进 9 条、逐条写；方法案盘点须纳入「独权已标下放的路径组」 |
| vs `独权撰写` | 类型铺陈与扩围细则 | 三版策略、确认节奏、变劣 |
| vs 主谓宾/条件句/预设值/其中定义 | 提醒必查 | 各规范全文 |

## 与独权三版策略的配合

由 `独权撰写` 挂接：

| 版本 | 本 skill |
|------|----------|
| **第一版** | 拆步 + I/O 可追踪；**建议**交 I/O 对照表；允许暂留部分路径 |
| **第二版** | **硬性**确认 I/O 对照表；用尽/咬合；规则四二分；**然后**再跑 `独立权利要求必要技术特征检查` |
| **第三版** | **硬性**确认 I/O 对照表；规则四之后再去钉死 + 规则八自检；不得抽空区别骨架、不得跌破可实施下限 |

术语命名仍先走 `部件命名优化总控`。正反例见同目录 `examples.md`（按需 Read）。

## 最低交付

1. **第二/三版：** 已确认的 I/O 对照表（步骤|输入|输出|不变量|拟下放路径）；第一版建议有表。步内无空挂、步间咬合；主语清楚。  
2. 规则四归类与表内「拟下放路径」列一致；供从权盘点。  
3. 「其中」定义语义；条件与预设符合配套 skill。  
4. 扩围后仍可实施，最小区别骨架仍在。

## 口诀

**按产物拆步，三到七步；循环整步写；  
先定 I/O，操作数用尽；空挂就挪步；  
三问归类，路径成组进从权；概括保底，准则留骨；  
先方法铺陈，再必要特征。**
