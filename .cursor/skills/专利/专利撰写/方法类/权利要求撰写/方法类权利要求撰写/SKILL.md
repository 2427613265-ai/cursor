# 方法类权利要求撰写（分步 I/O · 衔接闭合 · 路径下放 · 扩围）

## 适用场景

- 撰写「一种××方法」类**方法独立权利要求**（含算法/数据处理流程型）。
- 审核方法独权是否：步骤切分不清、I/O 不明、步内输入空挂、步间接不上、中间路径过细或假宽。
- 判断某段「输入→输出」的具体计算路径应留独权还是下从权。
- **不替代** `独权撰写`；**不替代** `结构类权利要求撰写`。

**典型触发：** 「写方法独权」「按输入输出重写步骤」「这一步是不是写太细」「步骤衔接不紧」。

---

## 保护客体（为何这样写）

方法发明保护的是：**为解决技术问题而采用的操作流程/处理步骤及其逻辑关系**。

- 侵权比对：是否实质实施同一条 **输入 →（必要变换）→ 输出** 流水线。
- 独权对准**分步流程契约**，不是某次实现的全部中间工序。
- **省去步内中间路径**（下从权）：避免把客体收成「一种具体算法实现」、换等价实现即规避；与扩围一致。
- **不能省的**：删掉后技术问题无解或失去区别的变换准则（不变量）。

须落成技术方案；禁止纯数学兴趣或「智能优化」类空词。

---

## 高质量方法独权总纲（硬性）

> **先把方案清楚拆成若干步；每步明确抽象出输入与输出；步内输入用尽、步间输出咬合；输入到输出的具体路径默认进从权。**

---

## 核心规则

### 规则一：先拆步，再写每步 I/O

1. 先把整体方案拆成**边界清楚**的主步骤（一步一个处理单元），禁止一大段连写导致无法核对 I/O。  
2. 每一步写成可核对契约：

```text
本步（输入）→ 输出
```

常用句式方向：`获取…` / `基于…` / `根据…` → `得到…`（或训练/识别/输出等可核对动词）。  
3. 代理人应能列出主步骤的「输入→输出」对照表（可笔记，交付时口头可复述）。

### 规则二：步内衔接——输入用尽（禁止空挂）

本步**写明的每一项输入**，都必须参与得到**本步输出**。

| 不合格 | 合格处置 |
|--------|----------|
| 「获取 A 和 B」，其后运算只用 A，B 留到后续步骤才用 | 将 B 的获取挪到真正使用它的步骤；或改写本步输出使 B 成为必要输入 |
| 本步输出与所获取输入对不上 | 重定本步 I/O，使「基于这些输入得到该输出」成立 |

**禁止**为凑「获取」清单而空挂输入（典型：与本步训练/抽特征无关的集合与水力模型捆在同一获取句）。

### 规则三：步间衔接——输出咬合输入

- 上一步输出名称与下一步输入对齐（数据血统闭合）。  
- 配合 `预设值与参数来源检查`：参数先获取/算得/标明预设再使用。  
- 集合可空等入口若交底支持，宜在说明书/从权交代；独权勿写别扭的「允许为空」注释句，也不要因此空挂输入。

### 规则四：路径下放——步内中间处理进从权

「输入如何变成输出」的**具体路径**（仿真造数细节、训练过程、抽哪一层、相似度公式、聚类算法名、软件名、超参等）**默认进从权/说明书**。

独权本步宜写成：基于（本步输入），得到（本步输出）；必要时只保留**必要变换准则**。

**客体理由：** 独权锁流程接口；路径是实现，写下独权则范围缩成该实现。

### 规则五：三层分离（扩围与保质）

| 层 | 内容 | 位置 |
|----|------|------|
| **I/O 层** | 分步、输入、输出、步内用尽、步间咬合 | **独权** |
| **不变量层** | 删则问题无解或无区别的准则/控制流 | **独权必须保留** |
| **实现层（路径）** | 可替换的算法、工具、参数、实施例数值 | **从权/说明书** |

- 扩围 = 压缩实现层；保质 = I/O 闭合 + 不变量仍在。  
- 禁止假宽空词冒充步骤；禁止为扩围抽空不变量。

### 规则六：不变量才在独权展开「怎么变」

- **要展开：** 不写清则方案不完整或无区别的准则（如「在信息盲区内选」「按定位误差减少量选」「加点后重评」）。  
- **不展开：** 可达同一 I/O 的等价实现细节。  
- **「其中」：** 只定义自定义名词的**语义**，不塞完整伪代码路径。

### 规则七：控制流接口化

条件句用 `条件判断语句规范`。独权只留必要分支（切换域、终止等）；细阈值进从权，写「预设的××条件」即可。

### 规则八：扩围手法（去钉死）

| 手法 | 动作 | 边界 |
|------|------|------|
| 去模型/算法/工具/参数/场景钉死 | 上位为完成该 I/O 的类名或预设条件 | 不得写空；说明书宜有支持 |
| 术语与问题同级 | 问题已上位则题名与步骤用词同步 | 避免问题宽、独权窄 |
| 成组下放路径 | 实现细节成组进从权 | **禁止**把最小区别骨架整组下放 |

### 规则九：交稿自检（合并五问 + 衔接）

1. 步骤是否拆清？每步能否一句话说清输入与输出？  
2. 步内是否输入用尽、无空挂？步间是否咬合？  
3. 具体路径是否已尽量下从权？留下的准则是否必要？  
4. 换等价实现是否仍想卡住？想则独权勿钉死该实现。  
5. 自定义词能否仅靠「其中」读懂？有无假宽空词？

## 与独权三版策略的配合

由 `独权撰写` 挂接：

| 版本 | 本 skill |
|------|----------|
| **第一版** | 拆步 + I/O 可追踪；允许暂留部分路径 |
| **第二版** | 步内用尽、路径下放、压实现层；并行 `独立权利要求必要技术特征检查` |
| **第三版** | 最大化去钉死 + 跑规则九；不得抽空区别骨架 |

术语命名仍先走 `部件命名优化总控`。正反例见同目录 `examples.md`（按需 Read）。

## 最低交付

1. 主步骤「输入→输出」对照可复述；步内无空挂、步间咬合。  
2. 路径已尽量下从权；不变量仍在（第一版可暂留部分路径）。  
3. 「其中」定义语义；条件与预设符合配套 skill。  
4. 扩围后可实施，最小区别骨架仍在。

## 检查清单

- [ ] 已按客体理解为「流程」而非「实现清单」  
- [ ] 已拆步；每步 I/O 明确  
- [ ] 步内输入用尽；步间输出咬合  
- [ ] 具体路径默认从权；不变量未误删  
- [ ] 无假宽；去钉死与问题层级一致  
- [ ] 未误用结构类「先总列后展开」
