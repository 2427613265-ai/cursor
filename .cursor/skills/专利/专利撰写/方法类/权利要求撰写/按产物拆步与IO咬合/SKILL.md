# 按产物拆步与IO咬合

方法/算法独立权利要求的**拆步与数据流**细则。由 `方法类权利要求具体撰写规则总控` 在各版写正文时挂接；不替代两版策略（`方法类独权撰写`）。

## 适用

- 方法案 / 算法·数据处理案写独权正文（第5/7步）；第4步组成最小集时也可用来核对方案是否完整可实施。
- **不适用：** 结构「先总列部件再展开」；纯装置构成罗列。

## 规则一：按产物拆步

1. 主步骤一般约 **3～7** 步；以本步**得到什么**（中间量、状态、方案、指令等）为切分点。  
2. **禁止**按代码行、仿真次数、训练 epoch、日志打印点等实现粒度拆碎。  
3. 循环、迭代、增量更新过程默认写成**一步**，在该步内用控制流写明切换与终止条件（条件句走 `条件判断语句规范`）。  
4. 一步内可含多个紧密咬合的子操作，但对外仍是一个「产物」节点；需要从权细化时再用步骤编号规范中的 `Sij`。

## 规则二：每步 I/O 可核对

对每一个主步骤，读者须能从权要文字看出：

| 核对项 | 要求 |
|--------|------|
| **基于什么** | 本步输入来自交底已引入的数据、上一步产物，或本步内先获取/算得 |
| **得到什么** | 本步产物有名称或可指代的结果，供后续步骤或权利要求结尾使用 |
| **步间咬合** | 上一步输出能被下一步合法使用；禁止「上步产出 A、下步却依赖从未出现的 B」 |

## 规则三：禁止空挂操作数

- **禁止**写「获取/采集/读取××」却在本步及后续独权步骤中**从不使用**该××。  
- 若某量仅在更后步骤才用：获取动作应写在**真正首次使用**的步骤，或写明获取后立即得到供后续使用的命名产物。  
- 空挂常见于：为凑「数据采集感」前置一堆无关读取；或把说明书实施例操作未加筛选写入独权。

### 与「获得××」精简独权的区分（重要）

| | **空挂（禁止）** | **非区别数据的「获得」精简（允许，见 `路径与不变量二分`）** |
|--|------------------|--------------------------------------------------------------|
| 后续是否使用×× | 不用 | **要用** |
| 独权写法 | 写了一堆获取却从不消费 | 只写「获得/获取××」，**不展开**具体获得过程 |
| 具体获得步骤 | — | 下放到从权 |

当××为非发明点输入时，「获得××」视为合法的**按产物一步**（本步产物即××），须与下一步咬合；**不得**据此把区别性预处理也收成光秃「获得」。

## 与编号、闭环、路径规则的分工

| 事项 | 本 skill | 其他 |
|------|----------|------|
| 如何切步、I/O 是否咬合 | **本页** | — |
| 非区别「获得」能否省具体过程 | 咬合/空挂在本页；能否省见 | `路径与不变量二分` |
| 步骤叫 S1/Sij | — | `方法步骤编号规范` |
| 调控是否缺环 | — | `调控闭环最低链` |
| 某细限定能否删 | — | `路径与不变量二分` |

## 最低自检（写完一版独权正文后）

- [ ] 主步骤数量与切分理由可解释（按产物，非按代码）  
- [ ] 每步能指出输入来源与产物  
- [ ] 无空挂获取；无「产出未用、所用未产」  
- [ ] 非区别输入的「获得××」未与空挂混淆；后续步骤有消费  
- [ ] 未用结构总列句式冒充方法步骤  

## 能力边界

- 不管技术问题如何界定、不管命名优化时机（见策略 skill / 命名时机叶）。  
- 不管条件句固定句式、预设值来源（见对应横切 skill）。
