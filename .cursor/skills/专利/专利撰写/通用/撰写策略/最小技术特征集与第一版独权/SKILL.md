# 最小技术特征集与第一版独权（独权第2/3步细则）

方法/结构类独权**第2步、第3步**必读。正反例见同目录 `examples.md`。

第1步的一句话抓住的是希望形成的完整方案的**核心**，突出与现有的区别，**本身不是**完整技术方案，也**不是**独立权利要求。第1步三栏表的机制栏说明**为什么有效**。须以这句话为中心、对着机制展开完整方案，再连缀成**核心独立权利要求**（本流水线称**第一版独立权利要求**）。

**分步交付（硬性）：** 第2步只交最小集，第3步才交第一版全文。组集时允许在心里/草稿里试连缀，用来发现缺词、多余、一名多义；**不得**把试写当第2步交付。连缀时若必须增删特征，先回改最小集并请用户确认，再写正文。第1步机制三栏未确认（或应按三选一停步）不得组集。

---

## 为何必须先有最小集

完整技术方案含许多特征。本步只找**围着一句话、构成完整方案所必不可少**的那些；**绝对不能**引入并非必须的特征。这样组成的集合才叫最小技术特征集。

最小集与第一版**相互促进**：可从一句话出发先想独权怎么写，再倒推最小集。最小集仍不可省——它逼着审核「有没有多写」，并保证**同一事物同一名称**，避免不清楚。

入集标准是「方案是否完整可实施」**并且**「第1步三栏表里的技术效果还产生得出来」。**不是**「能否解决交底声称问题」（主题与问题留给第4步）。第5步校核与必要特征检查见 `第二版独权校核`。

---

## 第2步：组成最小技术特征集

### 操作

1. **从一句话抽词。** 标出这句话里已经点到的对象、动作、状态。  
2. **不清楚的先改写成权要能用的说法。** 如「特别的触摸动作」不清楚，可写成「预先设定的解锁触摸动作」。这是组集时的**清楚化**，不是方法案第5步的命名总控优化，也不是把实施例钉死名灌进来。  
3. **补完整方案必不可少、但一句话字面上没有的支撑特征。** 优先从第1步机制栏往下推：没有它机制就不成立的，必须补。结构案常见：载体部件、使其成立的结构、位置/连接/**作用面**。方法案常见：步骤顺序与 I/O 咬合、**步骤间约束**（顺序/条件/数量——机制依赖它们时不得当成可省的连接词）。另如解锁前后须有「锁定状态 / 工作状态」，否则方案说不圆。  
4. **删一法（逐项，不得成组删）。** 对每个候选特征 F 问两句：①去掉后一句话还接得上吗、技术方案还完整可实施吗？②**没有 F，第1步三栏表里的技术效果还产生得出来吗？**  
   - 产生不出来 → 必要，入集。  
   - 还能产生，只是效果差一些 → 不入集，下放从权（从权主要来源）。  
   - 与效果无关 → 不入集，通常连从权都不占。  
   **不要**再问「去掉后还能不能解决交底声称问题」。最容易漏删的是**关系特征**和**步骤间约束**（「A 与 B 固定连接」「位于……之间」「S2 须在 S1 结束后限定时间内开始」），不得当成背景跳过。  
5. **同物同名。** 最小集里同一事物只用一个名称；不同事物不得共用一名（「触摸屏」≠「触摸屏设备」）。  
6. **不把关键创新点整份灌进最小集**，除非第1步已标「可能入独权」且离开它方案无法实施（或离开它机制效果产生不出来）。

**过窄：** 把交底实施例细节、优选路径、工具名、参数范围塞进最小集。  
**过残：** 只有一句话拆词，缺锁定/工作状态之类支撑，连不成方案；或部件/步骤都在，使机制成立的**关系或约束**却被当成背景删掉。

**结构案（机制 → 载体 → 结构 → 关系）：** 组集时可附短表（一行一个改进点）：机制｜载体部件｜该部件必须具备的结构｜必须限定的关系（含作用面）｜可下放的具体化。参与机制的部件没有关系限定 = 过残。作用面是机制发生部位（进风侧、抵接面等），写丢则关系在、机制仍不必然成立。本步只组集；正文铺陈仍走 `结构类权利要求撰写`。

**方法案（物料流 / 数据流）：** 兼用 `方法类权利要求专有细则` 第一、三节助判 I/O 与路径；路径不宜进最小集。每个拟入集步骤须能回答输入来源与产物去向：悬空输入要补；不参与机制的孤立步骤（常是上料、清洗、包装）不入集。机制所依赖的步骤间约束必须作为特征入集，不得写成「以后连缀时再加的连接词」。

两类均**不**调用 `独立权利要求必要技术特征检查`，**不**在本步写独权正文。

### 第2步交付格式

1. 复述已确认的一句话 **与机制三栏**（无三栏不得组集）。  
2. **一句话抽出的特征**（含清楚化对照：原词 → 入集用名）。  
3. **完整方案支撑特征**（各用一句说明为何必不可少：接得上 / 可实施 / **机制仍成立**）。  
4. 表：特征｜来源（抽出 / 清楚化 / 支撑）｜入集理由（接得上 / 可实施 / 机制效果）｜若不入如何下放。结构案有改进点时附「机制｜载体｜结构｜关系｜下放」短表；方法案对拟入集步骤注明 I/O 与是否含步骤间约束。  
5. **同名检查**（一名一物）。  
6. 未入集下放候选（含第1步宜下放的关键创新点；与效果无关、连从权不占的单独列出）。  
7. 标注「**待确认：最小技术特征集**」。

## 第3步：连缀为第一版独立权利要求

根据**已确认**最小集撰写第一版。本版**不预先锚定技术问题**；只把最小集落成完整、可实施的权1。

### 连缀规则

1. **只用最小集里的技术特征**，外加把它们连成方案的**连接词**（包括、接收、判断、设置于等）。连接词不是新的技术特征。  
2. **最小集列过的名称，正文里须出现且同名**；不得列了「工作状态」却只写「解锁」，造成一名两义。  
3. **客体与范围不得无故窄于一句话**（一句话说「触摸屏设备」，独权不要无故写成「触摸屏手机」）。系统审定技术主题（按第一版全部特征再放宽或收窄前序）在第4步，见 `审定技术主题与重新核定技术问题`。  
4. 不得把未入最小集的实施例细节（滑动图像、具体手势形状等）塞进第一版。  
5. 方法案条件分支走 `条件判断语句规范`；不得用「如果…那么…」等口语句式。

### 写正文前（类型分流）

| | 方法/算法案 | 结构/装置案 |
|--|-------------|-------------|
| 必经 | `方法类权利要求具体撰写规则总控` → `方法类权利要求专有细则`（至少第一、二节；第三节核对未把路径写进权1；闭环案加第四节） | `结构类权利要求撰写`（先总列后展开；列名未展不得交付） |
| 命名 | **不**走命名总控；沿用交底原名，**以已确认最小集用名为准** | 本步内先 `部件命名优化总控` 交对照表，**确认前不得输出独权全文** |
| 必要特征检查 | **不**对着交底声称问题再筛 | 同左 |

### 第3步交付格式

1. 第一版独立权利要求全文。  
2. **落入表**：最小集各特征 → 落在权要哪一句。  
3. 未入权项仍作下放候选。  
4. 标注「**第一版独权（最小特征集 · 核心独立权利要求）**」（方法案可补「原名未优化」）。

---

## 禁止

- 第2步同批输出第一版全文；第3步未确认最小集即写正文。  
- 用「能否解决声称问题」筛入集。  
- 把交底实施例或关键创新点整份算进最小集 / 灌进第一版。  
- 最小集有名、独权不用或改名造成不清楚。  
- 为凑完整而编造交底无启示的新手段。  
- 本两步重新核定技术问题或写第二版。  
- 第1步机制三栏未确认即组集；删一法跳过关系特征或步骤间约束。  
- 把交底未记载的机制/参数当既成事实写入最小集且未标 `[推定]`。

## 检查清单

- [ ] 一句话与机制三栏已确认；最小集含抽出特征 + 完整方案支撑，无非必须项  
- [ ] 每个入集特征已过删一法（可实施 **且** 机制效果仍成立）  
- [ ] 结构案关系/作用面、方法案 I/O 与步骤间约束未当背景漏掉  
- [ ] 不清楚的一句话用词已清楚化；同物同名  
- [ ] 第一版由最小集连缀而成，连接词之外无新特征  
- [ ] 未预先锚定技术问题；未同批第4/5步
