# 交底书评估和独权初步撰写（撰写前处理 / 本案入口，所有案件类型通用）

## 适用场景

- 拿到发明人/申请人提供的**交底书**，准备从零走到正式独权（及可选创造性）时使用——**本 skill 是默认入口**。
- 解决的是"这份交底书能不能直接写、信息够不够、先怎么起一版独权"这类**撰写前处理**问题；同时在第1步把后续正式独权与可选创造性一并规划进总览 plan。
- 不区分结构类/方法类/算法类，本流程对任意技术方案类型都适用。

## 一个前提：交底书是否浅显到必须先找发明人

发明人的交底书常常不够完善，大部分情况下需要撰写者自行补充完善；**只有当交底书实在过于浅显时，才需要退回去请发明人补充**。因此拿到交底书后先做一个粗判断：

- 如果交底书连"要解决什么问题、用什么手段、核心结构/步骤是什么"这类**最基本的信息都缺失或语焉不详**，导致无法据此展开撰写，则应当先与发明人沟通、请其补充，本skill后续步骤暂不展开，**也不建立 plan**。
- 如果交底书**不算太浅显**（技术问题、技术方案、核心创新点大体能看明白，只是存在细节缺漏或表述问题），则不必急于打扰发明人，进入下面的 **plan 分步**流程，由撰写者自行补充完善。

## AI 使用本skill的能力边界（重要）

- 本skill只负责交底书体检、交底书问题梳理、以及**忠实于交底书内容**的独权初稿输出；技术方案的白话读懂由同分支 `交底书技术方案理解` 承担（本 skill 第3步转入）。
- 不负责在本 skill 内展开正式独权修订、再上位、创造性评估或补强正文。
- 如需围绕主要技术问题重写独权、可选创造性评估、再上位并筛选/下放特征，应按第1步总览 plan 转入同分支 `独权撰写` / `创造性评估与独权补强`。

## 输出控制（硬性：用 plan 控步）

本 skill **禁止**在同一次回复中一次性输出「体检 + 技术方案理解 + 初版独权 + 技术问题清单」。必须用 **plan** 驱动，一步只交一个交付物，等用户确认后再进入下一步。

### 硬性规则

1. **第1步必须先建「全流程总览 plan」**：在确认交底书「不算太浅显」后，第1步除本 skill 子步骤外，**必须**把理解、初步撰写、独权撰写，以及**可选的创造性评估与补强**全部规划进去（见下表）；其后按总览推进，当前只执行本 skill 负责的阶段。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步；用户说「一口气写完」时仍分步。
3. **不得跳步、不得合并步骤**：不得跳过第3步技术方案理解直接写独权；不得把初版独权与主问题清单同批输出；不得在未建 plan 时直接写独权全文。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + 请用户确认 + 预告下一步。（第1步的「共N步」指本 skill 子步骤数；总览 plan 另块列出，不与子步骤编号混编。）
5. **始终只有一个「进行中」**：总览中已完成阶段与本 skill 子步骤均需可见；当前项进行中，后续待办。
6. **本 skill 阶段结束即停**：第5步交付完成后，只提示按总览转入 `独权撰写`，**禁止**同轮自动开跑独权全文或创造性评估正文。

### 全流程总览 plan（第1步必列；含可选创造性）

拿到交底书且确认可写后，**第1步必须完整列出**下列总览（不得只列本 skill 五步）：

```text
阶段一  交底书技术方案理解
        （读懂：方案名片 → 场景问题 → 构成地图 → 工作过程 → 创新点剥离）
  ↓
阶段二  交底书评估和独权初步撰写【本 skill】
        （体检 → 初版独权 → 待确认主问题 / 待确认事项）
  ↓
阶段三  独权撰写
        3.1 确认主技术问题
        3.2 按主要技术问题修订独权
        3.3 【可选】创造性评估与独权补强
            （评估对象 = 3.2 的「按主要技术问题修订后的独权」；
             足够可跳过补强；不足则补强后再回到独权撰写）
        3.4 再上位技术问题 + 第二轮筛选 / 成组下放
        3.5 正式独权工作稿收束
```

硬性位置：**创造性评估与补强（可选）必须画在「3.2 按主要技术问题修订独权」之后、「3.4 再上位」之前**，不得画到再上位之后或本 skill 结束之前。

### 本 skill 子步骤 plan（阶段二内执行，共5步）

```text
第1步 浅显可写性确认 + 全流程总览 plan + 本 skill 子步骤清单
  ↓
第2步 交底书体检（逻辑 / 形式 / 技术方案完善性）
  ↓
第3步 交底书技术方案理解（完整执行同分支 `交底书技术方案理解`；对应总览阶段一）
  ↓
第4步 交底书初版独权（忠实转化全文）
  ↓
第5步 技术问题梳理 + 待确认主问题 + 待确认事项清单
  ↓
（结束本 skill → 按总览转入阶段三 `独权撰写`）
```

总步数 N = 5（仅计本 skill 子步骤）。不得擅自增删合并本 skill 子步骤；若用户只要其中某一步，仍须标明该步在总览与子步骤中的位置。

**关于第3步：** 体检确认后、动笔写初版独权前，**必须**先完成技术方案理解。第3步不在本文件内展开讲解口径，而是**完整转入**同目录下的 `交底书技术方案理解` skill（该 skill 自行建其 5 步子 plan）；待用户确认「已读懂、可写独权」后，再回到本 skill 第4步输出初版独权。禁止跳过理解直接写独权；禁止把理解 skill 的多步交付压缩进本 skill 的单次回复。

## 第1步：浅显可写性确认 + 全流程总览 plan

**本步交付物：**

1. 一句结论：交底书是否「不算太浅显、可进入撰写前处理」；若太浅显，列出缺什么、请发明人补什么，并**终止**（不进入第2～5步，也不建总览 plan）。
2. 若可写：
   - **完整列出「全流程总览 plan」**（阶段一～三，含 3.1～3.5，且 3.3 标为可选创造性，位置在 3.2 与 3.4 之间）；
   - 列出**本 skill 子步骤**第2～5步名称；
   - 标明当前将进入本 skill 第2步（体检），总览上阶段一/二进行中、阶段三待办。

**本步禁止：** 输出体检表、技术方案理解正文、初版独权正文、主问题候选展开论述；禁止把总览缩成只含本 skill 五步。

---

## 第2步：交底书体检（逻辑 / 形式 / 技术方案完善性）

在撰写初版独权之前，先给交底书做一次"体检"，找出并（在能力范围内）修补以下三类问题：

- **逻辑错误**：技术问题与技术方案是否对得上（声称要解决的问题，方案是否真的解决了它）；前后描述是否自相矛盾；因果关系、动作先后是否说得通；是否违背物理/数学常识。
- **形式错误**：术语前后是否一致、部件/步骤命名是否统一、附图与文字是否对应、编号是否混乱等。
- **技术方案不完善**：是否存在缺环（某个部件/步骤悬空、缺少必要的连接或前置条件）、关键参数或实现方式缺失、只给了单一实施例而缺少替代方案等。

对能自行补齐的缺漏，撰写者补充完善；对涉及发明人真实技术选择、AI 无法凭空确定的关键缺环（如具体结构参数、真实实现方式），列成问题清单向用户/发明人确认，不要脑补编造。

**本步交付物：** 体检结论（可写/需补事项）+ 三类问题表（逻辑/形式/缺环）+ 体检结论摘要 + **预告下一步转入 `交底书技术方案理解`（总览阶段一）**。  
**本步禁止：** 输出完整初版独权；输出待确认主问题的最终选定表述（可在缺环中预告「主问题将在第5步给出」）；禁止在本步内展开技术方案理解全文。

---

## 第3步：交底书技术方案理解（读懂后再写独权）

体检完成且用户确认后，**不得直接写初版独权**，必须先完成技术方案理解。

**执行方式：**

1. 明确告知：本步转入同分支 `交底书技术方案理解` skill（对应总览**阶段一**）。
2. 按该 skill 的固定 5 步 plan 逐步交付（方案名片 → 场景问题 → 构成地图 → 工作过程 → 创新点剥离与自检），一步一确认。
3. 用户确认「已读懂、理解障碍不阻塞写独权」后，回到本 skill，进入第4步。

若用户在本案中**已经**完整跑完 `交底书技术方案理解` 且结论为可写独权，可在本步做一次简短确认后跳过重复讲解，直接进入第4步；但须在回复中写明「理解 skill 已完成，跳过重复」，并在总览上将阶段一标为完成。

**本步交付物：** 转入理解 skill 的声明（或「已完成理解、跳过重复」的确认）+ 理解结束后是否阻塞独权的结论摘要。  
**本步禁止：** 在本步输出初版独权；把理解 skill 五步内容一次性塞进本回复。

---

## 第4步：按交底书内容撰写初版独权并输出（必做交付物）

技术方案理解完成、交底书方案基本可读、且用户已确认可写独权后，**按交底书内容忠实撰写一版独立权利要求，并完整输出给用户**。这是本skill的**初版独权必做交付物**，不得跳过。

撰写要求：

- **忠实于交底书**：把交底书中发明人描述的技术问题、技术方案、核心结构/步骤/部件，如实转化为一条独立权利要求的正式文字；此阶段**不刻意拔高、不引入补强构思的新特征**，只把交底书已有内容写成规范的独权表述。
- **写成完整独权正文**：不是列提纲或骨架，而是输出可直接阅读的独立权利要求全文（含前序部分与"其特征在于"之后的特征部分）；具体措辞、句式、部件铺陈顺序等，按案件类型参考同分支下 `结构类`/`方法类`/`算法类` 的权利要求撰写规范，并同步对照通用分支下的 `权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范`、`自定义名词就地定义` 等。
- **明确标注为"交底书初版独权"**：输出时须标明这是基于交底书原文忠实转化的初版，尚未按主要技术问题定向修订，便于用户对照交底书审阅、确认发明人真实技术贡献是否被完整覆盖。
- **作为后续工作的基线**：后续若需围绕主要技术问题重写独权、扩宽或收窄保护范围、下放从权，均以这一版独权为起点和参照。

**本步交付物：** 标注「交底书初版独权」的全文 + 可选的要点映射表。  
**本步禁止：** 同批输出第5步的主问题选定与完整待确认事项长清单（映射表除外）；不得进入创造性评述或补强。

---

## 第5步：列出技术问题、输出待确认主问题与问题清单（必做交付物）

初版独权经用户确认后，**梳理交底书技术方案所解决的技术问题，并输出待确认的主问题候选和待确认事项清单**。这是本skill的**主问题必做交付物**，不得跳过。

梳理要求：

- **列出交底书技术方案解决的全部技术问题**：从交底书原文、第4步初版独权中归纳，逐一列出该方案能够解决或声称要解决的技术问题；若存在多个层次（表层问题、衍生问题、附带解决的问题），应分层列出，不要混为一谈。
- **说明各问题与方案特征的对应关系**：简要说明交底书哪些技术特征/结构/步骤分别对应解决哪一个问题，便于用户判断哪些问题真正由独权核心技术特征解决、哪些只是附带效果或由从权才覆盖。
- **输出待确认主问题**：在上述列表基础上，给出1个或少量主问题候选，明确标注为"待确认主问题"，供用户后续在独权撰写阶段进一步选择、调整或上位。
- **输出待确认问题清单**：把仍需发明人/用户确认的关键技术事实单独列清，包括但不限于结构参数、步骤先后、真实连接关系、是否存在替代实施方式等；可与理解 skill 第5步的障碍清单合并去重。

**本步交付物：** 问题分层列表 + 待确认主问题（含备选）+ 待确认事项清单 + 本 skill 结束与按总览转入阶段三的提示。  
**本步禁止：** 在用户未确认主问题之前，擅自输出「按主问题修订后的独权」或创造性补强全文。

---

## 本 skill 结束后的衔接（勿自动连跑）

本skill完成到第5步即止（总览阶段二完成）。后续按第1步已列出的总览进入**阶段三 `独权撰写`**：

- 3.1 确认主问题 → 3.2 按主问题修订独权；
- 3.3【可选】对 3.2 稿做创造性评估与补强；
- 3.4 再上位技术问题并第二轮筛选/成组下放 → 3.5 正式工作稿收束。

**下一阶段须由 `独权撰写` 自行建立其阶段内子 plan**，但应回扣第1步总览编号，不得另起一套与总览冲突的顺序（尤其不得把创造性挪到再上位之后）。

## 与其他 skill 的衔接顺序

```
【入口第1步已规划的总览】
阶段一 交底书技术方案理解
  → 阶段二 本skill（体检 →【理解】→ 初版独权 → 主问题/待确认）
  → 阶段三 独权撰写
        3.1 确认主问题 → 3.2 按主问题修订
        → 3.3【可选】创造性评估与独权补强
        → 3.4 再上位并筛选/下放 → 3.5 收束
  → 通用/说明书撰写
  → 权利要求质检/权利要求书质检
```

- 与 `交底书技术方案理解` 的分工：理解 skill 只负责让撰写者读懂方案，**不产出独权**；在总览中为阶段一，由本 skill 第3步转入。
- 与 `独权撰写` 的分工：本skill只负责初版独权与待确认主问题；**按主问题修订、可选创造性插入点、再上位与下放均在 `独权撰写` 总览阶段三**。
- 与 `创造性评估与独权补强` 的分工：可选；评估对象是「按主要技术问题修订后的独权」，**不得**在初版独权上做、也不得默认排在再上位之后才第一次评估。
- 与 `独立权利要求必要技术特征检查` 的分工：本skill不处理精简/上位/下放；该检查是 `独权撰写` 再上位步调用的判断细则。
- 与 `说明书技术问题陈述撰写` 的分工：本skill第5步输出的是待确认主问题；经 `独权撰写` 确认（及必要时再上位）后的技术问题，最终按该skill规范落笔。
