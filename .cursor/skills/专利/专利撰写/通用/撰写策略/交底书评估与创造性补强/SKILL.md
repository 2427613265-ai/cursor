# 交底书评估和独权初步撰写（撰写前处理，所有案件类型通用）

## 适用场景

- 拿到发明人/申请人提供的**交底书**、准备正式落笔撰写专利申请文件**之前**使用。
- 解决的是"这份交底书能不能直接写、信息够不够、先怎么起一版独权"这类**撰写前处理**问题，处在正式独权撰写之前。
- 不区分结构类/方法类/算法类，本流程对任意技术方案类型都适用。

## 一个前提：交底书是否浅显到必须先找发明人

发明人的交底书常常不够完善，大部分情况下需要撰写者自行补充完善；**只有当交底书实在过于浅显时，才需要退回去请发明人补充**。因此拿到交底书后先做一个粗判断：

- 如果交底书连"要解决什么问题、用什么手段、核心结构/步骤是什么"这类**最基本的信息都缺失或语焉不详**，导致无法据此展开撰写，则应当先与发明人沟通、请其补充，本skill后续步骤暂不展开。
- 如果交底书**不算太浅显**（技术问题、技术方案、核心创新点大体能看明白，只是存在细节缺漏或表述问题），则不必急于打扰发明人，进入下面的体检—初版独权—问题梳理流程，由撰写者自行补充完善。

## AI 使用本skill的能力边界（重要）

- 本skill只负责交底书体检、交底书问题梳理、以及**忠实于交底书内容**的独权初稿输出；不负责创造性评估、补强构思、整体布局或最终独权优化。
- 如需围绕主要技术问题重写独权、做第二轮必要技术特征筛选、成组下放从权等，应转入对应的独权撰写/独权筛选 skill 处理，而不是继续在本skill内展开。

## 第一步：交底书体检（逻辑 / 形式 / 技术方案完善性）

在撰写初版独权之前，先给交底书做一次"体检"，找出并（在能力范围内）修补以下三类问题：

- **逻辑错误**：技术问题与技术方案是否对得上（声称要解决的问题，方案是否真的解决了它）；前后描述是否自相矛盾；因果关系、动作先后是否说得通；是否违背物理/数学常识。
- **形式错误**：术语前后是否一致、部件/步骤命名是否统一、附图与文字是否对应、编号是否混乱等。
- **技术方案不完善**：是否存在缺环（某个部件/步骤悬空、缺少必要的连接或前置条件）、关键参数或实现方式缺失、只给了单一实施例而缺少替代方案等。

对能自行补齐的缺漏，撰写者补充完善；对涉及发明人真实技术选择、AI 无法凭空确定的关键缺环（如具体结构参数、真实实现方式），列成问题清单向用户/发明人确认，不要脑补编造。

## 第二步：按交底书内容撰写初版独权并输出（必做交付物）

体检完成、交底书方案基本可读后，**必须先按交底书内容忠实撰写一版独立权利要求，并完整输出给用户**，再进入后续步骤。这是本skill的**第一个必做交付物**，不得跳过。

撰写要求：

- **忠实于交底书**：把交底书中发明人描述的技术问题、技术方案、核心结构/步骤/部件，如实转化为一条独立权利要求的正式文字；此阶段**不刻意拔高、不引入补强构思的新特征**，只把交底书已有内容写成规范的独权表述。
- **写成完整独权正文**：不是列提纲或骨架，而是输出可直接阅读的独立权利要求全文（含前序部分与"其特征在于"之后的特征部分）；具体措辞、句式、部件铺陈顺序等，按案件类型参考同分支下 `结构类`/`方法类`/`算法类` 的权利要求撰写规范，并同步对照通用分支下的 `权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范`、`自定义名词就地定义` 等。
- **明确标注为"交底书初版独权"**：输出时须标明这是基于交底书原文忠实转化的初版，尚未按主要技术问题定向修订，便于用户对照交底书审阅、确认发明人真实技术贡献是否被完整覆盖。
- **作为后续工作的基线**：后续若需围绕主要技术问题重写独权、扩宽或收窄保护范围、下放从权，均以这一版独权为起点和参照。

## 第三步：列出技术问题、输出待确认主问题与问题清单（必做交付物）

初版独权输出后，**必须先梳理交底书技术方案所解决的技术问题，并输出待确认的主问题候选和待确认事项清单**。这是本skill的**第二个必做交付物**，不得跳过。

梳理要求：

- **列出交底书技术方案解决的全部技术问题**：从交底书原文、第二步初版独权中归纳，逐一列出该方案能够解决或声称要解决的技术问题；若存在多个层次（表层问题、衍生问题、附带解决的问题），应分层列出，不要混为一谈。
- **说明各问题与方案特征的对应关系**：简要说明交底书哪些技术特征/结构/步骤分别对应解决哪一个问题，便于用户判断哪些问题真正由独权核心技术特征解决、哪些只是附带效果或由从权才覆盖。
- **输出待确认主问题**：在上述列表基础上，给出1个或少量主问题候选，明确标注为"待确认主问题"，供用户后续在独权撰写阶段进一步选择、调整或上位。
- **输出待确认问题清单**：把仍需发明人/用户确认的关键技术事实单独列清，包括但不限于结构参数、步骤先后、真实连接关系、是否存在替代实施方式等。

## 第四步：转入独权撰写 skill 继续处理

本skill完成到第三步即止。后续如果需要：

- 围绕已确认主问题重写独权；
- 审查是否需要进一步上位技术问题；
- 做第二轮必要技术特征筛选；
- 将一组特征下放到从权；
- 处理独权保护范围与当前创造性骨架的平衡；
- 判断创造性是否足够，或在创造性不足时补强独权；

应转入对应的独权撰写、独权筛选或创造性补强 skill（如 `结构类权利要求撰写`、`独立权利要求必要技术特征检查`、`创造性评估与独权补强` 等）继续，而不是继续在本skill内展开。

## 与其他 skill 的衔接顺序

本skill位于整个撰写流程最前端，典型衔接如下：

```
本skill（交底书体检 → 按交底书撰写初版独权并输出 → 列出技术问题并输出待确认主问题/待确认事项）
  → 独权撰写/独权筛选 skill（围绕主问题修订独权、做必要技术特征筛选、下放从权）
  → 通用/说明书撰写（发明内容、附图说明、具体实施例）
  → 权利要求质检/权利要求书质检（定稿复核）
```

- 与 `独立权利要求必要技术特征检查` 的分工：本skill只负责把交底书内容转成初版独权，不处理后续精简、上位、下放从权；这些工作交给该skill及对应独权撰写 skill。
- 与 `说明书技术问题陈述撰写` 的分工：本skill第三步输出的是待确认主问题；最终写入说明书的技术问题表述，仍应按该skill规范落笔。
