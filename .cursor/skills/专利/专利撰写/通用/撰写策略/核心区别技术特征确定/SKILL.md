# 核心区别技术特征确定（独权第1步细则 · 顶天立地）

方法/结构类独权**第1步**必读。本步最关键：它定的是独权撰写的**两个内容问题**——独权往哪展开（顶天）、授权靠什么保底（立地）。必要技术特征能不能在第2步定对，取决于本步有没有把效果背后的**机制**写清。只定方向、机制与保底点，**不**写独权全文、**不**组成最小集。正反例见同目录 `examples.md`。

## 本步两件交付（硬性）

| 件 | 名称 | 是什么 | 服务 |
|----|------|--------|------|
| **① 顶天** | **核心区别技术特征** | 相对最接近现有/惯常、又能把保护范围放到最大合理边界的那一撮区别；须**一句话概括**（「核心区别的一句话描述」） | 独权展开方向；第2步最小集必须包含它所对应的边界特征 |
| **② 立地** | **关键创新点** | 优选实施例里最具创造性、最能撑住授权/无效的那一点（或很少几点） | 从权/实施例保底；**不得**整份灌进独权替代① |

禁止只做①或只做②；禁止把②的实施例钉死写法当成①。

## 机制三栏（硬性闸门 · 与①②同批）

机制说不清，第2步就无法判断哪个特征不可缺少，独权只能照抄实施例。交①②时必须同批交出下表；**填不满不得进入第2步**。

| 技术问题 | 物理/化学机制 | 技术效果 |
|----------|----------------|----------|
| 客观、可观测的缺陷，以及造成该缺陷的原因 | 从改进到效果的作用链；每一环须能用本领域原理说通 | 可验证、可对比的指标改善 |

中间栏是支点。方法案作用链可按主步骤拆开写，仍须落在这一栏，**不**另开独权步骤。结构案写清「什么结构条件触发什么物理过程」。三栏不是独立权利要求，也不是最小集。

机制栏一旦写成，第2步入集对象几乎可从表中读出（机制的载体、使机制成立的结构/步骤、使机制起作用的位置或约束）；实施例钉死的形状、参数、工具名默认仍下放。

**写不满时三选一（不得用猜测填平后继续组集）：**

| 情况 | 征兆 | 处理 |
|------|------|------|
| 发明人没说清 | 一问机制就改口讲效果 | 标阻塞项，停在第1步 |
| 参数型发明 | 「试出来的，这个区间最好」 | 机制栏标 `[推定]` 或写「机制不明、靠参数界定」；独权可靠参数范围，并列入说明书须补对比实验 |
| 方案不成立 | 与已知原理冲突 | 停；先解决技术问题，不是撰写问题 |

**`[推定]`：** 交底未记载、由撰写补上的机制假设、参数边界、替代方式，一律标 `[推定]` 并进入待确认清单。无标注的编造会变成专利法第 26 条第 3、4 款缺陷。已有「待确认」口径的，推定项须同时可见 `[推定]`。

## 顶天立地

权要撰写要**顶天立地**。权利范围不是「交底有技术方案」就自动定下来的，要靠撰写人抽象概括。

- **天 / 顶天：** 独权尽量站到「待申请技术 vs 现有技术」的边界上，覆盖交底未逐一写出、但由该区别可合理想到的实现。好比讨价还价时卖方第一次出价：要价高而合理。一句话找到了，独权撰写方向才有依据。
- **地 / 立地：** 撰写时看不见审查员（更不必说无效）可能检索到的现有技术。用②在权利要求树里留授权保底——多数权利人即使范围缩小，能授权仍有意义。立地 **≠** 结构案递交变劣（那是第8步）。

发明人交底只是**优选方案**。代理人须以该方案与现有技术的区别为出发点，重新概括成符合专利保护要求的抽象技术方案：只要求符合技术逻辑、具有实现可能。找出①，就是确定该抽象方案的出发点。

## ① 核心区别：如何找、如何写成一句话

**定义：** 能使本方案与现有/惯常相互区别、**并且**使待申请方案保护范围最大的技术特征。理想上恰好站在待申请技术与现有技术的边界上，并表明本申请站在边界这一边。

不是「交底实施例里看起来新的全部细节」，也不是「抄交底权要/实施例当独权」。交底只给了一条优选路径时，仍须对照现有，抽出那条路径底下真正的边界。

### 操作

1. **对照现有/惯常**（交底背景、理解 skill「创新点 vs 惯常剥离表」、用户给出的最接近现有）。未做检索则写「**未检索，独权宽窄为盲判**」，不得假装已知最接近现有，**不得编造对比文件号**。问：去掉交底里哪一层限定后，仍能和现有分开？再问：这一层是否已被实施例钉死（滑动、某算法名、某尺寸）？钉死则继续上抽。  
2. **写成一句话**。用普通技术话写清「用什么手段，在什么对象上，做成与现有不同的哪一类事情」；不写效果口号，不写工具/参数堆砌。这句话本身**不是**独立权利要求。展开完整方案、连缀第一版见 `最小技术特征集与第一版独权`。  
3. **边界检验（三问，须都过）：**
   - **区别？** 现有惯常做不到或不是这么做的。  
   - **顶天？** 交底实施例只是这句话下面的一条路径；换成同边界上的其他实现，这句话仍罩得住。  
   - **未过界？** 仍有交底技术启示（符合技术逻辑、有实现可能）；不是另一类发明。  
4. **展开示意（1～3 条即可）：** 一句话之下，除交底优选路径外，还可能罩住哪些实现（例如触摸解锁之下：划字符、点特定解锁点）。供后续独权上位，**不是**本步去写那些权要，也**不是**去编造交底毫无启示的新发明。

**过窄（未顶天）：** 把优选实施例整份当核心区别（如把「滑动并移动解锁图像」当成唯一区别），独权只罩这一条路。  
**过宽（过界）：** 抽到现有也有的公知手段，或抽到交底毫无启示的另一发明。

方法案可兼用 `方法类权利要求专有细则` 第三节三问，把路径（具体手势、聚类算法名）与不变量（用预定触摸动作切换锁定状态）分开；本步仍只定①②与三栏，不组最小集。

## ② 关键创新点：从优选实施例里抽

在交底**优选实施例**中，找出对创造性贡献最大、审查/无效中最可能被用来「立住授权」的点。

- 通常比①**更具体**（①是边界概括，②是实施例里真正做功的那一刀）。  
- **不得**把实施例步骤/部件全部标成关键创新点。  
- ②可以有一点或很少几点；多点须分主次。  
- ②默认进从权/说明书保底；**仅当**它同时是①的不可再抽边界时，才进入独权最小集（由第2步判断，本步只标注「可能入独权 / 宜下放」）。从权阶段须**逐层落实**，见 `从权分层次布置`。

## 交付格式（第1步正文）

1. **对照的现有/惯常**（一两句；来源：交底背景 / 理解剥离表 / 用户指定；未检索则写「未检索，独权宽窄为盲判」；不得编造对比文件号）。  
2. **问题–机制–效果三栏**（各一句够用；方法案机制栏可按步拆链；写不满则按上表三选一处理，不得空表过关）。  
3. **核心区别的一句话描述**（必有；须与机制栏同一边界，不是效果口号）。  
4. **为何是边界**（区别 + 顶天 + 未过界，各一句）。  
5. **一句话还能罩住的其他实现**（1～3 条示意）。  
6. **关键创新点**（实施例依据 + 主次 + 可能入独权 / 宜下放）。  
7. **非核心分流**：惯常、实施例钉死、配套细节。  
8. **`[推定]` / 待确认清单**（无则写「无」）。  
9. 标注「**待确认：核心区别一句话 + 机制三栏 + 关键创新点**」。

建议短表可并存，但不能用特征清单**代替**一句话，也不能用效果口号**代替**机制栏。

## 禁止

- 同批输出最小集或独权全文。  
- 无理由把交底几乎全部特征标成核心区别或关键创新点。  
- 没有一句话，只堆实施例步骤。  
- 把交底实施例或交底已写权要原样当独权，却未抽出边界一句话。  
- 把关键创新点整份写入独权冒充顶天。  
- 为顶天编造交底无启示的新手段。  
- 单列交底声称问题或解题特征全集清单。  
- 机制三栏为空、用效果口号充机制、或把未经标注的推测当交底事实。  
- 未检索却写成已有最接近对比文件。

## 检查清单

- [ ] 已有一句话，且过「区别 / 顶天 / 未过界」三问  
- [ ] 已交问题–机制–效果三栏；机制链能用本领域原理说通，或已按三选一停步 / 标 `[推定]`  
- [ ] 已从优选实施例抽出关键创新点，并与一句话分层  
- [ ] 未把实施例钉死路径当成核心区别  
- [ ] 推定已标注；未检索已写明盲判  
- [ ] 未写独权、未组最小集
