# 核心区别：一句话 vs 实施例钉死（正反例）

本页配合 `核心区别技术特征确定`。例子只说明**怎么抽一句话**，不是可抄的权要模板。

## 例：触摸屏解锁（交底只给了滑动）

**现有/惯常：** 解锁靠专用按键或几个按键的组合。  
**交底优选实施例：** 锁定状态下检测触敏显示器上的接触；按接触移动与解锁状态对应的图像；接触符合预定手势则解锁，否则保持锁定。

### 错误（未顶天）

未分析与现有的核心区别，把实施例（甚至交底已写的「滑动 + 移动解锁图像 + 预定手势」）原样当成独权。独权只罩这一条路。审查时一旦出现「点击解锁点」「在屏上划字符」等，容易被绕开；申请人本可合理覆盖的实现被写丢。

### 正确（一句话在边界上）

- **核心区别一句话：** 使用特别的触摸动作解锁触摸屏设备（或：用预定的触摸动作，把触摸屏设备从用户界面锁定切换到解锁）。  
- **为何是边界：** 现有靠按键组合，本申请靠触摸屏上的动作；交底的滑动只是预定触摸动作的一条路径；概括仍停在「触摸动作解锁」，没有跳到密码/生物识别等另一类发明。  
- **一句话还能罩住的实现（示意）：** 划特定字符；点击特定解锁点；其他预定手势。有了这些思路，后续独权才可能顶天，而不是钉死在滑屏这一条。  
- **关键创新点（立地）：** 按接触移动与解锁状态对应的图像，并以是否符合预定手势决定解锁或保持锁定——实施例里真正做功、宜作从权/无效对抗保底的点。

后续独权围绕一句话展开；滑动图像、手势形状等默认不塞进独权，除非第2步判断离开它们方案无法实施。一句话是抽象方案的出发点，不是独权全文。

## 抽一句话时的过界反例

交底只教了「在触摸屏上做手势解锁」，却写成「用任意信息验证用户身份」。现有按键解锁也是验证身份，这句话**既无区别、又过界**。
