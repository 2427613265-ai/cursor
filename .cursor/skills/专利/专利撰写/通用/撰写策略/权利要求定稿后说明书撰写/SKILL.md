# 权利要求定稿后说明书撰写（总控）

## 适用场景

- 权利要求书已基本定稿，准备继续撰写说明书其他部分；
- 用户说“开始写技术领域/背景技术/发明内容/附图说明/具体实施方式/摘要”；
- 需要统一调度多个说明书具体 skill，而不是零散只写一段。

**不适用：** 交底仍未读懂、独权尚未稳定、从权尚在大幅改动中的阶段。

---

## 总控职责

本 skill 只做三件事：

1. **确定顺序**：按说明书各部分的合理撰写顺序推进；
2. **调用下属 skill**：不同部分切到对应子 skill，而不是混写；
3. **用 plan 控复杂度**：全过程 TodoWrite，同一时刻仅一个 `in_progress`；复杂部分必须拆分分支 plan。

## 推荐顺序（硬性）

```text
权利要求书定稿
  ↓
第1步 技术领域
  ↓
第2步 背景技术
  ↓
第3步 发明内容（技术问题陈述 → 有益效果）
  ↓
第4步 附图说明
  ↓
第5步 具体实施方式【必须分支 plan】
  ├─ 5A 权1实施例主线
  ├─ 5B 从权实施例逐条展开
  ├─ 5C 名词释义 / 整体装配补充
  └─ 5D 未入权技术方案编排
  ↓
第6步 摘要
  ↓
第7步 全文一致性收束
```

**禁止：**
- 还没写技术领域/背景技术就先写摘要；
- 具体实施方式不拆分分支 plan，一次性倾倒全文；
- 在某一步混入其他部分定稿文本。

## Plan 控制（硬性）

### 总 plan

必须先建总 plan，至少包含：

1. 技术领域
2. 背景技术
3. 发明内容
4. 附图说明
5. 具体实施方式
6. 摘要
7. 一致性收束

要求：
- 始终一个 `in_progress`
- 每一步单独交付、单独确认再进入下一步
- 交付格式统一为：`【第X步 / 共7步】`

### 分支 plan（具体实施方式强制）

进入“具体实施方式”时，必须单独再建一层 branch plan：

- **5A：权1实施例主线**
- **5B：从权实施例逐条展开**
- **5C：名词释义与整体装配补充**
- **5D：未入权技术方案编排**

交付格式建议：
- `【第5A步 / 第5步分支】` 之类

**禁止：** 把第5步当成单块文本一次写完。

---

## 各步调用规则

### 第1步：技术领域
先 Read `说明书技术领域部分撰写`，输出技术领域一句定稿。

### 第2步：背景技术
先 Read `说明书背景技术部分撰写`，按“场景→现有技术→问题→固定收尾句”写。

### 第3步：发明内容
先 Read：
- `说明书技术问题陈述撰写`
- `说明书有益效果撰写`

要求技术问题与独权实际解决的问题对应；有益效果与技术问题镜像呼应。

### 第4步：附图说明
先 Read `说明书附图说明撰写`。只能依据现有附图写，不得编造新图。

### 第5步：具体实施方式
必须先建分支 plan，再依次调用：
- 主线：`说明书具体实施方式撰写`
- 有新名词：`具体实施方式名词先释义后展开`
- 有装配缺口：`具体实施方式补充整体装配方式`
- 主线之后：`未写入权利要求的技术方案在说明书中的编排`

### 第6步：摘要
最后 Read `说明书摘要撰写`，在技术领域定稿后再写，且不得超 300 字。

### 第7步：一致性收束
回看：
- 专利名称一致
- 技术领域一致
- 技术问题/有益效果与独权一致
- 附图说明与实施方式一致
- 未入权技术方案已妥善安放
