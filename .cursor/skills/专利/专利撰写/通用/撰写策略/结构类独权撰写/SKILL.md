# 结构类独权撰写（最小特征集至第二版 + 其后三版扩围 · 服务于结构/装置案）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  术语先释义 + 外行读懂 + 懂后再体检 + 问题候选
        ↓
第1步  确定核心区别技术特征与关键创新点
        ↓
第2步  按核心区别组成最小技术特征集（完整技术方案；不考虑先前技术问题）
        ↓
第3步  根据已确认的最小技术特征集撰写第一版独立权利要求
        ↓
第4步  根据第3步已写成的第一版独立权利要求，审定技术主题并重新核定技术问题
        ↓
第5步  在新问题下审视第一版是否合适，进一步删减/上位 → 第二版独权
        ↓
第6步  再上位技术问题
        ↓
第7步  第三版独权   要求最高：逻辑与表达清楚 + 保护范围最大
                    （命名/数量等上位优化，如下文方法）
        ↓
【可选】第8步  递交独权变劣与从权回退   （定稿再放宽一档作递交权1；改进进从权）
        ↓
第9步 收束为正式独权工作稿
```

**独权阶段不单列：** 「交底声称技术问题」「解题技术特征清单」。交底发明目的、背景缺陷、理解 skill 问题候选只作对照，不作为独立交付步，也不是最小集入集标准。

**三版要求依次提高（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求（递进） |
|------|----------------|------------------|
| **第一版** | **本版不预先锚定技术问题** | 只落实第2步已确认的**最小技术特征集**；完整可实施；**禁止**把交底实施例细节整份灌进独权 |
| **第二版** | 第4步**审定后的技术主题** + **重新核定后**的技术问题 | 前序用审定后的主题；在新问题下审视第一版是否仍合适；特征可进一步删减、上位；**不得含非必要技术特征**；方案完整可实施 |
| **第三版** | 第6步**再上位后**的技术问题 | 在第二版「无非必要特征」之上，进一步：**逻辑清楚、表达清楚、保护范围最大**（部件命名上位、数量词放宽、序数命名等——按命名规则权衡，非一律第一/第二） |

撰写方法（质量闸门、类型铺陈、命名规则等）**服务于上述策略**，不得颠倒成「先抠字眼、后定策略」。

## 适用场景与触发

- **客体：** 结构/装置类独立权利要求（「一种××装置/机构/系统」等以部件与连接关系为主的方案）。
- **入口：** 须经 `独权撰写` 判定为结构案后转入本 skill；已点名「结构类独权 / 装置独权」时可直进。
- 已完成 `交底书技术方案理解`（含术语词典、外行总故事、懂后体检与问题候选）；进入**阶段二**（本 skill 自建 2.1～2.9 plan）。
- 触发：「写结构类独权」「装置独权」「核心区别」「最小特征集」「审定技术主题」「重新核定技术问题」「第二版」「第三版」「再上位」等。
- **不适用：** 纯方法/算法流程型独权（回 `独权撰写` 分流至 `方法类独权撰写`）。

## 能力边界

- 产出：核心区别（含一句话）与关键创新点、最小特征集、三版独权工作稿链 + 主题审定、重新核定与再上位说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新结构/步骤；缺事实标「待确认」。
- 必要特征逐条细则调用 `独立权利要求必要技术特征检查`（主用于第二版、第三版；**不**用于第2步组集）；类型与表达规范按需调用，不在本文件全文粘贴。
- 本 skill 是**结构案**独权正文与变劣的执行层；**分流入口**是 `独权撰写`，勿与入口混淆。

## 输出控制（plan 硬性）

禁止一次输出「核心区别+最小集+多版独权」。必须用 plan/待办（TodoWrite 等）同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

```text

  ↓
第2步 组成最小技术特征集（完整技术方案；不考虑先前技术问题）【须用户确认】
  ↓
第3步 根据已确认最小集撰写第一版独立权利要求
  ↓
第4步 根据第3步第一版独立权利要求，审定技术主题并重新核定技术问题【须用户确认】
  ↓
第5步 在新问题下审视第一版，进一步删减/上位 → 第二版独权
  ↓
第6步 再上位技术问题（结论 + 与第二版问题分层）【须用户确认】
  ↓
第7步 第三版独权（清楚 + 范围最大；含命名/数量优化）
  ↓

  ↓
```

- 第1步同步建立 2.1～2.9 plan，**不**单列「只建 plan」的步骤。  
- **禁止**将第1步与第2步合并（未确认核心区别一句话与关键创新点不得组成最小集）。  
- **禁止**将第2步与第3步合并（未确认最小集不得写第一版独权）。  
- **禁止**将第3步与第4步合并（未写出第一版独权全文，不得审主题、重新核定问题）。  
- **禁止**将第4步与第5步合并（未确认审定后的主题与新核定问题不得写第二版）。  
- 第5步完成后，第6步再上位的问题锚定基线=第二版所锚定问题；第7步独权基线=第二版。  
- **禁止**将第6步与第7步合并交付；**须**用户确认再上位问题后，方可写第三版独权。  
- 第8步执行 → 按下文「第8步」内嵌子步骤 8.1～8.4 推进（仍属本 skill，不外转）；返回后第9步正式稿默认=递交独权。  
- 第8步跳过 → 写明；第9步正式稿默认=第三版；2.8=`cancelled`。  
- 未完成理解不得硬写第一版。

## 主题与问题只在第4步审定（禁止抢活）

独权阶段**不**再单列「交底声称问题」或「解题特征清单」。交底发明目的、背景缺陷、理解 skill 问题候选、交底原标题**只作对照**。

口径与操作**以 `审定技术主题与重新核定技术问题` 为准**（先审前序主题，再核问题；反推对象仅第一版全文）。

| | **第4步 审主题 + 核问题** | **第6步 再上位** |
|--|---------------------------|------------------|
| **时机** | 第一版全文已交付 → 第二版之前 | 第二版之后 → 第三版之前 |
| **输入** | **仅第一版独立权利要求** | 第二版已锚定的问题（及第二版独权） |
| **做什么** | 审前序技术主题（常过窄）；核定这份权1实际解决的问题 | 只再抽问题表述一层（或判定无需）；**不以改主题为主** |
| **服务** | 第5步第二版 | 第7步第三版 |

**禁止互相抢活：**

- 第1～3步不得写成主题/问题或再上位定稿。  
- 第4步不得跳过审主题只改问题；不得只拿交底标题、一句话、最小集空推。  
- 第3步独权全文未交付，不得进入第4步。  
- 第6步不以「再清一轮非必要部件」为目标，也**不得**顶替第4步未做的主题审定；若第二版仍明显过窄，回改第4/5步。

## 撰写方法总则（服务于三版策略）

### 最小技术特征集与第一版（第2/3步 · 短引）

口径与操作**以 `最小技术特征集与第一版独权` 为准**（一句话≠完整方案；抽出并清楚化 → 补必不可少支撑 → 连缀为第一版；同物同名）。结构案组集时重点核位置、连接、必要配合。主题与问题留到第4步。第3步写正文前仍须过命名闸门与 `结构类权利要求撰写`。

### 方法一：独权正文质量闸门（按版本加码）

**各版共通：** 类型铺陈正确；主谓宾完整；所述指代清楚；**每一版独权均须先触发一次 `部件命名优化总控`，再由总控分流到具体命名 skill；且必须先交付「部件命名优化对照表」供用户选择确认，确认后再写该版独权正文（禁止未确认先出独权全文）**；自定义名词就地定义；功能性限定守边界；不编造无支持特征。

**第二版加码（硬性）：**  
- 锚定=第4步审定后的技术主题 + 重新核定后的技术问题。第二版前序用审定后的主题。  
- 先问：第一版在新问题下是否仍合适（过窄/过宽/偏题）？再逐特征反问：去掉或改宽后该问题是否仍解决？能→必须删/概括/下放（`独立权利要求必要技术特征检查`）。  
- 重点清理：非必要数量词、排列方式、具体机构/工艺/驱动（除非恰为区别点）。  
- 删后方案须仍完整可实施；保留最小区别骨架。

**第三版加码（硬性）：**  
- 在第二版「无非必要特征」基础上，追求**保护范围最大**且**逻辑、表达清楚**。  
- **命名与数量优化（须结合案情；按下列规则权衡，禁止「默认一律第一/第二」）：**  
  - 「两块盖板」→「至少一块盖板」（除非「两块」本身解决问题所必需）。  
  - **部件命名两档对照（硬性）：** 第三版须给出**两档**命名优化对照（例如：交底/第二版原名 → **第一档优化** → **第二档优化**），并写明本版采用哪一档及理由；不得只给一档或只做半步改名即宣称已优化。  
  - **「第一×× / 第二××」选用规则（两步判断，不得跳步）：**  
    1. **先问是否扩大保护范围**：把方位/用途/材料等定语改成序数名后，是否使独权覆盖更多等同结构（不依赖「上游/下游」「防洪」等场景或用途绑死）？**若能扩大保护范围 → 优先推荐序数命名。**  
    2. **若不能扩大保护范围**（例如本案只有一处门组、改成「第一叠梁门」并不比「上游叠梁门」多盖住别的实施方式）：则**不再为序数而序数**；改为比较各档命名的**表达是否清楚**——若上一档（保留必要方位/功能区分、去掉过窄定语）更清楚，则采用上一档。  
  - **遇方位/场景限定语（左/右、前/后、上/下、上游/下游、迎水/背水、内外、防洪/高水头等）：** 必须同时遵循 `方位与场景限定上位规范`（观察方位优先「一侧」；上下游与功能侧慎改序数；场景钉死语能上位则上位）。**禁止**把「侧支/侧向」类结构名中的「侧」当作「左侧」删改。  
  - 过窄材料/结构/用途定语（如「钢」「防洪」「高水头」「专用」）能上位则上位；「叠梁」等结构词若去掉会导致与既有门槽配合关系不清楚，可保留或改为「门节」等并就地定义。  
  - 实施例专名、门组全称、场景绑定语能上位则上位；未采用的更宽档或更窄原名列入从权/说明书建议。  
- 先总列后展开、删冗、统一术语；不得为扩宽而写到不清楚或无法实施。  
- 仍不得削掉最小创造性/区别骨架。

### 方法二：类型铺陈（本 skill 以结构为主）

| 类型 | 要点 |
|------|------|
| 结构类（本 skill 主路径） | 「其特征在于」后先一句列全本层部件，再按序展开（`结构类权利要求撰写`）；硬守列名未展不得交付 |
| 结构+运行接口的混合 | 先结构骨架，再挂必要运行/接口限定；不得改写成纯方法独权冒充本 skill |
| 方法/算法 | **不走本 skill**；经 `独权撰写` 分流至 `方法类独权撰写` |

### 方法三：成组下放

第1步关键创新点中标注宜下放者、第2步未纳入最小集的特征、第一版→第二版、第二版→第三版剔出的关联特征，宜成组对应次级问题/效果，供从权与说明书；禁止为留后手而把当前版本的最小区别骨架整组藏进从权。

## 第1步：确定核心区别技术特征与关键创新点

标明阶段二（结构/装置案）；**由本 skill 建立** 2.1～2.9 plan；同步 todo。

**必读** `核心区别技术特征确定`（及按需其 `examples.md`），按该页完成两件交付后，才可进入第2步：

1. **核心区别的一句话描述**（顶天：相对现有/惯常的最大合理边界，不是交底实施例整份）；  
2. **关键创新点**（立地：优选实施例里最具创造性的点，默认作从权保底，不整份灌进独权）。立地 **≠** 第8步递交变劣。

- **优先引用**理解 skill 的「创新点 vs 惯常剥离表」；口径冲突须明示取舍。  
- 本步只定①②，不写独权、不组成最小集。  
- 标注「**待确认：核心区别一句话 + 关键创新点**」。  
- **须用户确认**后才能进入第2步。

**交付物：** plan + 该细则规定的第1步正文（一句话、边界三问、展开示意、关键创新点、非核心分流）。  
**禁止：** 同批输出最小集定稿或第一版独权全文；没有一句话只堆部件；把关键创新点整份当独权；为顶天编造交底无启示的新结构。

## 第2步：组成最小技术特征集【须确认】

**必读** `最小技术特征集与第一版独权`（及按需其 `examples.md`）。本步**只组集、不写独权正文**（允许心里试连缀，不得当交付）。

- 以已确认一句话为中心：抽出并清楚化 → 补完整方案必不可少的支撑（位置、连接、必要配合）→ 不得引入非必须特征。  
- **不**调用 `独立权利要求必要技术特征检查`。  
- **须用户确认**后才能进入第3步。本步**不开**命名对照表（命名在第3步写正文前）。

**交付物：** 该细则规定的第2步正文（抽出/清楚化、支撑、入集表、同名检查、下放候选）。  
**禁止：** 同批输出第一版独权全文；用「能否解决声称问题」筛入集；把交底实施例整份算进最小集；未确认核心区别即组集。

## 第3步：根据最小集撰写第一版独立权利要求

**必读** `最小技术特征集与第一版独权`。根据第2步已确认的最小集，用连接词连缀为第一版（核心独立权利要求）。

- **本版不预先锚定技术问题**；只用最小集中的技术特征 + 连接词。  
- 过「各版共通」闸门；不过第二版「零非必要」硬杠。  
- **命名闸门（硬性）：** 本步内须先触发 `部件命名优化总控`，交付「部件命名优化对照表」（含推荐采用名与保护范围影响），标注「**待确认：独权部件命名表**」；**用户确认前不得输出第一版独权全文**。可拆为「3a 命名表确认 → 3b 第一版正文」。  
- 结构铺陈：`结构类权利要求撰写`（先总列后展开；列名未展不得交付）。  
- 附落入表；标注「**第一版独权（最小特征集 · 核心独立权利要求）**」。

**禁止：** 未确认第2步最小集即写正文；未确认命名表即写独权正文；把交底实施例整份灌进第一版；最小集有名却不用或改名；同批重新核定问题；同批第二/三版。

## 第4步：审定技术主题并重新核定技术问题

**必读** `审定技术主题与重新核定技术问题`（及按需其 `examples.md`）。本步＝对着第3步第一版**全部特征**先审前序技术主题（常过窄），再核这份权1实际解决的技术问题。

- 标注「**待确认：审定后的技术主题 + 重新核定后的技术问题**」。  
- **须用户确认**后才能进入第5步。

**交付物：** 该细则规定的第4步正文。  
**禁止：** 第3步独权全文未交付即做本步；跳过审主题只改问题；同批输出第二版；只拿交底标题或理解候选空推。

## 第5步：第二版独权

锚定第4步已确认的审定主题与新问题，重写独立权利要求。第二版前序采用审定后的技术主题。

- 在新问题下重新考虑第一版是否合适，并进一步删减、上位。  
- **硬性：不得包含非必要技术特征**（方法一第二版加码 + `独立权利要求必要技术特征检查`）。  
- **命名闸门（硬性）：** 先触发 `部件命名优化总控`，交付相对第一版的命名对照表（尤其清理高强/材料/场景等非必要定语），供用户确认；**确认前不得输出第二版独权全文**。可拆为「5a 命名表确认 → 5b 第二版正文」。  
- 附：第一版在新问题下何处过窄/可删/可上位；相对第一版删除/概括/下放对照；成组下放清单。  
- 标注「**第二版独权（重新核定技术问题 · 无非必要特征）**」。

**交付物：** （先）命名对照表 →（确认后）第二版全文 + 对照要点 + 下放组。  
**禁止：** 未确认第4步主题与问题即写正文；未确认命名表即写独权正文；同批创造性长评；同批第三版；故意保留已知非必要特征。

## 第6步：再上位技术问题

相对第二版锚定问题再抽一层（本质化、去场景绑死、去效果堆砌）。**不以改技术主题为主**（主题已在第4步审定）；不得用本步顶替第4步未做的主题审定。

- 给出再上位后的问题表述 + 与第二版问题的分层关系（保留/放宽了什么）。  
- 若判断无需再上位：说明理由，并写明第三版仍锚定第二版问题、仅做表达/命名扩围。  
- 标注「**待确认：再上位后的技术问题**」。  
- **须用户确认**后才能进入第7步。

**交付物：** 上位问题表述（或「无需再上位」结论）+ 分层说明。  
**禁止：** 同批输出第三版独权全文；把再上位与第三版合并成一步；用本步顶替未完成的第4/5步去非必要。

## 第7步：第三版独权

锚定第6步已确认的再上位问题（或已确认的「无需再上位、仍用第二版问题」），重写独立权利要求。

- 执行方法一**第三版加码**（清楚 + 范围最大 + 命名/数量优化）。  
- **命名闸门（硬性）：** 先触发 `部件命名优化总控` → `部件命名具体优化`，交付**完整两档命名对照表**（须含「对保护范围的影响」列与推荐采用名），标注「**待确认：独权部件命名表**」；**用户确认或改选采用名之后**，才写第三版独权正文。可拆为「7a 命名表确认 → 7b 第三版正文」。  
- 成组下放非必要或过窄限定。  
- 标注「**第三版独权（再上位技术问题 · 清楚且范围最大）**」。

**交付物：** （先）两档命名对照表 →（确认后）第三版全文 + 相对第二版优化对照 + 下放组。  
**禁止：** 未确认命名表即写第三版正文；同批收束交接长文代替本步；把第三版要求降到第二版；用户未确认第6步问题就写第三版。

## 第8步：【可选】递交独权变劣与从权回退（本 skill 内嵌）

第三版完成后询问是否再做「递交权1放宽 + 定稿改进进从权」。  
- **跳过** → 写明；第9步正式稿默认=第三版；2.8=`cancelled`。  
- **执行** → 以第三版（或用户指定的定稿独权）为输入，按下列 **8.1～8.4** 推进；全部完成后进入第9步，正式稿默认=**递交独权**。

**含义（先对齐口径）：**

| 称谓 | 含义 |
|------|------|
| **定稿独权** | 第三版（或用户指定定稿） |
| **递交独权** | 定稿再去掉/改宽一层「改进限定」后的权1，用于正式递交 |
| **变劣 / 放宽** | 不是写成不能用的劣解，而是让权1覆盖更上位/更简化实现，保护面更宽 |
| **从权回退** | 定稿相对递交独权多出的特征，成组写入从权作退路 |

**一句话：** 定稿保质量 → 递交权1再放宽抓范围 → 定稿多出的改进进从权保退路。

**边界：** 变劣只能去掉/上位定稿已有限定，不能换成另一套发明；递交权1须完整可实施并保留最小创造性骨架；不得用本步替代第三版的命名/清楚性优化。

**子步骤硬性：** 一步一交付；8.1 变劣点**须用户确认**后才能写 8.2；禁止 8.2 与 8.3 一次倾倒。

### 8.1 锁定定稿 + 可变劣清单【须确认】

1. 复贴或引用定稿独权全文。  
2. 列出可下放的改进限定及变劣方式（示例）：

| 类型 | 定稿中的样子 | 变劣后进递交权1的常见写法 |
|------|----------------|---------------------------|
| 结构分型/分节 | 叠梁门 = 挡水门节 + 输水门节 | 整体门体 / 上游门体（不强制分节） |
| 安装依托 | 设于既有检修门槽 | 独权不写门槽；从权再写 |
| 位置优选 | 输水门节在最下方 | 独权不写；从权写 |
| 材料/驱动/阀型 | 电动球阀、钢制等 | 上位为流量调节阀等 |
| 数量/并联 | 多管并联 | 独权「至少一根」；多管进从权 |
| 运行能力 | 闸门可开启连通等 | 按案情留独权或进从权 |

3. 标注「**待确认：拟变劣点**」与建议保留的最小骨架。  

**交付物：** 定稿定位 + 可变劣清单 + 最小骨架建议。  
**禁止：** 同批输出递交独权全文、完整从权。

### 8.2 撰写递交独权

按已确认变劣点重写权1。

1. 比定稿**更宽**，不得更窄。  
2. 完整可实施；主谓宾完整；结构类先总列后展开；自定义名词就地定义。  
3. 标注「**递交独权（定稿变劣稿）**」。  
4. 附相对定稿删除/上位对照。  

**交付物：** 递交权1全文 + 与定稿对照。  
**禁止：** 同批倾倒全部从权；抽空最小骨架（风险高须明示并请用户确认）。

### 8.3 成组从权回退

把「定稿有、递交权1没有」的特征成组写入从权（或核心组+待写清单）。

1. 同一改进点串联成组（如：分节叠梁 → 最下方 → 既有门槽）。  
2. 引用合规（形式合规规范）；结构类多新部件先总列后展开。  
3. 每组注明对应定稿语句与退守效果。  

**交付物：** 从权条文或核心组 + 与变劣点映射表。  
**禁止：** 把递交权1最小骨架误下放。

### 8.4 对照 + 风险 → 进入第9步收束

1. 三栏对照：定稿独权 | 递交独权 | 从权回退组。  
2. 风险：创造性压力；说明书技术问题是否仍绑死已下放约束；待同步术语。  
3. 预告第9步正式稿默认=递交独权；定稿第三版作内部对照保留。  
4. 可选建议对递交权1经 `质检总控` → `权利要求质检总控` 做 `单条权利要求审查`。  

**交付物：** 对照摘要 + 风险 + 收束预告。  
**禁止：** 同轮说明书定稿。

**示例（非模板）：** 定稿「上游叠梁门含挡水/输水门节，管穿输水门节」→ 递交「上游门体整体设置，管穿门体」→ 从权回退分节叠梁，再从权最下方、既有门槽。

## 第9步：收束 + 交接

1. **正式独权工作稿**默认：若执行了第8步则为**递交独权**；否则为**第三版**（用户指定另选须明示）。  
2. 对照摘要：原主题 vs 第4步审定主题；三版锚定问题与要求层级；交底问题表述（对照）vs 第4步核定问题 vs 第6步再上位；若有递交变劣稿，另附「定稿 | 递交权1 | 从权回退」三栏。  
3. 下放组汇总（第1步关键创新点宜下放者 + 第2步未入最小集 + 各版剔出）、待确认事实、待同步说明书事项。  
4. 衔接：说明书问题/效果对齐（若改进仅在从权，技术问题勿再绑死在独权已下放的约束上）；**提示转入 `从权撰写`**（默认布局 9 条；第1/2/5/7步下放组与第8步回退组作种子）；质检；若跳过创造性可事后另开。  
5. 结束；不自动连跑说明书或从权全文（从权由 `从权撰写` 专轮执行）。

**交付物：** 正式稿定位（可复贴）+ 摘要与清单 + 衔接。  
**禁止：** 同轮说明书定稿；未经确认回改第三版/递交稿（有意见回第7步或第8步相应子步骤）。
