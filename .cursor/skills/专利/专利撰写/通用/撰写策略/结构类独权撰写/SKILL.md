# 结构类独权撰写（最小特征集至第二版 + 其后三版扩围 · 服务于结构/装置案）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  术语先释义 + 外行读懂 + 懂后再体检 + 问题候选
        ↓
第1步  输出交底书声称要解决的技术问题
        ↓
第2步  输出交底书中解决该问题的技术特征
        ↓
第3步  确定其中的核心区别技术特征
        ↓
第4步  按核心区别构造最小技术特征集 → 第一版独立权利要求
        ↓
第5步  根据第4步已写成的第一版独立权利要求，重新核定其所对应的技术问题
        ↓
第6步  在新问题下审视第一版是否合适，进一步删减/上位 → 第二版独权
        ↓
第7步  再上位技术问题
        ↓
第8步  第三版独权   要求最高：逻辑与表达清楚 + 保护范围最大
                    （命名/数量等上位优化，如下文方法）
        ↓
【可选】第9步  递交独权变劣与从权回退   （定稿再放宽一档作递交权1；改进进从权）
        ↓
第10步 收束为正式独权工作稿
```

**三版要求依次提高（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求（递进） |
|------|----------------|------------------|
| **第一版** | 第1步交底书**声称**的技术问题 | 由第3步核心区别构造**最小技术特征集**；完整可实施；**禁止**把交底实施例细节整份灌进独权 |
| **第二版** | 第5步**重新核定后**的技术问题 | 在新问题下审视第一版是否仍合适；特征可进一步删减、上位；**不得含非必要技术特征**；方案完整可实施 |
| **第三版** | 第7步**再上位后**的技术问题 | 在第二版「无非必要特征」之上，进一步：**逻辑清楚、表达清楚、保护范围最大**（部件命名上位、数量词放宽、序数命名等——按命名规则权衡，非一律第一/第二） |

撰写方法（质量闸门、类型铺陈、命名规则等）**服务于上述策略**，不得颠倒成「先抠字眼、后定策略」。

## 适用场景与触发

- **客体：** 结构/装置类独立权利要求（「一种××装置/机构/系统」等以部件与连接关系为主的方案）。
- **入口：** 须经 `独权撰写` 判定为结构案后转入本 skill；已点名「结构类独权 / 装置独权」时可直进。
- 已完成 `交底书技术方案理解`（含术语词典、外行总故事、懂后体检与问题候选）；进入**阶段二**（本 skill 自建 2.1～2.10 plan）。
- 触发：「写结构类独权」「装置独权」「核心区别」「最小特征集」「重新核定技术问题」「第二版」「第三版」「再上位」等。
- **不适用：** 纯方法/算法流程型独权（回 `独权撰写` 分流至 `方法类独权撰写`）。

## 能力边界

- 产出：声称问题、特征清单、核心区别、三版独权工作稿链 + 重新核定与再上位两轮问题说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新结构/步骤；缺事实标「待确认」。
- 必要特征逐条细则调用 `独立权利要求必要技术特征检查`；类型与表达规范按需调用，不在本文件全文粘贴。
- 本 skill 是**结构案**独权正文与变劣的执行层；**分流入口**是 `独权撰写`，勿与入口混淆。

## 输出控制（plan 硬性）

禁止一次输出「声称问题+特征清单+核心区别+多版独权」。必须用 plan/待办（TodoWrite 等）同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

### 固定 plan（共10步 = 总览 2.1～2.10）

```text
第1步 输出交底书声称要解决的技术问题【须用户确认】
  ↓
第2步 输出交底书中解决该问题的技术特征【须用户确认无重大遗漏】
  ↓
第3步 确定其中的核心区别技术特征【须用户确认】
  ↓
第4步 按核心区别构造最小技术特征集 → 第一版独立权利要求
  ↓
第5步 根据第4步第一版独立权利要求，重新核定其所对应的技术问题【须用户确认】
  ↓
第6步 在新问题下审视第一版，进一步删减/上位 → 第二版独权
  ↓
第7步 再上位技术问题（结论 + 与第二版问题分层）【须用户确认】
  ↓
第8步 第三版独权（清楚 + 范围最大；含命名/数量优化）
  ↓
第9步 【可选】递交独权变劣与从权回退（定稿再放宽作递交权1）
  ↓
第10步 正式工作稿收束 + 三版/递交对照摘要 + 交接
```

- 第1步同步建立 2.1～2.10 plan，**不**单列「只建 plan」的步骤。  
- **禁止**将第3步与第4步合并（未确认核心区别不得写第一版）。  
- **禁止**将第4步与第5步合并（未写出第一版独权全文，不得重新核定问题）。  
- **禁止**将第5步与第6步合并（未确认新核定问题不得写第二版）。  
- 第6步完成后，第7步再上位的问题锚定基线=第二版所锚定问题；第8步独权基线=第二版。  
- **禁止**将第7步与第8步合并交付；**须**用户确认再上位问题后，方可写第三版独权。  
- 第9步执行 → 按下文「第9步」内嵌子步骤 9.1～9.4 推进（仍属本 skill，不外转）；返回后第10步正式稿默认=递交独权。  
- 第9步跳过 → 写明；第10步正式稿默认=第三版；2.9=`cancelled`。  
- 未完成理解不得硬写第一版。

## 第1步声称问题 vs 第5步重新核定 vs 第7步再上位（禁止抢活）

| | **第1步 交底声称问题** | **第5步 重新核定** | **第7步 再上位** |
|--|------------------------|--------------------|------------------|
| **时机** | 尚未写独权 | **第4步第一版独立权利要求全文已交付之后** → 第二版之前 | 第二版之后 → 第三版之前 |
| **输入对象** | 交底书 / 理解 skill 问题候选 | **仅第4步已写成的第一版独立权利要求** | 第二版已锚定的问题（及第二版独权） |
| **一句话** | 交底书自己声称要解决什么 | 这份第一版独权**实际能稳定解决**的是哪一层问题 | 第二版已对齐后，再抽场景/效果/客体表述一层（或判定无需） |
| **改写** | **不改写** | **要核定**（三点权衡，创造性落点）；反推起点是权1，不是交底声称问题 | 只动问题表述层级，或交付「无需再上位」 |
| **服务对象** | 第2步列特征、第4步最小集 | 第6步第二版：进一步删减/上位 | 第8步第三版：清楚 + 范围最大 |

**禁止互相抢活：**

- 第1步不得写成重新核定或再上位定稿。  
- 第5步**不得**再摘一遍交底声称问题，**不得**只拿第3步核心区别清单或理解 skill 问题候选空推；**唯一反推对象是第4步已写成的独立权利要求**；**不**预写第三版问题。  
- 第4步独权全文未交付，不得进入第5步。  
- 第7步**不以**「再清一轮非必要部件」为目标（非必要应已在第二版清完）；若第二版仍明显过窄，应回改第5/6步，而非用第7步顶替。

## 重新核定技术问题：怎么考虑（第5步专用方法）

**输入对象（硬性）：** 第5步只根据**第4步已经构造并交付的第一版独立权利要求**重新核定技术问题。交底声称问题、理解 skill 候选、第3步核心区别清单只作对照，**不得**代替第一版独权成为反推起点。未写出第一版独权全文，本步不成立。

重新核定**不是**把交底书问题换个说法，也**不是**把技术方案手段写进问题里。交付第5步时，必须先点明「反推对象=第4步第一版独权」，再用小节写清「本次核定的考虑」。

结构为：**三点综合权衡（主轴）** + **六点操作方法（融进三点、用于落地）**。六点不是与三点并列的另一套主轴，而是帮助把三点判准、写清、检验的方法。

### 一、三点综合权衡（主轴，三点都要写到）

1. **最核心的问题**  
   对着第4步第一版独权看：若不解决就会导致这份方案整体失败或痛点最尖锐的那一个（或极少数）问题。可用交底场景校核「没跑偏」，但**起点是权1，不是交底声称句**。优先「主矛盾」。

2. **第一版独权中最具有创造性的技术特征所解决的问题**  
   **反推对象=第4步已写成的独立权利要求**（其中已含核心区别与必要支撑）：这撮高贡献手段真正稳定解决的是什么问题。重新核定后的主问题应尽量落在这撮手段所能支撑的问题上，使第二版能把创造性骨架留在独权里。

3. **好通过补强来增强创造性的技术方案所解决的问题**  
   在第一版独权已有骨架基础上，哪些问题方向若创造性仍边缘/不足，**相对容易**沿交底书脉络深化、补场景或补特征从而抬创造性（而非另起炉灶、发明人难确认）。可适当偏向「可补强」方向（便于后续答复或补材料）；不得脱离交底已有事实、也不得脱离第一版独权已有特征，空定无法落地的问题。

**综合规则：**  
- 三点指向同一问题（或同一表述层级）→ 直接定为重新核定后的主问题。  
- 不一致 → 列出三点各自指向，说明以谁为纲、其余如何兼顾或降为次级问题；**默认优先**点2，兼顾点1，并评估点3；用户另有指示从其指示。

### 二、六点操作方法（融进三点）

写「核定考虑」时，用下列方法支撑三点判断；可在各点之下嵌用，也可单列「操作检视」短节，但**不得用六点替代三点主轴**。

| 操作方法 | 主要服务哪一点 | 怎么用 |
|----------|----------------|--------|
| **交底书问题盘点** | 点1 | 分清哪些是核心痛点，哪些是附带效果/宣传语；附带/宣传不得当成重新核定后的主问题。 |
| **特征反推** | 点2（兼点1） | **对着第4步第一版独权全文**看核心区别：实际稳定解决的是哪一层「不良后果」；据此校准「最具创造性手段所解问题」与「最核心问题」是否同层。 |
| **手段不进问题** | 三点共用（表述硬约束） | 问题只写不利后果/需求缺口，不写专用门、算法名、具体参数等手段；手段留在特征里。 |
| **区分度落点** | 点2（兼点3） | 问题过宽→难支撑新颖性/创造性；过窄→非必要特征被逼进第二版。落点应能被高贡献手段撑住，且宽度适合后续补强。 |
| **用户/布局侧重** | 三点加权 | 用户明确的保护重心、场景约束等作加权，**不作唯一依据**；不得压过三点中已能自洽的结论，除非用户明示改选。 |
| **可检验** | 三点收束检验 | 假定第二版已剔到只剩必要特征：是否仍能完整解决拟核定的问题？不能→问题过大或特征不足，须改问题层级或回到第一版/交底补事实。 |

### 三、输出格式

- **反推对象**：复贴或明确引用第4步第一版独立权利要求（可摘要，但须能对上全文）  
- **重新核定后的技术问题**（一句或两句定稿候选）  
- **核定考虑**  
  - 先写明「反推对象=第一版独权」；再按**点1 / 点2 / 点3**分述结论；  
  - 在相应点下（或另附「操作检视」）体现问题盘点、特征反推、区分度落点、用户加权、可检验等；全文遵守手段不进问题；  
  - 三点冲突时写明取舍。  
- **与交底书声称问题的差异**（保留/收窄/改表述；此栏是对照，不是本步起点）  
- **对第二版的预期**（一句：拟删/概括哪些非必要结构，因问题已不再绑死它们）  
- 请用户确认后再写第二版。

## 撰写方法总则（服务于三版策略）

### 最小技术特征集（第4步硬性口径）

最小技术特征集 **≠** 只写核心区别、把方案写残。它是：

1. **必须包含**第3步已确认的核心区别技术特征；  
2. **另含**使方案完整可实施、仍能解决第1步声称问题所必需的支撑特征（位置、连接、必要配合关系等）；  
3. **不得**把交底中的实施例细节、优选数量/排列、材料牌号、具体驱动/工艺等非必要项塞进第一版。

构造时逐项反问：去掉该支撑特征后，核心区别是否还接得上、方案是否还能实施并解决声称问题？能去掉则不要进最小集（列入第2步未入独权的下放候选）。

### 方法一：独权正文质量闸门（按版本加码）

**各版共通：** 类型铺陈正确；主谓宾完整；所述指代清楚；**每一版独权均须先触发一次 `部件命名优化总控`，再由总控分流到具体命名 skill；且必须先交付「部件命名优化对照表」供用户选择确认，确认后再写该版独权正文（禁止未确认先出独权全文）**；自定义名词就地定义；功能性限定守边界；不编造无支持特征。

**第二版加码（硬性）：**  
- 锚定=重新核定后的技术问题。  
- 先问：第一版在新问题下是否仍合适（过窄/过宽/偏题）？再逐特征反问：去掉或改宽后该问题是否仍解决？能→必须删/概括/下放（`独立权利要求必要技术特征检查`）。  
- 重点清理：非必要数量词、排列方式、具体机构/工艺/驱动（除非恰为区别点）。  
- 删后方案须仍完整可实施；保留最小区别骨架。

**第三版加码（硬性）：**  
- 在第二版「无非必要特征」基础上，追求**保护范围最大**且**逻辑、表达清楚**。  
- **命名与数量优化（须结合案情；按下列规则权衡，禁止「默认一律第一/第二」）：**  
  - 「两块盖板」→「至少一块盖板」（除非「两块」本身解决问题所必需）。  
  - **部件命名两档对照（硬性）：** 第三版须给出**两档**命名优化对照（例如：交底/第二版原名 → **第一档优化** → **第二档优化**），并写明本版采用哪一档及理由；不得只给一档或只做半步改名即宣称已优化。  
  - **「第一×× / 第二××」选用规则（两步判断，不得跳步）：**  
    1. **先问是否扩大保护范围**：把方位/用途/材料等定语改成序数名后，是否使独权覆盖更多等同结构（不依赖「上游/下游」「防洪」等场景或用途绑死）？**若能扩大保护范围 → 优先推荐序数命名。**  
    2. **若不能扩大保护范围**（例如本案只有一处门组、改成「第一叠梁门」并不比「上游叠梁门」多盖住别的实施方式）：则**不再为序数而序数**；改为比较各档命名的**表达是否清楚**——若上一档（保留必要方位/功能区分、去掉过窄定语）更清楚，则采用上一档。  
  - **遇方位/场景限定语（左/右、前/后、上/下、上游/下游、迎水/背水、内外、防洪/高水头等）：** 必须同时遵循 `方位与场景限定上位规范`（观察方位优先「一侧」；上下游与功能侧慎改序数；场景钉死语能上位则上位）。**禁止**把「侧支/侧向」类结构名中的「侧」当作「左侧」删改。  
  - 过窄材料/结构/用途定语（如「钢」「防洪」「高水头」「专用」）能上位则上位；「叠梁」等结构词若去掉会导致与既有门槽配合关系不清楚，可保留或改为「门节」等并就地定义。  
  - 实施例专名、门组全称、场景绑定语能上位则上位；未采用的更宽档或更窄原名列入从权/说明书建议。  
- 先总列后展开、删冗、统一术语；不得为扩宽而写到不清楚或无法实施。  
- 仍不得削掉最小创造性/区别骨架。

### 方法二：类型铺陈（本 skill 以结构为主）

| 类型 | 要点 |
|------|------|
| 结构类（本 skill 主路径） | 「其特征在于」后先一句列全本层部件，再按序展开（`结构类权利要求撰写`）；硬守列名未展不得交付 |
| 结构+运行接口的混合 | 先结构骨架，再挂必要运行/接口限定；不得改写成纯方法独权冒充本 skill |
| 方法/算法 | **不走本 skill**；经 `独权撰写` 分流至 `方法类独权撰写` |

### 方法三：成组下放

第4步未纳入最小集的特征、第一版→第二版、第二版→第三版剔出的关联特征，宜成组对应次级问题/效果，供从权与说明书；禁止为留后手而把当前版本的最小区别骨架整组藏进从权。

4. 标注「**待确认：交底书声称的技术问题**」。

**交付物：** plan + 交底声称技术问题（原文/归纳 + 来源）。

## 第2步：输出交底书中解决该问题的技术特征

对准第1步已确认的声称问题，列出交底书中用于解决该问题的技术特征（部件、位置、连接、配合关系等）。

- **优先引用**理解 skill 的构成地图、特征与问题对应关系；补交底中理解阶段未逐条展开、但确实用于解题的特征。

- 标注「**待确认：解决声称问题的技术特征清单**」；请用户确认有无重大遗漏。

**交付物：** 特征清单（可含「疑似实施例细节」标记）。  
**禁止：** 输出独权全文；把清单直接当成最小特征集。

## 第3步：确定核心区别技术特征

从第2步清单中，确定**核心区别技术特征**（相对现有惯常结构、真正做功且支撑声称问题的那一撮）。

- **优先引用**理解 skill 的「创新点 vs 惯常剥离表」，并与第2步清单对齐；口径冲突须明示取舍。  
- 建议表列：特征｜相对现有/惯常的区别点｜是否核心区别｜理由。  
- **不得**把第2步全部特征都标成核心区别；惯常连接、纯实施例钉死、材料牌号、优选数量等默认非核心。  
- 标注「**待确认：核心区别技术特征**」。  
- **须用户确认**后才能进入第4步。

**交付物：** 核心区别清单 + 非核心/惯常/细节分流说明。  
**禁止：** 同批输出第一版独权全文；无理由把交底几乎全部部件标成核心区别。

## 第4步：最小技术特征集 → 第一版独立权利要求

按已确认的核心区别，构造**最小技术特征集**，并据此撰写第一版独立权利要求。

- 最小集口径见上文「最小技术特征集」；锚定第1步声称问题。  
- 过「各版共通」闸门；不过第二版「零非必要」硬杠（支撑特征只保留实施所必需者，但本步仍对准声称问题而非核定后问题）。  
- **命名闸门（硬性）：** 本步内须先触发 `部件命名优化总控`，交付「部件命名优化对照表」（含推荐采用名与保护范围影响），标注「**待确认：独权部件命名表**」；**用户确认前不得输出第一版独权全文**。可拆为「4a 命名表确认 → 4b 第一版正文」。  
- 结构铺陈：`结构类权利要求撰写`（先总列后展开；列名未展不得交付）。  
- 附：最小集构成（核心区别 / 必要支撑）；第2步未入最小集的下放候选。  
- 标注「**第一版独权（交底声称问题 · 最小特征集）**」。

**禁止：** 未确认第3步核心区别即写正文；未确认命名表即写独权正文；把交底实施例整份灌进第一版；同批重新核定问题；同批第二/三版。

## 第5步：重新核定独立权利要求的技术问题

**本步＝根据第4步已经构造的第一版独立权利要求，重新核定这份权1实际解决的技术问题。**

- 先锁定反推对象：复贴或引用第4步第一版独权全文。  
- 必须按上文「重新核定技术问题：怎么考虑」输出**结论 + 考虑说明**。  
- 标注「**待确认：重新核定后的技术问题**」。  
- **须用户确认**后才能进入第6步。

**交付物：** 反推对象（第一版独权）+ 新问题表述 + 核定考虑（三点主轴 + 六点操作融入；含取舍）+ 与交底声称问题差异（对照）+ 对第二版预期。  
**禁止：** 第4步独权全文未交付即做本步；同批输出第二版独权全文；只拿核心区别清单或理解候选空推而不对着第一版独权。

## 第6步：第二版独权

锚定第5步已确认的新问题，重写独立权利要求。

- 在新问题下重新考虑第一版是否合适，并进一步删减、上位。  
- **硬性：不得包含非必要技术特征**（方法一第二版加码 + `独立权利要求必要技术特征检查`）。  
- **命名闸门（硬性）：** 先触发 `部件命名优化总控`，交付相对第一版的命名对照表（尤其清理高强/材料/场景等非必要定语），供用户确认；**确认前不得输出第二版独权全文**。可拆为「6a 命名表确认 → 6b 第二版正文」。  
- 附：第一版在新问题下何处过窄/可删/可上位；相对第一版删除/概括/下放对照；成组下放清单。  
- 标注「**第二版独权（重新核定技术问题 · 无非必要特征）**」。

**交付物：** （先）命名对照表 →（确认后）第二版全文 + 对照要点 + 下放组。  
**禁止：** 未确认第5步问题即写正文；未确认命名表即写独权正文；同批创造性长评；同批第三版；故意保留已知非必要特征。

## 第7步：再上位技术问题

相对第二版锚定问题再抽一层（本质化、去场景绑死、去效果堆砌）。

- 给出再上位后的问题表述 + 与第二版问题的分层关系（保留/放宽了什么）。  
- 若判断无需再上位：说明理由，并写明第三版仍锚定第二版问题、仅做表达/命名扩围。  
- 标注「**待确认：再上位后的技术问题**」。  
- **须用户确认**后才能进入第8步。

**交付物：** 上位问题表述（或「无需再上位」结论）+ 分层说明。  
**禁止：** 同批输出第三版独权全文；把再上位与第三版合并成一步；用本步顶替未完成的第5/6步去非必要。

## 第8步：第三版独权

锚定第7步已确认的再上位问题（或已确认的「无需再上位、仍用第二版问题」），重写独立权利要求。

- 执行方法一**第三版加码**（清楚 + 范围最大 + 命名/数量优化）。  
- **命名闸门（硬性）：** 先触发 `部件命名优化总控` → `部件命名具体优化`，交付**完整两档命名对照表**（须含「对保护范围的影响」列与推荐采用名），标注「**待确认：独权部件命名表**」；**用户确认或改选采用名之后**，才写第三版独权正文。可拆为「8a 命名表确认 → 8b 第三版正文」。  
- 成组下放非必要或过窄限定。  
- 标注「**第三版独权（再上位技术问题 · 清楚且范围最大）**」。

**交付物：** （先）两档命名对照表 →（确认后）第三版全文 + 相对第二版优化对照 + 下放组。  
**禁止：** 未确认命名表即写第三版正文；同批收束交接长文代替本步；把第三版要求降到第二版；用户未确认第7步问题就写第三版。

## 第9步：【可选】递交独权变劣与从权回退（本 skill 内嵌）

第三版完成后询问是否再做「递交权1放宽 + 定稿改进进从权」。  
- **跳过** → 写明；第10步正式稿默认=第三版；2.9=`cancelled`。  
- **执行** → 以第三版（或用户指定的定稿独权）为输入，按下列 **9.1～9.4** 推进；全部完成后进入第10步，正式稿默认=**递交独权**。

**含义（先对齐口径）：**

| 称谓 | 含义 |
|------|------|
| **定稿独权** | 第三版（或用户指定定稿） |
| **递交独权** | 定稿再去掉/改宽一层「改进限定」后的权1，用于正式递交 |
| **变劣 / 放宽** | 不是写成不能用的劣解，而是让权1覆盖更上位/更简化实现，保护面更宽 |
| **从权回退** | 定稿相对递交独权多出的特征，成组写入从权作退路 |

**一句话：** 定稿保质量 → 递交权1再放宽抓范围 → 定稿多出的改进进从权保退路。

**边界：** 变劣只能去掉/上位定稿已有限定，不能换成另一套发明；递交权1须完整可实施并保留最小创造性骨架；不得用本步替代第三版的命名/清楚性优化。

**子步骤硬性：** 一步一交付；9.1 变劣点**须用户确认**后才能写 9.2；禁止 9.2 与 9.3 一次倾倒。

### 9.1 锁定定稿 + 可变劣清单【须确认】

1. 复贴或引用定稿独权全文。  
2. 列出可下放的改进限定及变劣方式（示例）：

| 类型 | 定稿中的样子 | 变劣后进递交权1的常见写法 |
|------|----------------|---------------------------|
| 结构分型/分节 | 叠梁门 = 挡水门节 + 输水门节 | 整体门体 / 上游门体（不强制分节） |
| 安装依托 | 设于既有检修门槽 | 独权不写门槽；从权再写 |
| 位置优选 | 输水门节在最下方 | 独权不写；从权写 |
| 材料/驱动/阀型 | 电动球阀、钢制等 | 上位为流量调节阀等 |
| 数量/并联 | 多管并联 | 独权「至少一根」；多管进从权 |
| 运行能力 | 闸门可开启连通等 | 按案情留独权或进从权 |

3. 标注「**待确认：拟变劣点**」与建议保留的最小骨架。  

**交付物：** 定稿定位 + 可变劣清单 + 最小骨架建议。  
**禁止：** 同批输出递交独权全文、完整从权。

### 9.2 撰写递交独权

按已确认变劣点重写权1。

1. 比定稿**更宽**，不得更窄。  
2. 完整可实施；主谓宾完整；结构类先总列后展开；自定义名词就地定义。  
3. 标注「**递交独权（定稿变劣稿）**」。  
4. 附相对定稿删除/上位对照。  

**交付物：** 递交权1全文 + 与定稿对照。  
**禁止：** 同批倾倒全部从权；抽空最小骨架（风险高须明示并请用户确认）。

### 9.3 成组从权回退

把「定稿有、递交权1没有」的特征成组写入从权（或核心组+待写清单）。

1. 同一改进点串联成组（如：分节叠梁 → 最下方 → 既有门槽）。  
2. 引用合规（形式合规规范）；结构类多新部件先总列后展开。  
3. 每组注明对应定稿语句与退守效果。  

**交付物：** 从权条文或核心组 + 与变劣点映射表。  
**禁止：** 把递交权1最小骨架误下放。

### 9.4 对照 + 风险 → 进入第10步收束

1. 三栏对照：定稿独权 | 递交独权 | 从权回退组。  
2. 风险：创造性压力；说明书技术问题是否仍绑死已下放约束；待同步术语。  
3. 预告第10步正式稿默认=递交独权；定稿第三版作内部对照保留。  
4. 可选建议对递交权1经 `质检总控` → `权利要求质检总控` 做 `单条权利要求审查`。  

**交付物：** 对照摘要 + 风险 + 收束预告。  
**禁止：** 同轮说明书定稿。

**示例（非模板）：** 定稿「上游叠梁门含挡水/输水门节，管穿输水门节」→ 递交「上游门体整体设置，管穿门体」→ 从权回退分节叠梁，再从权最下方、既有门槽。

## 第10步：收束 + 交接

1. **正式独权工作稿**默认：若执行了第9步则为**递交独权**；否则为**第三版**（用户指定另选须明示）。  
2. 对照摘要：三版锚定问题与要求层级；第1步声称问题 vs 第5步核定问题 vs 第7步再上位；若有递交变劣稿，另附「定稿 | 递交权1 | 从权回退」三栏。  
3. 下放组汇总（第2步未入最小集 + 各版剔出）、待确认事实、待同步说明书事项。  
4. 衔接：说明书问题/效果对齐（若改进仅在从权，技术问题勿再绑死在独权已下放的约束上）；**提示转入 `从权撰写`**（默认布局 9 条；第4/6/8步下放组与第9步回退组作种子）；质检；若跳过创造性可事后另开。  
5. 结束；不自动连跑说明书或从权全文（从权由 `从权撰写` 专轮执行）。

**交付物：** 正式稿定位（可复贴）+ 摘要与清单 + 衔接。  
**禁止：** 同轮说明书定稿；未经确认回改第三版/递交稿（有意见回第8步或第9步相应子步骤）。
