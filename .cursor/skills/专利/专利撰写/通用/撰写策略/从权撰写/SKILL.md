# 从权撰写（布局 → 逐条写）

## 适用场景

- 已完成 `独权撰写`：至少有正式权1（第三版或**递交独权**）；若执行过第8步，已有从权回退组种子。
- 用户要系统写从属权利要求树，而不仅是质检或零散补一条。
- 典型触发：「写从权」「从权布局」「九条从权」「接着写权3」。

## 在总流程中的位置

```text
独权撰写（含可选第8步变劣回退）→ 收束
        ↓
【本 skill】从权撰写：盘点 → 布局9条【确认】→ 逐条撰写 → 复核交接
        ↓
质检总控 → 权利要求质检总控（可选）→ 说明书撰写
```

## 默认案规（可改，须在布局步明示）

| 项 | 默认 |
|----|------|
| 从权条数 | **9 条**（权2～权10） |
| 已有权2 | **计入** 9 条之一，布局表须占用权2行；不重复新写除非用户要改权2 |
| 第8步回退组 | **强制作为布局种子**（须优先排入 9 条；排不下的进「暂缓/说明书」清单并说明） |
| 撰写节奏 | 默认**一条一确认**；用户明确说「写完核心链再停」时，允许一次交付**串联核心链**（通常权2所在链上的连续依赖从权）后暂停，平行组仍建议逐条或下一批再开 |

## 能力边界

- 产出：布局表 + 至多 9 条从权正文 + 复核摘要；不是说明书定稿，不是完整创造性评述。
- 不得编造交底/定稿未支持的特征；缺事实标待确认。
- 不替代 `质检总控` / `权利要求质检总控` / `权利要求书质检`；本 skill 末步做形式、引用结构与**依附编号／术语出处**自检（须交核对表），正式质检另开。

---

## 输出控制（plan 硬性）

必须 TodoWrite 同步；始终一个 `in_progress`；格式 `【第X步 / 共4步】`（第3步内再标 `权N · 第k/9条`）。

```text
第1步 输入锁定 + 改进点盘点（含第8步种子强制入库）
  ↓
第2步 从权布局表（默认9条）【须用户确认】
  ↓
第3步 逐条撰写（默认一条一确认；可「核心链一批后停」）
  ↓
第4步 形式合规 + 引用结构 + 依附编号核对表 + 交接
```

**禁止：** 未确认布局就写权3及以后；一次倾倒全部 9 条正文（核心链例外须用户明示）；布局默认条数悄悄改成非 9；术语出处核对失败仍交付下一条。

---

## 第1步：输入锁定 + 改进点盘点

1. 锁定权1全文（递交独权优先，否则第三版/用户指定）。  
2. 若已有权2，原样载入，标明「已占用 9 条中的 1 条」。  
3. **强制导入** `独权撰写` 第8步从权回退组（若未做第8步：从「定稿相对权1多出的特征」+ 交底优点/显著特点自行抽种子，并注明来源）。  
4. 补充交底未入权、可作从权的候选（诱鱼、双通道、细部结构等）。  
5. 输出「种子 / 候选 / 暂缓」三栏清单。

**交付物：** 权1（+已有权2）+ 改进点盘点表。  
**禁止：** 输出 9 条布局定稿表以外的从权正文长文。

---

## 第2步：布局（默认 9 条）【须确认】

做一张 **权2～权10** 布局表，列至少：

| 权号 | 引用 | 改进点 | 平行/串联 | 种子来源 | 次级问题/效果 |
|------|------|--------|-----------|----------|----------------|
| 2 | 1 | … | — | 已有/第8步 | … |
| … | … | … | … | … | … |
| 10 | … | … | … | … | … |

**布局规则：**

1. **独立改进点平行**引用同一合适基础（多为权1）；**依赖改进点串联**。  
2. 第8步种子**全部优先占位**；冲突时合并条目或说明为何落入暂缓。  
3. 已有权2占权2行；其后编号连续。  
4. 预检：避免「多项从权再被多项引用」的布局陷阱（详见形式合规 skill）。  
5. 条数：默认 9；用户要求增减须改表并再确认。

**交付物：** 9 行布局表 + 引用关系简图 + 暂缓清单。  
**禁止：** 未确认即进入第3步撰写。

## 第3步：逐条撰写 + 规范 skill 门禁（硬性）

### 3.0 能否「准确调用」相应 skill——本 skill 的强制答法

**能，前提是本步执行时遵守下列门禁，而不是凭记忆临场发挥：**

1. **写每一条（或每一核心链批次）之前**，根据该条特征类型，对下表「必读」列的 skill **先 Read 再写**（允许本会话已读且未改规则时不重复读，但须在交付物中写明「已遵循：xxx skill」）。  
2. 禁止只写「参考某某规范」却不打开文件、不按清单自检。  
3. 一条从权可触发多行门禁（例如结构多部件 + 自定义名词 → 两行都要满足）。

### 3.1 门禁表（按特征触发）

| 本条从权出现的情况 | 必读并遵循 |
|--------------------|------------|
| **本条从权新增、改写或复用部件名称** | **`部件命名优化总控`（硬性：每条从权都要先做一次总控命名审查；总控按分型分流到直接命名类与间接校正类具体 skill，包括 `部件命名具体优化`、口语名改写、方位上位、就地定义，以及按条件分流的清楚性/指代/结构类铺陈/功能性限定边界等；如“高强螺栓”应先判断是否优化为“螺栓”；**新部件名必须对照已入权部件名表做同名多物审查，冲突则按 `部件命名具体优化` 规则五消歧**）** |
| 结构类；或一次引入新部件（含「还包括」）；或部件有内部构成 | `结构类权利要求撰写`（先总列后展开；**同级并列≠上下位**，子件不得与母件同句还包括；**总列后每个子件至少一句位置/连接展开，列名未展不得交付**） |
| **本条出现「所述××」（含「所述A的B」中的子件名）** | **本节 3.2.1 术语出处／依附编号机械核对（硬性；与 `权利要求书质检` 维度二第1点同算法；待抽出独立规范后改挂该规范）** |
| 含「用于…」「以便…」等功能/效果尾 | `功能性限定使用边界规范` |
| 任何一条（默认） | `权利要求主谓宾结构规范` + `权利要求指代与参照清晰性规范` |
| **出现左/右、前/后、上/下、上游/下游、迎水侧/背水侧、内外侧，或防洪/高水头等场景钉死语** | **`方位与场景限定上位规范`（按类别判断上位档位后再落笔）** |
| 出现交底口语名/非自明名称（可疑需靠“其中”解释） | `交底口语名改写为自明结构名规范`（先判断能否改名，再决定是否用“其中”） |
| 出现自定义/非常识名词 | `自定义名词就地定义` |
| 方法/算法步骤、条件分支 | `条件判断语句规范` |
| 参数/预设值先用后取风险 | `预设值与参数来源检查` |
| 写完一条或一批后的引用与格式 | `权利要求形式合规性规范`（微型核对） |
| 清楚性、孤岛、术语一致 | `权利要求清楚性与逻辑一致性规范`（摘要自检） |

### 3.2 单条交付格式

`【从权 第k/9条 · 权利要求N】`  

- 正文  
- 对应布局表行（改进点一句话）  
- **已遵循 skill：** 列出本条实际 Read/遵循的规范名  
- **微型自检（须逐项勾过，缺一不得请确认下一条）：**  
  1. 引用方向：引用号 ＜ 本条编号；主题名称与独权一致；无多项套多项  
  2. **术语出处：** 已按 3.2.1 做完机械核对；失败项已三选一处置；交付物中附本条「术语出处微表」  
  3. 结构类：新部件已先总列；**已逐件展开**（每个总列子件至少一句位置/连接）；声明「已逐件展开：是／不适用」  
  4. 命名：本条新名已过 `部件命名优化总控`；无跨权同名多物未消歧  
- 请确认后写下一条（或按用户指示开下一批）

### 3.2.1 术语出处／依附编号机械核对（硬性）

对**即将交付的本条从权**执行（与整份质检同一算法；禁止凭感觉写「所述有先行基础」）：

1. **列词：** 列出本条正文中所有带「所述」的名词（含「所述锚固箱的底板」→ 须分别核对「锚固箱」「底板」是否都有出处）。  
2. **溯源：** 对每个词，在权1～本条引用链上的已有权利要求中查找**首次出现**的权号；本条**首次引入**的词（写「包括／设有××」而非「所述××」）记为「本条新引入」，不要求上游出处。  
3. **取最大号：** 在「须有出处」的词中，取其首次出现权号的**最大值** \(M\)。  
4. **覆盖判定：** 本条的依附对象及其向上引用链，必须**包含**首次出现于权 \(M\) 的那条路径上的全部必要节点——亦即每个「所述××」都能在「本条 → 引用对象 → … → 权1」链上某条权利要求中找到定义／首次引入。  
5. **失败则三选一处置（禁止带病交付）：**  
   - **A. 改引用：** 改为引用（或经串联能覆盖）首次出现该词的权利要求；或  
   - **B. 本条首次引入：** 去掉不当「所述」，改为「所述母件设有／包括××」在本条首次给出；或  
   - **C. 布局调整：** 先写／合并能提供出处的上游从权，或增加组合依赖后再写本条。  

**正例：** 权2引入「顶板」；权6写「所述钢牛腿的顶板」且引用链为 6→5→1 → **失败**（顶板不在链上）→ 选 A 改挂能覆盖权2的路径，或选 B 在权6写「所述钢牛腿设有顶板，…」。  
**反例（禁止）：** 权4引入「侧板」；权7引权1却写「所述锚固箱的侧板」——出处断裂，不得交付。

**本条术语出处微表（交付必附，可一行多词）：**

| 所述词 | 首次出现权号 | 本条引用链是否覆盖 | 处置（通过／A／B／C） |
|--------|--------------|--------------------|------------------------|

### 3.3 「核心链一批后停」

- 仅当用户明示。  
- 「核心链」= 布局表中从权2出发的**连续串联依赖**各条（例如 2→3→4），**不含**平行引权1的独立改进点。  
- 一批交付后暂停，等待确认再写平行组。  
- 批次内每条仍须满足门禁；交付物中按条列出「已遵循 skill」；**每条仍须附术语出处微表**。

**禁止：** 未经明示一次写完权2～权10；平行独立改进点伪装成核心链批量倾倒；术语出处微表未过或结构「列名未展」仍请用户确认下一条。
---

## 第4步：复核 + 交接

1. 对权2～权10跑一遍：`权利要求形式合规性规范` + `权利要求引用结构检查`（可摘要表，不必长文重述全文）。  
2. **强制交付「依附编号／术语出处核对表」（全文）：** 按 3.2.1 算法对权2～权10逐条重核，合并为下表；**任一行「覆盖=否」且未标明已处置 → 不得宣布从权撰写完成**。  

| 权号 | 所述词（可多词合并） | 首次出现权号 | 引用链 | 覆盖 | 处置 |
|------|----------------------|--------------|--------|------|------|
| … | … | … | … | 是/否 | 通过／A／B／C＋说明 |

3. 结构类抽查：凡「包括／还包括」总列子件的从权，确认无「列名未展」；未展条退回第3步改写。  
4. 输出：从权全文合订（可复贴）+ 布局符合性 + **上述核对表** + 待同步说明书事项。  
5. 衔接：`质检总控` → `权利要求质检总控` / `说明书质检总控` → 回到案件主流程。

**交付物：** 合订稿 + 自检结论（含依附编号核对表）+ 衔接。  
**禁止：** 同轮说明书定稿；用「形式都过了」代替术语出处全文表。

## 与其他 skill 的关系

- 前置：`独权撰写`（第8步种子强制用）。  
- 方法层：门禁表所列各规范；其中 `部件命名优化总控` 为每条从权的强制前置，再由其分流调用具体命名 skill；布局与复核用 `权利要求引用结构检查`；**术语出处／依附编号以本节 3.2.1 为撰写期硬门禁**（与 `权利要求书质检` 维度二第1点同算法；抽出独立规范后改挂该规范）。  
- 后接：`质检总控`（→ 二级总控）、说明书各 skill。  
- 与第8步区别：第8步只要求「变劣点成组回退」示例级从权；本 skill 负责**默认 9 条的完整布局与逐条成稿**。
