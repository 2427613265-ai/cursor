# 从权撰写（布局 → 逐条写）

## 适用场景

- 已完成独权阶段（经 `独权撰写` 分流；执行层为 `结构类独权撰写` 或 `方法类独权撰写`）：至少有正式权1（第三版或**递交独权**）；若执行过第8步，已有从权回退组种子。
- 用户要系统写从属权利要求树，而不仅是质检或零散补一条。
- 典型触发：「写从权」「从权布局」「九条从权」「接着写权3」。

## 在总流程中的位置

```text
独权撰写分流 → 结构类/方法类独权撰写（含可选第8步变劣回退）→ 收束
        ↓
【本 skill】从权撰写：盘点 → 布局9条【确认】→ 逐条撰写 → 复核交接
        ↓
质检总控 → 权利要求质检总控（可选）→ 说明书撰写
```

## 默认案规（可改，须在布局步明示）

| 项 | 默认 |
|----|------|
| 从权条数 | **9 条**（权2～权10） |
| 已有权2 | **计入** 9 条之一，布局表须占用权2行；不重复新写除非用户要改权2 |
| 第8步回退组 | **强制作为布局种子**（须优先排入 9 条；排不下的进「暂缓/说明书」清单并说明） |
| 撰写节奏 | 默认**一条一确认**；用户明确说「写完核心链再停」时，允许一次交付**串联核心链**（通常权2所在链上的连续依赖从权）后暂停，平行组仍建议逐条或下一批再开 |

## 能力边界

- 产出：布局表 + 至多 9 条从权正文 + 复核摘要；不是说明书定稿，不是完整创造性评述。
- 不得编造交底/定稿未支持的特征；缺事实标待确认。
- 不替代 `质检总控` / `权利要求质检总控` / `权利要求书质检`；本 skill 末步做形式、引用结构与**依附编号／术语出处**自检（须交核对表），正式质检另开。

---

## 输出控制（plan 硬性）

必须 TodoWrite 同步；始终一个 `in_progress`；格式 `【第X步 / 共4步】`（第3步内再标 `权N · 第k/9条`）。

```text
第1步 输入锁定 + 改进点盘点（含第8/9步种子强制入库）
  ↓
第2步 从权布局表（默认9条）【须用户确认】
  ↓
第3步 逐条撰写（默认一条一确认；可「核心链一批后停」）
  ↓
第4步 形式合规 + 引用结构 + 依附编号核对表 + 交接
```

**禁止：** 未确认布局就写权3及以后；一次倾倒全部 9 条正文（核心链例外须用户明示）；布局默认条数悄悄改成非 9；术语出处核对失败仍交付下一条。

---

## 第1步：输入锁定 + 改进点盘点

1. 锁定权1全文（递交独权优先，否则第三版/用户指定）。  
2. 若已有权2，原样载入，标明「已占用 9 条中的 1 条」。  
3. **强制导入** 执行层独权撰写（`结构类独权撰写` / `方法类独权撰写`）第8步从权回退组（若未做第8步：从「定稿相对权1多出的特征」+ 交底优点/显著特点自行抽种子，并注明来源）。  
5. 补充交底未入权、可作从权的候选（诱鱼、双通道、细部结构等）。  
6. 输出「种子 / 候选 / 暂缓」三栏清单。

**交付物：** 权1（+已有权2）+ 改进点盘点表。  
**禁止：** 输出 9 条布局定稿表以外的从权正文长文。

---

## 第2步：布局（默认 9 条）【须确认】

做一张 **权2～权10** 布局表，列至少：

| 权号 | 引用 | 改进点 | 平行/串联 | 种子来源 | 次级问题/效果 |
|------|------|--------|-----------|----------|----------------|
| 2 | 1 | … | — | 已有/第8步 | … |
| … | … | … | … | … | … |
| 10 | … | … | … | … | … |

**布局规则：**

1. **独立改进点平行**引用同一合适基础（多为权1）；**依赖改进点串联**。  
2. 第8步种子**全部优先占位**；冲突时合并条目或说明为何落入暂缓。  
3. 已有权2占权2行；其后编号连续。  
5. 预检：避免「多项从权再被多项引用」的布局陷阱（详见形式合规 skill）。  
6. 条数：默认 9；用户要求增减须改表并再确认。

**交付物：** 9 行布局表 + 引用关系简图 + 暂缓清单。  
**禁止：** 未确认即进入第3步撰写。

## 第3步：逐条撰写 + 规范 skill 门禁（硬性）

### 3.0 门禁分层（准确调用，禁止凭记忆临场发挥）

门禁分三层。**判定标准与处置规则不降级**；分层只决定「本条是否必须全文 Read」。

| 层级 | 何时 | 要求 |
|------|------|------|
| **A. 硬必读** | 每条（或命中即强制） | **先 Read 对应 skill 全文**再写；本会话已读且规则未改可不重复读，交付须写明「已遵循」 |
| **B. 条件必读** | 本条特征命中下表 | 同 A：命中则先 Read 再写 |
| **C. 摘要自检** | 默认每条 | **不强制**全文 Read；交付时按摘要清单逐项勾选。有疑点、用户要举例、或摘要勾选失败 → 再 Read 该 skill（及其 `examples.md`，若有） |

硬性：
1. 禁止只写「参考某某规范」却不打开硬必读/条件必读文件、不按清单自检。  
2. 一条从权可同时触发多层多行（例如结构多部件 + 自定义名词 → 均须满足）。  
3. **摘要自检不等于可以违反主谓宾/指代/清楚性规则**——只是改为交付勾选，规则仍有效。

### 3.1 门禁表

#### A. 硬必读（每条或命中即全文 Read）

| 本条情况 | 必读并遵循 |
|----------|------------|
| **新增、改写或复用部件名称**（默认每条都做） | **`部件命名优化总控`**：每条先做总控命名审查；总控按分型分流（`部件命名具体优化`、口语改写、方位上位、就地定义，及按条件的清楚性/指代/结构类/功能性限定等）。新名须对照已入权部件名表做同名多物审查；冲突按 `部件命名具体优化` 规则五消歧 |
| **出现「所述××」**（含「所述A的B」中的子件名） | **`权利要求依附编号与术语出处规范`**：先 Read 再核；交付附术语出处微表；失败 A/B/C 三选一，禁止带病交付 |
| 结构类；或一次引入新部件（含「还包括」）；或部件有内部构成 | `结构类权利要求撰写`：先总列后展开；同级≠上下位；**总列后逐件展开，列名未展不得交付** |

#### B. 条件必读（特征命中才全文 Read）

| 本条情况 | 必读并遵循 |
|----------|------------|
| 含「用于…」「以便…」等功能/效果尾 | `功能性限定使用边界规范` |
| 左/右、前/后、上/下、上游/下游、迎水/背水、内外侧，或防洪/高水头等场景钉死语 | `方位与场景限定上位规范` |
| 交底口语名/非自明名（可疑需靠「其中」解释） | `交底口语名改写为自明结构名规范` |
| 自定义/非常识名词 | `自定义名词就地定义` |
| 方法/算法步骤、条件分支 | `条件判断语句规范`；`预设值与参数来源检查` |
| 参数/预设值先用后取风险 | `预设值与参数来源检查` |

#### C. 摘要自检（默认不强制全文 Read；交付须勾选）

| 范围 | 遵循（摘要勾选；疑点再 Read 全文/`examples.md`） |
|------|--------------------------------------------------|
| 任何一条 | `权利要求主谓宾结构规范`：动作/状态/关系有明确主语；并列动作主语变化已标出 |
| 任何一条 | `权利要求指代与参照清晰性规范`：优先「所述××」；多同类已消歧；方位词有参照物 |
| 写完一条/一批后的引用与格式 | `权利要求形式合规性规范`（微型核对：引用方向、多项套多项、主题名称） |
| 清楚性、孤岛、术语一致 | `权利要求清楚性与逻辑一致性规范`（摘要自检） |

**从权摘要自检五勾（C 层，缺一不得请确认下一条）：**
1. 每个动作/状态能指出主语（或合法承前省略）  
2. 无「该/其」造成多对象歧义；优先「所述+完整名称」  
3. 周向/轴向/平行/上下等若出现，文字内能回答「相对什么」  
4. 引用号 ＜ 本条；主题名称与独权一致；无多项套多项  
5. 无孤岛特征、无未定义的人为术语跳出来  

### 3.2 单条交付格式

`【从权 第k/9条 · 权利要求N】`  

- 正文  
- 对应布局表行（改进点一句话）  
- **已遵循 skill：** 区分「全文 Read（A/B）」与「摘要自检（C）」列出  
- **微型自检（须逐项勾过，缺一不得请确认下一条）：**  
  1. 引用方向：引用号 ＜ 本条编号；主题名称与独权一致；无多项套多项  
  2. **术语出处：** 已按 `权利要求依附编号与术语出处规范` 做完机械核对；失败项已三选一处置；交付物中附本条「术语出处微表」  
  3. 结构类：新部件已先总列；**已逐件展开**（每个总列子件至少一句位置/连接）；声明「已逐件展开：是／不适用」  
  4. 命名：本条新名已过 `部件命名优化总控`；无跨权同名多物未消歧  
  5. **C 层摘要五勾**（主谓宾 / 指代与参照 / 形式微核 / 清楚性）已全部勾过；失败项已回读全文并改正  
- 请确认后写下一条（或按用户指示开下一批）

### 3.2.1 术语出处／依附编号（执行独立规范）

**算法与处置以 `权利要求依附编号与术语出处规范` 为准**（先 Read 再核；禁止在本 skill 内另写一套冲突规则）。

本条交付时仍须：

1. 按该规范完成列词 → 溯源 → 覆盖判定；  
2. 失败则 A（改引用）／B（本条首次引入）／C（布局调整）三选一，禁止带病交付；  
3. 附该规范规定的「本条术语出处微表」。

### 3.3 「核心链一批后停」
- 仅当用户明示。  
- 「核心链」= 布局表中从权2出发的**连续串联依赖**各条（例如 2→3→4），**不含**平行引权1的独立改进点。  
- 一批交付后暂停，等待确认再写平行组。  
- 批次内每条仍须满足门禁；交付物中按条列出「已遵循 skill」；**每条仍须附术语出处微表**。

**禁止：** 未经明示一次写完权2～权10；平行独立改进点伪装成核心链批量倾倒；术语出处微表未过或结构「列名未展」仍请用户确认下一条。

---
## 第4步：复核 + 交接

1. 对权2～权10跑一遍：`权利要求形式合规性规范` + `权利要求引用结构检查`（可摘要表，不必长文重述全文）。  
2. **强制交付「依附编号／术语出处核对表」（全文）：** 按 `权利要求依附编号与术语出处规范` 对权2～权10逐条重核并合并为该规范规定的全文表；**任一行「覆盖=否」且未标明已处置 → 不得宣布从权撰写完成**。

3. 结构类抽查：凡「包括／还包括」总列子件的从权，确认无「列名未展」；未展条退回第3步改写。  
4. 输出：从权全文合订（可复贴）+ 布局符合性 + **上述核对表** + 待同步说明书事项。  
5. 衔接：`质检总控` → `权利要求质检总控` / `说明书质检总控` → 回到案件主流程。

**交付物：** 合订稿 + 自检结论（含依附编号核对表）+ 衔接。  
**禁止：** 同轮说明书定稿；用「形式都过了」代替术语出处全文表。

- [ ] 结构类从权「还包括」已按 `结构类权利要求撰写` 核对上下位（子件未与母件并列）；**总列子件已逐件展开，无列名未展**  
- [ ] 每条从权交付前已附术语出处微表；失败项已三选一处置，无带病交付

- [ ] 未一次倾倒全部 9 条（除非用户改条数策略且明示）  
- [ ] 末步完成形式、引用结构与依附编号自检并交接  

## 与其他 skill 的关系

- 前置：执行层独权撰写（第8步种子强制用；经 `独权撰写` 分流进入）。  
- 方法层：门禁分层（A 硬必读 / B 条件必读 / C 摘要自检）；`部件命名优化总控` 与依附编号为 A 层硬门禁；主谓宾/指代默认走 C 层摘要（疑点再读全文与 `examples.md`）；布局与复核用 `权利要求引用结构检查`。  
- 后接：`质检总控`（→ 二级总控）、说明书各 skill。  
- 与独权第9步区别：第9步只要求「变劣点成组回退」示例级从权；本 skill 负责**默认 9 条的完整布局与逐条成稿**。
