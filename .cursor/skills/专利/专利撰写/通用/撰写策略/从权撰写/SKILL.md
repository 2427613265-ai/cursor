# 从权撰写（核心组从权 → 可选次要权利要求组）

## 策略总览

```text
核心权利要求组 = 核心独立权利要求（权1）+ 其从权
  第1步  盘点（关键创新点强制入库）
  第2步  分层次布局默认9条【确认】     ← 必读 `从权分层次布置`
  第3步  逐条写（假想代入被引用权全文）
  第4步  核心组复核
次要权利要求组（核心组完成之后）
  第5步  按产业链 / 对应 / 单边判定并按需撰写  ← 必读 `次要权利要求组撰写`
```

权1一般最重要。次要独权与核心独权通常**不等同**；不得为告下游整机而改写权1主题。单边原则下各组维权地位可相当，但第一组仍决定后面写什么。

## 适用场景

- 已完成独权阶段（经 `独权撰写` 分流；执行层为 `结构类独权撰写` 或 `方法类独权撰写`）：至少有正式权1（**方法案默认第二版**；**结构案**为第三版或**递交独权**）；独权阶段下放组（及结构案若执行第8步则含变劣回退组）作为布局种子。
- 用户要系统写从属权利要求树，而不仅是质检或零散补一条。
- 核心组已完成、要写「其它权利要求组 / 产业链 / 对应装置 / 单边」→ 可直进第5步。
- 典型触发：「写从权」「从权布局」「九条从权」「接着写权3」「次要权利要求组」「产业链原则」。核心组已完成、只要写其它权利要求组 → 可直进第5步。

## 默认案规（可改，须在布局步明示）

| 项 | 默认 |
|----|------|
| 从权条数 | **9 条**（权2～权10） |
| 已有权2 | **计入** 9 条之一，布局表须占用权2行；不重复新写除非用户要改权2 |
| 独权下放组 | **强制作为布局种子**（须优先排入 9 条；排不下的进「暂缓/说明书」清单并说明） |
| 撰写节奏 | 默认**一条一确认**；用户明确说「写完核心链再停」时，允许一次交付**串联核心链**（通常权2所在链上的连续依赖从权）后暂停，平行组仍建议逐条或下一批再开 |

## 能力边界

- 产出：核心组布局 + 至多 9 条从权 + 第5步次要组判定（按需写次要独权；其次权**不**默认再铺 9 条）。不是说明书/创造性评述。
- 不得编造未支持特征。不替代 `质检总控`；核心组复核须交依附编号核对表。不替代结构案第8步变劣。

---

## 输出控制（plan 硬性）

必须 TodoWrite 同步；始终一个 `in_progress`；格式 `【第X步 / 共5步】`（第3步内再标 `权N · 第k/9条`）。

```text
第1步 输入锁定 + 改进点盘点（含关键创新点/独权下放组/变劣回退组强制入库）
  ↓
第2步 从权分层次布局表（默认9条）【须用户确认】
  ↓
第3步 逐条撰写（假想代入；默认一条一确认；可「核心链一批后停」）
  ↓
第4步 核心权利要求组复核（形式合规 + 引用结构 + 依附编号核对表）
  ↓
第5步 次要权利要求组【判定须确认；不需要则 cancelled】
```

**禁止：** 未确认布局就写权3及以后；一次倾倒全部 9 条正文（核心链例外须用户明示）；布局默认条数悄悄改成非 9；术语出处核对失败仍交付下一条；未完成核心组即写次要独权；将第4步与第5步合并。

---

## 第1步：输入锁定 + 改进点盘点

1. 锁定权1全文（结构案：递交独权优先，否则第三版/用户指定；方法案：第二版/用户指定）。  
2. 若已有权2，原样载入，标明「已占用 9 条中的 1 条」。  
3. **强制导入**独权阶段下放组：方法案为未入最小集的交底特征 + 第1步**关键创新点**中标注宜下放者 + 第5步相对第一版剔出；结构案另含第7步剔出，若执行了第8步则**强制导入变劣回退组**（若无上述种子：从「定稿相对权1多出的特征」+ 交底优点/显著特点自行抽种子，并注明来源）。**关键创新点须在盘点表单列**，供第2步逐层占位（见 `从权分层次布置`）。  
4. 补充交底未入权、可作从权的候选（诱鱼、双通道、细部结构等）。  
5. 输出「种子 / 候选 / 暂缓」三栏清单。

**交付物：** 权1（+已有权2）+ 改进点盘点表。  
**禁止：** 输出 9 条布局定稿表以外的从权正文长文。

---

## 第2步：分层次布局（默认 9 条）【须确认】

**必读** `从权分层次布置`（及按需其 `examples.md`）。关键创新点是从权重点，须**逐层**占位；独立改进仍平行引同一基础。

做一张 **权2～权10** 布局表，列至少：

| 权号 | 引用 | 改进点 | 平行/串联 | 关键创新点层次 | 种子来源 | 次级问题/效果 |
|------|------|--------|-----------|----------------|----------|----------------|
| 2 | 1 | … | — | 主干 / 再具体 / 否 | 已有/独权下放组 | … |
| … | … | … | … | … | … | … |
| 10 | … | … | … | … | … | … |

**布局规则：**

1. **独立改进点平行**引用同一合适基础（多为权1）；**依赖改进点串联**（`权利要求引用结构检查`）。  
2. 关键创新点分层占位**优先**；独权下放组（含结构案第8步变劣回退组，若有）**全部优先入库**；与分层骨架冲突时合并或进暂缓。  
3. 已有权2占权2行；其后编号连续。  
4. 预检：避免「多项从权再被多项引用」的布局陷阱（详见形式合规 skill）。  
5. 条数：默认 9；用户要求增减须改表并再确认。

**交付物：** 9 行布局表（含关键创新点层次列）+ 引用关系简图 + 暂缓清单。  
**禁止：** 未确认即进入第3步撰写；用边角特征占满 9 条却不落实关键创新点。

---

## 第3步：逐条撰写 + 规范 skill 门禁（硬性）

写每条前按 `从权分层次布置`：**假想代入**被引用权（及引用链至权1）全文，把本条当成一个独立技术方案来组织语言；引用只是简化写法。

### 3.0 门禁分层（准确调用，禁止凭记忆临场发挥）

门禁分三层。**判定标准与处置规则不降级**；分层只决定「本条是否必须全文 Read」。

| 层级 | 何时 | 要求 |
|------|------|------|
| **A. 硬必读** | 每条（或命中即强制） | **先 Read 对应 skill 全文**再写；本会话已读且规则未改可不重复读，交付须写明「已遵循」 |
| **B. 条件必读** | 本条特征命中下表 | 同 A：命中则先 Read 再写 |
| **C. 摘要自检** | 默认每条 | **不强制**全文 Read；交付时按摘要清单逐项勾选。有疑点、用户要举例、或摘要勾选失败 → 再 Read 该 skill（及其 `examples.md`，若有） |

硬性：
1. 禁止只写「参考某某规范」却不打开硬必读/条件必读文件、不按清单自检。  
2. 一条从权可同时触发多层多行（例如结构多部件 + 自定义名词 → 均须满足）。  
3. **摘要自检不等于可以违反主谓宾/指代/清楚性规则**——只是改为交付勾选，规则仍有效。

### 3.1 门禁表

#### A. 硬必读（每条或命中即全文 Read）

| 本条情况 | 必读并遵循 |
|----------|------------|
| **新增、改写或复用部件名称**（默认每条都做） | **`部件命名优化总控`**：每条先做总控命名审查；总控按分型分流（`部件命名具体优化`、口语改写、方位上位、就地定义，及按条件的清楚性/指代/结构类/功能性限定等）。新名须对照已入权部件名表做同名多物审查；冲突按 `部件命名具体优化` 规则五消歧 |
| **出现「所述××」**（含「所述A的B」中的子件名） | **`权利要求依附编号与术语出处规范`**：先 Read 再核；交付附术语出处微表；失败 A/B/C 三选一，禁止带病交付 |
| 结构类；或一次引入新部件（含「还包括」）；或部件有内部构成 | `结构类权利要求撰写`：先总列后展开；同级≠上下位；**总列后逐件展开，列名未展不得交付** |

#### B. 条件必读（特征命中才全文 Read）

| 本条情况 | 必读并遵循 |
|----------|------------|
| 含「用于…」「以便…」等功能/效果尾 | `功能性限定使用边界规范` |
| 左/右、前/后、上/下、上游/下游、迎水/背水、内外侧，或防洪/高水头等场景钉死语 | `方位与场景限定上位规范` |
| 交底口语名/非自明名（可疑需靠「其中」解释） | `交底口语名改写为自明结构名规范` |
| 自定义/非常识名词 | `自定义名词就地定义` |
| 方法/算法步骤细化、承接独权下放组、条件分支 | `方法类权利要求专有细则`；`条件判断语句规范`；`预设值与参数来源检查` |
| 参数/预设值先用后取风险 | `预设值与参数来源检查` |

**与命名总控的关系：** A 层总控只审查**部件名称**，并按 `部件命名/README.md` 流水线分流。本会话若已因总控读过某叶，不必重复全文 Read。但下列情形即使名称已过总控，仍须按本表 B 层读：方位/场景语出现在**句子限定**（如「设置于左侧」）；布置口语出现在步骤/关系表述而非部件名；非公知参数（如「调节比」）需要就地定义。

#### C. 摘要自检（默认不强制全文 Read；交付须勾选）

| 范围 | 遵循（摘要勾选；疑点再 Read 全文/`examples.md`） |
|------|--------------------------------------------------|
| 任何一条 | `权利要求主谓宾结构规范`：动作/状态/关系有明确主语；并列动作主语变化已标出 |
| 任何一条 | `权利要求指代与参照清晰性规范`：优先「所述××」；多同类已消歧；方位词有参照物 |
| 写完一条/一批后的引用与格式 | `权利要求形式合规性规范`（微型核对：引用方向、多项套多项、主题名称） |
| 清楚性、孤岛、术语一致 | `权利要求清楚性与逻辑一致性规范`（摘要自检） |

**从权摘要自检五勾（C 层，缺一不得请确认下一条）：**
1. 每个动作/状态能指出主语（或合法承前省略）  
2. 无「该/其」造成多对象歧义；优先「所述+完整名称」  
3. 周向/轴向/平行/上下等若出现，文字内能回答「相对什么」  
4. 引用号 ＜ 本条；主题名称与独权一致；无多项套多项  
5. 无孤岛特征、无未定义的人为术语跳出来  

### 3.2 单条交付格式

`【从权 第k/9条 · 权利要求N】`  

- 正文  
- 对应布局表行（改进点一句话）  
- **已遵循 skill：** 区分「全文 Read（A/B）」与「摘要自检（C）」列出  
- **微型自检（须逐项勾过，缺一不得请确认下一条）：**  
  1. 引用方向：引用号 ＜ 本条编号；主题名称与独权一致；无多项套多项  
  2. **术语出处：** 已按 `权利要求依附编号与术语出处规范` 做完机械核对；失败项已三选一处置；交付物中附本条「术语出处微表」  
  3. 结构类：新部件已先总列；**已逐件展开**（每个总列子件至少一句位置/连接）；声明「已逐件展开：是／不适用」  
  4. 命名：本条新名已过 `部件命名优化总控`；无跨权同名多物未消歧  
  5. **C 层摘要五勾**（主谓宾 / 指代与参照 / 形式微核 / 清楚性）已全部勾过；失败项已回读全文并改正  
  6. **假想代入：** 已把被引用权全文代入后审视本条；拼起来仍可实施、不缺前提、不矛盾（`从权分层次布置`）  
- 请确认后写下一条（或按用户指示开下一批）

### 3.2.1 术语出处／依附编号（执行独立规范）

**算法与处置以 `权利要求依附编号与术语出处规范` 为准**（先 Read 再核；禁止在本 skill 内另写一套冲突规则）。

本条交付时仍须：

1. 按该规范完成列词 → 溯源 → 覆盖判定；  
2. 失败则 A（改引用）／B（本条首次引入）／C（布局调整）三选一，禁止带病交付；  
3. 附该规范规定的「本条术语出处微表」。

### 3.3 「核心链一批后停」
- 仅当用户明示。  
- 「核心链」= 布局表中从权2出发的**连续串联依赖**各条（例如 2→3→4），**不含**平行引权1的独立改进点。  
- 一批交付后暂停，等待确认再写平行组。  
- 批次内每条仍须满足门禁；交付物中按条列出「已遵循 skill」；**每条仍须附术语出处微表**。

**禁止：** 未经明示一次写完权2～权10；平行独立改进点伪装成核心链批量倾倒；术语出处微表未过或结构「列名未展」仍请用户确认下一条。

## 第4步：核心权利要求组复核

1. 对权2～权10跑一遍：`权利要求形式合规性规范` + `权利要求引用结构检查`（可摘要表，不必长文重述全文）。  
2. **强制交付「依附编号／术语出处核对表」（全文）：** 按 `权利要求依附编号与术语出处规范` 对权2～权10逐条重核并合并为该规范规定的全文表；**任一行「覆盖=否」且未标明已处置 → 不得宣布核心组完成、不得进入第5步**。

3. 结构类抽查：凡「包括／还包括」总列子件的从权，确认无「列名未展」；未展条退回第3步改写。  
4. 输出：核心组从权全文合订（可复贴）+ 布局符合性（含关键创新点是否逐层落实）+ **上述核对表** + 待同步说明书事项。  
5. 预告第5步：次要权利要求组判定；**禁止**本步同批写次要独权。  
6. 第5步结束后再衔接：`质检总控` → `权利要求质检总控` / `说明书质检总控` → 回到案件主流程。

**交付物：** 核心组合订稿 + 自检结论（含依附编号核对表）。  
**禁止：** 同轮说明书定稿；用「形式都过了」代替术语出处全文表；未复核完核心组即开次要组正文。

---

## 第5步：次要权利要求组

**必读** `次要权利要求组撰写`（及按需其 `examples.md`）。核心组（权1+其从权）已完成后，才根据**产业链原则、对应原则、单边权利要求原则**判定是否撰写其它权利要求组。

- 须先交付判定（用哪些原则 / 均不需要 + 理由）；**须用户确认**后才写次要独权。  
- 不需要 → 写明理由；本步 `cancelled`；衔接质检/说明书。  
- 需要 → 按该细则：组布局【确认】→ 逐组先写次要**独立**权利要求，再写其从权（门禁同第3步；条数须明示，**不**默认再铺 9 条）。  
- **禁止**为告下游整机而改写权1主题（权1仍用独权阶段审定后的主题）。

**交付物：** 该细则规定的第5步正文。  
**禁止：** 核心组未完成即做本步；无涉外需求把方法+装置对应组当中国案必做；同批倾倒全部次要组；用本步代替结构案第8步变劣。
