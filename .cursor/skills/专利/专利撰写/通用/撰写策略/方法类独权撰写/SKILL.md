# 方法类独权撰写（最小特征集两版策略 · 服务于方法/算法流程案）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  术语先释义 + 外行读懂 + 懂后再体检 + 问题候选
        ↓
第1步  确定核心区别技术特征与关键创新点
        ↓
第2步  按核心区别组成最小技术特征集（完整技术方案；不考虑先前技术问题）
        ↓
第3步  根据已确认的最小技术特征集撰写第一版独立权利要求
        ↓
第4步  根据第3步已写成的第一版独立权利要求，重新核定其所对应的技术问题
        ↓
第5步  在新问题下审视第一版是否合适，进一步删减/上位 → 第二版独权
        ↓
第6步  收束为正式独权工作稿（默认=第二版）
```

**两版要求（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求 |
|------|----------------|----------|
| **第一版** | **本版不预先锚定技术问题** | 只落实第2步已确认的**最小技术特征集**；方案完整可实施；允许沿用交底原名；**禁止**把交底实施例细节整份灌进独权 |
| **第二版** | 第4步**重新核定后**的技术问题 | 在新问题下审视第一版是否仍合适；特征可进一步删减、上位；**不得含非必要技术特征**；本案唯一一次命名优化 |

撰写方法（质量闸门、步骤铺陈、命名规则等）**服务于上述策略**，细则经 `方法类权利要求具体撰写规则总控` 挂接，不得颠倒成「先抠字眼、后定策略」。

**独权阶段不单列：** 「交底声称技术问题」「解题技术特征清单」。交底发明目的、背景缺陷、理解 skill 问题候选只作对照，不作为独立交付步，也不是最小集入集标准。

## 适用场景与触发

- **客体：** 方法类 / 算法·数据处理流程类独立权利要求（「一种××方法」；以步骤、输入输出变换、判断与循环控制为主）。
- **入口：** 须经 `独权撰写` 判定为方法案或算法案后转入本 skill；已点名「方法类独权 / 算法独权」时可直进。
- 已完成 `交底书技术方案理解`（含术语词典、外行总故事、懂后体检与问题候选）；进入**阶段二**（本 skill 自建 2.1～2.6 plan）。
- 触发：「写方法类独权」「算法独权」「核心区别」「最小特征集」「重新核定技术问题」「第二版」等。
- **不适用：** 纯结构/装置独权（走 `结构类独权撰写`）；**禁止**对本案套用「其特征在于后先总列部件再展开」。方法案**无第三版、无再上位、无递交变劣**；第二版即为正式工作稿默认稿。

## 能力边界

- 产出：核心区别（含一句话）与关键创新点、最小特征集、两版独权工作稿 + 一轮重新核定说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新步骤/数据/参数；缺事实标「待确认」。
- **正文具体写法**经 `方法类权利要求具体撰写规则总控` 挂接 `方法类权利要求专有细则` / 横切；本文件不粘贴细则全文。
- 本 skill 是**方法/算法案**独权策略执行层；**分流入口**是 `独权撰写`；**正文细则入口**是上述总控。

## 输出控制（plan 硬性）

禁止一次输出「核心区别+最小集+两版独权」。必须用 plan/待办同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

### 固定 plan（共6步 = 总览 2.1～2.6）

```text
第1步 确定核心区别技术特征与关键创新点【须用户确认】
  ↓
第2步 组成最小技术特征集（完整技术方案；不考虑先前技术问题）【须用户确认】
  ↓
第3步 根据已确认最小集撰写第一版独立权利要求
  ↓
第4步 根据第3步第一版独立权利要求，重新核定其所对应的技术问题【须用户确认】
  ↓
第5步 在新问题下审视第一版，进一步删减/上位 → 第二版独权
  ↓
第6步 正式工作稿收束 + 两版对照摘要 + 交接
```

- 第1步同步建立 2.1～2.6 plan，**不**单列「只建 plan」的步骤。  
- **禁止**将第1步与第2步合并（未确认核心区别一句话与关键创新点不得组成最小集）。  
- **禁止**将第2步与第3步合并（未确认最小集不得写第一版独权）。  
- **禁止**将第3步与第4步合并（未写出第一版独权全文，不得重新核定问题）。  
- **禁止**将第4步与第5步合并（未确认新核定问题不得写第二版）。  
- 第6步正式稿默认=第二版。  
- 未完成理解不得硬写第一版（用户明示跳过理解除外）。

## 技术问题只在重新核定步写出（禁止抢活）

独权阶段**不**再单列「交底声称问题」或「解题特征清单」。交底发明目的、背景「然而」后缺陷、理解 skill 问题候选**只作对照**，不是独立交付物，也不是第一版独权的预先锚定问题。

| | **理解/交底侧（对照）** | **第4步 重新核定问题** |
|--|------------------------|------------------------|
| **时机** | 阶段一或读交底时 | **第3步第一版独立权利要求全文已交付之后** |
| **输入对象** | 交底书 / 理解 skill 问题候选 | **仅第3步已写成的第一版独立权利要求**（最小特征集落成的权1） |
| **一句话** | 交底自己怎么说痛点 | 这份第一版独权**实际能稳定解决**的是哪一层问题 |
| **改写** | 不在独权阶段单列、不改写成独权锚定问题 | **要核定**；方法案主目标是扩围（去场景/工具/参数/效果钉死） |
| **服务对象** | 第1步定核心区别时可对照；不作入集标准 | 第5步第二版：进一步删减/上位 |
| **方法案默认** | 不单列摘录 | **几乎总要做**，以扩围为主；不以「更好补强创造性」为主取舍 |

**禁止互相抢活：**

- 第1～3步不得写成重新核定定稿，不得预写第二版锚定问题。  
- 交底声称问题**不是**第2步入集标准，也**不是**第一版独权的预先锚定问题。  
- 第4步**不得**再做一遍「交底声称了什么」，**不得**只拿第1步核心区别清单、第2步最小集或理解 skill 问题候选空推；**唯一反推对象是第3步已写成的独立权利要求**。  
- 第3步独权全文未交付，不得进入第4步。  
- 第4步不预写第二版独权全文。

## 重新核定技术问题：怎么考虑（第4步专用 · 方法案）

### 方法案前提（硬性口径）

**输入对象（硬性）：** 第4步只根据**第3步已经构造并交付的第一版独立权利要求**重新核定技术问题。交底发明目的、理解 skill 候选、第1步核心区别清单、第2步最小集只作对照，**不得**代替第一版独权成为反推起点。未写出第一版独权全文，本步不成立。

方法/算法流程案的创造性**通常已经够**；第4步重新核定**默认不是为了「找创造性落点 / 为补强留抓手」**，而是为了：

> **对着这份第一版独权，把它实际能稳定解决的问题定到更合适的层级，使第二版能丢掉交底钉死的场景、工具、参数与效果堆砌，从而获得更大、仍可实施的保护范围。**

重新核定**不是**把交底书问题换个说法，也**不是**把技术方案手段写进问题里。交付第4步时，必须先点明「反推对象=第3步第一版独权」，再写清「本次核定如何服务于扩围」。

### 操作方法

写「核定考虑」时用下列方法；不另设三点主轴，也不按点1/2/3分述。

| 操作方法 | 怎么用 |
|----------|--------|
| **交底书问题盘点** | 分清核心痛点 vs 附带效果/宣传语；标出交底发明目的/背景里绑死场景、工具名、指标堆砌的句子。附带/宣传不得当成重新核定后的主问题。此栏是对照，不是本步起点。 |
| **特征反推（为扩围）** | **对着第3步第一版独权全文**反推：这份权1实际稳定消除哪一层不良后果；删掉其中仍像实施例钉死的表述后，还能撑住哪一层更上位问题。 |
| **手段不进问题** | 问题不写算法名、软件名、具体参数等手段；手段留在特征里，问题只写后果/需求缺口。 |
| **范围落点（扩围主检）** | **过窄**→第二版被迫保留非必要路径；**过宽**→假宽或无可实施依托。目标：第二版能明显变宽，且仍可实施。再宽即变成「提高效率/更加智能」等空问题，或第二版必要步骤已解不了，则停在当前层级。 |
| **用户/布局侧重** | 用户要的保护重心、竞品规避面加权；不作唯一依据。 |
| **可检验** | 假定第二版只剩必要步骤：能否完整解决拟核定问题？能 → 扩围成功；不能 → 问题过大或骨架不足，回调问题层级或回到第一版/交底补事实。 |

### 输出格式

- **反推对象**：复贴或明确引用第3步第一版独立权利要求（可摘要，但须能对上全文）  
- **重新核定后的技术问题**（一句或两句定稿候选）  
- **核定考虑**（先写明「方法案以扩围为主、反推对象=第一版独权」；再按上表操作方法写清依据，不按三点分述）  
- **与交底书问题表述的差异**（保留/收窄钉死语/放宽层级——重点写清**扩了哪一层范围**；对照交底原文或理解候选，不是本步起点）  
- **对第二版的预期**（一句：拟删/概括哪些非必要路径，因问题已不再绑死它们）  
- 标注「**待确认：重新核定后的技术问题**」；确认后再写第二版。

## 撰写方法总则（服务于两版策略 · 细则外置）

写任一版**独权正文**前：先 Read `方法类权利要求具体撰写规则总控`，再按其挂接表加载 `方法类权利要求专有细则`（按分节何时用）与横切。下表只保留策略级要点，**不**替代专有细则。

### 最小技术特征集与第一版（第2/3步 · 短引）

口径与操作**以 `最小技术特征集与第一版独权` 为准**（一句话≠完整方案；抽出并清楚化 → 补必不可少支撑 → 连缀为第一版；同物同名）。方法案组集时重点核步骤顺序与 I/O 咬合；路径不宜进最小集。技术问题留到第4步。

### 正文质量要点（各版共通 · 短引）

| 要点 | 细则落点（经总控） |
|------|-------------------|
| 拆步与I/O、步骤编号、路径/不变量、闭环、成组下放、命名时机 | `方法类权利要求专有细则`（按该页「分节何时用」） |
| 条件句 / 预设来源 / 主谓宾 / 指代 / 就地定义 / 清楚性 | 总控「通用横切」各 skill |
| **禁止**结构「先总列后展开」 | 总控「明确不挂」 |

> 以 `方法类权利要求专有细则` 为准，本页只保留策略级短引，不平行维护长细则。

### 命名时机（方法案硬性 · 只在第二版优化）

| 版本 | 命名动作 | 说明 |
|------|----------|------|
| **第一版** | **不走命名总控** | 沿用交底原名，**以第2步已确认最小集用名为准**（组集时的清楚化不是本表「命名优化」） |
| **第二版** | **唯一一次命名优化** | 经总控 → `方法类权利要求专有细则` 第六节 → `部件命名优化总控`；对照表确认前不得写第二版正文 |

方法案无第三版；第二版确认名即全书基准。

### 第二版加码（硬性 · 策略）

- 锚定=第4步重新核定后的技术问题。  
- **完成本案唯一一次命名优化**（见上表）。  
- 先问：第一版在新问题下是否仍合适（过窄/过宽/偏题）？再问：特征能否进一步删减、上位？  
- 去非必要：经总控挂 `独立权利要求必要技术特征检查` + `方法类权利要求专有细则` 第三节（路径与不变量）；删后仍可实施，保留最小区别骨架。  
- **非区别输入**：宜「获得/获取××」概括，具体获得步骤进从权（见 `方法类权利要求专有细则` 第三节）；区别性获得不得误省。

### 类型铺陈（短引）

| 类型 | 要点 | 细则 |
|------|------|------|
| 方法/数据处理、算法流程 | 有序步骤；产物清楚；条件与参数合规 | `方法类权利要求专有细则` 第一、二节 |
| 调控闭环 | 感知→（可选判定）→中间调控量→执行 | `方法类权利要求专有细则` 第四节（仅闭环案） |
| 结构装置 | **不走本 skill** | `结构类独权撰写` |

### 成组下放（短引）

第1步关键创新点中标注宜下放者、第2步未纳入最小集的特征、以及第5步从第一版剔出的路径/细分支，宜按独权步骤成组 → `方法类权利要求专有细则` 第五节（经总控）；禁止把当前版最小区别骨架整组藏进从权。

## 第1步：确定核心区别技术特征与关键创新点

标明阶段二（方法/算法案）；**由本 skill 建立** 2.1～2.6 plan；同步 todo。

**必读** `核心区别技术特征确定`（及按需其 `examples.md`），按该页完成两件交付后，才可进入第2步：

1. **核心区别的一句话描述**（顶天：相对现有/惯常的最大合理边界，不是交底实施例整份）；  
2. **关键创新点**（立地：优选实施例里最具创造性的点，默认作从权保底，不整份灌进独权）。

- **优先引用**理解 skill 的「创新点 vs 惯常剥离表」；口径冲突须明示取舍。  
- 方法案可兼用 `方法类权利要求专有细则` 第三节三问，把路径与不变量分开；本步仍只定①②，不写独权、不组成最小集。  
- 标注「**待确认：核心区别一句话 + 关键创新点**」。  
- **须用户确认**后才能进入第2步。

**交付物：** plan + 该细则规定的第1步正文（一句话、边界三问、展开示意、关键创新点、非核心分流）。  
**禁止：** 同批输出最小集定稿或第一版独权全文；没有一句话只堆步骤；把关键创新点整份当独权；为顶天编造交底无启示的新手段。

## 第2步：组成最小技术特征集【须确认】

**必读** `最小技术特征集与第一版独权`（及按需其 `examples.md`）。本步**只组集、不写独权正文**（允许心里试连缀，不得当交付）。
