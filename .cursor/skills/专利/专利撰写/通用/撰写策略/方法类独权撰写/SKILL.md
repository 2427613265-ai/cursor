# 方法类独权撰写（三版递进策略 · 服务于方法/算法流程案）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  术语先释义 + 外行读懂 + 懂后再体检 + 问题候选
        ↓
第一版独权   按「交底书中界定的技术问题」忠实转化技术方案
        ↓
重新界定技术问题   （方法案主目标：扩保护范围；须明示怎么考虑、为何这样定）
        ↓
第二版独权   对准新界定问题；不得包含非必要技术特征
        ↓
再上位技术问题
        ↓
第三版独权   要求最高：逻辑与表达清楚 + 保护范围最大
              （步骤/术语/参数上位优化，如下文方法）
        ↓
【可选】递交独权变劣与从权回退   （定稿再放宽一档作递交权1；改进进从权）
        ↓
收束为正式独权工作稿
```

**三版要求依次提高（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求（递进） |
|------|----------------|------------------|
| **第一版** | 交底书已界定/声称的技术问题 | 忠实覆盖交底方案；完整可读；允许暂留实施例级细节 |
| **第二版** | **重新界定后**的技术问题（方法案多为**扩围后的问题层级**） | 特征与问题精准对应；**不得含非必要技术特征**；方案完整可实施 |
| **第三版** | **再上位后**的技术问题 | 在第二版「无非必要特征」之上，进一步：**逻辑清楚、表达清楚、保护范围最大**（去工具/参数钉死、步骤粒度上位等——按案情权衡） |

撰写方法（质量闸门、步骤铺陈、命名规则等）**服务于上述策略**，不得颠倒成「先抠字眼、后定策略」。

## 适用场景与触发

- **客体：** 方法类 / 算法·数据处理流程类独立权利要求（「一种××方法」；以步骤、输入输出变换、判断与循环控制为主）。
- **入口：** 须经 `独权撰写` 判定为方法案或算法案后转入本 skill；已点名「方法类独权 / 算法独权」时可直进。
- 已完成 `交底书技术方案理解`（含术语词典、外行总故事、懂后体检与问题候选）；进入**阶段二**（本 skill 自建 2.1～2.8 plan）。
- 触发：「写方法类独权」「算法独权三版」「按交底问题写第一版」「重新界定技术问题」「第二版」「第三版」「再上位」等。
- **不适用：** 纯结构/装置独权（走 `结构类独权撰写`）；**禁止**对本案套用「其特征在于后先总列部件再展开」。

## 能力边界

- 产出三版独权工作稿链 + 两轮技术问题界定说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新步骤/数据/参数；缺事实标「待确认」。
- 必要特征逐条细则调用 `独立权利要求必要技术特征检查`；条件句 / 预设值 / 主谓宾等按需 Read，不在本文件全文粘贴。
- 本 skill 是**方法/算法案**独权三版正文与变劣的执行层；**分流入口**是 `独权撰写`，勿与入口混淆。

## 输出控制（plan 硬性）

禁止一次输出「第一版+重新界定+第二版+第三版」。必须用 plan/待办同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

### 固定 plan（共8步 = 总览 2.1～2.8）

```text
第1步 建立阶段二 plan（2.1～2.8）+ 固定「交底书界定的技术问题」
  ↓
第2步 第一版独权（按交底书界定的技术问题）
  ↓
第3步 重新界定技术问题（结论 + 界定时的考虑说明）【须用户确认】
  ↓
第4步 第二版独权（对准新问题；无非必要技术特征）
  ↓
第5步 再上位技术问题（结论 + 与第二版问题分层）【须用户确认】
  ↓
第6步 第三版独权（清楚 + 范围最大；步骤/参数上位；**不再优化命名**）
  ↓
第7步 【可选】递交独权变劣与从权回退（定稿再放宽作递交权1）
  ↓
第8步 正式工作稿收束 + 三版/递交对照摘要 + 交接
```

- 第4步完成后，第5/6步基线=第二版。  
- **禁止**将第5步与第6步合并交付；**须**用户确认再上位问题后，方可写第三版。  
- 第7步执行 → 内嵌 7.1～7.4；返回后第8步正式稿默认=递交独权。  
- 第7步跳过 → 第8步正式稿默认=第三版；2.7=`cancelled`。  
- 未完成理解不得硬写第一版（用户明示跳过理解除外）。

## 重新界定技术问题：怎么考虑（第3步专用方法 · 方法案）

### 方法案前提（硬性口径）

方法/算法流程案的创造性**通常已经够**；第3步重新界定**默认不是为了「找创造性落点 / 为补强留抓手」**，而是为了：

> **把技术问题定到更合适的层级，使第二版能丢掉交底钉死的场景、工具、参数与效果堆砌，从而获得更大、仍可实施的保护范围。**

重新界定**不是**把交底书问题换个说法，也**不是**把技术方案手段写进问题里。交付第3步时，必须写清「本次界定如何服务于扩围」。

结构为：**三点综合权衡（主轴）** + **六点操作方法（融进三点）**。

### 一、三点综合权衡（主轴，三点都要写到）

1. **最核心的问题（仍要）** — 若不解决则方案整体失败或痛点最尖锐的那一个（或极少数）；避免把附带效果/宣传语当成主问题。  
2. **高贡献手段链所能稳定支撑的更上位问题** — 先识别交底里真正做功的步骤骨架，再反推它消除的不良后果可以上提到哪一层；**落点应尽量宽到仍被该骨架撑住**，以便第二版只留必要步骤。  
3. **扩围上限（刹车）** — 再宽一步是否变成假宽空问题（「提高效率/更加智能」等）、是否第二版必要步骤仍解得了、是否还写得清楚可实施；触及上限则停在点2的层级，不要为扩围而空。

**综合规则：**  
- 默认以**点2（扩围落点）**为纲，点1校核「没跑偏主痛点」，点3校核「没有假宽」；  
- 方法案**不以**「哪个问题更好补强创造性」作为主取舍；若用户明示要收窄保授权，从其指示并写明。  
- 三点同层 → 直接定主问题；冲突 → 说明取舍。

### 二、六点操作方法（融进三点）

| 操作方法 | 主要服务 | 怎么用 |
|----------|----------|--------|
| **交底书问题盘点** | 点1 | 分清核心痛点 vs 附带效果/宣传语；标出交底问题里绑死场景、工具名、指标堆砌的句子 |
| **特征反推（为扩围）** | 点2 | 由第一版核心步骤反推：删掉实施例钉死后，这套步骤还能稳定消除哪一层更上位的不良后果 |
| **手段不进问题** | 三点共用 | 问题不写算法名、软件名、具体参数等手段；手段留在特征里，问题只写后果/需求缺口 |
| **范围落点（扩围主检）** | 点2/3 | **过窄**→第二版被迫保留非必要路径；**过宽**→假宽或无可实施依托。目标：第二版能明显变宽，且仍可实施 |
| **用户/布局侧重** | 三点加权 | 用户要的保护重心、竞品规避面加权；不作唯一依据 |
| **可检验** | 收束 | 假定第二版只剩必要步骤：能否完整解决拟界定问题？能 → 扩围成功；不能 → 问题过大或骨架不足，回调点2/3 |

### 三、输出格式

- **重新界定后的技术问题**（一句或两句定稿候选）  
- **界定考虑**（先写明「方法案以扩围为主」；再按点1/2/3分述；附操作检视）  
- **与交底书原问题的差异**（保留/收窄钉死语/放宽层级——重点写清**扩了哪一层范围**）  
- **对第二版的预期**（一句：拟删/概括哪些非必要路径，因问题已不再绑死它们）  
- 标注「**待确认：重新界定后的技术问题**」；确认后再写第二版。

## 撰写方法总则（服务于三版策略）

### 方法一：独权正文质量闸门（按版本加码）

**各版共通：**

1. **按产物拆步**：主步骤一般约 3～7 步；按「得到什么」切分，不按代码行/仿真次数/迭代轮次拆碎；循环/增量过程默认写成**一步**（用控制流写切换与终止）。  
2. **每步 I/O 可核对**：读者能看出本步基于什么、得到什么；步间输出与下一步输入咬合；禁止空挂「获取了却本步不用」的操作数（应挪到真正使用的步骤）。  
3. **主语/执行者清楚**：全文统一执行主体（如计算机执行的方法）或逐步写明谁获取/谁判断/谁输出。  
4. **条件句**遵循 `条件判断语句规范`；**预设值/阈值**先有来源（`预设值与参数来源检查`）。  
5. **自定义概念**优先前置白话说清（`自定义名词就地定义`）；**不**等于每版都做命名优化。  
6. **禁止**结构类「先总列部件再展开」句式冒充方法独权。

### 命名时机（方法案硬性 · 只在第二版优化）

| 版本 | 命名动作 | 说明 |
|------|----------|------|
| **第一版** | **不优化命名** | 一律沿用交底书原名（含口语/缩略/工具名）；可不交付命名对照表；允许「沿用交底原名」一句声明后直接写正文 |
| **第二版** | **唯一一次命名优化** | 必须触发 `部件命名优化总控`，交付命名对照表（关键名至少两档 + 推荐采用名 + 范围影响）；**用户确认前不得写第二版正文**；此后全书以本版确认名为准 |
| **第三版** | **不再优化命名** | 沿用第二版已确认名称；本版只做步骤/参数/表述扩围与清楚性，**禁止**再开命名对照表或改名（除非用户明示改名，并记入交付说明） |

**第三版加码（硬性）：**

- 在第二版「无非必要」上追求**保护范围最大**且**逻辑、表达清楚**。  
- **不重做命名优化**（见上表）；术语与第二版确认名保持一致。  
- 去钉死：具体模型结构、训练超参、实施例管网规模等能上位则上位或进从权（属路径/参数，不是「再起一轮命名表」）。  
- 步骤表述与再上位问题同级；不得抽空区别骨架，不得写成「智能分析并优化」类假宽空词。  
- 仍不得削掉最小创造性/区别骨架。

**第二版加码（硬性）：**

- 锚定=重新界定后的技术问题。  
- **完成本案唯一一次命名优化**（见「命名时机」）。  
- 逐特征/逐步反问：去掉或改宽后该问题是否仍解决？能 → 删/概括/下放（`独立权利要求必要技术特征检查`）。  
- 重点清理：非必要工具名、软件名、层数/维数、具体相似度度量、聚类算法名、抽样数值范围、冗余检测周期等**实现路径**（除非恰为区别点）。  
- 删后流程须仍完整可实施；保留最小区别骨架（关键变换准则与控制逻辑）。

### 方法二：类型铺陈（本 skill 以方法/算法为主）

| 类型 | 要点 |
|------|------|
| 方法/数据处理（主路径） | 有序步骤；每步产物清楚；条件用规范判断句；参数有来源 |
| 算法流程 | 同方法主路径；数据/特征先获取或算得再使用；模块或阶段边界清楚 |
| 调控闭环 | 感知 →（可选判定）→ **中间调控量** → 按偏差/准则执行；细则见交底；公式进从权 |
| 结构装置 | **不走本 skill** → `结构类独权撰写` |

### 方法三：成组下放

从第一版→第二版、第二版→第三版剔出的关联路径（工具、参数、细分支），宜**按独权步骤成组**对应次级问题/效果，供从权与说明书；禁止把当前版本最小区别骨架整组藏进从权。

## 第1步：建立阶段二 plan + 固定交底书技术问题

1. 标明阶段二（方法/算法案）；**由本 skill 建立** 2.1～2.8 plan；同步 todo。  
2. 摘录并固定「交底书界定的技术问题」（标注来源）；不作重新界定。  
3. 预告下一步写第一版。

**交付物：** plan + 交底书技术问题。  
**禁止：** 输出独权全文；输出重新界定定稿。

---

## 第2步：第一版独权

按交底书界定的技术问题，忠实转化为完整方法独立权利要求。

- 允许暂留实施例细节（具体算法名、参数范围等）。  
- **命名：不优化** — 沿用交底原名；**不**触发命名总控、**不**交付命名对照表（可声明「本版沿用交底原名」）。  
- 标注「**第一版独权（交底书技术问题 · 原名未优化）**」。

**禁止：** 同批重新界定；同批第二/三版；本版擅自改名优化。

---

## 第3步：重新界定技术问题

按上文「怎么考虑（方法案）」输出：以**扩保护范围**为主的结论 + 界定考虑（含对第二版拟删非必要路径的预期）；标注待确认；**须用户确认**后进入第4步。  
**禁止：** 同批输出第二版全文；把本步写成「为创造性补强选问题」。

---

## 第4步：第二版独权

锚定已确认新问题；**不得含非必要技术特征**。

- **命名（本案唯一一次优化）：** 先触发 `部件命名优化总控` → 交付对照表 → **用户确认采用名** → 再写正文（可拆 4a 命名表 / 4b 正文）。  
- 附删除/概括/下放对照与按步成组的下放清单。  
- 标注「**第二版独权（重新界定技术问题 · 无非必要特征 · 命名已优化）**」。  

**禁止：** 未确认命名表即写正文；同批第三版；把命名优化留到第三版。

---


## 第5步：再上位技术问题

给出再上位表述（或「无需再上位」）+ 与第二版分层关系；标注待确认；**须确认**后进第6步。  
**禁止：** 同批第三版全文。

---

## 第6步：第三版独权

执行第三版加码（清楚 + 范围最大；步骤/参数上位）；**沿用第二版已确认名称，不再做命名优化**；成组下放过窄限定。  
标注「**第三版独权（再上位技术问题 · 清楚且范围最大 · 命名沿用第二版）**」。  
**禁止：** 未确认第5步就写第三版；本版再开命名对照表或擅自改名（除非用户明示）。

---

## 第7步：【可选】递交独权变劣与从权回退（本 skill 内嵌）

第三版后询问是否「递交权1放宽 + 定稿改进进从权」。  
- 跳过 → 第8步正式稿=第三版；2.7=`cancelled`。  
- 执行 → 7.1～7.4；第8步正式稿=递交独权。

| 称谓 | 含义 |
|------|------|
| **定稿独权** | 第三版（或用户指定） |
| **递交独权** | 定稿再去掉/改宽一层改进限定后的权1 |
| **从权回退** | 定稿相对递交权1多出的特征成组进从权 |

**边界：** 只能上位/省略定稿已有限定；递交权1须可实施并保留最小创造性骨架。  
**子步骤：** 一步一交付；7.1 变劣点须确认后才能写 7.2；禁止 7.2 与 7.3 一次倾倒。

### 7.1 锁定定稿 + 可变劣清单【须确认】

复贴定稿；列出可下放改进（示例）：

| 类型 | 定稿中的样子 | 变劣后常见写法 |
|------|----------------|----------------|
| 工具/软件名 | EPANET、某商业求解器 | 水力模型 / 仿真模型 |
| 模型结构钉死 | 4 残差块 TCN、128 维 | 时间序列定位模型 / 节点特征向量 |
| 度量/算法名 | 余弦相似度、谱聚类 | 特征相似度、聚类 |
| 数值范围 | 漏损面积 0.0005～0.1 | 多工况漏损模拟（细则从权） |
| 工程配套步 | 独立验证指标清单、安装优先级字段 | 独权只保留「输出布设方案」；细项从权 |

标注「**待确认：拟变劣点**」与最小骨架建议。  
**禁止：** 同批输出递交全文、完整从权。

### 7.2 撰写递交独权

按确认点重写；比定稿更宽；步骤可实施；主谓宾完整；参数有来源。标注「**递交独权（定稿变劣稿）**」+ 对照。

### 7.3 成组从权回退

「定稿有、递交无」的特征按独权步骤成组写入从权（或核心组+待写清单）；引用合规。

### 7.4 对照 + 风险 → 第8步

三栏对照；创造性/说明书问题是否绑死已下放约束；预告正式稿默认=递交独权。

## 第8步：收束 + 交接

1. 正式稿默认：执行了第7步则为递交独权，否则为第三版。  
2. 三版锚定问题与要求层级摘要；若有变劣附三栏对照。  
3. 按步下放组汇总、待确认事实、说明书同步事项。  
4. 提示转入 `从权撰写`（第7步回退组作种子）；质检；创造性若跳过可事后另开。  
5. 不自动连跑说明书/从权全文。

**禁止：** 同轮说明书定稿；未经确认回改第三版/递交稿。
