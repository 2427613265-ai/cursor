# 方法类独权撰写（最小特征集两版策略 · 服务于方法/算法流程案）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  术语先释义 + 外行读懂 + 懂后再体检 + 问题候选
        ↓
第1步  输出交底书声称要解决的技术问题
        ↓
第2步  输出交底书中解决该问题的技术特征
        ↓
第3步  确定其中的核心区别技术特征
        ↓
第4步  按核心区别组成最小技术特征集（完整技术方案；不考虑先前技术问题）
        ↓
第5步  根据已确认的最小技术特征集撰写第一版独立权利要求
        ↓
第6步  根据第5步已写成的第一版独立权利要求，重新核定其所对应的技术问题
        ↓
第7步  在新问题下审视第一版是否合适，进一步删减/上位 → 第二版独权
        ↓
第8步  收束为正式独权工作稿（默认=第二版）
```

**两版要求（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求 |
|------|----------------|----------|
| **第一版** | **本版不预先锚定技术问题** | 只落实第4步已确认的**最小技术特征集**；方案完整可实施；允许沿用交底原名；**禁止**把交底实施例细节整份灌进独权 |
| **第二版** | 第6步**重新核定后**的技术问题 | 在新问题下审视第一版是否仍合适；特征可进一步删减、上位；**不得含非必要技术特征**；本案唯一一次命名优化 |

撰写方法（质量闸门、步骤铺陈、命名规则等）**服务于上述策略**，细则经 `方法类权利要求具体撰写规则总控` 挂接，不得颠倒成「先抠字眼、后定策略」。

## 适用场景与触发

- **客体：** 方法类 / 算法·数据处理流程类独立权利要求（「一种××方法」；以步骤、输入输出变换、判断与循环控制为主）。
- **入口：** 须经 `独权撰写` 判定为方法案或算法案后转入本 skill；已点名「方法类独权 / 算法独权」时可直进。
- 已完成 `交底书技术方案理解`（含术语词典、外行总故事、懂后体检与问题候选）；进入**阶段二**（本 skill 自建 2.1～2.8 plan）。
- 触发：「写方法类独权」「算法独权」「按交底问题写第一版」「核心区别」「最小特征集」「重新核定技术问题」「第二版」等。
- **不适用：** 纯结构/装置独权（走 `结构类独权撰写`）；**禁止**对本案套用「其特征在于后先总列部件再展开」。方法案**无第三版、无再上位、无递交变劣**；第二版即为正式工作稿默认稿。

## 能力边界

- 产出：声称问题、特征清单、核心区别、最小特征集、两版独权工作稿 + 一轮重新核定说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新步骤/数据/参数；缺事实标「待确认」。
- **正文具体写法**经 `方法类权利要求具体撰写规则总控` 挂接叶 skill / 横切；本文件不粘贴细则全文。
- 本 skill 是**方法/算法案**独权策略执行层；**分流入口**是 `独权撰写`；**正文细则入口**是上述总控。

## 输出控制（plan 硬性）

禁止一次输出「声称问题+特征清单+核心区别+最小集+两版独权」。必须用 plan/待办同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

### 固定 plan（共8步 = 总览 2.1～2.8）

```text
第1步 输出交底书声称要解决的技术问题【须用户确认】
  ↓
第2步 输出交底书中解决该问题的技术特征【须用户确认无重大遗漏】
  ↓
第3步 确定其中的核心区别技术特征【须用户确认】
  ↓
第4步 组成最小技术特征集（完整技术方案；不考虑先前技术问题）【须用户确认】
  ↓
第5步 根据已确认最小集撰写第一版独立权利要求
  ↓
第6步 根据第5步第一版独立权利要求，重新核定其所对应的技术问题【须用户确认】
  ↓
第7步 在新问题下审视第一版，进一步删减/上位 → 第二版独权
  ↓
第8步 正式工作稿收束 + 两版对照摘要 + 交接
```

- 第1步同步建立 2.1～2.8 plan，**不**单列「只建 plan」的步骤。  
- **禁止**将第3步与第4步合并（未确认核心区别不得组成最小集）。  
- **禁止**将第4步与第5步合并（未确认最小集不得写第一版独权）。  
- **禁止**将第5步与第6步合并（未写出第一版独权全文，不得重新核定问题）。  
- **禁止**将第6步与第7步合并（未确认新核定问题不得写第二版）。  
- 第8步正式稿默认=第二版。  
- 未完成理解不得硬写第一版（用户明示跳过理解除外）。

## 第1步声称问题 vs 第6步重新核定（禁止抢活）

| | **第1步 交底声称问题** | **第6步 重新核定问题** |
|--|------------------------|------------------------|
| **时机** | 尚未写独权 | **第5步第一版独立权利要求全文已交付之后** |
| **输入对象** | 交底书 / 理解 skill 问题候选 | **仅第5步已写成的第一版独立权利要求**（最小特征集落成的权1） |
| **一句话** | 交底书自己声称要解决什么 | 这份第一版独权**实际能稳定解决**的是哪一层问题 |
| **改写** | **不改写**；忠实摘录/归纳，标注来源 | **要核定**；方法案主目标是扩围（去场景/工具/参数/效果钉死） |
| **服务对象** | 第2步列特征（盘点解题手段） | 第7步第二版：进一步删减/上位 |
| **方法案默认** | 摘交底发明目的/背景「然而」后问题/理解 skill 候选 | **几乎总要做**，以扩围为主；不以「更好补强创造性」为主取舍 |

**禁止互相抢活：**

- 第1步不得写成重新核定定稿，不得预写第二版锚定问题。  
- 第1步声称问题**不是**第4步入集标准，也**不是**第一版独权的预先锚定问题。  
- 第6步**不得**再做一遍「交底声称了什么」，**不得**只拿第3步核心区别清单、第4步最小集或理解 skill 问题候选空推；**唯一反推对象是第5步已写成的独立权利要求**。  
- 第5步独权全文未交付，不得进入第6步。  
- 第6步不预写第二版独权全文。

## 重新核定技术问题：怎么考虑（第6步专用 · 方法案）

### 方法案前提（硬性口径）

**输入对象（硬性）：** 第6步只根据**第5步已经构造并交付的第一版独立权利要求**重新核定技术问题。交底声称问题、理解 skill 候选、第3步核心区别清单、第4步最小集只作对照，**不得**代替第一版独权成为反推起点。未写出第一版独权全文，本步不成立。

方法/算法流程案的创造性**通常已经够**；第6步重新核定**默认不是为了「找创造性落点 / 为补强留抓手」**，而是为了：

> **对着这份第一版独权，把它实际能稳定解决的问题定到更合适的层级，使第二版能丢掉交底钉死的场景、工具、参数与效果堆砌，从而获得更大、仍可实施的保护范围。**

重新核定**不是**把交底书问题换个说法，也**不是**把技术方案手段写进问题里。交付第6步时，必须先点明「反推对象=第5步第一版独权」，再写清「本次核定如何服务于扩围」。

### 操作方法

写「核定考虑」时用下列方法；不另设三点主轴，也不按点1/2/3分述。

| 操作方法 | 怎么用 |
|----------|--------|
| **交底书问题盘点** | 分清核心痛点 vs 附带效果/宣传语；标出第1步声称问题里绑死场景、工具名、指标堆砌的句子。附带/宣传不得当成重新核定后的主问题。此栏是对照，不是本步起点。 |
| **特征反推（为扩围）** | **对着第5步第一版独权全文**反推：这份权1实际稳定消除哪一层不良后果；删掉其中仍像实施例钉死的表述后，还能撑住哪一层更上位问题。 |
| **手段不进问题** | 问题不写算法名、软件名、具体参数等手段；手段留在特征里，问题只写后果/需求缺口。 |
| **范围落点（扩围主检）** | **过窄**→第二版被迫保留非必要路径；**过宽**→假宽或无可实施依托。目标：第二版能明显变宽，且仍可实施。再宽即变成「提高效率/更加智能」等空问题，或第二版必要步骤已解不了，则停在当前层级。 |
| **用户/布局侧重** | 用户要的保护重心、竞品规避面加权；不作唯一依据。 |
| **可检验** | 假定第二版只剩必要步骤：能否完整解决拟核定问题？能 → 扩围成功；不能 → 问题过大或骨架不足，回调问题层级或回到第一版/交底补事实。 |

### 输出格式

- **反推对象**：复贴或明确引用第5步第一版独立权利要求（可摘要，但须能对上全文）  
- **重新核定后的技术问题**（一句或两句定稿候选）  
- **核定考虑**（先写明「方法案以扩围为主、反推对象=第一版独权」；再按上表操作方法写清依据，不按三点分述）  
- **与交底书声称问题的差异**（保留/收窄钉死语/放宽层级——重点写清**扩了哪一层范围**；此栏是对照，不是本步起点）  
- **对第二版的预期**（一句：拟删/概括哪些非必要路径，因问题已不再绑死它们）  
- 标注「**待确认：重新核定后的技术问题**」；确认后再写第二版。

## 撰写方法总则（服务于两版策略 · 细则外置）

写任一版**独权正文**前：先 Read `方法类权利要求具体撰写规则总控`，再按其挂接表加载本案所需叶 skill / 横切。下表只保留策略级要点，**不**替代叶 skill。

### 最小技术特征集（第4步硬性口径）

最小技术特征集 **≠** 只写核心区别、把方案写残。它是组成一个**完整技术方案**所需要的技术特征：

1. **必须包含**第3步已确认的核心区别技术特征；  
2. **另含**使技术方案完整可实施所必需的支撑特征（步骤顺序、输入输出咬合、必要前提等）；  
3. **不考虑**第1步声称问题，也**不以**「是否仍能解决该声称问题」作为入集或剔出标准；只要技术方案完整即可；  
4. **不得**把交底中的实施例细节、优选路径、工具/软件名钉死、具体参数范围等非必要项塞进最小集。

构造时逐项反问：去掉该支撑特征后，核心区别是否还接得上、**技术方案是否仍完整可实施**？能去掉则不要进最小集（列入第2步未入独权的下放候选）。**不要**再问「去掉后还能不能解决声称问题」。

技术问题留到第6步：根据第5步已写成的第一版独权再重新核定。

### 正文质量要点（各版共通 · 短引）

| 要点 | 细则落点（经总控） |
|------|-------------------|
| 按产物拆步；步间 I/O 咬合；禁空挂 | `按产物拆步与IO咬合` |
| 步骤编号（S1… / Sij） | `方法步骤编号规范` |
| 路径 vs 不变量（去钉死/下放）；非区别「获得××」 | `路径与不变量二分` |
| 条件句 / 预设来源 / 主谓宾 / 指代 / 就地定义 / 清楚性 | 总控「通用横切」各 skill |
| **禁止**结构「先总列后展开」 | 总控「明确不挂」 |

> 以叶 skill 为准，本页只保留策略级短引，不平行维护长细则。

### 命名时机（方法案硬性 · 只在第二版优化）

| 版本 | 命名动作 | 说明 |
|------|----------|------|
| **第一版** | **不优化命名** | 一律沿用交底书原名；可不交付命名对照表 |
| **第二版** | **唯一一次命名优化** | 经总控 → `方法独权命名时机` → `部件命名优化总控`；对照表确认前不得写第二版正文 |

方法案无第三版；第二版确认名即全书基准。

### 第二版加码（硬性 · 策略）

- 锚定=第6步重新核定后的技术问题。  
- **完成本案唯一一次命名优化**（见上表）。  
- 先问：第一版在新问题下是否仍合适（过窄/过宽/偏题）？再问：特征能否进一步删减、上位？  
- 去非必要：经总控挂 `独立权利要求必要技术特征检查` + `路径与不变量二分`；删后仍可实施，保留最小区别骨架。  
- **非区别输入**：宜「获得/获取××」概括，具体获得步骤进从权（见 `路径与不变量二分`「非区别数据的获得表述」）；区别性获得不得误省。

### 类型铺陈（短引）

| 类型 | 要点 | 细则 |
|------|------|------|
| 方法/数据处理、算法流程 | 有序步骤；产物清楚；条件与参数合规 | `按产物拆步与IO咬合` 等 |
| 调控闭环 | 感知→（可选判定）→中间调控量→执行 | `调控闭环最低链`（仅闭环案） |
| 结构装置 | **不走本 skill** | `结构类独权撰写` |

### 成组下放（短引）

第4步未纳入最小集的特征、以及第7步从第一版剔出的路径/细分支，宜按独权步骤成组 → 细则 `方法独权成组下放`（经总控）；禁止把当前版最小区别骨架整组藏进从权。

## 第1步：输出交底书声称要解决的技术问题

1. 标明阶段二（方法/算法案）；**由本 skill 建立** 2.1～2.8 plan；同步 todo。  
2. 从交底书发明目的/背景「然而」后问题/理解 skill 问题分层中，**摘录并固定「交底书声称要解决的技术问题」**（可多条并列时标明交底书主写的那条）；**不作重新核定**。  
3. 标注来源（交底原文位置或理解 skill 候选编号）。  
4. 标注「**待确认：交底书声称的技术问题**」。

**交付物：** plan + 交底声称技术问题（原文/归纳 + 来源）。  
**禁止：** 输出独权全文；输出重新核定定稿；把理解 skill 的「待确认候选」直接写成已确认独权锚定问题；把本步问题预写成第4步入集标准。

## 第2步：输出交底书中解决该问题的技术特征

对准第1步已确认的声称问题，列出交底书中用于解决该问题的技术特征（步骤、输入输出、判断、中间量、执行动作等）。

- **优先引用**理解 skill 的构成/过程、特征与问题对应关系；补交底中理解阶段未逐条展开、但确实用于解题的特征。  
- 建议表列：序号｜交底表述｜对应声称问题的哪一面｜是否明显实施例细节/优选路径。  
- 本步是**特征盘点**，不是独权正文；不在本步做创造性定性（留给第3步）。  
- 标注「**待确认：解决声称问题的技术特征清单**」；请用户确认有无重大遗漏。

**交付物：** 特征清单（可含「疑似实施例细节」标记）。  
**禁止：** 输出独权全文；把清单直接当成最小特征集；漏列交底中明显做功的步骤。

## 第3步：确定核心区别技术特征

从第2步清单中，确定**核心区别技术特征**（相对现有惯常做法、真正做功且支撑声称问题的那一撮）。

- **优先引用**理解 skill 的「创新点 vs 惯常剥离表」，并与第2步清单对齐；口径冲突须明示取舍。  
- 建议表列：特征｜相对现有/惯常的区别点｜是否核心区别｜理由。  
- **不得**把第2步全部特征都标成核心区别；惯常步骤、纯实施例钉死、配套工程细节默认非核心。  
- 可借助 `路径与不变量二分` 的「三问」帮助区分路径与不变量，但本步仍只定「哪些是核心区别」，不写独权、不组成最小集。  
- 标注「**待确认：核心区别技术特征**」。  
- **须用户确认**后才能进入第4步。

**交付物：** 核心区别清单 + 非核心/惯常/细节分流说明。  
**禁止：** 同批输出最小集定稿或第一版独权全文；无理由把交底几乎全部步骤标成核心区别。

## 第4步：组成最小技术特征集【须确认】

按已确认的核心区别，组成**最小技术特征集**。本步**只组集、不写独权正文**。

- 最小集口径见上文「最小技术特征集」：**完整技术方案所需特征**；**不考虑**第1步声称问题。  
- 助判：`路径与不变量二分`（路径不宜进最小集）；`按产物拆步与IO咬合`（步间是否接得上、方案是否完整可实施）。  
- **不**调用 `独立权利要求必要技术特征检查`（该检查须对着已核定的技术问题；本步无锚定问题）。  
- 建议表列：特征｜核心区别 / 完整方案支撑｜入集理由（接得上 / 可实施）｜若不入集则如何下放。  
- 附：第2步未入最小集的下放候选。  
- 标注「**待确认：最小技术特征集**」。  
- **须用户确认**后才能进入第5步。

**交付物：** 最小集清单（核心区别 / 完整方案支撑）+ 未入集下放候选。  
**禁止：** 同批输出第一版独权全文；用「能否解决声称问题」筛入集；把交底实施例整份算进最小集；未确认核心区别即组集。

## 第5步：根据最小集撰写第一版独立权利要求

根据第4步已确认的最小技术特征集，撰写第一版独立权利要求。

- **本版不预先锚定技术问题**；只把最小集落成完整、可实施的权1。  
- **写正文前：** 经 `方法类权利要求具体撰写规则总控` 按表 Read（本版至少：拆步与 I/O、步骤编号；路径/不变量用于核对未把路径写进权1；横切按需）。**不**用必要特征检查对着声称问题再筛一遍。  
- **命名：不优化** — 沿用交底原名；**不**触发命名总控、**不**交付命名对照表（可声明「本版沿用交底原名」）。  
- 附：最小集如何落入各步骤（可简表）；未入权项仍作下放候选。  
- 标注「**第一版独权（最小特征集 · 原名未优化）**」。

**禁止：** 未确认第4步最小集即写正文；把交底实施例整份灌进第一版；同批重新核定问题；同批第二版；本版擅自改名优化。

## 第6步：重新核定独立权利要求的技术问题

**本步＝根据第5步已经写成的第一版独立权利要求，重新核定这份权1实际解决的技术问题**（服务第二版进一步删减/上位）；与第1步分工见上文。

1. 先锁定反推对象：复贴或引用第5步第一版独权全文。  
2. 按上文「怎么考虑（方法案）」输出：以**扩保护范围**为主的结论 + 核定考虑（含对第二版拟删非必要路径的预期）。  
3. 标注「**待确认：重新核定后的技术问题**」；**须用户确认**后进入第7步。

**禁止：** 第5步独权全文未交付即做本步；同批输出第二版全文；把本步写成「为创造性补强选问题」；把本步写成再摘一遍交底声称问题；只拿核心区别清单、最小集或理解候选空推而不对着第一版独权。

## 第7步：第二版独权

锚定已确认的重新核定问题；在新问题下重新考虑第一版是否合适，并进一步删减、上位。

- **写正文前：** 经 `方法类权利要求具体撰写规则总控` 按表 Read（本版重点：命名时机、路径/不变量、必要特征、拆步与 I/O、成组下放）。  
- **命名（本案唯一一次优化）：** 经总控 → `方法独权命名时机` → `部件命名优化总控` → 交付对照表 → **用户确认采用名** → 再写正文（可拆 7a 命名表 / 7b 正文）。  
- 须写明：第一版在新问题下何处过窄/可删/可上位；相对第一版的删除/概括/下放对照；按步成组的下放清单。  
- 标注「**第二版独权（重新核定技术问题 · 无非必要特征 · 命名已优化）**」。  

**禁止：** 未确认第6步问题即写正文；未确认命名表即写正文；把命名优化留到本步之后；同批倾倒从权全文。

## 第8步：收束 + 交接

1. **正式独权工作稿**默认=第二版（用户指定另选须明示）。  
2. 对照摘要：第1步声称问题 vs 第6步核定问题；第一版最小集 vs 第二版进一步删减/上位。  
3. 下放组汇总（第2步未入最小集 + 第7步从第一版剔出）、待确认事实、待同步说明书事项。  
4. 衔接：说明书问题/效果对齐（技术问题勿再绑死在独权已下放的约束上）；**提示转入 `从权撰写`**（默认布局 9 条；上述下放组作种子）；质检。  
5. 结束；不自动连跑说明书或从权全文。

**交付物：** 正式稿定位（可复贴）+ 摘要与清单 + 衔接。  
**禁止：** 同轮说明书定稿；未经确认回改第二版（有意见回第7步）。
