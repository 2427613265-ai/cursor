# 通用·撰写策略

本分支用于存放**不区分结构类/方法类/算法类**的策略层 skill：解决交底书能不能写、方案怎么读懂、独权怎么分流与递进、从权如何布局与逐条撰写等整体方向问题；具体某一句权利要求/说明书的措辞形态，仍由类型分支与通用规范承担。

## Plan 控输出（本分支硬约定）

`交底书技术方案理解`、`独权撰写`（分流后的执行层）、`从权撰写`（及创造性等）**必须使用 Cursor plan / 待办清单功能**：

1. **交底理解**：第1步只建本 skill 子步骤 plan；**不在入口倾倒**独权阶段二细目；交接时提示转入 `独权撰写` 分流。  
2. **独权撰写（入口）**：只输出类型判定 + 下游 skill；**不**自建阶段二细目。  
3. **结构类独权撰写**：转入后第1步列出 2.1～2.9（至第二版后保留再上位/第三版；递交变劣在第三版与收束之间）并同步待办。  
   **方法类独权撰写**：转入后第1步列出 2.1～2.6（至第二版后收束，无第三版/变劣）并同步待办。  
4. **同步 TodoWrite / CreatePlan**；始终一个 `in_progress`。  
5. **一步一交付**；从权须先确认布局再写；禁止未确认布局倾倒多条从权正文（「核心链一批后停」除外）；次要权利要求组须先判定再写，禁止与核心组复核合并。  
6. **用户说「一口气写完」仍分步**。

## 推荐调用顺序

```
阶段一  交底书技术方案理解【入口】
        可写确认 → 术语词典 → 场景痛点 → 外行总故事
        → 构成地图 → 工作过程 → 体检 → 创新点/问题候选/交接
  ↓
阶段二  独权撰写【分流】
        S 结构案 → 结构类独权撰写（自建 2.1～2.9）
              核心区别一句话 + 关键创新点 → 组成最小集【确认】
              → 连缀第一版（核心独立权利要求）→ 审定技术主题 + 重新核定问题 → 校核第一版得第二版 → 再上位【确认】→ 第三版
              →【可选】递交变劣（2.8）→ 收束（2.9）
        M/A 方法·算法 → 方法类独权撰写（自建 2.1～2.6）
              写正文前 → 方法类权利要求具体撰写规则总控（横切）
              核心区别一句话 + 关键创新点 → 组成最小集【确认】
              → 连缀第一版（核心独立权利要求）→ 审定技术主题 + 重新核定问题 → 校核第一版得第二版 → 收束
  ↓
阶段三  从权撰写
        盘点 → 分层次布局9条【确认】→ 逐条撰写（假想代入；门禁 Read）→ 核心组复核
        → 次要权利要求组【判定；见 `次要权利要求组撰写`】
  ↓
  → 权利要求质检 / 说明书撰写
```

说明：

- **至第二版（结构/方法共用构思）**：第1步先定**核心区别一句话**（顶天）与**关键创新点**（立地，见 `核心区别技术特征确定`）；第2/3步以一句话为中心组成**最小技术特征集**并连缀为第一版（见 `最小技术特征集与第一版独权`）；第4步对着第一版**审定技术主题**（常过窄）并**重新核定技术问题**（见 `审定技术主题与重新核定技术问题`）；第5步在新主题与新问题下校核第一版（全文对齐用语、再删减/上位）得第二版（见 `第二版独权校核`）。独权阶段不单列交底声称问题或解题特征全集清单。
- **结构案其后三版要求依次提高**：第二版对准核定问题且无非必要特征；第三版再上位后追求逻辑表达清楚且保护范围最大。
- **递交变劣不等于否定第三版**（仅结构案）：第三版是定稿质量基准；递交权1可再放宽，定稿多出的改进进从权退守。
- **从权撰写**负责核心组从权树（关键创新点逐层落实，见 `从权分层次布置`）及核心组之后的次要权利要求组判定（见 `次要权利要求组撰写`）；结构案第8步只提供变劣回退种子，不替代本 skill。
- **撰写方法服务于策略**：类型铺陈、必要特征检查、表达规范等在对应版本/门禁表加码调用。
- **方法/算法案**走 `方法类独权撰写`；禁止硬套结构「总列后展开」；方法案无第三版/再上位/变劣。
