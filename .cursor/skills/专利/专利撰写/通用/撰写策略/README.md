# 通用·撰写策略

本分支用于存放**不区分结构类/方法类/算法类**的策略层 skill：解决交底书能不能写、独权怎么定问题与范围、创造性够不够等整体方向问题；具体某一句权利要求/说明书的措辞形态，仍由类型分支与通用规范承担。

## 已有 skill

| skill | 用途 | 典型触发 |
|-------|------|----------|
| `交底书技术方案理解` | 独权前读懂方案：白话、构成图、工况流程、创新点剥离（总览阶段一） | "先讲清楚技术方案""独权前先梳方案" |
| `交底书评估与创造性补强`（目录名；skill 名：交底书评估和独权初步撰写） | **本案入口**：第1步输出全流程总览 plan；本 skill 做体检→理解→初版独权→待确认主问题 | "拿到交底书""帮我看看能不能写""先起一版独权" |
| `独权撰写` | 正式独权（总览阶段三）：确认主问题→按主问题修订→【可选】创造性→再上位并筛选/下放→收束 | "正式写独权""按主问题改独权""再上位技术问题" |
| `创造性评估与独权补强` | **可选**；插在按主问题修订之后、再上位之前；评估修订稿，不足则补强，再回独权撰写 | "创造性够不够""要不要补强" |
| `专利申请文件撰写策略` | 落笔前整体方向规划：商业前景与抵御方向、保护范围与稳定性、侵权判定友好性、竞争对手规避、权利要求布局五维度 | "撰写策略""怎么布局""从战略/商业角度考虑" |

## Plan 控输出（本分支硬约定）

独权相关策略 skill **必须用 plan 控制输出内容**：

1. **入口第1步列全流程总览**：拿到交底书进入 `交底书评估和独权初步撰写` 时，第1步须列出阶段一～三（含独权撰写 3.1～3.5），并把**可选创造性**标在「按主问题修订」与「再上位」之间。  
2. **一步一交付物**：每步格式 `【第X步 / 共N步】步骤名称`；须用户确认（或「下一步」）后再续。  
3. **禁止一次倾倒**：禁止同批输出「体检+初版独权+主问题」或「主问题独权+上位独权」或「初判+补强路径+补强独权」。  
4. **阶段边界不连跑正文**：一阶段结束后只提示下一阶段；下一阶段建子 plan 时须**回扣总览编号与顺序**，不得把创造性挪到再上位之后。  
5. **用户说「一口气写完」仍分步**。

与审查意见答复 skill 中的 plan 机制同构：用待办清单驱动，始终只有一个「进行中」。

## 推荐调用顺序（与入口总览一致）

```
【入口第1步已规划】
阶段一  交底书技术方案理解
  → 阶段二  交底书评估和独权初步撰写（初版独权 + 待确认主问题）
  → 阶段三  独权撰写
        3.1 确认主问题
        3.2 按主要技术问题修订独权
        3.3 【可选】创造性评估与独权补强
        3.4 再上位技术问题 + 第二轮筛选/成组下放
        3.5 正式独权工作稿收束
  → 专利申请文件撰写策略（若需要）
  → 通用/说明书撰写
  → 权利要求质检/权利要求书质检
```

说明：

- **再上位技术问题、成组下放** 落在 `独权撰写` 3.4，在可选创造性之后。
- **创造性评估与补强** 可选，但位置固定：必须在 3.2 按主问题修订之后、3.4 再上位之前。
- `独立权利要求必要技术特征检查` 是独权撰写再上位步调用的**判断细则**，不是排在创造性之后的单独大步骤。
- 类型分支的 `结构类/方法类/算法类` 权利要求撰写规范，在独权撰写输出正文时按需对照，不替代本分支的策略步骤。

新增相关 skill 时，请在本目录下按照 `.cursor/skills/专利/专利撰写/通用/撰写策略/<中文名称>/SKILL.md` 的结构添加，并更新本 README；凡多步交付的策略 skill，均应内置 plan 控步规则。
