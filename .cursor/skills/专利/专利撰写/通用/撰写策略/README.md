# 通用·撰写策略

本分支用于存放**不区分结构类/方法类/算法类、处在正式落笔撰写之前**的策略层 skill：解决"这份交底书够不够格、要不要补强、这件专利往哪个方向布局"这类整体方向问题，不涉及具体某一句权利要求/说明书文字怎么措辞。

## 已有 skill

| skill | 用途 | 典型触发 |
|-------|------|----------|
| `交底书评估与创造性补强`（目录名；skill 名：交底书评估和独权初步撰写） | 撰写前处理：plan 控步 → 可写确认 → 体检 → 初版独权 → 主问题/待确认 | "帮我看看这份交底书能不能写""先起一版独权" |
| `创造性评估与独权补强` | 主问题独权形成后：plan 控步 → 初判 →（不足则）分型+路径 → 补强独权 → 够用判断 | "创造性够不够""交底书不够怎么补强" |
| `专利申请文件撰写策略` | 落笔前整体方向规划：商业前景与抵御方向、保护范围与稳定性、侵权判定友好性、竞争对手规避、权利要求布局五维度 | "撰写策略""怎么布局""从战略/商业角度考虑" |

## Plan 控输出（本分支硬约定）

独权相关策略 skill **必须用 plan 控制输出内容**：

1. **先建 plan，再交付**：进入 skill 后先列出本 skill 内逐步名称，再按序执行。  
2. **一步一交付物**：每步格式 `【第X步 / 共N步】步骤名称`；须用户确认（或「下一步」）后再续。  
3. **禁止一次倾倒**：禁止同批输出「体检+初版独权+主问题」或「初判+补强路径+补强独权」。  
4. **skill 边界不连跑**：一个 skill 的 plan 结束后只提示下一 skill；下一 skill 须**重新建 plan**，不得把全流程揉进一张 plan 一次跑完。  
5. **用户说「一口气写完」仍分步**。

与审查意见答复 skill 中的 plan 机制同构：用待办清单驱动，始终只有一个「进行中」。

## 推荐调用顺序

```
交底书评估和独权初步撰写（plan 分步，最先执行）
  → （用户确认主问题后）结构类/方法类/算法类独权撰写（围绕主问题修订）
  → 创造性评估与独权补强（plan 分步；必要时补强）
  → 独立权利要求必要技术特征检查（创造性站住后再上位/下放）
  → 专利申请文件撰写策略（在已确定独权骨架基础上做五维度布局，若需要）
  → 通用/说明书撰写（发明内容、附图说明、具体实施例）
  → 权利要求质检/权利要求书质检（定稿复核）
```

前者先判断"交底书能不能写、够不够格、独权含哪些特征"，创造性补强先保证"窄独权能站住"，再谈放大范围与布局。

新增相关 skill 时，请在本目录下按照 `.cursor/skills/专利/专利撰写/通用/撰写策略/<中文名称>/SKILL.md` 的结构添加，并更新本 README；凡多步交付的策略 skill，均应内置 plan 控步规则。
