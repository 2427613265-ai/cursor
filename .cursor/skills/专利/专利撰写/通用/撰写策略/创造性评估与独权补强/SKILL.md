# 创造性评估与独权补强（可选中段，插在第二版与第三版之间）

## 适用场景

- 已进入 `独权撰写`，且已形成「**第二版独权**」（总览 2.4 / 独权撰写第4步：对准重新界定问题且无非必要技术特征）；用户选择执行可选的创造性评估。
- 现在要处理的是："这版第二版独权创造性够不够""如果不够，往哪里补""补强后的独权怎么构建"。
- **可选**：用户可在独权撰写第5步跳过本 skill。
- 不负责交底书读懂；不负责「再上位 / 第三版」（那属于 `独权撰写` 第6～7步，在本 skill **之后**执行）。

## 与前后 skill 的分工

- 与 `交底书技术方案理解` 的分工：理解 skill 是入口（读懂 + 问题候选；不在入口倾倒独权细目）；本 skill 标为阶段二中的可选 2.5；理解产出的创新点剥离是读懂用工作假设，不是创造性结论。
- 与 `独权撰写` 的分工：在其第二版（第4步）之后转入本 skill；本 skill 结束后**必须回到** `独权撰写` 第6步做再上位（须确认）并第7步写第三版，而不是直接结束独权流程。本 skill 不承接第一版独权。
- 与 `独立权利要求必要技术特征检查` 的分工：第三版再筛时的逐特征细则在回到 `独权撰写` 第7步时调用；本 skill 补强时勿把该检查误当成「排在创造性之后才第一次上位」的独立大阶段。
- 与 `说明书技术问题陈述撰写`、`说明书有益效果撰写` 的分工：本skill中确定的主问题、深化问题、以及补强后的核心效果，后续应落实到说明书对应段落，但本skill本身不负责说明书正文定稿。

## AI 使用本skill的能力边界（重要）

- **创造性评估依赖现有技术检索。** AI 本身不具备专利数据库检索能力；在没有检索结果、也没有用户提供现有技术概况时，不能凭空断言"有创造性/没有创造性"，更不能编造对比文件。
- 在缺少检索结果时，只能给出**倾向性判断**，并明确标注不确定性来源。
- 本skill提出的深化技术问题、补强特征、极端场景、意想不到效果，本质上是**合理推演和建议方向**，不是既定技术事实；应提醒用户/发明人确认其技术可行性和真实意图后，再写入正式申请文件。

## 输出控制（硬性：用 plan 控步）

本 skill **禁止**在同一次回复中一次性输出「创造性评估全文 + 补强路径全文 + 补强后独权全文」。必须用 **plan** 驱动，一步只交一个交付物，等用户确认后再进入下一步。

### 硬性规则

1. **先建 plan，再按 plan 交付**：第1步在固定评估对象的同时建立本 skill 的 plan；其后严格按 plan 推进。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步；用户说「一口气写完」时仍分步。
3. **不得跳步、不得把评估与补强独权同批输出**：第2步初判未确认前，不得输出补强后独权；补强路径步不得夹带完整补强独权正文。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + 请用户确认 + 预告下一步。
5. **始终只有一个「进行中」**：按初判结果更新 plan 分支（足够则标记补强步为不适用）。
6. **本 skill 结束即停**：够用判断交付后，只提示**返回 `独权撰写` 第6步（再上位，须确认）→ 第7步（第三版）**，禁止同轮自动写说明书；也不得在本 skill 内做再上位/第三版全文。

### 本 skill 的 plan 模板（含分支）

**启动时（第1步）先列出下列完整 plan**；其中补强相关步在初判前标注为「待初判后激活/跳过」：

```text
第1步 明确评估对象和口径 + 建立 plan
  ↓
第2步 创造性初判（足够 / 边缘可争 / 明显不足）
  ↓
【分支 A：初判为「基本足够」】
第3步 结论收束 + 待确认事项 + 返回独权撰写（再上位）
  （补强路径步、补强独权步标记为不适用）

【分支 B：初判为「边缘可争」或「明显不足」】
第3步 不足原因分型 + 选定补强路径（只交路径与要点，不交补强独权全文）
  ↓
第4步 补强后独权全文（含新增/恢复特征对照）
  ↓
第5步 补强后够用判断 + 待确认事项 + 返回独权撰写（再上位）
```

- 分支 A：N = 3。  
- 分支 B：N = 5。  
- 第2步确认后，**必须更新 plan**：写明走 A 还是 B，并给出激活后的逐步名称表。  
- 「边缘可争」默认走分支 B（出补强备选独权）；若用户明确只要主线、暂不补强，经确认后可改走 A。

## 第1步：明确评估对象和口径 + 建立 plan

在开始评估前，先固定当前工作对象：

- 当前要评估的是哪一版独权（**必须是** `独权撰写` 的「第二版独权」，不是第一版，也不是尚未完成的第三版）；
- 当前独权所对应的（重新界定后的）主技术问题是什么；
- 相对交底书初版已经做过哪些概括、精简或后移。

优先选择**第二版独权**作为评估对象。本 skill 位于再上位与第三版**之前**：先判断第二版创造性是否够；够或补强后再回 `独权撰写` 做再上位并出第三版。

**本步交付物：** 评估对象说明 + 完整 plan 模板（含 A/B 分支说明）+ 标明下一步为创造性初判。  
**本步禁止：** 给出足够/不足的结论；输出补强独权；展开三条补强路径的长文；输出再上位后的独权。

---

## 第2步：做创造性初判

围绕当前独权，先回答以下问题：

1. 相比现有技术，**区别技术特征**是什么？
2. 这些区别技术特征分别解决了什么问题？
3. 它们带来了什么技术效果？
4. 对本领域技术人员来说，这些区别是否容易想到？

结论建议分成三档：

- **创造性基本足够**：返回 `独权撰写` 做再上位与第三版，无需刻意补强；
- **创造性边缘可争**：建议保留当前第二版作为一条主线，同时准备一组补强方案或补强版独权作为备选；
- **创造性明显不足**：应进入后续补强路径，重新构建更有支撑力的独权，然后再回 `独权撰写` 出第三版。

**本步交付物：** 区别特征要点 + 三档之一的倾向性结论（缺检索时标明不确定性）+ **更新后的 plan**（激活分支 A 或 B）。  
**本步禁止：** 输出补强后独权全文；把三条补强路径写完。

---

## 第3步（分支 A）：结论收束与交接

仅当第2步为「基本足够」、或用户确认「边缘可争但暂不补强」时执行。

**本步交付物：** 简要收束为何可返回独权撰写继续再上位与第三版 + 仍待确认事项 + 提示返回 `独权撰写` 第6步（再上位确认）。  
**本步禁止：** 擅自开始说明书正文或全套从权铺陈；不得在本步做再上位/第三版全文。

---

## 第3步（分支 B）：不足原因分型 + 选定补强路径

仅当走分支 B 时执行。创造性不足不一定都是同一种原因，要先分型，再选定路径（可组合，但须写明主路径）。

### 分型

#### 1. 问题定得太浅

- 当前独权只解决表层问题；
- 与现有技术相比，只是做了常规优化；
- 区别技术特征不足以支撑更深层技术效果。

→ 优先走**补强路径一：深化技术问题（问题 → 方案）**。

#### 2. 方案写得太薄

- 真正有贡献的区别技术特征没有写进独权；
- 为了追求宽保护，把当前创造性的最小骨架也删薄了；
- 本来应当成组保留的特征，被拆散或过早下放。

→ 优先走**补强路径三：重组最小骨架**。

#### 3. 现有问题有价值，但技术效果说服力弱

- 区别技术特征虽存在，但效果不突出；
- 与现有技术相比，改进幅度看起来像常规替换、常规并列、常规拼装；
- 缺少能够突出非显而易见性的场景或效果表达。

→ 优先走**补强路径二：极端场景反推**。

### 路径要点（本步只交到「要点与拟用特征清单」，不写独权全文）

**路径一——深化技术问题**

- 从当前主问题出发，追问更本质、更难、更具价值的问题；
- 观察交底书已有特征中哪些指向更深约束或系统瓶颈；
- 输出：原主问题 / 深化后问题 / 拟补回或新增的特征清单（待确认）。

**路径二——极端场景反推**

- 设想极端工况下的短板 → 非常规手段 → 可能超出预期的效果；
- 常见场景：极高温低温、高压大载荷、极小体积/极大规模、长时连续运行、安装维护受限等；
- 输出：场景 / 逼出的手段 / 效果主张（待确认）。

**路径三——重组最小骨架**

- 回看已删除或下放的特征，找出应成组留在独权中的最小创造性骨架；
- 输出：拟回收的特征组及其协同关系（待确认）。

**本步交付物：** 分型结论 + 主路径（及可选辅路径）+ 拟用特征/问题清单。  
**本步禁止：** 输出补强后独立权利要求全文。

---

## 第4步（分支 B）：构建补强后的独立权利要求

只有在第3步（分支 B）经用户确认后，才进入本步。

补强后独权的构建原则是：

- **基础部分**：保留交底书中真实存在、且已被用户/发明人认可的核心技术贡献；
- **增强部分**：加入经过确认可行的补强特征；
- **结构原则**：让新增特征与补强后的技术问题、技术效果一一对应，避免只加特征、不改问题。

输出时应至少同时给出三项内容：

1. **补强后独权全文**；
2. **相对补强前独权新增/恢复了哪些特征**；
3. **每一项新增或恢复特征分别解决什么问题、带来什么效果**。

**本步交付物：** 上述三项。  
**本步禁止：** 同批展开完整从权树与说明书实施例（可一句预告下放方向）。

---

## 第5步（分支 B）：判断补强后独权是否已经够用 + 交接

补强不是加得越多越好。补强后还要反查：

- 是否已经足以支撑当前拟申请的专利类型；
- 是否仍保留了合理的保护范围，没有因过度补强而写得过窄；
- 是否把本该作为从权储备的内容一股脑塞进了独权；
- 是否需要同时保留一版较宽主线独权和一版较强备选独权。

如果补强后创造性已基本站住，则应提示**返回 `独权撰写` 第6步**确认再上位技术问题，再进入第7步写第三版独权，以补强稿为输入；若仍明显不足，则应如实告知用户，说明需要进一步检索、进一步确认方案，或者重新评估申请路径（此时是否仍做再上位与第三版由用户决定）。

**本步交付物：** 够用与否判断 + 仍待确认事项 + 返回 `独权撰写` 的衔接提示。  
**本步禁止：** 同轮自动完成再上位全文或说明书定稿（除非用户明确要求并接受对应 skill 自行建 plan）。

## 与其他 skill 的衔接顺序

典型顺序如下（与撰写策略推荐调用顺序一致）：

```
交底书技术方案理解（入口：术语先释义 + 读懂 + 问题候选）
  → 独权撰写（自建阶段二 plan）：第一版 → 重新界定问题 → 第二版
  →【可选】本skill（对象+plan → 初判 → [分型+路径] → 补强独权 → 够用判断）
  → 返回独权撰写：再上位 → 第三版 → 收束
  → 通用/说明书撰写
  → 质检总控 → 权利要求质检总控 → 权利要求书质检
```

其中，本skill评估对象是「第二版独权」；**再上位（第6步，须确认）与第三版（第7步）默认在本 skill 之后**由 `独权撰写` 完成。
