# 交底书技术方案理解（本案入口：先读懂，再交给独权）

## 适用场景

- 拿到发明人/申请人**交底书**（及附图），准备从零走到正式独权时——**本 skill 是阶段默认入口**（亦可经 `专利撰写总控` 分流至此）。
- 用户需要先判断「能不能写、信息够不够」，并把方案真正读懂，再进入独权撰写。
- 典型触发语：「拿到交底书」「先讲清楚技术方案」「独权前先梳方案」「这个案子到底怎么实现的」「帮我看看交底书」。
- 不区分结构类/方法类/算法类；按类型调整构成图 / 步骤链 / 模块数据流的形态。

## 设计目标（对本 skill 成败的判定）

本 skill **成功**的唯一标准：用户（默认=**非本领域**的专利代理人）在结束时可**不看交底书**用自己的话讲清：场景痛点、整案在干什么、关键部件/步骤各自干什么、主流程怎么走、哪一点像发明贡献。

**失败形态（须避免）：** 输出很「专业」、术语堆满、步骤齐全，但用户仍说「还是不太懂」——尤其算法案里领域专有名词、缩写、模型/损失/特征名被默认读者已知。

## 一个前提：交底书是否浅显到必须先找发明人

- 连「要解决什么问题、用什么手段、核心结构/步骤是什么」都缺失或语焉不详 → 请发明人补充，**后续步骤暂不展开，也不建 plan**。
- **不算太浅显**（问题、手段、核心创新点大体能看明白，只是细节缺漏或表述问题）→ 进入 plan 分步；关键事实缺环标待确认，不脑补。

## AI 使用本 skill 的能力边界

- 只做**可写性判断、忠实解读、术语转译与结构化讲解**；可纠正明显违背物理/常识的口误，但须**明示「原文 X → 按常理应理解为 Y」**，不得悄悄改写成另一套发明。
- **禁止**在本 skill 内输出独立权利要求全文、从权布局、创造性评述或说明书正文。
- **禁止**为「讲圆」而脑补交底书未记载的关键结构/步骤；缺环标「理解障碍 / 待发明人确认」。
- 附图存在时必须对照标号；无图时用文字关系图或 mermaid 补「逻辑图」，并注明「非发明人附图」。
- 技术问题分层与主问题**候选**在本 skill 末步给出；**主问题正式确认**与独权正文经 `独权撰写` 分流后，在结构案由 `结构类独权撰写`、方法/算法案由 `方法类独权撰写` 执行。

## 读者假设与行话门禁（硬性，贯穿全 skill）

1. **默认读者不懂本领域**：不默认其懂行业缩写、标准号俗称、模型名、损失名、特征名、工艺口诀、设备内部习惯名。
2. **先释义，后出场**：任一领域专有名词 / 缩写 / 本案自定义名，须先进入「术语词典」（第2步或后续补录），**之后**才允许在讲解正文中使用；禁止「用未释义词解释未释义词」。
3. **人话优先于术语**：能用人话/类比说清的，先人话；术语作标签挂在后面，而不是反过来。
4. **每步自检**：本步正文若出现词典外术语 → 当场补录释义，或改写为已释义说法；不得「留给后面再说」。
5. **算法/方法案加码**：对每个关键**输入、中间量、判定量、输出**，除术语释义外，还须写清「在业务/物理世界里代表什么、算完之后拿它干什么」。

## 输出控制（硬性：用 plan 功能控步）

本 skill **禁止**在同一次回复中倾倒「术语表 + 场景 + 总故事 + 构成 + 过程 + 体检 + 创新点」。必须用 Cursor **plan / 待办清单**驱动：先建 plan，再一步一交付，等用户确认后再进入下一步。

### Plan 功能用法

1. 确认可写后，第1步把**本 skill 子步骤**写成可勾选待办（每步一条），并**同步** TodoWrite / CreatePlan（或等价工具）。
2. 回复正文亦展示当前 plan 状态表；**始终只有一个 `in_progress`**。
3. 用户说「下一步/继续」时按 plan 顺序交付下一项；说「一口气讲完」仍分步。
4. **不得跳步、不得合并步骤**（尤其不得跳过术语词典或外行总故事）。

### 硬性规则

1. **第1步只建本 skill 的子步骤 plan**；**不在第1步展开**独权阶段二细目 / 从权全文总览（避免一上来就被撰写流水线淹没）。全案阶段名可在第1步用**三行以内**点到：理解 → 独权 → 从权/说明书；**细目总览改到第8步交接时再列**，并由 `独权撰写` 分流后、结构案/`方法类独权撰写`（方法·算法案）自建阶段二 plan。
2. **一步只做一个交付物**；格式：`【第X步 / 共N步】步骤名称` + 正文 + **更新后的 plan 状态** + 请用户确认 + 预告下一步。
3. **第2步（术语词典）、第4步（外行总故事）**交付后，须明确请用户确认「是否听懂」；用户表示没懂时，**停在该步改写/补释义**，不得强行推进。
4. **本 skill 结束即停**：第8步完成后只提示转入 `独权撰写`，**禁止**同轮开写独权全文。

### 本 skill 子步骤 plan（共8步）

```text
第1步 浅显可写性确认 + 类型判定 + 零行话名片 + 本 skill plan
  ↓
第2步 术语词典（先扫词、先释义）【懂方案的前置】
  ↓
第3步 场景与痛点（只用已释义词）
  ↓
第4步 外行版总故事（整案一气讲完，禁止新词）
  ↓
第5步 整体构成地图（部件/步骤/模块 + 附图对照）
  ↓
第6步 工作过程拆解（主流程 + 分工况；算法加码 I/O 人话）
  ↓
第7步 交底书体检（逻辑 / 形式 / 缺环）【懂之后再检】
  ↓
第8步 创新点剥离 + 问题分层/候选 + 懂了吗验收 + 障碍清单 + 交接
  ↓
（结束 → 转入 `独权撰写` 分流；结构或方法执行层建阶段二 plan）
```

总步数 N = 8。不得擅自增删合并；若用户只要某一步，仍须标明该步在总览中的位置。

## 相对旧流程：删 / 留 / 调序 / 新增（设计说明）

| 动作 | 内容 | 原因 |
|------|------|------|
| **删/外移** | 第1步倾倒独权阶段二细目 + 从权全文总览 | 干扰「读懂」；细目改由独权 skill 自建，本 skill 仅第8步简列阶段名 |
| **删/弱化** | 「默认读者已懂领域词」的隐含前提；构成图里「一句带过」式释义 | 正是「讲完仍不懂」的主因 |
| **保留** | 浅显可写性门禁、plan 一步一交付、禁止产独权、类型判定、场景/构成/过程、创新点剥离、问题候选、障碍清单、交接 | 仍是入口职责 |
| **调序** | **体检从「讲解前」挪到「构成+过程讲完之后」** | 先读懂再体检，才检得准；避免未懂就列一堆形式问题 |
| **新增** | **术语词典**（第2步，**分阶段 A/B/C/D + 列写满含公知人话/类比**）、**外行版总故事**（第4步）、行话门禁、算法 I/O 人话加码、第2/4步「听懂了吗」停步、第8步「懂了吗验收」 | 专治专有名词墙与「讲完仍不懂」；词典观感对齐优化后第一次交付 |

## 第1步：浅显可写性确认 + 类型判定 + 零行话名片 + plan

**本步要做的事：**

1. 一句结论：是否「不算太浅显、可进入读懂」；若太浅显，列缺什么、请发明人补什么，并**终止**。
2. 若可写：
   - 判定主类型：`结构类` / `方法类` / `算法类` / `混合`（混合时写明以哪一类为主叙事）；
   - 建立并同步**本 skill 第2～8步**待办；
   - 用**三行以内**点明后置链路：`理解（本 skill）→ 独权撰写 → 从权/说明书`（不展开独权子步）；
   - 给出**零行话名片**（各不超过两句，**禁止**未释义领域词；暂时用不上的术语一律留到第2步）：
     - **叫什么**（交底标题/主题，可保留原名）；
     - **一句话做什么**（「在什么场合，用什么大类办法，想避免/得到什么」——生活语言）；
     - **最靠中间的那一招**（仍用人话点名贡献点，不堆参数/模块名）。

**本步交付物：** 可写结论 + 类型 + 零行话名片 + 本 skill 子步骤 plan（已同步工具）。  
**本步禁止：** 术语长表、体检表、构成/流程长文、独权细目总览、独权全文。

---

## 第2步：术语词典（先扫词、先释义）

**本步是读懂的前置。** 扫交底书（及附图名）中将反复出现的词，建成词典后再讲方案。交付观感须对齐「优化后第一版」模版：**分阶段小表 + 列写满（含公知人话/类比）**，禁止扁表、禁止公知人话留空。

**收录范围（宁多勿漏）：**

- 领域专有名词、缩写、型号/标准俗称；
- **领域公知常识也要收录进表**（管网、节点、压力表、漏损等底座词），用于搭认知架子；不得因「大家都懂」整行删掉；
- 本案自定义名、图纸习惯名、口语名；
- 算法案：模型/网络/模块名、损失/目标、特征/表征、关键中间量与阈值名；
- 结构/方法案：非常识部件名、工艺术语、特殊工况名。

**每一词必须写满下表各列（不得空列；公知行也不例外）：**

| 列 | 要求 |
|----|------|
| 交底原词 | 原文怎么写 |
| 类型 | 领域公知 / 本案自定义 / 缩写 / 习惯口称 / 算法内部量 等 |
| 人话是什么 | 外行人能懂的定义；禁止只用同领域另一黑话解释。**类型为领域公知时仍须填写人话**，不得留空或「—」 |
| 类比 | 用生活或通用工程类比钉住直觉；**算法/监测优化案各行均应填写**（含公知行），不得整列省略 |
| 本案中干什么用 | 它在本方案里承担的角色（输入/中间结果/判定依据/执行对象等） |

**输出必须分阶段分组（硬性，对齐优化后第一次交付模版）：**

- **禁止**一张无分组的大表一锅端；须拆成 **A / B / C / D…** 多段，每段：`### 标题` + 该段词表。
- **算法 / 监测优化类案默认标题（优先原样沿用，可微调括号说明，层次不乱）：**
  - **A. 管网与监测（业务底座）**——场景对象、监测对象、任务形态、验收指标、初始方案等
  - **B. 仿真与数据**——造数工具、时序/数据集等
  - **C. 模型与「它眼里的世界」**——模型名、内部特征、相似度/聚类、特征簇、信息盲区等
  - **D. 怎么选点（优化策略）**——贡献度、增量优化、双层策略、冗余检测、候选池等
- 结构类等其他案：保持「先底层对象 → 再数据/介质 → 再关键机构或模型视角 → 再运行/优化策略」的分阶段精神，自拟 A/B/C/… 标题，仍须分组。
- 组内词序：先被后文依赖的词在前；跨组引用时，被引用词须已在先出现的组中释义。
- 某组若确无相关词可整组省略，但**不得**为「省事」把有底座词的 A 组整组删掉。

**硬性：**

- 释义中若不得不再用到别的术语，该术语须**同表先于本行出现**或同批补齐。
- 本步结束时列出「暂未释义、后文若出现再补」的观察项（若有），不得假装已穷尽。
- 请用户确认：这些词是否都听懂；没懂的当场重写释义。

**本步交付物：** 分阶段术语词典（A/B/C/D… 小表，列写满）+ 听懂确认请求。  
**本步禁止：** 无分组扁表；公知行「人话/类比」留空；展开完整构成/时序；输出独权；用权要腔堆定义。

## 第3步：场景与痛点（只用已释义词）

站在「现场工程师 / 业务人员」视角，不站在「写权利要求」视角。**正文只用第2步已释义词或日常用语。**

**本步要讲清：**

1. **用在什么场景**（行业、系统位置、典型工况——仅交底书有的）。
2. **现有做法通常怎么做**（客观描述，不升格为检索结论）。
3. **痛点**：改写成「会发生什么不好的事」，2～4 条，且后文手段能对上。
4. **缓解思路**：白话一句，大类手段级，不进零件/公式级。

**本步交付物：** 场景短述 + 痛点列表 + 缓解思路一句。  
**本步禁止：** 零件/步骤级展开；构成图或完整流程图；独权。

---

## 第4步：外行版总故事（整案一气讲完）

在进入「零件图/流程图」之前，先用**一篇短文**把整案讲完，让用户脑中先有电影而非零件表。

**写法要求：**

- 长度：约 150～400 字（复杂案可略长，但仍是「一篇故事」不是说明书）；
- **禁止引入词典外新词**；必须用新词时先补录词典再写；
- 顺序建议：谁在什么场合遇到什么麻烦 → 本案大致怎么处理 → 处理完得到什么好转；
- 算法案须点明：吃进什么信息 → 中间在判断/变换什么 → 吐出什么决策或结果（全部人话）；
- 结束时用 3 句以内「如果只能记住三句」的复述提纲，并请用户确认是否听懂。

**本步交付物：** 外行总故事 + 三句提纲 + 听懂确认请求。  
**本步禁止：** 附图标号长表、完整分模式时序、创新点终表、独权。

---

## 第5步：整体构成地图

按第1步类型选主表达（可辅以另一种）：

| 类型 | 主表达 | 建议形式 |
|------|--------|----------|
| 结构类 | 沿空间/物流等方向的部件布置与连接 | 分层清单 + mermaid；有图则「标号→名称→作用」对照 |
| 方法类 | 步骤先后与条件分支骨架 | 有序列表 + 流程图；标明谁执行、输入输出 |
| 算法类 | 模块/数据/判定的信息流 | 模块图 + 关键数据从哪来到哪去（指回词典与总故事） |
| 混合 | 先装置骨架，再挂运行/算法接口 | 先结构后流程接口，避免两套叙事打架 |

**硬性要求：**

- **先总后分**：先顶层构成，再进关键子系统。
- 每个顶层块只写「是什么 + 在哪 + 跟谁相连/前后是谁」；细部留到第6步。
- 有附图：**必须**标号对照；图文不一致记入障碍，不擅自改图意。
- 块名称优先用词典中的「人话 + 原词」对照，避免只甩原词。

**本步交付物：** 顶层构成 + 关系图/步骤骨架 + 附图对照（若有）+ 本步新发现障碍（若有）。  
**本步禁止：** 完整运行时序长文；创新点终局结论；独权。

---

## 第6步：工作过程拆解

把「静态构成」变成「动态怎么用」。继续遵守行话门禁。

**本步要讲清：**

1. **主流程**（默认工况）：时间顺序「先怎样 → 再怎样 → 对象/信号如何走 → 结束条件」；步骤主语明确。
2. **多通道/多模式**（交底有则分节）：触发条件、入口、路径、与主流程共用段。
3. **关键状态/开关量**：仅交底已有；缺则标障碍。
4. **原文 vs 常理冲突**：显式标注。
5. **算法/方法加码（硬性）：** 对主流程中每个关键步骤，用同一小表或并列句写清：
   - 输入是什么（业务含义，不只是变量名）；
   - 这一步对它做了什么（人话）；
   - 输出是什么、下一步拿它干什么。

推荐：编号步骤 + 可选 mermaid sequence/flowchart。

**本步交付物：** 主流程 + 分模式（若有）+ 关键状态 + 算法 I/O 人话（若适用）+ 原文/理解冲突（若有）。  
**本步禁止：** 独权；把第8步创新点终表提前写完。

---

## 第7步：交底书体检（懂之后再检）

在已具备总故事、构成与过程之后，再体检：

- **逻辑**：问题与方案是否对得上；前后是否矛盾；因果/先后是否说得通；是否违背物理/数学常识。
- **形式**：术语是否一致、命名是否统一、附图与文字是否对应、编号是否混乱。
- **完善性**：缺环（悬空部件/步骤、缺连接或前置条件）、关键参数/实现方式缺失、仅单一实施例等。

能自行统一的形式问题：后续口径一致即可。涉及发明人真实技术选择的缺环：列问题清单，不脑补。

**本步交付物：** 体检结论（可继续/需补）+ 三类问题表 + 摘要。  
**本步禁止：** 重讲整案长文；选定正式主问题表述（候选在第8步）；独权。

## 第8步：创新点剥离 + 问题分层/候选 + 懂了吗验收 + 交接

1. **创新点 vs 惯常剥离表**（各写「交底书依据」）：像贡献的点 / 明显惯常的点 / 尚分不清的点。
2. **技术问题分层 + 待确认主问题候选**：
   - 全部问题可分层（核心 / 入口或伴生 / 辅层）；
   - 各问题与方案特征的对应关系（简述）；
   - 1 个或少量**待确认主问题**候选（标推荐项），供 `独权撰写` 第1步摘录交底声称问题时选用；**正式重新核定与独权正文经 `独权撰写` 分流后，在结构案由 `结构类独权撰写`、方法/算法案由 `方法类独权撰写` 执行**。
3. **懂了吗验收（硬性）：** 给出 3～5 个短问题，用户应能**不看交底书**答出大意（覆盖：场景痛点、总故事、关键块作用、主流程、贡献点）。若答不上，回到第2/4/5/6步补讲，不得假装已读懂。
4. **理解障碍清单**：是否阻塞写第一版独权。
5. **交接：**
   - 障碍不阻塞 → 转入 `独权撰写`（分流；结构案进 `结构类独权撰写`、方法/算法案进 `方法类独权撰写`，自建阶段二 plan：声称问题→解题特征→核心区别→组成最小集（方案完整、不锚定先前问题）→据此写第一版→根据该独权重新核定→第二版；结构案其后保留再上位→第三版→可选变劣→收束）；
   - 需补事实 → 带障碍清单问发明人，暂缓独权；
   - 本步可用**简短**阶段总览（理解已完成 → 独权子步名列表 → 从权/说明书），**仍不写独权正文**。

**本步交付物：** 剥离表 + 问题分层/候选 + 验收题 + 障碍清单 + 下一 skill 衔接说明。  
**本步禁止：** 独权全文；擅自开创造性/说明书；用户未确认就把候选写成「已确认」。

```
阶段一【本 skill】读懂（术语→场景→总故事→构成→过程→体检→候选问题）
```
