# 交底书技术方案理解（本案入口：读懂交底书，所有案件类型通用）

## 适用场景

- 拿到发明人/申请人**交底书**（及附图），准备从零走到正式独权时——**本 skill 是默认入口**。
- 用户需要先判断「能不能写、信息够不够」，并把方案真正读懂，再进入独权撰写。
- 典型触发语：「拿到交底书」「先讲清楚技术方案」「独权前先梳方案」「这个案子到底怎么实现的」「帮我看看交底书」。
- 不区分结构类/方法类/算法类；按案件类型调整构成图 / 步骤链 / 模块数据流的表达形态。

## 一个前提：交底书是否浅显到必须先找发明人

- 如果交底书连「要解决什么问题、用什么手段、核心结构/步骤是什么」都缺失或语焉不详，导致无法讲解、无法后续写独权，则应请发明人补充，**本 skill 后续步骤暂不展开，也不建全流程总览 plan**。
- 如果交底书**不算太浅显**（问题、手段、核心创新点大体能看明白，只是细节缺漏或表述问题），则进入 plan 分步流程，由撰写者在能力范围内补齐形式问题；关键事实缺环标待确认，不脑补。

## AI 使用本 skill 的能力边界（重要）

- 只做**可写性判断、体检、忠实解读与结构化转译**；可纠正交底书中明显违背物理常识的口误式表述，但必须**明示「交底书原文写的是X，按技术常理应理解为Y」**，不得悄悄改写成另一套发明。
- **禁止**在本 skill 内输出独立权利要求全文、从权布局、创造性评述或说明书正文。
- **禁止**为「讲圆」而脑补交底书未记载的关键结构/步骤；缺环标为「理解障碍 / 待发明人确认」。
- 附图存在时必须对照标号；无图时用文字关系图或 mermaid 补「逻辑图」，并注明「非发明人附图」。
- 技术问题分层与主问题**候选**在本 skill 末步给出；**主问题正式确认**与独权正文均在 `独权撰写` 中完成。

## 输出控制（硬性：用 plan 功能控步）

本 skill **禁止**在同一次回复中一次性输出「总览 + 体检 + 构成图 + 全流程 + 创新点 + 主问题清单」。必须用 Cursor **plan / 待办清单功能**驱动全过程：先建 plan，再一步一交付，等用户确认后再进入下一步。

### Plan 功能用法（与意见陈述书 skill 同构，硬性）

1. **必须建立 plan 待办清单**：确认交底书可写后，在第1步把「全流程总览」与「本 skill 子步骤」写成可勾选的待办项（每步一条，不得合并成含糊的大项）。
2. **必须同步到 plan/todo 工具**：环境若提供 TodoWrite、CreatePlan 或等价 plan 文件，第1步**必须调用**创建/覆盖本案待办；其后每推进或完成一步，**必须更新**对应项状态（`pending` / `in_progress` / `completed` / 不适用则 `cancelled`）。不得只在回复里写 plan、不同步工具。
3. **用 plan 驱动全过程**：回复正文中亦须展示当前 plan 状态表；**始终只有一个 `in_progress`**；用户说「下一步/继续」时按 plan 顺序交付下一项，不得跳步、不得一次做多项。
4. **用户说「一口气讲完」仍分步**，并继续按 plan 更新状态。

### 硬性规则

1. **第1步必须先建「全流程总览 plan」+ 本 skill 待办清单**：确认交底书「不算太浅显」后，第1步除方案名片外，**必须**把阶段一（本 skill）与阶段二（`独权撰写`，含可选创造性位置）全部规划进 plan；并同步写入 plan/todo 工具；其后按总览推进，当前只执行本 skill。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步。
3. **不得跳步、不得合并步骤**：不得把构成图与运行流程同批倾倒；不得跳过体检直接讲工况；不得在未建 plan 时直接长文讲解。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + **更新后的 plan 状态** + 请用户确认 + 预告下一步。（第1步的「共N步」指本 skill 子步骤数；总览 plan 另块列出，不与子步骤编号混编。）
5. **始终只有一个「进行中」**（正文与 todo 工具一致）。
6. **本 skill 结束即停**：第6步交付完成后，将本 skill 待办全部标为完成，只提示按总览转入 `独权撰写`（并说明应由独权撰写 skill 新建/续写阶段二 plan 待办），**禁止**同轮自动开写独权全文或创造性评估正文。

### 全流程总览 plan（第1步必列；含可选创造性）

拿到交底书且确认可写后，**第1步必须完整列出**下列总览（不得只列本 skill 子步骤）：

```text
阶段一  交底书技术方案理解【本案入口 / 本 skill】
        （浅显确认 → 体检 → 读懂：名片/场景/构成/过程 → 创新点剥离 + 问题分层/候选）
  ↓
阶段二  独权撰写（三版递进）
        2.1 固定交底书界定的技术问题 + plan
        2.2 第一版独权（按交底书技术问题）
        2.3 重新界定技术问题（须说明界定考虑）
        2.4 第二版独权（对准新问题；无非必要技术特征）
        2.5 【可选】创造性评估与独权补强（对象=第二版）
        2.6 再上位技术问题【须用户确认】
        2.7 第三版独权（清楚 + 保护范围最大）
        2.8 【可选】递交独权变劣与从权回退（独权撰写第8步内嵌，非外挂 skill）
        2.9 正式独权工作稿收束
```

硬性位置：**创造性（可选）在第二版之后、第三版之前**；三版要求依次提高，不得降级合并倾倒。

### 本 skill 子步骤 plan（阶段一内执行，共6步）

```text
第1步 浅显可写性确认 + 全流程总览 plan + 类型判定 + 方案名片
  ↓
第2步 交底书体检（逻辑 / 形式 / 技术方案完善性）
  ↓
第3步 场景与问题（白话）
  ↓
第4步 整体构成地图（部件/步骤/模块 + 附图标号对照）
  ↓
第5步 工作过程拆解（主流程 + 分工况/多通道）
  ↓
第6步 创新点剥离 + 技术问题分层/待确认主问题候选 + 障碍清单 + 交接
  ↓
（结束本 skill → 按总览转入阶段二 `独权撰写`）
```

总步数 N = 6。不得擅自增删合并本 skill 子步骤；若用户只要其中某一步，仍须标明该步在总览与子步骤中的位置。

## 第1步：浅显可写性确认 + 全流程总览 plan + 类型判定 + 方案名片

**本步要做的事：**

1. 一句结论：交底书是否「不算太浅显、可进入撰写前读懂」；若太浅显，列出缺什么、请发明人补什么，并**终止**（不进入第2～6步，也不建总览 plan）。
2. 若可写：
   - **完整列出「全流程总览 plan」**（阶段一～二，含独权撰写 2.1～2.9；创造性可选在第二版与再上位之间；递交变劣可选在第三版与收束之间）；
   - 列出**本 skill 子步骤**第2～6步名称；
   - 判定案件主类型：`结构类` / `方法类` / `算法类` / `混合`（混合时写明以哪一类为主叙事）；
   - 给出**方案名片**（各不超过两句）：
     - **叫什么**（交底书标题/主题名称）；
     - **一句话做什么**（杜绝权利要求腔，用「用A在B场景实现C」）；
     - **最靠中间的那一招**（真正承担发明贡献的那一个手段，先点名、后文再展开）。

**本步交付物：** 可写/可讲结论 + 全流程总览 plan + 本 skill 子步骤**待办清单**（已同步 plan/todo 工具）+ 类型判定 + 方案名片。  
**本步禁止：** 输出体检表、完整结构清单、完整运行步骤、创新点对照表、主问题候选展开、独权全文。

---

## 第2步：交底书体检（逻辑 / 形式 / 技术方案完善性）

在深入讲解构成与工况之前，先给交底书做一次体检：

- **逻辑错误**：技术问题与技术方案是否对得上；前后是否自相矛盾；因果关系、动作先后是否说得通；是否违背物理/数学常识。
- **形式错误**：术语前后是否一致、部件/步骤命名是否统一、附图与文字是否对应、编号是否混乱等。
- **技术方案不完善**：是否存在缺环（部件/步骤悬空、缺少必要连接或前置条件）、关键参数或实现方式缺失、只有单一实施例等。

对能自行补齐的形式缺漏，撰写者在后续讲解中统一口径；对涉及发明人真实技术选择、AI 无法凭空确定的关键缺环，列成问题清单，不要脑补编造。

**本步交付物：** 体检结论（可继续讲解/需补事项）+ 三类问题表（逻辑/形式/缺环）+ 体检结论摘要。  
**本步禁止：** 输出完整构成地图长文、完整运行时序、独权全文；不得在本步最终选定主问题表述（主问题候选在第6步）。

---

## 第3步：场景与问题（白话）

站在「现场工程师 / 运维人员」视角，不站在「权利要求撰写」视角。

**本步要讲清：**

1. **用在什么场景**：行业、装置/系统所处位置、典型工况（仅写交底书有的）。
2. **现有做法通常怎么做**（客观描述，不升格为检索结论）。
3. **痛点是什么**：把交底书背景里的问题改写成「会发生什么不好的事」，条数宜少（2～4条），每条都能在后文方案中找到对应手段。
4. **交底书声称的缓解思路**：仍用白话，对应到「准备靠什么大类手段缓解」，不进入零件级。

**本步交付物：** 场景短述 + 痛点列表（与后文手段可对齐）+ 缓解思路一句话。  
**本步禁止：** 零件/步骤级展开；输出构成图或完整流程图；输出独权。

---

## 第4步：整体构成地图

按第1步判定的类型选一种主表达（可辅以另一种）：

| 类型 | 主表达 | 建议形式 |
|------|--------|----------|
| 结构类 | 沿空间/物流/水流等方向的部件布置与连接 | 分层清单 + mermaid 关系图；有图则做「标号→名称→作用」对照表 |
| 方法类 | 步骤先后与条件分支的骨架 | 有序列表 + 流程图；标明谁执行、输入输出是什么 |
| 算法类 | 模块/数据/判定的信息流 | 模块图 + 关键数据从哪来到哪去 |
| 混合 | 先装置骨架，再挂运行/算法 | 先结构后流程接口，避免两套叙事平行打架 |

**硬性要求：**

- **先总后分**：先给顶层构成，再进入关键子系统；不要一上来陷入某一零件内部。
- **每个顶层块只写「是什么 + 在哪 + 跟谁相连/前后是谁」**，内部细部留到第5步按需展开。
- 交底书有附图时：**必须**做附图标号对照；发现图文不一致，记入「理解障碍」，不要擅自改图意。
- 自定义、非常识名词：用一句人话解释「它在本交底书里指什么」。

**本步交付物：** 顶层构成说明 + 关系图（或步骤骨架）+ 附图对照表（若有）+ 本步新发现的图文/术语障碍（若有）。  
**本步禁止：** 完整运行时序长文（留给第5步）；创新点终局结论（留给第6步）；输出独权。

---

## 第5步：工作过程拆解

把「静态构成」变成「动态怎么用」。

**本步要讲清：**

1. **主流程**（默认工况）：按时间顺序写清「先怎样 → 再怎样 → 介质/对象/信号如何走 → 结束条件」。
2. **多通道 / 多模式**（交底书有则分节）：每一模式单独一小段，写清**触发条件、入口、路径、与主流程的共用段**。
3. **关键开关量/状态**：仅写交底书已有信息，缺则标障碍。
4. **物理/逻辑方向自检**：若交底书用语与常理冲突，显式标注「原文 vs 理解」。

推荐用「编号步骤 + 可选 mermaid sequence/flowchart」；步骤主语必须明确。

**本步交付物：** 主流程 + 分模式流程（若有）+ 关键状态说明 + 原文/理解冲突标注（若有）。  
**本步禁止：** 输出独权；把第6步的「创新点 vs 惯常」终表提前写完。

---

## 第6步：创新点剥离 + 技术问题分层/待确认主问题候选 + 交接

**本步要做的事：**

1. **创新点 vs 惯常部分剥离表**（各写「交底书依据」）：看起来像发明贡献的点 / 明显惯常的点 / 尚分不清的点。
2. **技术问题分层 + 待确认主问题候选**：
   - 列出交底书方案解决的全部技术问题（可分层：核心层 / 入口或伴生层 / 辅层）；
   - 简要说明各问题与方案特征的对应关系；
   - 给出 1 个或少量**待确认主问题**候选（标注推荐项），供 `独权撰写` 在「重新界定技术问题」步选用或改写；**正式重新界定与三版独权正文均在 `独权撰写`**。
3. **理解自检**：用 3～5 个短问题，用户应能不看交底书答出大意。
4. **仍存理解障碍清单**：汇总未消化的缺环，标明是否阻塞写第一版独权。
5. **交接提示**（由用户确认）：
   - 障碍不阻塞 → 转入 `独权撰写` 从 **2.1 / 第一版独权**开始；
   - 需要先补事实 → 带着障碍清单问发明人，暂缓独权。

**本步交付物：** 剥离表 + 问题分层 + 待确认主问题候选 + 自检问题 + 障碍清单（含是否阻塞独权）+ 下一 skill 衔接说明。  
**本步禁止：** 输出独权全文；擅自开始创造性补强或说明书；在用户未确认前把候选主问题写成「已确认」。

## 与其他 skill 的衔接顺序

```
【入口第1步已规划的总览】
阶段一【本 skill】交底书技术方案理解（读懂 + 问题分层/候选）
  → 阶段二 独权撰写（三版递进）
        第一版（交底问题）→ 重新界定问题 → 第二版（无非必要）
        →【可选】创造性 → 再上位 → 第三版（清楚+最大范围）→【可选】递交变劣 → 收束
  → 通用/说明书撰写
  → 权利要求质检/权利要求书质检
```

- 与 `独权撰写` 的分工：本 skill 只负责读懂与问题**分层/候选**，**不产出独权**；三版独权与正式重新界定均在 `独权撰写`。
- 与 `创造性评估与独权补强` 的分工：理解阶段的「创新点剥离」是读懂用工作假设；创造性可选，插在**第二版之后、第三版之前**。
- 与说明书各 skill 的分工：本 skill 的白话讲解与关系图可作代理人笔记，**不是**说明书定稿素材的替代件。
