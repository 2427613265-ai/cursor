# 交底书技术方案理解（撰写独权前的读懂程序，所有案件类型通用）

## 适用场景

- 已拿到交底书（及附图），且交底书**不算太浅显**、体检已完成或至少主线可读。
- 用户需要的是：**先真正读懂方案**，再进入初版独权或按主问题修订独权。
- 典型触发语：「帮我理解交底书」「先讲清楚技术方案」「独权前先梳方案」「这个案子到底怎么实现的」。
- 不区分结构类/方法类/算法类；按案件类型调整第2～4步的表达形态（部件图 / 步骤链 / 模块数据流）。

## 一个前提

- 若交底书连「问题—手段—核心结构/步骤」都缺失，应先回到 `交底书评估和独权初步撰写` 的浅显判断，或请发明人补充；**本 skill 不硬讲空方案**。
- 本 skill 服务对象是**撰写者理解**，不是向发明人做技术交底；表述以「代理人能复述、能画图、能指出创新点」为准。

## AI 使用本 skill 的能力边界（重要）

- 只做**忠实解读与结构化转译**；可纠正交底书中明显违背物理常识的口误式表述，但必须**明示「交底书原文写的是X，按技术常理应理解为Y」**，不得悄悄改写成另一套发明。
- **禁止**在本 skill 内输出独立权利要求全文、从权布局、创造性评述或说明书正文。
- **禁止**为「讲圆」而脑补交底书未记载的关键结构/步骤；缺环标为「理解障碍 / 待发明人确认」，不要假装已经懂了。
- 附图存在时必须对照标号；无图时用文字关系图或 mermaid 补「逻辑图」，并注明「非发明人附图」。

---

## 输出控制（硬性：用 plan 控步）

本 skill **禁止**在同一次回复中一次性输出「白话总览 + 构成图 + 全流程 + 创新点剥离」。必须用 **plan** 驱动，一步只交一个交付物，等用户确认后再进入下一步。

### 硬性规则

1. **先建 plan，再按 plan 交付**：确认可讲之后，**第1步**建立本 skill 内的 plan；其后严格按 plan 顺序推进。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步；用户说「一口气讲完」时仍分步。
3. **不得跳步、不得合并步骤**：不得把构成图与运行流程同批倾倒；不得在未建 plan 时直接长文讲解。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + 请用户确认 + 预告下一步。
5. **始终只有一个「进行中」**：plan 中已完成项标记完成，当前项进行中，后续项待办。
6. **本 skill 结束即停**：第5步交付完成后，只提示返回/转入下一 skill，**禁止**同轮自动开写独权。

### 本 skill 固定 plan（共5步）

```text
第1步 可讲确认 + 案件类型判定 + 建立 plan + 一句话方案名片
  ↓
第2步 场景与问题（白话）：用在哪、痛在哪、交底书声称怎么缓解
  ↓
第3步 整体构成地图：部件/步骤/模块关系 + 附图标号对照（若有）
  ↓
第4步 工作过程拆解：主流程 + 分工况/多通道（若有）按时间顺序讲清
  ↓
第5步 创新点 vs 惯常部分剥离 + 理解自检 + 仍存障碍清单 + 交接
  ↓
（结束本 skill → 返回交底书评估写初版独权，再转入 `独权撰写`）
```

总步数 N = 5。不得擅自增删合并；若用户只要其中某一步，仍须标明该步在 plan 中的位置。

---

## 第1步：可讲确认 + 类型判定 + plan + 一句话方案名片

**本步要做的事：**

1. 用一两句确认：交底书是否已具备「可讲解」的最低信息（对象、问题方向、核心手段）。
2. 判定案件主类型：`结构类` / `方法类` / `算法类` / `混合`（混合时写明以哪一类为主叙事）。
3. 列出完整 5 步 plan，标明下一步为第2步。
4. 给出**方案名片**（各不超过两句）：
   - **叫什么**（交底书标题/主题名称）；
   - **一句话做什么**（杜绝权利要求腔，用「用A在B场景实现C」）；
   - **最靠中间的那一招**（真正承担发明贡献的那一个手段，先点名、后文再展开）。

**本步交付物：** 可讲结论 + 类型判定 + 完整 plan + 方案名片。  
**本步禁止：** 展开完整结构清单、完整运行步骤、创新点对照表；禁止输出独权。

---

## 第2步：场景与问题（白话）

站在「现场工程师 / 运维人员」视角，不站在「权利要求撰写」视角。

**本步要讲清：**

1. **用在什么场景**：行业、装置/系统所处位置、典型工况（如高水头、已建枢纽、场地受限等——仅写交底书有的）。
2. **现有做法通常怎么做**（客观描述，不升格为检索结论）。
3. **痛点是什么**：把交底书背景里的问题改写成「会发生什么不好的事」，条数宜少（2～4条），每条都能在后文方案中找到对应手段。
4. **交底书声称的缓解思路**：仍用白话，对应到「准备靠什么大类手段缓解」，不进入零件级。

**本步交付物：** 场景短述 + 痛点列表（与后文手段可对齐）+ 缓解思路一句话。  
**本步禁止：** 零件/步骤级展开；输出构成图或完整流程图；输出独权。

---

## 第3步：整体构成地图

按第1步判定的类型选一种主表达（可辅以另一种）：

| 类型 | 主表达 | 建议形式 |
|------|--------|----------|
| 结构类 | 沿空间/物流/水流等方向的部件布置与连接 | 分层清单 + mermaid 关系图；有图则做「标号→名称→作用」对照表 |
| 方法类 | 步骤先后与条件分支的骨架 | 有序列表 + 流程图；标明谁执行、输入输出是什么 |
| 算法类 | 模块/数据/判定的信息流 | 模块图 + 关键数据从哪来到哪去 |
| 混合 | 先装置骨架，再挂运行/算法 | 先结构后流程接口，避免两套叙事平行打架 |

**硬性要求：**

- **先总后分**：先给顶层构成（系统由哪些大块组成），再进入关键子系统；不要一上来陷入某一零件内部。
- **每个顶层块只写「是什么 + 在哪 + 跟谁相连/前后是谁」**，内部细部留到第4步按需展开。
- 交底书有附图时：**必须**做附图标号对照；发现图文不一致，记入「理解障碍」，不要擅自改图意。
- 自定义、非常识名词：用一句人话解释「它在本交底书里指什么」。

**本步交付物：** 顶层构成说明 + 关系图（或步骤骨架）+ 附图对照表（若有）+ 本步新发现的图文/术语障碍（若有）。  
**本步禁止：** 完整运行时序长文（留给第4步）；创新点终局结论（留给第5步）；输出独权。

---

## 第4步：工作过程拆解

把「静态构成」变成「动态怎么用」。

**本步要讲清：**

1. **主流程**（默认工况）：按时间顺序写清「先怎样 → 再怎样 → 鱼/介质/信号如何走 → 结束条件」。
2. **多通道 / 多模式**（交底书有则分节）：每一模式单独一小段，写清**触发条件、入口、路径、与主流程的共用段**。
3. **关键开关量/状态**：哪些门、阀、叠梁门、泵、开关在过鱼（或本方案运行）时处于什么状态；与通航/检修等其他工况如何互斥——仅写交底书已有信息，缺则标障碍。
4. **物理/逻辑方向自检**：水流、力、数据、控制方向是否自洽；若交底书用语与常理冲突，按能力边界规则显式标注「原文 vs 理解」。

推荐用「编号步骤 + 可选 mermaid sequence/flowchart」；步骤主语必须明确（哪个部件/谁在动作）。

**本步交付物：** 主流程 + 分模式流程（若有）+ 关键状态说明 + 原文/理解冲突标注（若有）。  
**本步禁止：** 输出独权；把第5步的「创新点 vs 惯常」终表提前写完（可在流程中自然点到，但不做剥离表）。

---

## 第5步：创新点剥离 + 理解自检 + 交接

**本步要做的事：**

1. **创新点 vs 惯常部分剥离表**（各写「交底书依据」）：

| 类别 | 内容 | 依据 |
|------|------|------|
| 看起来像发明贡献的点 | … | 交底书哪一段/哪一图 |
| 明显属于既有船闸/通用设施的点 | … | … |
| 尚分不清贡献还是惯常的点 | … | 待确认 |

2. **理解自检**（写给用户勾认，不是考试）：用 3～5 个短问题，用户应能不看交底书答出大意，例如：
   - 连续诱导水流是从哪来的、经过哪些空间？
   - 鱼类进闸有几条路、各自靠什么集中水流？
   - 若拆掉「底节专用门」，方案还能否成立？
3. **仍存理解障碍清单**：汇总第2～4步未消化的缺环（结构不明、名词悬空、图文冲突、工况未交代等），标明是否阻塞写初版独权。
4. **交接提示**（二选一，由用户确认）：
   - 障碍不阻塞 → 返回 `交底书评估和独权初步撰写` 写**交底书初版独权**（或若该 skill 已跑完体检，直接进入其初版独权步）；初版与主问题清单完成后，再转入 `独权撰写`；
   - 需要先补事实 → 带着障碍清单问发明人，暂缓独权。

**本步交付物：** 剥离表 + 自检问题 + 障碍清单（含是否阻塞独权）+ 下一 skill 衔接说明。  
**本步禁止：** 输出独权全文；擅自开始创造性补强或说明书。

## 与其他 skill 的衔接

本 skill 插在「交底书能读」与「动笔写独权」之间：

```
交底书评估和独权初步撰写
  （浅显确认 → 体检）
    →【本 skill】交底书技术方案理解（读懂）
      → 返回交底书评估：初版独权 → 主问题/待确认
        → 独权撰写（确认主问题 → 按主问题修订 → 再上位并筛选/下放）
        → 创造性评估与独权补强
        → ……
```

- 与 `交底书评估和独权初步撰写` 的分工：评估 skill 负责可写性、体检、初版独权转化、主问题清单；**本 skill 只负责让撰写者读懂**，不产出独权。
- 与 `独权撰写` 的分工：理解结束后不直接写正式独权；正式独权（含再上位）在评估 skill 交出初版与待确认主问题之后，由 `独权撰写` 承担。
- 与 `创造性评估与独权补强` 的分工：理解阶段的「创新点剥离」是**读懂用的工作假设**，不是检索后的创造性结论；不得在本 skill 宣称「已具备创造性」。
- 与说明书各 skill 的分工：本 skill 的白话讲解与关系图可作代理人笔记，**不是**说明书定稿素材的替代件；正式说明书仍按说明书 skill 撰写。

---

## 表达风格（贯穿各步）

- **先人话，后术语**：首次出现术语时用括号或短句解释。
- **短段落 + 列表 + 图**：避免长篇权利要求腔复述交底书。
- **一次只加深一层**：总览 → 场景问题 → 构成 → 过程 → 贡献剥离。
- **承认不懂**：讲不清处明确标出，优于用流畅文笔掩盖。
