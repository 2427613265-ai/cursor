# 独权撰写（正式独权阶段，所有案件类型通用）

## 适用场景

- 已完成 `交底书技术方案理解` 与 `交底书评估和独权初步撰写`，手头有**交底书初版独权**和**待确认主问题**。
- 现在要做的是：**正式撰写独权**——确认主问题、按主问题修订，再上位一层技术问题并据此再次修改独权（筛选/下放特征）。
- 不负责交底书体检、初版独权忠实转化；也不负责创造性评估与补强（那些在本 skill 之后）。

## 典型触发

- 「按主问题改独权」「正式写独权」「再上位一下技术问题」「独权撰写」
- 交底书初步撰写结束后，用户确认主问题并要求继续

## AI 使用本 skill 的能力边界（重要）

- 本 skill 产出的是**正式独权工作稿**（含必要时的上位修订版），不是创造性结论，也不是最终说明书定稿。
- 上位与下放不得编造交底书未记载、且未经用户/发明人确认的新结构/步骤；缺事实标「待确认」。
- 具体措辞、句式、部件铺陈顺序，按案件类型参照 `结构类权利要求撰写` 等类型规范，并对照通用分支下的主谓宾、指代、自定义名词等规范；本 skill 管**策略步骤与内容取舍**，类型 skill 管**表达形态**。
- 必要技术特征的逐特征反问细则，复用 `独立权利要求必要技术特征检查`，不在本 skill 重复展开判断口诀。

---

## 输出控制（硬性：用 plan 控步）

本 skill **禁止**在同一次回复中一次性输出「主问题确认 + 按主问题修订独权 + 再上位后独权」。必须用 **plan** 驱动，一步只交一个交付物，等用户确认后再进入下一步。

### 硬性规则

1. **先建 plan，再按 plan 交付**：第1步建立本 skill 内的 plan；其后严格按序推进。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步；用户说「一口气写完」时仍分步。
3. **不得跳步**：不得跳过主问题确认直接写上位独权；不得把「按主问题修订」与「再上位修订」同批输出。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + 请用户确认 + 预告下一步。
5. **始终只有一个「进行中」**。
6. **本 skill 结束即停**：第4步交付完成后，只提示可转入 `创造性评估与独权补强`，**禁止**同轮自动开跑创造性全文或说明书。

### 本 skill 固定 plan（共4步）

```text
第1步 确认主技术问题 + 建立 plan
  ↓
第2步 按已确认主问题修订独权（输出「按主要技术问题修订后的独权」）
  ↓
第3步 审查是否需要进一步上位技术问题，并做第二轮独权筛选/成组下放
  ↓
第4步 输出正式独权工作稿收束 + 待确认事项 + 交接下一 skill
  ↓
（结束本 skill → 创造性评估与独权补强）
```

总步数 N = 4。不得擅自增删合并；若用户只要其中某一步，仍须标明该步在 plan 中的位置。

若第3步审查结论为「主问题已足够上位、无需再上位」，则第3步交付「无需再上位」的理由与特征保留说明，第4步以第2步独权作为正式工作稿收束——**不得跳过第3步不问**。

---

## 第1步：确认主技术问题 + 建立 plan

**本步要做的事：**

1. 承接 `交底书评估和独权初步撰写` 第5步给出的待确认主问题（及备选）。
2. 以用户提示为准：用户可确认候选、改表述、或另定更深/更侧重的主问题。
3. 列出完整 4 步 plan，标明下一步为第2步。
4. 醒目标注**已确认主技术问题**全文，供后续修订与说明书技术问题陈述对齐。

**本步交付物：** 已确认主问题 + 完整 plan。  
**本步禁止：** 输出修订后独权全文；展开上位分层长文。

---

## 第2步：按已确认主问题修订独权

在交底书初版独权基础上，使独权记载的技术方案与已确认主问题**精准对应**。

执行要求：

- **前序与特征选取均服务于该主问题**；与主问题无关或可由从权覆盖的特征，可考虑后移。
- **写成完整独权正文**（含前序与「其特征在于」之后的特征部分），标注为「按主要技术问题修订后的独权」。
- **对照说明**：相对交底书初版独权做了哪些调整、各调整与主问题的对应关系。
- 表达形态按案件类型调用 `结构类`/`方法类`/`算法类` 权利要求撰写规范。

**本步交付物：** 「按主要技术问题修订后的独权」全文 + 相对初版的调整要点。  
**本步禁止：** 同批做进一步上位审查或输出「按更上位技术问题再次修订后的独权」；不得进入创造性评述。

---

## 第3步：再上位技术问题 + 第二轮独权筛选（本 skill 核心）

在第2步已得到「按主要技术问题修订后的独权」之后，**不要立即将其视为最终独权**。应进一步审查：该主问题是否仍偏具体，是否还存在继续上位概括的空间；若存在，则据此对独权做第二轮筛选与成组下放。

这一步是正式独权撰写内部的缓冲层，位于创造性评估**之前**，用于避免把仅服务于较具体问题的一整组特征过早写死在最宽独权中。

执行要求：

- **先问技术问题是否仍偏具体**：看当前解决的是本质问题、实施层问题，还是某种优选效果层问题；若仍明显贴近具体实施方式、具体性能目标或具体应用场景，应考虑再上位一层。
- **把技术问题分层看待**：至少区分上位技术问题、当前主要技术问题、以及更具体的次级技术问题，并梳理各层与独权特征的对应关系。
- **重新核查必要技术特征**：对第2步独权再次逐特征提问——「如果把该特征删除、概括或改写为更宽泛的说法，方案是否仍能解决更上位的技术问题？」若能，则该特征相对于更上位问题已非必要，可考虑移出。细则调用 `独立权利要求必要技术特征检查`。
- **允许成组下放，不鼓励零碎拆散**：只在解决较具体技术问题时才必要的多个关联特征，宜作为一组整体下放到从属权利要求。
- **保留当前最小创造性骨架**：**不得为了给后续答复留后手，而把支撑当前创造性的核心区别技术特征整体提前下放**。独权中仍应保留足以支撑当前拟主张创造性的最小技术特征集。
- **说明书同步公开**：凡拟下放的一组特征及其对应的较具体问题、效果、替代实施方式，均应在说明书中充分公开（本步只列明下放清单与公开提示，不写说明书正文）。
- **输出**：若发生上位与精简，输出「按更上位技术问题再次修订后的独权」，并说明相对第2步哪些特征保留为最宽骨架、哪些成组下放及各自对应的次级问题/效果；若无需再上位，明确写明理由。

**本步交付物：** 上位与否结论 +（若上位）再次修订后的独权全文 + 下放特征组清单（或「无需再上位」说明）。  
**本步禁止：** 输出创造性评估全文；同批写说明书实施例。

---

## 第4步：正式独权工作稿收束 + 交接

收束本 skill 的工作结果：

1. 标明**正式独权工作稿**是第3步后的版本（若未再上位，则为第2步版本）。
2. 列出仍待确认事项（若有）。
3. 提示下一步转入 `创造性评估与独权补强`（对该正式工作稿做创造性初判；不足再补强）。
4. **本 skill 到此结束**，不自动连跑。

**本步交付物：** 正式独权工作稿定位说明 + 待确认事项 + 下一 skill 衔接。  
**本步禁止：** 同轮输出创造性初判长文或补强独权。

---

## 与其他 skill 的衔接顺序

```
交底书技术方案理解
  → 交底书评估和独权初步撰写（初版独权 + 待确认主问题）
  →【本 skill】独权撰写（确认主问题 → 按主问题修订 → 再上位并筛选/下放 → 正式工作稿）
  → 创造性评估与独权补强
  → 通用/说明书撰写
  → 权利要求质检/权利要求书质检
```

- 与 `交底书评估和独权初步撰写`：前者只出初版独权与待确认主问题；**按主问题修订、再上位、下放均在本 skill**。
- 与 `独立权利要求必要技术特征检查`：本 skill 第2～3步调用其判断方法；第二轮「再上位 + 下放」的**流程位置在本 skill**，不放到创造性补强之后。
- 与 `创造性评估与独权补强`：本 skill 结束后再评估正式工作稿的创造性；补强若改动了问题或特征，可再回本 skill 做有限轮次的上位/下放复核，但默认主路径是「先独权撰写，后创造性」。
- 与类型权利要求撰写 skill：本 skill 决定写什么、留什么；类型 skill 决定怎么把部件/步骤写清楚。

## 检查清单

- [ ] 已确认主技术问题后再改独权，未擅自定稿主问题
- [ ] 已建 4 步 plan，且未把创造性评估揉进本 plan
- [ ] 第2步与第3步未同批倾倒
- [ ] 第3步已明确回答「是否再上位」；若上位已输出再次修订独权与下放组
- [ ] 未为留后手而把最小创造性骨架整体下放
- [ ] 结束后只提示创造性评估，未自动连跑
