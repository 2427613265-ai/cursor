# 独权撰写（正式独权阶段，所有案件类型通用）

## 适用场景

- 已完成 `交底书技术方案理解`（总览**阶段一**），手头有读懂结论与**待确认主问题候选**；进入入口总览中的**阶段二**。
- 现在要做的是：**从忠实初版独权写到正式工作稿**——初版转化、确认主问题、按主问题修订；**可选**对修订稿做创造性评估与补强；然后再上位一层技术问题并据此再次修改独权（筛选/下放特征）。
- 不负责交底书体检与白话读懂（那属于 `交底书技术方案理解`）。

## 典型触发

- 「写独权」「先起一版独权」「按主问题改独权」「正式写独权」「再上位一下技术问题」
- 技术方案理解结束后，用户确认可写独权并要求继续

## AI 使用本 skill 的能力边界（重要）

- 本 skill 产出的是**独权工作稿**（初版 → 主问题修订稿 → 可选补强稿 → 上位修订稿 → 正式工作稿），不是说明书定稿。
- 上位与下放不得编造交底书未记载、且未经用户/发明人确认的新结构/步骤；缺事实标「待确认」。
- 具体措辞、句式、部件铺陈顺序，按案件类型参照 `结构类权利要求撰写` 等类型规范，并对照通用分支下的主谓宾、指代、自定义名词等规范；本 skill 管**策略步骤与内容取舍**，类型 skill 管**表达形态**。
- 必要技术特征的逐特征反问细则，复用 `独立权利要求必要技术特征检查`，不在本 skill 重复展开判断口诀。
- 创造性评估的实质判断在 `创造性评估与独权补强`；本 skill 第4步只做转入/跳过决策与交接，不在本步倾倒评估全文。

## 输出控制（硬性：用 plan 功能控步）

本 skill **禁止**在同一次回复中一次性输出「初版独权 + 主问题确认 + 按主问题修订独权 + 再上位后独权」。必须用 Cursor **plan / 待办清单功能**驱动全过程：先建 / 回扣 plan，再一步一交付，等用户确认后再进入下一步。

### Plan 功能用法（与意见陈述书 skill 同构，硬性）

1. **必须建立或回扣 plan 待办清单**：第1步把阶段二 2.1～2.6（含可选 2.4）写成可勾选待办项；须**回扣**入口全流程总览编号，不得另起冲突顺序。
2. **必须同步到 plan/todo 工具**：环境若提供 TodoWrite、CreatePlan 或等价 plan 文件，第1步**必须调用**创建/续写本案阶段二待办；其后每推进或完成一步，**必须更新**对应项状态（`pending` / `in_progress` / `completed`；跳过创造性则将 2.4 标为 `cancelled` 并注明「用户跳过」）。不得只在回复里写 plan、不同步工具。
3. **用 plan 驱动全过程**：回复正文中亦须展示当前 plan 状态表；**始终只有一个 `in_progress`**；用户说「下一步/继续」时按 plan 顺序交付下一项，不得跳步、不得一次交付多版独权。
4. **用户说「一口气写完」仍分步**，并继续按 plan 更新状态。

### 硬性规则

1. **先建 / 回扣 plan，再按 plan 交付**：第1步建立本阶段子 plan 待办，并**回扣入口全流程总览**中阶段二的编号（2.1～2.6）；同步写入 plan/todo 工具；其后严格按序推进。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步。
3. **不得跳步**：不得跳过初版独权直接写主问题修订稿；不得跳过主问题确认直接写上位独权；不得把「按主问题修订」与「再上位修订」同批输出；**不得在再上位之后才第一次做创造性评估**。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + **更新后的 plan 状态** + 请用户确认 + 预告下一步。
5. **始终只有一个「进行中」**（正文与 todo 工具一致）。
6. **创造性为可选但位置固定**：第4步由用户决定执行或跳过；若执行，必须针对第3步「按主要技术问题修订后的独权」，完成后再进入第5步再上位；跳过则更新 plan 中 2.4 状态后进入第5步。

### 本 skill 固定 plan（共6步；对应总览 2.1～2.6）

```text
第1步 回扣总览 + 交底书初版独权（忠实转化）
  ↓
第2步 确认主技术问题
  ↓
第3步 按已确认主问题修订独权（输出「按主要技术问题修订后的独权」）
  ↓
第4步 【可选】创造性评估与独权补强
      （转入 `创造性评估与独权补强`；或用户确认跳过）
      评估对象 = 第3步修订稿；补强后以补强稿作为后续再上位的输入
  ↓
第5步 再上位技术问题 + 第二轮独权筛选/成组下放
  ↓
第6步 输出正式独权工作稿收束 + 待确认事项 + 交接
```

总步数 N = 6。不得擅自把第4步挪到第5步之后；若用户只要其中某一步，仍须标明该步在 plan 中的位置。

若第4步跳过：在回复中写明「用户确认跳过创造性评估」，直接进入第5步；第5步输入仍为第3步修订稿。  
若第5步审查结论为「无需再上位」：交付理由与特征保留说明，第6步以第5步输入稿（第3步稿或补强稿）作为正式工作稿——**不得跳过第5步不问**。

若用户在本案中**跳过**了理解 skill 直接要求写独权：第1步须先用简短段落确认「是否已读懂、主问题候选是否已有」；若无，应退回 `交底书技术方案理解`，不得硬写。

## 第1步：回扣总览 + 交底书初版独权（忠实转化）

**本步要做的事：**

1. 回扣入口总览：标明当前为阶段二 / 2.1，列出本 skill 完整 6 步 plan（含可选创造性位置）。
2. 按交底书内容**忠实撰写一版独立权利要求并完整输出**（必做交付物）。

撰写要求：

- **忠实于交底书**：把交底书中发明人描述的技术问题、技术方案、核心结构/步骤/部件，如实转化为一条独立权利要求；此阶段**不刻意拔高、不引入补强构思的新特征**。理解阶段已明示纠正的口误（如方向写反、溢流/管道笔误）按纠正后的技术含义写，并在要点映射中注明。
- **写成完整独权正文**：含前序部分与「其特征在于」之后的特征部分；表达形态按案件类型调用 `结构类`/`方法类`/`算法类` 权利要求撰写规范，并同步对照主谓宾、指代、自定义名词等通用规范。
- **明确标注为「交底书初版独权」**：尚未按主要技术问题定向修订。
- **可选要点映射表**：初版特征块 ↔ 交底书来源。

**本步交付物：** 阶段二 plan **待办清单**（已同步 plan/todo 工具）+ 标注「交底书初版独权」的全文 + 可选映射表。  
**本步禁止：** 同批确认并写死主问题后的修订独权；同批做上位或创造性评述。

---

## 第2步：确认主技术问题

承接 `交底书技术方案理解` 第6步给出的待确认主问题候选（及备选），以及用户对本案的侧重。

执行要求：

1. 以用户提示为准：用户可确认候选、改表述、或另定更深/更侧重的主问题。
2. 若理解阶段候选缺失，本步须先补列分层问题与候选，再请用户确认（仍不改独权正文）。
3. 醒目标注**已确认主技术问题**全文，供后续修订与说明书技术问题陈述对齐。

**本步交付物：** 已确认主问题全文（可附「相对候选的调整说明」）。  
**本步禁止：** 输出修订后独权全文；展开上位分层长文；展开创造性评估正文。

---

## 第3步：按已确认主问题修订独权

在交底书初版独权基础上，使独权记载的技术方案与已确认主问题**精准对应**。

执行要求：

- **前序与特征选取均服务于该主问题**；与主问题无关或可由从权覆盖的特征，可考虑后移。
- **写成完整独权正文**，标注为「按主要技术问题修订后的独权」。
- **对照说明**：相对交底书初版独权做了哪些调整、各调整与主问题的对应关系。
- 表达形态按案件类型调用类型权利要求撰写规范；精简时的逐特征判断可调用 `独立权利要求必要技术特征检查`。

**本步交付物：** 「按主要技术问题修订后的独权」全文 + 相对初版的调整要点 + 预告下一步为可选创造性（或跳过后进入再上位）。  
**本步禁止：** 同批做进一步上位审查；同批输出创造性初判/补强独权全文。

---

## 第4步：【可选】创造性评估与独权补强

在第3步「按主要技术问题修订后的独权」已经交付并经用户确认后执行本步决策。

**执行方式：**

1. 询问用户：是否对本稿做创造性评估与（若不足）补强。
2. **若执行**：明确告知转入同分支 `创造性评估与独权补强`；评估对象固定为第3步修订稿（或用户指定的该稿微调版）；按该 skill 自有 plan 分步交付；完成后回到本 skill，以**补强后独权**（若未补强则为原修订稿）作为第5步输入。
3. **若跳过**：写明「跳过创造性评估与补强」，第5步输入 = 第3步修订稿。

**本步交付物：** 执行/跳过决定 +（若执行）转入声明与返回后的当前独权版本定位（修订稿 / 补强稿）。  
**本步禁止：** 在本步内不经创造性 skill 而自行倾倒长篇创造性评述与补强独权；禁止在未完成第3步时进入本步。

---

## 第5步：再上位技术问题 + 第二轮独权筛选

在第3步修订稿（或第4步补强稿）基础上，**不要立即将其视为最终独权**。应进一步审查：当前技术问题是否仍偏具体，是否还存在继续上位概括的空间；若存在，则据此对独权做第二轮筛选与成组下放。

执行要求：

- **先问技术问题是否仍偏具体**：本质问题 / 实施层问题 / 优选效果层问题。
- **把技术问题分层看待**：上位技术问题、当前主要技术问题、更具体的次级技术问题，并梳理与独权特征的对应关系。
- **重新核查必要技术特征**：逐特征提问「删除、概括或改写为更宽泛说法后，是否仍能解决更上位的技术问题？」细则调用 `独立权利要求必要技术特征检查`。
- **允许成组下放，不鼓励零碎拆散**。
- **保留当前最小创造性骨架**：**不得为了给后续答复留后手，而把支撑当前创造性的核心区别技术特征整体提前下放**。若第4步刚补强过，尤须避免把刚补进独权的最小骨架整组下放。
- **说明书同步公开提示**：拟下放的特征组应在说明书中充分公开（本步只列下放清单与公开提示，不写说明书正文）。
- **输出**：若发生上位与精简，输出「按更上位技术问题再次修订后的独权」+ 下放特征组清单；若无需再上位，明确写明理由。

**本步交付物：** 上位与否结论 +（若上位）再次修订后的独权全文 + 下放特征组清单（或「无需再上位」说明）。  
**本步禁止：** 同批写说明书实施例；把本步前移到创造性之前（默认禁止）。

---

## 第6步：正式独权工作稿收束 + 交接

收束本 skill 的工作结果：

1. 标明**正式独权工作稿**是第5步后的版本（若未再上位，则为第5步的输入稿：第3步修订稿或第4步补强稿）。
2. 列出仍待确认事项（若有）。
3. 提示下一步可转入说明书撰写等；若第4步跳过且用户事后仍要评创造性，说明需另开创造性 skill。
4. **本 skill 到此结束**，不自动连跑说明书。

**本步交付物：** 正式独权工作稿定位说明 + 待确认事项 + 下一环节衔接。  
**本步禁止：** 同轮输出说明书定稿。

## 与其他 skill 的衔接顺序

```
【入口总览】
阶段一  交底书技术方案理解（读懂 + 主问题候选）
  → 阶段二【本 skill】
        2.1 初版独权 → 2.2 确认主问题 → 2.3 按主问题修订
        → 2.4【可选】创造性评估与独权补强
        → 2.5 再上位并筛选/下放 → 2.6 正式工作稿收束
  → 通用/说明书撰写
  → 权利要求质检/权利要求书质检
```

- 与 `交底书技术方案理解`：前者是入口，第1步列出含本阶段的总览 plan；只负责读懂与主问题候选，不写独权。
- 与 `创造性评估与独权补强`：**可选**；插在本 skill 第3步与第5步之间；评估对象为「按主要技术问题修订后的独权」。
- 与 `独立权利要求必要技术特征检查`：本 skill 第5步（及第3步精简时）调用其判断方法。
- 与类型权利要求撰写 skill：本 skill 决定写什么、留什么；类型 skill 决定怎么把部件/步骤写清楚。

## 检查清单

- [ ] 已回扣总览 2.1～2.6；创造性（若有）在按主问题修订之后、再上位之前
- [ ] 已建立/续写阶段二 plan **待办清单**，并已同步 TodoWrite/CreatePlan（或等价工具）；每步已更新状态
- [ ] 第1步已输出「交底书初版独权」，且忠实未补强
- [ ] 已确认主技术问题后再出「按主问题修订后的独权」
- [ ] 第1、3、5步未同批倾倒多版独权
- [ ] 第4步已明确执行或跳过创造性（并更新 plan 中 2.4 状态）
- [ ] 第5步已明确回答「是否再上位」
- [ ] 未为留后手而把最小创造性骨架整体下放
- [ ] 结束后未自动连跑说明书
