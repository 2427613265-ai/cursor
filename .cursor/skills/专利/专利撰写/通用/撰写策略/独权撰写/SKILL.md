# 独权撰写（正式独权阶段 · 整合优化版，所有案件类型通用）

## 适用场景

- 已完成 `交底书技术方案理解`（总览**阶段一**），手头有读懂结论与**待确认主问题候选**；进入入口总览中的**阶段二**。
- 从**忠实初版独权**推进到**正式独权工作稿**：对准主问题 → 可选创造性 → 问题层再上位与成组下放 → 特征/名称层优化 → 收束。
- 不负责交底书体检与白话读懂（`交底书技术方案理解`）；不代替说明书定稿；不代替整份权利要求书质检（收束后可转）。

## 典型触发

- 「写独权」「先起一版独权」「按主问题改独权」「正式写独权」「再上位」「优化独权」「把部件名再上位」
- 技术方案理解结束后，用户确认可写独权并要求继续

## 本 skill 与配套 skill 的分工（先读）

| 角色 | Skill | 本流程中的位置 |
|------|--------|----------------|
| 入口/读懂 | `交底书技术方案理解` | 阶段一；交出主问题候选与障碍清单 |
| **策略主控（本文件）** | `独权撰写` | 阶段二 2.1～2.7；决定写什么、留什么、何时上位/下放/优化 |
| 可选创造性 | `创造性评估与独权补强` | 仅第4步转入；对象=按主问题修订稿；结束后回第5步 |
| 必要特征判断细则 | `独立权利要求必要技术特征检查` | 第3/5/6步精简或上位时调用；不另起大阶段 |
| 结构类铺陈 | `结构类权利要求撰写` | 结构类案件凡输出独权正文时 |
| 功能性限定边界 | `功能性限定使用边界规范` | 凡用「用于/能够/以使」等时 |
| 表达通则 | `主谓宾` / `指代与参照` / `自定义名词就地定义` / `清楚性与逻辑一致性` | 凡输出独权正文时自查 |
| 方法/算法专项 | `条件判断语句规范` / `预设值与参数来源检查` | 方法类、算法类独权 |
| 写后质检 | `单条权利要求审查` / `权利要求书质检` | **本 skill 结束后**按需转入 |
| 说明书对齐 | `说明书技术问题陈述撰写` / `说明书有益效果撰写` | 收束后提示对齐已确认（上位）技术问题与独权效果 |

**硬性：** 细则 skill 的判断口诀**不在本文件全文复制**；本文件给出**调用时机 + 独权正文质量闸门（摘要）**。改版本 skill 时，步骤内写作要求默认整段保留，禁止为「清交叠」而压短细则。

## AI 使用本 skill 的能力边界

- 产出是**独权工作稿链**（初版 → 主问题修订稿 → 可选补强稿 → 上位修订稿 → 优化稿 → 正式工作稿），不是说明书定稿、不是从权全文树（仅列下放/保留组清单）。
- 不得编造交底书未记载且未经用户/发明人确认的新结构/步骤；缺事实标「待确认」。
- 理解阶段已明示的口误纠正（如方向写反）按纠正含义写入，并在映射/对照中注明。
- 创造性实质判断只在 `创造性评估与独权补强` 内展开；本 skill 第4步只做执行/跳过与交接。

## 输出控制（硬性：plan 功能控步）

禁止同一次回复倾倒「初版 + 主问题确认 + 主问题独权 + 上位独权 + 优化独权」。必须用 Cursor **plan / 待办清单**驱动。

### Plan 功能用法（硬性）

1. 第1步把 2.1～2.7（含可选 2.4）写成待办；**回扣**入口总览编号。
2. 同步 TodoWrite / CreatePlan（或等价工具）；每步更新 `pending` / `in_progress` / `completed`；跳过创造性则 2.4=`cancelled`。
3. 正文展示 plan 状态；**始终一个 `in_progress`**；「下一步/继续」按序一项；「一口气写完」仍分步。

### 硬性规则

1. 先建/回扣 plan，再交付。
2. 一步一个交付物；须用户确认后推进。
3. 不得跳过初版直接写主问题修订稿；不得跳过主问题确认直接上位；不得把「按主问题修订 / 再上位 / 优化」同批输出；不得在再上位之后才第一次评创造性；不得未经第6步（或「无需优化」说明）直接收束。
4. 格式：`【第X步 / 共N步】` + 正文 + **plan 状态** + 请确认 + 预告下一步。
5. 凡本步**输出独权全文**，交付前须过下方「独权正文质量闸门」。

### 固定 plan（共7步 = 总览 2.1～2.7）

```text
第1步 回扣总览 + 交底书初版独权（忠实转化）
  ↓
第2步 确认主技术问题
  ↓
第3步 按已确认主问题修订独权
  ↓
第4步 【可选】创造性评估与独权补强  → 回第5步
  ↓
第5步 再上位技术问题 + 第二轮筛选/成组下放
  ↓
第6步 优化独权（特征/名称上位、扩大保护范围、表达简洁清楚）
  ↓
第7步 正式独权工作稿收束 + 待确认事项 + 交接
```

- 第4步跳过 → 第5步输入=第3步稿。  
- 第5步「无需再上位」→ 仍须进第6步（输入=第5步之输入稿）。  
- 第6步「无需优化」→ 第7步以第5步输出稿或输入稿为正式稿。  
- 未完成理解却直接要写独权：第1步先确认读懂与主问题候选；否则退回理解 skill。

## 独权正文质量闸门（凡输出独权全文必过）

输出前快速自查；不通过则先改再交付。细则见对应 skill，此处为摘要闸门。

### A. 策略与必要特征（对齐当前锚定技术问题）

- 每个特征：去掉或改宽后，**当前锚定问题**是否仍解决？能则删/概括/下放（`独立权利要求必要技术特征检查`）。
- 警惕三类非必要写死：**数量词、排列方式、具体机构/工艺/驱动**（除非恰为发明点）。
- **最小创造性骨架**不得整组下放；下放宜**成组**，并对应次级问题/效果；拟下放内容须能在说明书公开（本流程只列清单）。

### B. 类型铺陈

| 类型 | 要点 | 主规范 |
|------|------|--------|
| 结构类 | 「其特征在于」后**先一句列全本层部件**，再按序展开位置/连接/自身结构；子部件递归先列后展 | `结构类权利要求撰写` |
| 方法类 | 步骤有序；条件用规范判断句式；主语为执行者 | `条件判断语句规范` + 主谓宾 |
| 算法类 | 模块/数据来源清楚；预设值/阈值须先获取后使用 | `预设值与参数来源检查` + 条件判断 |
| 混合 | 先装置骨架，再挂运行接口，避免两套叙事打架 | 理解阶段类型判定 |

### C. 表达清楚

- 主谓宾完整，动作有执行者（`权利要求主谓宾结构规范`）。
- 优先「所述+全名」；少用「该/其」；方位词有参照物（`指代与参照清晰性规范`）。
- 非公知自定义名词用「其中，……」就地定义（`自定义名词就地定义`）。
- 无孤岛特征、无未定义术语突现、术语前后一致（`清楚性与逻辑一致性规范`）。
- 功能性限定：默认结构；仅当结构说不清或功能更清楚简洁时使用；禁止结构已清仍堆「从而实现××效果」（`功能性限定使用边界规范`）。

### D. 支持与范围（撰写期观察，详质检后置）

- 不编造无交底支持的特征；理解障碍未消的写成待确认，不假装已定。
- 概括不得宽到无法实施或明显无区分度而不自知；过窄则在第5/6步处理。
- 「说明书尚未同步」本身不在本 skill 当缺陷扣分；记入收束时的「待同步说明书事项」。

## 第1步：回扣总览 + 交底书初版独权（忠实转化）

1. 标明阶段二 / 2.1；列出完整 7 步 plan；同步 todo。  
2. **忠实**输出完整独立权利要求全文（必做）。

要求：

- 覆盖交底书核心结构/步骤；不拔高、不补强新特征；理解阶段口误纠正须注明。
- 完整前序+「其特征在于」+特征部分；过**质量闸门**（本步以忠实完整为主，必要特征精简从宽，明显笔误与指代仍须改）。
- 标注「**交底书初版独权**」；可选「特征块 ↔ 交底书」映射表；作为后续基线。

**调用：** 类型铺陈规范 + 表达通则（闸门 B/C）。  
**交付物：** plan 待办 + 初版独权全文 + 可选映射。  
**禁止：** 同批确认主问题后的修订稿；同批上位/优化/创造性正文。

---

## 第2步：确认主技术问题

承接理解 skill 主问题候选与用户侧重。

1. 用户确认/改写/另定主问题。  
2. 候选缺失则本步先补分层问题与候选，再请确认（仍不改独权正文）。  
3. 醒目标注**已确认主技术问题**全文（供后文修订及日后 `说明书技术问题陈述撰写` 对齐）。

**交付物：** 已确认主问题（可附相对候选调整说明）。  
**禁止：** 输出修订独权；展开上位长文；创造性正文。

---

## 第3步：按已确认主问题修订独权

使独权与已确认主问题**精准对应**。

- 前序与特征服务于该主问题；无关或可从权覆盖的特征后移。
- 精简时调用 `独立权利要求必要技术特征检查`（可与闸门 A 摘要合并自查；若用户要求逐特征长表，再按该 skill 分步）。
- 标注「**按主要技术问题修订后的独权**」；附相对初版调整要点与主问题对应关系。
- 过质量闸门；**本步不做**完整问题层再上位，**不做**第6步级名称/特征全面优化（可修笔误与指代）。

**交付物：** 主问题修订稿全文 + 调整要点 + 预告第4步可选创造性。  
**禁止：** 同批再上位全文；同批优化稿；同批创造性初判/补强独权。

---

## 第4步：【可选】创造性评估与独权补强

第3步稿经确认后询问是否评估。

- **执行：** 转入 `创造性评估与独权补强`；对象=第3步修订稿；按其自有 plan 分步；返回后以补强稿（或未补强的修订稿）为第5步输入。  
- **跳过：** 写明跳过；第5步输入=第3步稿；更新 plan 中 2.4=`cancelled`。

**交付物：** 执行/跳过决定 + 当前独权版本定位。  
**禁止：** 不经创造性 skill 倾倒长篇评述与补强独权；未完成第3步进入本步。

---

## 第5步：再上位技术问题 + 第二轮筛选/成组下放

**问题层扩宽**：在按主问题修订（及可选创造性）之后、表达优化之前，避免把仅服务较具体问题的特征组写死在最宽独权中。

执行要求：

- 判断当前问题是否仍偏具体（本质 / 实施层 / 优选效果层）；区分上位问题、当前主问题、次级问题，并对应到特征。
- 逐特征：相对**更上位问题**是否仍必要？细则=`独立权利要求必要技术特征检查`。
- **成组下放**，不鼓励零碎拆散；每组对应次级问题/效果；列说明书公开提示。
- **保留最小创造性骨架**；刚补强的骨架尤禁整组下放。
- 输出「**按更上位技术问题再次修订后的独权**」+ 骨架保留说明 + 下放特征组清单；或「无需再上位」及理由。
- 可做必要表述清理；**系统的名称上位、特征上位概括、语序简洁全面优化留给第6步**。
- 过质量闸门。

**交付物：** 上位与否结论 +（若有）再次修订独权 + 下放组清单。  
**禁止：** 同批说明书实施例；同批第6步优化稿；默认禁止把本步挪到创造性之前。

---

## 第6步：优化独权（特征/名称上位与表达）

在第5步稿（或第5步输入稿）上，**不另定主问题**，把独权写得**更宽、更短、更清楚**。

**四目标（兼顾）：**

1. 扩大保护范围（在锚定问题可解、骨架仍在的前提下概括过窄特征）。  
2. 表达简洁清楚（删冗、先总后分、主谓宾与指代）。  
3. 部件/模块名称上位（实施例专名→本领域可接受上位名；窄名入从权/实施例建议）。  
4. 技术特征上位（具体结构/连接/参数/阀型等→更上位表述；功能限定守边界规范）。

执行要求：

- 必过质量闸门全文；结构类强调清单句不夹带展开。  
- 自定义名词上位后仍非公知 →「其中」定义。  
- 不得扩到无法实施或无交底/说明书支持；缺公开标待确认。  
- 不得削掉最小创造性骨架；动摇区别的上位须小步或保留，对照表说明。  
- 标注「**优化后独权**」+ **优化对照表**（名称上位 / 特征上位 / 删冗句式 / 拟从权或说明书保留）。

**交付物：** 优化后独权 + 对照表；或「无需优化」说明。  
**禁止：** 同批第7步长文交接冒充收束完成；同批重开创造性；同批说明书定稿。

---

## 第7步：正式独权工作稿收束 + 交接

1. 正式稿=第6步优化稿（或第6步确认无需优化时的第5步输出/输入稿）；可复贴定稿全文。  
2. 汇总：仍有效的下放组 + 优化对照中「拟从权/说明书保留」+ **待同步说明书事项**。  
3. 待确认技术事实清单（若有）。  
4. 衔接提示：  
   - 说明书：`说明书技术问题陈述撰写`（对齐已确认/再上位问题）、`说明书有益效果撰写`（对齐独权核心特征效果）；具体实施例等；  
   - 从权展开（按类型从权写法）；  
   - 质检：`单条权利要求审查`（权1）或 `权利要求书质检`；  
   - 若第4步跳过且事后要评创造性 → 另开 `创造性评估与独权补强`。  
5. 本 skill **结束**；不自动连跑说明书或整书质检。

**交付物：** 正式工作稿定位（+全文）+ 汇总清单 + 衔接。  
**禁止：** 同轮说明书定稿；未经确认再改优化稿（有意见回第6步）。
