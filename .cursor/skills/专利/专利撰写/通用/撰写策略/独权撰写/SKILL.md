# 独权撰写（三版递进策略 · 方法服务于策略）

## 策略总览（本 skill 的灵魂）

```text
阶段一（理解 skill）  读懂方案 + 体检交底书问题
        ↓
第一版独权   按「交底书中界定的技术问题」忠实转化技术方案
        ↓
重新界定技术问题   （须明示：怎么考虑、为何这样定）
        ↓
第二版独权   对准新界定问题；不得包含非必要技术特征
        ↓
【可选】创造性评估与补强   （对象=第二版；不足则补强后再往下）
        ↓
再上位技术问题
        ↓
第三版独权   要求最高：逻辑与表达清楚 + 保护范围最大
              （命名/数量等上位优化，如下文方法）
        ↓
【可选】递交独权变劣与从权回退   （定稿再放宽一档作递交权1；改进进从权）
        ↓
收束为正式独权工作稿
```

**三版要求依次提高（硬性）：**

| 版本 | 锚定的技术问题 | 质量要求（递进） |
|------|----------------|------------------|
| **第一版** | 交底书已界定/声称的技术问题 | 忠实覆盖交底方案；完整可读；允许暂留实施例级细节 |
| **第二版** | **重新界定后**的技术问题 | 特征与问题精准对应；**不得含非必要技术特征**；方案完整可实施 |
| **第三版** | **再上位后**的技术问题 | 在第二版「无非必要特征」之上，进一步：**逻辑清楚、表达清楚、保护范围最大**（部件命名上位、数量词放宽、序数命名等——按命名规则权衡，非一律第一/第二） |

撰写方法（质量闸门、类型铺陈、命名规则等）**服务于上述策略**，不得颠倒成「先抠字眼、后定策略」。

---

## 适用场景与触发

- 已完成 `交底书技术方案理解`（含体检与读懂）；进入总览**阶段二**。
- 触发：「写独权」「三版独权」「按交底问题写第一版」「重新界定技术问题」「第二版」「第三版」「再上位」等。

## 能力边界

- 产出三版独权工作稿链 + 两轮技术问题界定说明；不是说明书定稿，不是完整从权树（可列下放组）。
- 不得编造交底书未记载且未经确认的新结构/步骤；缺事实标「待确认」。
- 创造性实质判断只在 `创造性评估与独权补强`；本 skill 只做转入/跳过。
- 必要特征逐条细则调用 `独立权利要求必要技术特征检查`；类型与表达规范按需调用，不在本文件全文粘贴。

## 输出控制（plan 硬性）

禁止一次输出「第一版+重新界定+第二版+第三版」。必须用 plan/待办（TodoWrite 等）同步；一步一交付；始终一个 `in_progress`；格式 `【第X步 / 共N步】` + 正文 + plan 状态 + 确认 + 预告。

### 固定 plan（共9步 = 总览 2.1～2.9）

```text
第1步 回扣总览 + 建立 plan + 固定「交底书界定的技术问题」
  ↓
第2步 第一版独权（按交底书界定的技术问题）
  ↓
第3步 重新界定技术问题（结论 + 界定时的考虑说明）【须用户确认】
  ↓
第4步 第二版独权（对准新问题；无非必要技术特征）
  ↓
第5步 【可选】创造性评估与独权补强（对象=第二版）
  ↓
第6步 再上位技术问题（结论 + 与第二版问题分层）【须用户确认】
  ↓
第7步 第三版独权（清楚 + 范围最大；含命名/数量优化）
  ↓
第8步 【可选】递交独权变劣与从权回退（定稿再放宽作递交权1）
  ↓
第9步 正式工作稿收束 + 三版/递交对照摘要 + 交接
```

- 第5步跳过 → 第6步输入问题锚定基线=第二版所锚定问题；第7步输入独权基线=第二版。  
- 第5步补强 → 第6/7步输入以补强后的第二版（或标注「补强第二版」）为基线。  
- **禁止**将第6步与第7步合并交付；**须**用户确认再上位问题后，方可写第三版独权。  
- 第8步执行 → 按下文「第8步」内嵌子步骤 8.1～8.4 推进（仍属本 skill，不外转）；返回后第9步正式稿默认=递交独权。  
- 第8步跳过 → 写明；第9步正式稿默认=第三版；2.8=`cancelled`。  
- 未完成理解不得硬写第一版。

## 重新界定技术问题：怎么考虑（第3步专用方法）

重新界定**不是**把交底书问题换个说法，也**不是**把技术方案手段写进问题里。交付第3步时，必须用小节写清「本次界定的考虑」。

结构为：**三点综合权衡（主轴）** + **六点操作方法（融进三点、用于落地）**。六点不是与三点并列的另一套主轴，而是帮助把三点判准、写清、检验的方法。

### 一、三点综合权衡（主轴，三点都要写到）

1. **最核心的问题**  
   交底书场景里，若不解决就会导致方案整体失败或痛点最尖锐的那一个（或极少数）问题。优先「主矛盾」。

2. **交底书中最具有创造性的技术方案所解决的问题**  
   先识别交底书里相对现有做法区分度最高、最像发明贡献的那一撮技术手段，再反推：这撮手段真正稳定解决的是什么问题。重新界定后的主问题应尽量落在这撮高贡献手段所能支撑的问题上，使第二版能把创造性骨架留在独权里。

3. **好通过补强来增强创造性的技术方案所解决的问题**  
   在交底书已有方案基础上，哪些问题方向若创造性仍边缘/不足，**相对容易**沿交底书脉络深化、补场景或补特征从而抬创造性（而非另起炉灶、发明人难确认）。可适当偏向「可补强」方向，为后续可选创造性评估留抓手；不得脱离交底已有事实空定无法落地的问题。

**综合规则：**  
- 三点指向同一问题（或同一表述层级）→ 直接定为重新界定后的主问题。  
- 不一致 → 列出三点各自指向，说明以谁为纲、其余如何兼顾或降为次级问题；**默认优先**点2，兼顾点1，并评估点3；用户另有指示从其指示。

### 二、六点操作方法（融进三点）

写「界定考虑」时，用下列方法支撑三点判断；可在各点之下嵌用，也可单列「操作检视」短节，但**不得用六点替代三点主轴**。

| 操作方法 | 主要服务哪一点 | 怎么用 |
|----------|----------------|--------|
| **交底书问题盘点** | 点1 | 分清哪些是核心痛点，哪些是附带效果/宣传语；附带/宣传不得当成重新界定后的主问题。 |
| **特征反推** | 点2（兼点1） | 看第一版独权的核心区别：实际稳定解决的是哪一层「不良后果」；据此校准「最具创造性手段所解问题」与「最核心问题」是否同层。 |
| **手段不进问题** | 三点共用（表述硬约束） | 问题只写不利后果/需求缺口，不写专用门、算法名、具体参数等手段；手段留在特征里。 |
| **区分度落点** | 点2（兼点3） | 问题过宽→难支撑新颖性/创造性；过窄→非必要特征被逼进第二版。落点应能被高贡献手段撑住，且宽度适合后续补强。 |
| **用户/布局侧重** | 三点加权 | 用户明确的保护重心、场景约束等作加权，**不作唯一依据**；不得压过三点中已能自洽的结论，除非用户明示改选。 |
| **可检验** | 三点收束检验 | 假定第二版已剔到只剩必要特征：是否仍能完整解决拟界定的问题？不能→问题过大或特征不足，须改问题层级或回到第一版/交底补事实。 |

### 三、输出格式

- **重新界定后的技术问题**（一句或两句定稿候选）  
- **界定考虑**  
  - 按**点1 / 点2 / 点3**分述结论；  
  - 在相应点下（或另附「操作检视」）体现问题盘点、特征反推、区分度落点、用户加权、可检验等；全文遵守手段不进问题；  
  - 三点冲突时写明取舍。  
- **与交底书原问题的差异**（保留/收窄/改表述）  
- 请用户确认后再写第二版。

## 撰写方法总则（服务于三版策略）

### 方法一：独权正文质量闸门（按版本加码）

**各版共通：** 类型铺陈正确；主谓宾完整；所述指代清楚；自定义名词就地定义；功能性限定守边界；不编造无支持特征。

**第二版加码（硬性）：**  
- 锚定=重新界定后的技术问题。  
- 逐特征反问：去掉或改宽后该问题是否仍解决？能→必须删/概括/下放（`独立权利要求必要技术特征检查`）。  
- 重点清理：非必要数量词、排列方式、具体机构/工艺/驱动（除非恰为区别点）。  
- 删后方案须仍完整可实施；保留最小区别骨架。

**第三版加码（硬性）：**  
- 在第二版「无非必要特征」基础上，追求**保护范围最大**且**逻辑、表达清楚**。  
- **命名与数量优化（须结合案情；按下列规则权衡，禁止「默认一律第一/第二」）：**  
  - 「两块盖板」→「至少一块盖板」（除非「两块」本身解决问题所必需）。  
  - **部件命名两档对照（硬性）：** 第三版须给出**两档**命名优化对照（例如：交底/第二版原名 → **第一档优化** → **第二档优化**），并写明本版采用哪一档及理由；不得只给一档或只做半步改名即宣称已优化。  
  - **「第一×× / 第二××」选用规则（两步判断，不得跳步）：**  
    1. **先问是否扩大保护范围**：把方位/用途/材料等定语改成序数名后，是否使独权覆盖更多等同结构（不依赖「上游/下游」「防洪」等场景或用途绑死）？**若能扩大保护范围 → 优先推荐序数命名。**  
    2. **若不能扩大保护范围**（例如本案只有一处门组、改成「第一叠梁门」并不比「上游叠梁门」多盖住别的实施方式）：则**不再为序数而序数**；改为比较各档命名的**表达是否清楚**——若上一档（保留必要方位/功能区分、去掉过窄定语）更清楚，则采用上一档。  
  - 过窄材料/结构/用途定语（如「钢」「防洪」「高水头」「专用」）能上位则上位；「叠梁」等结构词若去掉会导致与既有门槽配合关系不清楚，可保留或改为「门节」等并就地定义。  
  - 实施例专名、门组全称、场景绑定语能上位则上位；未采用的更宽档或更窄原名列入从权/说明书建议。  
- 先总列后展开、删冗、统一术语；不得为扩宽而写到不清楚或无法实施。  
- 仍不得削掉最小创造性/区别骨架。

### 方法二：类型铺陈

| 类型 | 要点 |
|------|------|
| 结构类 | 「其特征在于」后先一句列全本层部件，再按序展开（`结构类权利要求撰写`） |
| 方法类 | 步骤有序；条件用规范判断句；主语为执行者 |
| 算法类 | 数据/参数先获取后使用；模块边界清楚 |
| 混合 | 先结构骨架，再挂运行接口 |

### 方法三：成组下放

从第一版→第二版、第二版→第三版剔出的关联特征，宜成组对应次级问题/效果，供从权与说明书；禁止为留后手而把当前版本的最小区别骨架整组藏进从权。

## 第1步：回扣总览 + 建立 plan + 固定交底书技术问题

1. 标明阶段二；列出 2.1～2.9；同步 todo。  
2. 从交底书发明目的/背景「然而」后问题/理解 skill 问题分层中，**摘录并固定「交底书界定的技术问题」**（可多条并列时标明交底书主写的那条）；不作重新界定。  
3. 预告下一步写第一版。

**交付物：** plan + 交底书界定的技术问题原文/归纳（标注来源）。  
**禁止：** 输出独权全文；输出重新界定后的问题定稿。

---

## 第2步：第一版独权

按第1步固定的**交底书界定的技术问题**，把交底书技术方案忠实转化为完整独立权利要求。

- 目标：覆盖发明人贡献、可对照交底审阅；允许暂留实施例细节。  
- 过「各版共通」闸门；不过第二版「零非必要」硬杠。  
- 标注「**第一版独权（交底书技术问题）**」；可选特征↔交底映射。

**交付物：** 第一版全文 + 所锚定的交底书技术问题复述。  
**禁止：** 同批重新界定问题；同批第二/三版。

---

## 第3步：重新界定技术问题

在第一版与理解结论基础上，**重新界定**供第二版锚定的技术问题。

- 必须按上文「重新界定技术问题：怎么考虑」输出**结论 + 考虑说明**。  
- 标注「**待确认：重新界定后的技术问题**」。  
- **须用户确认**后才能进入第4步。

**交付物：** 新问题表述 + 界定考虑（三点主轴 + 六点操作融入；含取舍）+ 与交底书原问题差异。  
**禁止：** 同批输出第二版独权全文。


---

## 第4步：第二版独权

锚定第3步已确认的新问题，重写独立权利要求。

- **硬性：不得包含非必要技术特征**（方法一第二版加码 + `独立权利要求必要技术特征检查`）。  
- 附：相对第一版删除/概括/下放对照；成组下放清单。  
- 标注「**第二版独权（重新界定技术问题 · 无非必要特征）**」。

**交付物：** 第二版全文 + 对照要点 + 下放组。  
**禁止：** 同批创造性长评；同批第三版；故意保留已知非必要特征。

---

## 第5步：【可选】创造性评估与独权补强

- 询问是否对**第二版**做创造性评估与补强。  
- 执行 → 转入 `创造性评估与独权补强`；对象=第二版；返回后以补强结果作为第6/7步输入基线（仍视为第二版基线之上的补强稿）。  
- 跳过 → 写明；第6/7步基线=第二版；2.5=`cancelled`。

**交付物：** 执行/跳过 + 版本定位。  
**禁止：** 不经创造性 skill 倾倒补强独权长文。

---

## 第6步：再上位技术问题

相对第二版锚定问题再抽一层（本质化、去场景绑死、去效果堆砌）。

- 给出再上位后的问题表述 + 与第二版问题的分层关系（保留/放宽了什么）。  
- 若判断无需再上位：说明理由，并写明第三版仍锚定第二版问题、仅做表达/命名扩围。  
- 标注「**待确认：再上位后的技术问题**」。  
- **须用户确认**后才能进入第7步。

**交付物：** 上位问题表述（或「无需再上位」结论）+ 分层说明。  
**禁止：** 同批输出第三版独权全文；把再上位与第三版合并成一步。

## 第7步：第三版独权

锚定第6步已确认的再上位问题（或已确认的「无需再上位、仍用第二版问题」），重写独立权利要求。

- 执行方法一**第三版加码**（清楚 + 范围最大 + 命名/数量优化；附**两档**命名对照表及选用理由）。  
- 成组下放非必要或过窄限定。  
- 标注「**第三版独权（再上位技术问题 · 清楚且范围最大）**」。

**交付物：** 第三版全文 + 相对第二版优化对照（含两档命名对照表及「扩围/清楚」选用理由）+ 下放组。  
**禁止：** 同批收束交接长文代替本步；把第三版要求降到第二版；用户未确认第6步问题就写第三版。

## 第8步：【可选】递交独权变劣与从权回退（本 skill 内嵌）

第三版完成后询问是否再做「递交权1放宽 + 定稿改进进从权」。  
- **跳过** → 写明；第9步正式稿默认=第三版；2.8=`cancelled`。  
- **执行** → 以第三版（或用户指定的定稿独权）为输入，按下列 **8.1～8.4** 推进；全部完成后进入第9步，正式稿默认=**递交独权**。

**含义（先对齐口径）：**

| 称谓 | 含义 |
|------|------|
| **定稿独权** | 第三版（或用户指定定稿） |
| **递交独权** | 定稿再去掉/改宽一层「改进限定」后的权1，用于正式递交 |
| **变劣 / 放宽** | 不是写成不能用的劣解，而是让权1覆盖更上位/更简化实现，保护面更宽 |
| **从权回退** | 定稿相对递交独权多出的特征，成组写入从权作退路 |

**一句话：** 定稿保质量 → 递交权1再放宽抓范围 → 定稿多出的改进进从权保退路。

**边界：** 变劣只能去掉/上位定稿已有限定，不能换成另一套发明；递交权1须完整可实施并保留最小创造性骨架；不得用本步替代第三版的命名/清楚性优化。

**子步骤硬性：** 一步一交付；8.1 变劣点**须用户确认**后才能写 8.2；禁止 8.2 与 8.3 一次倾倒。

### 8.1 锁定定稿 + 可变劣清单【须确认】

1. 复贴或引用定稿独权全文。  
2. 列出可下放的改进限定及变劣方式（示例）：

| 类型 | 定稿中的样子 | 变劣后进递交权1的常见写法 |
|------|----------------|---------------------------|
| 结构分型/分节 | 叠梁门 = 挡水门节 + 输水门节 | 整体门体 / 上游门体（不强制分节） |
| 安装依托 | 设于既有检修门槽 | 独权不写门槽；从权再写 |
| 位置优选 | 输水门节在最下方 | 独权不写；从权写 |
| 材料/驱动/阀型 | 电动球阀、钢制等 | 上位为流量调节阀等 |
| 数量/并联 | 多管并联 | 独权「至少一根」；多管进从权 |
| 运行能力 | 闸门可开启连通等 | 按案情留独权或进从权 |

3. 标注「**待确认：拟变劣点**」与建议保留的最小骨架。  

**交付物：** 定稿定位 + 可变劣清单 + 最小骨架建议。  
**禁止：** 同批输出递交独权全文、完整从权。

### 8.2 撰写递交独权

按已确认变劣点重写权1。

1. 比定稿**更宽**，不得更窄。  
2. 完整可实施；主谓宾完整；结构类先总列后展开；自定义名词就地定义。  
3. 标注「**递交独权（定稿变劣稿）**」。  
4. 附相对定稿删除/上位对照。  

**交付物：** 递交权1全文 + 与定稿对照。  
**禁止：** 同批倾倒全部从权；抽空最小骨架（风险高须明示并请用户确认）。

### 8.3 成组从权回退

把「定稿有、递交权1没有」的特征成组写入从权（或核心组+待写清单）。

1. 同一改进点串联成组（如：分节叠梁 → 最下方 → 既有门槽）。  
2. 引用合规（形式合规规范）；结构类多新部件先总列后展开。  
3. 每组注明对应定稿语句与退守效果。  

**交付物：** 从权条文或核心组 + 与变劣点映射表。  
**禁止：** 把递交权1最小骨架误下放。

### 8.4 对照 + 风险 → 进入第9步收束

1. 三栏对照：定稿独权 | 递交独权 | 从权回退组。  
2. 风险：创造性压力；说明书技术问题是否仍绑死已下放约束；待同步术语。  
3. 预告第9步正式稿默认=递交独权；定稿第三版作内部对照保留。  
4. 可选建议对递交权1做 `单条权利要求审查`。  

**交付物：** 对照摘要 + 风险 + 收束预告。  
**禁止：** 同轮说明书定稿。

**示例（非模板）：** 定稿「上游叠梁门含挡水/输水门节，管穿输水门节」→ 递交「上游门体整体设置，管穿门体」→ 从权回退分节叠梁，再从权最下方、既有门槽。

## 第9步：收束 + 交接

1. **正式独权工作稿**默认：若执行了第8步则为**递交独权**；否则为**第三版**（用户指定另选须明示）。  
2. 对照摘要：三版锚定问题与要求层级；若有递交变劣稿，另附「定稿 | 递交权1 | 从权回退」三栏。  
3. 下放组汇总、待确认事实、待同步说明书事项。  
4. 衔接：说明书问题/效果对齐（若改进仅在从权，技术问题勿再绑死在独权已下放的约束上）；**提示转入 `从权撰写`**（默认布局 9 条；第8步回退组作种子）；质检；若跳过创造性可事后另开。  
5. 结束；不自动连跑说明书或从权全文（从权由 `从权撰写` 专轮执行）。

**交付物：** 正式稿定位（可复贴）+ 摘要与清单 + 衔接。  
**禁止：** 同轮说明书定稿；未经确认回改第三版/递交稿（有意见回第7步或第8步相应子步骤）。
