# 独权撰写（正式独权阶段，所有案件类型通用）

## 适用场景

- 已完成 `交底书技术方案理解`（总览**阶段一**），手头有读懂结论与**待确认主问题候选**；进入入口总览中的**阶段二**。
- 现在要做的是：**从忠实初版独权写到正式工作稿**——初版转化、确认主问题、按主问题修订；**可选**对修订稿做创造性评估与补强；再上位技术问题并筛选/成组下放；然后**优化独权**（上位技术特征与部件名称、扩大保护范围、表达简洁清楚）；最后收束。
- 不负责交底书体检与白话读懂（那属于 `交底书技术方案理解`）。

## 典型触发

- 「写独权」「先起一版独权」「按主问题改独权」「正式写独权」「再上位一下技术问题」「优化独权」「把部件名再上位」
- 技术方案理解结束后，用户确认可写独权并要求继续

## AI 使用本 skill 的能力边界（重要）

- 本 skill 产出的是**独权工作稿**（初版 → 主问题修订稿 → 可选补强稿 → 上位修订稿 → **优化稿** → 正式工作稿），不是说明书定稿。
- 上位、下放与名称概括不得编造交底书未记载、且未经用户/发明人确认的新结构/步骤；缺事实标「待确认」。
- 具体措辞、句式、部件铺陈顺序，按案件类型参照 `结构类权利要求撰写` 等类型规范，并对照通用分支下的主谓宾、指代、自定义名词、功能性限定边界等规范；本 skill 管**策略步骤与内容取舍**，类型 skill 管**表达形态**。
- 必要技术特征的逐特征反问细则，复用 `独立权利要求必要技术特征检查`，不在本 skill 重复展开判断口诀。
- 创造性评估的实质判断在 `创造性评估与独权补强`；本 skill 第4步只做转入/跳过决策与交接，不在本步倾倒评估全文。

## 输出控制（硬性：用 plan 功能控步）

本 skill **禁止**在同一次回复中一次性输出「初版独权 + 主问题确认 + 按主问题修订独权 + 再上位后独权 + 优化后独权」。必须用 Cursor **plan / 待办清单功能**驱动全过程：先建 / 回扣 plan，再一步一交付，等用户确认后再进入下一步。

### Plan 功能用法（与意见陈述书 skill 同构，硬性）

1. **必须建立或回扣 plan 待办清单**：第1步把阶段二 2.1～2.7（含可选 2.4）写成可勾选待办项；须**回扣**入口全流程总览编号，不得另起冲突顺序。
2. **必须同步到 plan/todo 工具**：环境若提供 TodoWrite、CreatePlan 或等价 plan 文件，第1步**必须调用**创建/续写本案阶段二待办；其后每推进或完成一步，**必须更新**对应项状态（`pending` / `in_progress` / `completed`；跳过创造性则将 2.4 标为 `cancelled` 并注明「用户跳过」）。不得只在回复里写 plan、不同步工具。
3. **用 plan 驱动全过程**：回复正文中亦须展示当前 plan 状态表；**始终只有一个 `in_progress`**；用户说「下一步/继续」时按 plan 顺序交付下一项，不得跳步、不得一次交付多版独权。
4. **用户说「一口气写完」仍分步**，并继续按 plan 更新状态。

### 硬性规则

1. **先建 / 回扣 plan，再按 plan 交付**：第1步建立本阶段子 plan 待办，并**回扣入口全流程总览**中阶段二的编号（2.1～2.7）；同步写入 plan/todo 工具；其后严格按序推进。
2. **一步只做一个交付物**：须等用户确认（或明确说「下一步/继续」）再进入下一步。
3. **不得跳步**：不得跳过初版独权直接写主问题修订稿；不得跳过主问题确认直接写上位独权；不得把「按主问题修订」「再上位修订」「优化独权」同批输出；**不得在再上位之后才第一次做创造性评估**；**不得跳过优化步直接收束**（除非用户明确确认第5步稿已无需优化，则第6步交付「无需优化」说明后进入第7步）。
4. **每步输出格式**：`【第X步 / 共N步】步骤名称` + 本步正文 + **更新后的 plan 状态** + 请用户确认 + 预告下一步。
5. **始终只有一个「进行中」**（正文与 todo 工具一致）。
6. **创造性为可选但位置固定**：第4步由用户决定执行或跳过；若执行，必须针对第3步「按主要技术问题修订后的独权」，完成后再进入第5步再上位；跳过则更新 plan 中 2.4 状态后进入第5步。

### 本 skill 固定 plan（共7步；对应总览 2.1～2.7）

```text
第1步 回扣总览 + 交底书初版独权（忠实转化）
  ↓
第2步 确认主技术问题
  ↓
第3步 按已确认主问题修订独权（输出「按主要技术问题修订后的独权」）
  ↓
第4步 【可选】创造性评估与独权补强
      （转入 `创造性评估与独权补强`；或用户确认跳过）
      评估对象 = 第3步修订稿；补强后以补强稿作为后续再上位的输入
  ↓
第5步 再上位技术问题 + 第二轮独权筛选/成组下放
      （输出「按更上位技术问题再次修订后的独权」+ 下放特征组清单）
  ↓
第6步 优化独权（上位技术特征与部件名称、扩大保护范围、表达简洁清楚）
      （输出「优化后独权」+ 相对第5步的优化对照）
  ↓
第7步 输出正式独权工作稿收束 + 待确认事项 + 交接
```

总步数 N = 7。不得擅自把第4步挪到第5步之后；不得把第6步并入第5步或第7步；若用户只要其中某一步，仍须标明该步在 plan 中的位置。

若第4步跳过：在回复中写明「用户确认跳过创造性评估」，直接进入第5步；第5步输入仍为第3步修订稿。  
若第5步审查结论为「无需再上位」：交付理由与特征保留说明，第6步输入仍为第5步的输入稿（第3步稿或补强稿）——**不得跳过第5步不问**，也**不得因此跳过第6步优化**。  
若第6步用户确认「无需再优化」：交付简要说明，第7步以第5步输出稿（或第5步输入稿）作为正式工作稿。

若用户在本案中**跳过**了理解 skill 直接要求写独权：第1步须先用简短段落确认「是否已读懂、主问题候选是否已有」；若无，应退回 `交底书技术方案理解`，不得硬写。

## 第1步：回扣总览 + 交底书初版独权（忠实转化）

**本步要做的事：**

1. 回扣入口总览：标明当前为阶段二 / 2.1，列出本 skill 完整 7 步 plan（含可选创造性位置与第6步优化）。
2. 按交底书内容**忠实撰写一版独立权利要求并完整输出**（必做交付物）。

撰写要求：

- **忠实于交底书**：把交底书中发明人描述的技术问题、技术方案、核心结构/步骤/部件，如实转化为一条独立权利要求的正式文字；此阶段**不刻意拔高、不引入补强构思的新特征**，只把交底书已有内容写成规范的独权表述。理解阶段已明示纠正的口误（如方向写反、溢流/管道笔误）按纠正后的技术含义写，并在要点映射中注明。
- **写成完整独权正文**：不是列提纲或骨架，而是输出可直接阅读的独立权利要求全文（含前序部分与「其特征在于」之后的特征部分）；具体措辞、句式、部件铺陈顺序等，按案件类型参考 `结构类`/`方法类`/`算法类` 的权利要求撰写规范，并同步对照 `权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范`、`自定义名词就地定义`、`功能性限定使用边界规范` 等。
- **明确标注为「交底书初版独权」**：尚未按主要技术问题定向修订，便于用户对照交底书审阅、确认发明人真实技术贡献是否被完整覆盖。
- **作为后续工作的基线**：后续若需围绕主要技术问题重写独权、扩宽或收窄保护范围、下放从权、优化名称与特征，均以这一版独权为起点和参照。
- **可选要点映射表**：初版特征块 ↔ 交底书来源。

**本步交付物：** 阶段二 plan **待办清单**（已同步 plan/todo 工具）+ 标注「交底书初版独权」的全文 + 可选映射表。  
**本步禁止：** 同批确认并写死主问题后的修订独权；同批做上位、优化或创造性评述。

---

## 第2步：确认主技术问题

承接 `交底书技术方案理解` 第6步给出的待确认主问题候选（及备选），以及用户对本案的侧重。

执行要求：

1. 以用户提示为准：用户可确认候选、改表述、或另定更深/更侧重的主问题。
2. 若理解阶段候选缺失，本步须先补列分层问题与候选，再请用户确认（仍不改独权正文）。
3. 醒目标注**已确认主技术问题**全文，供后续修订与说明书技术问题陈述对齐。

**本步交付物：** 已确认主问题全文（可附「相对候选的调整说明」）。  
**本步禁止：** 输出修订后独权全文；展开上位分层长文；展开创造性评估正文。

---

## 第3步：按已确认主问题修订独权

在交底书初版独权基础上，使独权记载的技术方案与已确认主问题**精准对应**。

执行要求：

- **前序与特征选取均服务于该主问题**；与主问题无关或可由从权覆盖的特征，可考虑后移。
- **写成完整独权正文**（含前序与「其特征在于」之后的特征部分），标注为「按主要技术问题修订后的独权」。
- **对照说明**：相对交底书初版独权做了哪些调整、各调整与主问题的对应关系。
- 表达形态按案件类型调用类型权利要求撰写规范；精简时的逐特征判断可调用 `独立权利要求必要技术特征检查`。
- 本步以「对准主问题」为主，**不要**在本步做完整的再上位扩宽，也**不要**在本步做第6步那种名称/特征全面优化（可做明显笔误与指代修正）。

**本步交付物：** 「按主要技术问题修订后的独权」全文 + 相对初版的调整要点 + 预告下一步为可选创造性（或跳过后进入再上位）。  
**本步禁止：** 同批做进一步上位审查；同批输出优化后独权；同批输出创造性初判/补强独权全文。

---

## 第4步：【可选】创造性评估与独权补强

在第3步「按主要技术问题修订后的独权」已经交付并经用户确认后执行本步决策。

**执行方式：**

1. 询问用户：是否对本稿做创造性评估与（若不足）补强。
2. **若执行**：明确告知转入同分支 `创造性评估与独权补强`；评估对象固定为第3步修订稿（或用户指定的该稿微调版）；按该 skill 自有 plan 分步交付；完成后回到本 skill，以**补强后独权**（若未补强则为原修订稿）作为第5步输入。
3. **若跳过**：写明「跳过创造性评估与补强」，第5步输入 = 第3步修订稿。

**本步交付物：** 执行/跳过决定 +（若执行）转入声明与返回后的当前独权版本定位（修订稿 / 补强稿）。  
**本步禁止：** 在本步内不经创造性 skill 而自行倾倒长篇创造性评述与补强独权；禁止在未完成第3步时进入本步。

---

## 第5步：再上位技术问题 + 第二轮独权筛选

在第3步修订稿（或第4步补强稿）基础上，**不要立即将其视为最终独权**。应进一步审查：当前技术问题是否仍偏具体，是否还存在继续上位概括的空间；若存在，则据此对独权做第二轮筛选与成组下放。

这一步是正式独权撰写内部的**问题层扩宽**，位于**按主问题修订（及可选创造性）之后、独权表达优化之前**，用于避免把仅服务于较具体问题的一整组特征过早写死在最宽独权中。

执行要求：

- **先问技术问题是否仍偏具体**：看当前解决的是本质问题、实施层问题，还是某种优选效果层问题；若仍明显贴近具体实施方式、具体性能目标或具体应用场景，应考虑再上位一层。
- **把技术问题分层看待**：至少区分上位技术问题、当前主要技术问题、以及更具体的次级技术问题，并梳理各层与独权特征的对应关系。
- **重新核查必要技术特征**：对当前输入独权再次逐特征提问——「如果把该特征删除、概括或改写为更宽泛的说法，方案是否仍能解决更上位的技术问题？」若能，则该特征相对于更上位问题已非必要，可考虑移出。细则调用 `独立权利要求必要技术特征检查`。
- **允许成组下放，不鼓励零碎拆散**：只在解决较具体技术问题时才必要的多个关联特征，宜作为一组整体下放到从属权利要求。
- **保留当前最小创造性骨架**：**不得为了给后续答复留后手，而把支撑当前创造性的核心区别技术特征整体提前下放**。若第4步刚补强过，尤须避免把刚补进独权的最小骨架整组下放。
- **说明书同步公开**：凡拟下放的一组特征及其对应的较具体问题、效果、替代实施方式，均应在说明书中充分公开（本步只列明下放清单与公开提示，不写说明书正文）。
- **输出**：若发生上位与精简，输出「按更上位技术问题再次修订后的独权」，并说明相对输入稿哪些特征保留为最宽骨架、哪些成组下放及各自对应的次级问题/效果；若无需再上位，明确写明理由。
- 本步可做必要的表述清理，但**系统的部件名称上位、技术特征上位概括、语序与简洁性全面优化留给第6步**，避免与第6步合并倾倒。

**本步交付物：** 上位与否结论 +（若上位）再次修订后的独权全文 + 下放特征组清单（或「无需再上位」说明）。  
**本步禁止：** 同批写说明书实施例；同批输出第6步「优化后独权」全文；把本步前移到创造性之前（除非用户明确要求且总览已同步改写——默认禁止）。

## 第6步：优化独权（上位技术特征与部件名称、扩大保护范围、表达简洁清楚）

在第5步「按更上位技术问题再次修订后的独权」（若第5步无需再上位，则为第5步的输入稿）基础上，**再做一轮表达与特征层面的优化**。本步不重新另定主技术问题，而是在已锚定的（上位）技术问题下，把独权写得**更宽、更短、更清楚**。

**优化目标（须同时兼顾）：**

1. **扩大保护范围**：在仍能解决已锚定技术问题、且不丧失创造性最小骨架的前提下，对过窄的技术特征做上位概括。
2. **表达简洁清楚**：删冗、理顺「先总列部件/步骤、后展开」、主谓宾完整、指代无歧义。
3. **部件/模块名称上位**：将过窄的实施例专名、组合名、场景名改为本领域可接受的上位名称（例如门组具体称谓、装置商品名式叫法）；被替换的窄名称列入从权或说明书实施例建议。
4. **技术特征上位**：将非必要的具体结构、具体连接、具体参数、具体阀型/驱动方式等改为更上位的结构/连接/功能表述（仍优先结构语言；功能性限定遵守 `功能性限定使用边界规范`）。

**执行要求：**

- 对照调用：`结构类/方法类/算法类` 权利要求撰写规范、`权利要求主谓宾结构规范`、`权利要求指代与参照清晰性规范`、`自定义名词就地定义`、`独立权利要求必要技术特征检查`（本步做特征上位时）。
