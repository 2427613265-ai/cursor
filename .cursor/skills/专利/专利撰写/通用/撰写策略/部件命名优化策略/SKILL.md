# 部件命名优化策略（总控）

## 适用场景 / 触发词

- 交底或草稿中出现**较长部件命名**；
- 名称中夹带场景、方位、用途、材料、驱动、实现方式等限定词；
- 用户问「部件名怎么优化」「长名字怎么修剪」「LED诱鱼灯组能不能改成诱鱼灯组」；
- 独权第三版命名优化、从权逐条撰写、单条/整份质检中发现命名过窄或不自明。

**本 skill 是总控，不替代下属具体规范。** 先读本 skill 定流程，再按触发类型 Read 对应子 skill。

---

## 下属具体优化 skill（必须挂接）

| 顺序 | 子 skill | 管什么 |
|------|----------|--------|
| 1 | `方位与场景限定上位规范` | 左/右、前/后、上/下、上游/下游、迎水/背水、内外、防洪/高水头等方位与场景定语如何上位或保留 |
| 2 | `交底口语名改写为自明结构名规范` | 口语名/临时名优先改成自明结构名（如侧支孔→出水孔） |
| 3 | `独立权利要求必要技术特征检查` | 实现方式限定（LED、电动、可调、钢制、专用等）删掉后是否仍必要 |
| 4 | `自定义名词就地定义` | **仅当改名/修剪后仍不自明**时，用「其中」就地定义 |
| 5 | `权利要求清楚性与逻辑一致性规范` | 修剪/改名后回看：是否混淆、术语是否前后一致 |

辅助（非命名专条，但命名后常连用）：

- `权利要求指代与参照清晰性规范`：保留下来的方位词是否有参照物；
- `结构类权利要求撰写`：命名确定后的部件树上下位列举。

---

## 核心口诀

**先拆词，后删定；能改名，不解释；保骨架，去冗余；清楚优先，扩围其次。**

---

## 统一流程（硬性）

### 第1步：拆成「骨架词 + 限定词」

把长名称拆开：

- **骨架词**：真正说明它是什么的核心名词（门、门节、阀、灯组、装置、廊道、孔……）
- **限定词**：场景/方位/用途/材料/驱动/实现方式等附加信息（上游、防洪、LED、电动、左侧、可调、专用……）

自问：只剩骨架词，是否仍能被本领域识别？

### 第2步：按限定词类别调用子 skill

| 限定词类型 | 例子 | 默认动作 | 必读子 skill |
|------------|------|----------|--------------|
| 场景/工程钉死 | 防洪、高水头、某枢纽 | 能删则删 / 上位 | `方位与场景限定上位规范` |
| 观察方位 | 左/右、前/后、上/下 | 优先一侧/一端 | `方位与场景限定上位规范` |
| 流程/功能侧 | 上游/下游、迎水/背水 | 慎改，必要则保留 | `方位与场景限定上位规范` |
| 实现方式 | LED、电动、球阀、钢制、可调 | 非必要则上位 | `独立权利要求必要技术特征检查` |
| 口语/临时名 | 侧支孔、小孔、专用门 | 优先改自明结构名 | `交底口语名改写为自明结构名规范` |

**禁止：** 未分类就机械照抄长名；未尝试改名/修剪就先写「其中」硬解释。

### 第3步：清楚性回看

删改后必须再问：

1. 名称还知道它是什么吗？
2. 会不会与文中其他部件混淆？
3. 全文术语是否前后一致？

→ 用 `权利要求清楚性与逻辑一致性规范` 摘要自检；方位残留再查 `权利要求指代与参照清晰性规范`。

### 第4步：仍不自明才「其中」

只有同时满足：

- 没有更自明的规范名可替换；或
- 改名会丢失发明特有含义；

才保留原词，并调用 `自定义名词就地定义`。

## 典型正例

| 原名 | 优化结果 | 用到的子 skill |
|------|----------|----------------|
| LED诱鱼灯组 | 诱鱼灯组 | 必要特征检查（删实现方式） |
| 侧支孔 | 出水孔 | 口语名改写为自明结构名 |
| 可调配重环 | 配重环 | 必要特征检查 |
| 左侧阀门 | 一侧阀门 / 阀门（视语境） | 方位与场景限定上位 |
| 上游防洪检修叠梁门 | 上游叠梁门 / 上游门体 | 场景钉死上位 + 命名扩围 |

---

## 什么时候不能硬修剪

- 删掉后失去部件身份（「出水口」→「口」）；
- 删掉后失去必要技术关系（作为流向骨架的上游/下游；作为布置贡献的背水侧）；
- 删掉后改变发明区别事实（区别点就在该具体实现方式时）。

---

## 在独权 / 从权 / 质检中的调用方式

### 独权撰写
第三版命名优化、递交变劣命名放宽时：**先 Read 本 skill**，再按第2步表调用子 skill；两档命名对照表应体现本流程结论。

### 从权撰写
逐条撰写时，只要本条出现较长部件名、方位/场景定语、口语名或实现方式定语：**先 Read 本 skill**（可与门禁表其他行并行），再打开对应子 skill。

### 质检 / 单条审查
发现命名过窄、口语名不自明、不必要实现方式钉死范围时：按需加载本 skill 作为总控入口。

## 检查清单

- [ ] 已拆「骨架词 + 限定词」
- [ ] 场景/方位限定已按 `方位与场景限定上位规范` 处理
- [ ] 口语名已按 `交底口语名改写为自明结构名规范` 优先改名
- [ ] 实现方式限定已按必要特征思路判断能否上位
- [ ] 改名/修剪后已做清楚性回看
- [ ] 仅在必要时才使用「其中」就地定义
- [ ] 交付物中声明：已遵循本策略 + 实际调用的子 skill 名称

## 与其他策略 skill 的关系

- `独权撰写`：第三版命名规则是本策略在独权阶段的落点；本 skill 提供可复用总流程与子 skill 挂接。
- `从权撰写`：门禁表应指向本 skill 作为「长部件名/命名优化」入口。
- 下属具体规范仍各自可被单独触发；但凡「先总览命名怎么优化」应从本 skill 进入。
