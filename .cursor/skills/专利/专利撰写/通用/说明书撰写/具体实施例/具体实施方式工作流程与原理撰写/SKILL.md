# 具体实施方式：工作流程与原理撰写（所有案件类型通用）

## 适用场景

交底书或技术方案中存在**整系统/整装置如何运行**的描述，而权利要求多为结构限定、未把完整运行时序写入独权/从权时，具体实施方式应补充**工作流程与原理**段，例如：

- 过鱼、过流、启停、切换通道等端到端过程；
- 主流程 + 多通道/分工况（如两条进鱼通道、两种运行模式）；
- “先形成什么条件 → 再如何进入 → 再如何完成”的原理说明。

**触发：** 说明书总控进入第5E步；或用户明确要求补写工作过程/运行原理/交底中的“如何使用/如何过鱼”等段落。

## 核心规则

### 1. 要写，且单独成段

工作流程与原理属于充分公开的重要内容，不能因为“权利要求没写步骤”就从说明书丢掉。应单独成段撰写，使本领域技术人员能按说明书完整实施运行过程。

### 2. 落位：结构实施例与装配/未入权细部之后

建议合订顺序：

```text
权1～权N 结构实施例（5A/5B，含挂靠的强相关未入权细部）
  → 整体装配详述（5C）
  → 未入权独立细部（5D 文末部分）
  → 工作流程与原理（5E）   ← 本 skill
```

即：**先讲清“是什么、装在哪”，再讲“怎么跑起来”。**

### 3. 与权利要求实施例主线严格区分

- **不要**把完整运行时序写进权1～权N的复述段；
- **不要**塞进各条“具体而言”主线展开里冒充权利要求特征；
- 用“**进一步地，**对本实用新型……的工作原理与运行过程说明如下。”等引导语另起。

### 4. 内容组织（推荐）

按交底实际有无取舍，一般包括：

1. **总体原理**：关键条件如何形成（如持续引导水流、压差、通路连通等）；
2. **分工况/多通道**（若有）：各通道如何启用、入口在哪、进入后如何继续；
3. **收束**：如何到达终点状态（如过坝、复位、吊离门体等）；
4. **协同手段**（若有）：与诱鱼、传感、控制等辅助手段如何配合——点到与已有结构实施例的呼应即可，不重复展开结构细部。

### 5. 术语对齐当前权利要求

交底口语名、旧名、实施例专名，一律改写为**当前权利要求书已采用的名称**（如消力池→缓冲池、侧支孔→进水口等）。交底中的效果性口语（如“溢流”）若已另有确认口径，按确认口径写清物理含义，避免与结构术语冲突。

### 6. 工程参数与可选运行提示

具体枢纽水位、水头、建议操作顺序等，若未入权，可在本段末用“在一个可选的工程实施例中”“在一个可选的运行方式中”补充；**不得编造交底没有的数值**。

## 与相邻 skill 的分工

| skill | 负责 |
|-------|------|
| `说明书具体实施方式撰写` | 各权利要求“复述+展开”结构/步骤主线 |
| `具体实施方式补充整体装配方式` | 怎么装到整机/既有构筑物上（5C） |
| `未写入权利要求的技术方案在说明书中的编排` | 未入权结构细部的就近/文末安放（5D） |
| **本 skill** | 整系统**怎么运行**的过程与原理（5E） |

## 检查清单

- [ ] 交底若有主流程/多通道/端到端过程，具体实施方式是否已补工作流程与原理段？
- [ ] 是否落在结构实施例及 5C/5D 之后，且未混入权利要求复述/“具体而言”主线？
- [ ] 术语是否与当前权利要求一致？
- [ ] 多通道是否分别写清启用条件与进入后路径？
- [ ] 可选工程参数/运行提示是否单独标注，且未编造数值？

## 应用范围

适用于任意技术方案类型说明书“具体实施方式”中的运行过程公开。由 `权利要求定稿后说明书撰写` 总控第5E步调度。
