# 通用·说明书撰写·具体实施例

本分支存放说明书**"具体实施方式"**（具体实施例）部分的通用撰写规范，不区分结构类/方法类/算法类。

## 已有 skill

- `说明书具体实施方式撰写`（说明书具体实施方式撰写）：每一条权利要求（含从属权利要求）的实施例第一段都原样复述对应权利要求/步骤的技术方案；删除"其特征在于"，从权还须删除"根据权利要求X所述的……"引用套话并改用"进一步地，"接特征部分；再用"具体而言，"按序展开。相邻特征可以合段，配合只写与相邻部件的那一下；结构展开后用承接句写该条方案的有益效果，不用「本实施例的有益效果在于：」起句。端到端过程留给 5E。「进一步地」只用于从权复述。不遗漏、不夹带新特征；并规范附图标记（部件名称+标号；无标号部件只写名称）。
- `具体实施方式名词先释义后展开`（具体实施方式名词先释义后展开）：某条权利要求含新定义名词时，释义放在复述段之后、「具体而言」之前。结构名写形态和连接；参数或量写计算方式。背景或公知词义已经能读懂的，不单列。
- `未写入权利要求的技术方案在说明书中的编排`（未写入权利要求的技术方案在说明书中的编排）：交底里已有、未入权的内容直接起草；交底没有的新增须用户确认。与某条权利要求强相关的紧跟其实施例之后，独立方案放在 5E 之前。引导语用「在一个可选的实施方式中」等，不用「进一步地」。
- `具体实施方式补充整体装配方式`（具体实施方式补充整体装配方式）：权利要求只保护部件/组件本身、未限定其与外部部件装配连接关系时，权1展开段用一句总述装配，详述放在 5E 之前。不把装配写进权1复述段，不在各从权实施例重复。
- `具体实施方式工作流程与原理撰写`（具体实施方式工作流程与原理撰写）：交底含主流程/多通道/端到端运行时，在结构实施例与装配、未入权细部之后单独撰写工作流程与原理段；术语对齐当前权利要求，不得混入各权利要求复述主线。由总控第5E步调度。

后续新增具体实施例相关 skill 时，请在本目录下按照 `.cursor/skills/专利/专利撰写/通用/说明书撰写/具体实施例/<中文名称>/SKILL.md` 的结构添加。
