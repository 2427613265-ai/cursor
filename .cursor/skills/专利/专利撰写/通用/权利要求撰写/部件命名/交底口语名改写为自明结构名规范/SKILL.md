# 交底口语名改写为自明结构名规范

撰写时本页是 `部件命名优化总控` 流水线**第 1 闸**：只管「这个交底叫法能不能改成自明名 / 可核对几何表述」。材料/性能定语、两档对照、同名多物见 `部件命名具体优化`；改不动后如何说清见 `自定义名词就地定义`。质检命中口语名时可直读本页，不必先经总控。

## 核心规则

当交底书里出现“发明人自己叫的名字”时，**不要默认原词照抄进权利要求，再靠“其中，……”补解释**。应先做一层判断：

1. **能否直接改成更自明的结构名 / 功能结构名？**
   - 能：**优先改名**，让权利要求本身一眼可懂；
   - 不能：再保留短名，并转 `自定义名词就地定义`——**优先在名称出现前白话写清**，勿默认「其中」。
2. 判断标准不是“说明书里能不能解释”，而是：**本领域技术人员不查说明书，单看权利要求文字，能否准确理解这个部件是什么。**

**优先级：改名清楚 > 前置白话说清 > 原名+其中兜底。**

对**布置／排列类口语**（如「对称错位」「上下左右错开」）同理：优先改写成**可核对的几何或位置关系**（错开相对谁、对称相对哪条中心线），不要只留黑话词；若必须保留原词，按 `自定义名词就地定义` 先前置描述。

---

## 适用场景 / 触发词

- 交底中的称呼明显口语化、临时化：如“侧支孔”“小孔”“导流口”“底节专用门”等；
- 名称听起来像方位/习惯叫法，但读者不清楚它到底是孔、口、通道、件、段还是组件；
- **布置／排列口语**：如「对称错位」「花错布置」「上下左右错开」等——读者无法单凭该词判断错位方向、对称参照；
- 用户指出“其实它本质上就是某种更常见的结构名”；
- 撰写从权时，某个名称一上来就需要“其中，……”才能勉强读懂。

---

## 两步判断（硬性）

### 第一步：先问能不能改名

把交底原名拿出来，问三件事：

1. **这个名称是否本身不自明？**
   例如“侧支孔”并不能让读者立刻知道它是“廊道对应的出水孔”还是“侧向支路通道”；“对称错位”并不能让读者立刻知道错的是哪一层、对称相对哪条线。
2. **是否存在本领域更常见、边界更清楚的名称（或可核对的几何／位置表述）？**
   例如把“侧支孔”改成“出水孔”；把“对称错位设置”改成“相邻层在水平投影上相互错开，并关于××中心线对称布置”。
3. **改名后是否不改变技术事实，只是把表达说清楚？**
   若只是从口语名改成规范结构名／可核对布置表述，则应改；若改名会改掉技术内涵，则不能硬改。

**三问结论：**
- 能改清楚 → 直接改名；
- 改名仍不清楚或会改错含义 → 保留原名，转 `自定义名词就地定义`：**优先在名称出现前白话写清**，不要默认「其中」。

### 第二步：改名后再判断要不要再解释

- 若改名后已经**客观清楚**（如“出水孔”“安装孔”“导流槽”，或已写明错开维度与对称参照），**一般不再需要**额外定义句。
- 若改名后仍需限定专属含义：优先把限定写进**名称出现前的句子**；仅当前置会极臃肿时，再补「其中」（见 `自定义名词就地定义`）。

---

## 与 `自定义名词就地定义` 的分工

| 情形 | 应用 |
|------|------|
| 原名只是交底口语，存在更自明的规范名 | **先用本 skill 改名** |
| 布置类口语可改写成可核对几何／位置关系 | **先用本 skill 改写**（通常不必再定义句） |
| 没有更好的现成名称，或改名会丢失发明特有含义 | **保留短名 + `自定义名词就地定义`（先前置白话，其中兜底）** |
| 改名后仍有特殊边界需交代 | **先改名，再前置白话补足；仍不够才「其中」** |

**禁止的坏顺序：** 口语名原样进权利要求 → 每次都靠“其中”硬解释。  
**推荐顺序：** 先改自明名 → 真改不动则名称出现前白话说清 → 仍不行才「其中」。

## 示例

### 示例1：本案“侧支孔”

```
原写法：
所述输水廊道包括阀门、出水口和侧支孔；
……其中，所述侧支孔为所述阀门所对应的、供鱼类由所述出水口进入所述船闸闸室的通道。
```

若发明人确认该“侧支孔”本质上就是与廊道出水口对应的**出水孔**，则优先改为：

```
所述输水廊道包括阀门、出水口和出水孔；
所述阀门控制所述出水口的通断；
所述出水口经所述出水孔与所述船闸闸室连通。
```

此时名称已自明，**一般不必再用“其中”解释**。

### 示例2：改不动时才定义

```
……包括导稳组件；
其中，所述导稳组件包括……。
```

如果“导稳组件”没有更常见的可替代名，且该词概括了一组发明特有构成，则可以保留原词，并用“其中”或下位部件清单解释。

### 示例3：布置类口语「对称错位」

```
原写法：
所述拉杆为多根，多根所述拉杆沿竖向分层布置，并对称错位设置。
```

问题：「对称错位」非自明——错位相对谁、对称相对哪条参照不清楚；交底「左右」属观察方位，不宜钉死。

优先改写为可核对表述（示意）：

```
所述拉杆为多根，多根所述拉杆沿竖向分层布置；
相邻层的所述拉杆在水平投影上相互错开，并关于索塔纵向中心线对称布置。
```

此时不必保留「对称错位」再靠“其中”解释。若用户坚持保留该词，则须按 `自定义名词就地定义` **先前置白话写清**错开维度与对称参照（其中仅兜底），且观察方位仍宜按 `方位与场景限定上位规范` 处理。

## 反例（应避免）

### 反例1：能改名却不改

```
……包括过鱼小孔；
其中，所述过鱼小孔为……。
```

若该“小孔”其实就是“进鱼孔”或“出水孔”，就不应继续使用“小孔”这种口语词。

### 反例2：为求口语贴近而牺牲清楚性

```
……包括侧支孔；
```

若不解释读者根本不知其为何物，就不应仅因交底原词如此而照抄。

### 反例3：布置黑话原样入权

```
……并对称错位设置。
```

未说明错开维度与对称参照，读者无法判断何种布置落入保护范围。

## 与其他 skill 的关系

- `部件命名优化总控`：撰写时由总控分型 B 后进入本页；本页不代替总控入口。
- `自定义名词就地定义`：本 skill 在前，负责**先判断能否改名**；后者负责**改不动时如何说清**（先前置白话，其中兜底）。
- `部件命名具体优化`：改名之后删非必要定语、两档对照、同名多物；不要在本页做那些。
- `权利要求清楚性与逻辑一致性规范`：负责识别“名称不自明、突然出现”的问题；本 skill 给出优先改名的处理路线。
- `方位与场景限定上位规范`：布置改写时若出现左／右等观察方位，按该规范上位（如改为中心线对称），与本 skill 并行。
- `从权撰写`：部件名上的口语由总控分流到本 skill；布置口语出现在步骤/关系表述而非部件名时，B 层可直读本 skill。

## 检查清单

- [ ] 该名称是不是发明人口语、图纸习惯称呼或临时叫法？
- [ ] 是否属于布置／排列口语（对称错位、花错等）？若是，能否改成可核对的几何／位置关系？
- [ ] 本领域有没有更常见、更自明的结构名/功能结构名可替换？
- [ ] 改名是否只改变表达清楚性，而不改变技术事实？
- [ ] 若已能用更自明名称说清楚，是否避免了不必要的“其中”句？
- [ ] 若仍保留原名，是否确实已无更好名称，且已按 `自定义名词就地定义` 优先前置白话说清（其中仅兜底）？
