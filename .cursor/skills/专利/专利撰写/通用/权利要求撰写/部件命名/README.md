# 部件命名（权利要求撰写子簇）

本子目录只放**以「这个对象叫什么」为对象**的 skill。  
`方位与场景限定上位规范`、`自定义名词就地定义` 还服务句中限定与清楚性落地，正文留在上一级；本簇总控按需挂接，不另建一层总控。

## 目录多一层会不会改调用？

**不会。** Cursor 按各 `SKILL.md` 的 `name` / `description` 发现 skill，不按目录深度。本簇调用关系仍是：

```text
撰写（独权各版 / 每条从权）
  → 部件命名优化总控（唯一入口；方法/算法案仅第二版）
       → 按分型读叶子（未命中的跳过）
```

禁止再套「命名总控的总控」。质检命中口语名、方位钉死语、非公知概念时，**可直读对应叶**，不必先经本总控。

`name` 未改：`部件命名优化总控`、`部件命名具体优化`、`交底口语名改写为自明结构名规范`。策略/质检正文里的挂接名不用改路径。

## 一条名称的处理顺序（硬性）

对每个拟入权名称，按序过闸；未命中的闸跳过。一个名称可同时命中多型（如口语 + 方位 + 功能定语）。

| 序 | 闸 | 谁执行 | 不管 |
|----|----|--------|------|
| 0 | 对照已入权名表：是否同名多物 | `部件命名具体优化` **规则五**（改名落地） | 同物多名的识别口径见清楚性规范 |
| 1 | 交底口语 / 图纸习惯 / 临时名 / 布置黑话？ | `交底口语名改写为自明结构名规范`（三问：能否改成自明名或可核对几何表述） | 材料/性能定语是否必要；「其中」句式 |
| 2 | 名称里的左/右、上下游、迎水/背水、内外、场景钉死语？ | `方位与场景限定上位规范` | 参照物清不清楚（`权利要求指代与参照清晰性规范`） |
| 3 | 拆词：材料/性能/效果/用途定语是否必要；两档对照 | `部件命名具体优化` 规则一～四；功能色彩并行 `功能性限定使用边界规范` | 口语三问；方位要不要钉死的专条 |
| 4 | 改完仍不自明？ | `自定义名词就地定义`（前置白话 → 「其中」兜底） | 改名三问（须先完成第 1 闸） |
| 5 | 间接校正（命中才加） | 清楚性（同物多名/术语跳变**识别**）；指代（第一/第二）；`结构类权利要求撰写`（母子件层级） | 不替代第 0～4 闸的改名/说清 |

**产出：** 独权须交命名对照表，用户确认前不得写该版正文；从权默认可简记分型 + 采用名。闸门细则见 `部件命名优化总控` 第四节，不在本页复述。

## 本目录 skill

| skill | 角色 |
|-------|------|
| `部件命名优化总控` | 分型、分流、何时触发、对照表闸门。**不**写改名三问、删定语细则、「其中」句式 |
| `交底口语名改写为自明结构名规范` | 第 1 闸：能否改名 |
| `部件命名具体优化` | 第 0、3 闸：非必要定语、两档对照、同名多物改名落地 |

## 上一级、本簇挂接但不搬入的叶

| skill | 为何不搬进本目录 |
|-------|------------------|
| `方位与场景限定上位规范` | 从权句中「设置于左侧」即使部件名已优化，仍可能要命中；质检也可直触 |
| `自定义名词就地定义` | 方法参数「调节比」等不是部件名；清楚性/质检可直触 |
| `功能性限定使用边界规范` | 结构类专有；名称偷带功能时由总控并行挂接 |
| `结构类权利要求撰写` | 管母子件列举层级，不是改名手法 |
| `权利要求指代与参照清晰性规范` | 管清楚（参照物、第一/第二），不管方位是否过窄 |
| `权利要求清楚性与逻辑一致性规范` | 识别同名多物/同物多名；改名回第 0 闸 |

## 方法/算法案

时机只由 `方法类权利要求专有细则` 第六节管：第一版沿用交底原名；**仅第二版**触发 `部件命名优化总控`。步骤或问题句里的场景钉死语（不是对象名）仍可直读 `方位与场景限定上位规范`，见方法类具体撰写规则总控。
