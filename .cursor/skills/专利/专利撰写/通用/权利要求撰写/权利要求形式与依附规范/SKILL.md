# 权利要求形式与依附规范

原 `权利要求形式合规性规范`、`权利要求依附编号与术语出处规范` 已收束于此。**规则全文保留**。点名旧名即读对应节。平行/串联布局策略见 `权利要求引用结构检查`（策略对仍可能术语出处失败，两套都要过）。指代是否写全称见 `权利要求表达清楚性规范` 第二节。

## 分节何时用

| 时机 | 节 |
|------|----|
| 写从权 / 整份质检第一步 | 一、形式硬伤 |
| 从权出现「所述××」；从权第3步微表、第4步全文表；质检「依附编号错误」 | 二、术语出处 |

独立权利要求无引用链，但独权内部「所述」仍须在本条已出现特征中有先行基础（本条自洽），不适用「改引用」。

## 一、形式硬伤（原「权利要求形式合规性规范」）

### 适用场景

- 撰写从属权利要求时，或对已撰写完成的权利要求书做形式核对时使用。
- 本节检查的是《专利法实施细则》规定的**硬性格式规则**，属于"非黑即白"的合规问题，没有专业判断的商榷空间——一旦违反，审查员会直接在审查意见中指出形式缺陷。
- 与 `质检总控` → `权利要求质检总控` / `权利要求书质检` 配合使用：整份质检时，本节是**必读第一步**——在引用结构检查（`权利要求引用结构检查`）和实质布局审查（`权利要求书质检`）之前，先排除形式硬伤。

### 规则一：从属权利要求只能引用"在前"的权利要求

依据《专利法实施细则》（2023年修订）第二十五条第二款："从属权利要求只能引用在前的权利要求。"

- 权利要求 N 的依附对象，编号必须**严格小于 N**——只能引用排在它前面的权利要求，不能引用编号等于（引用自己）或大于自己（引用排在它后面）的权利要求。
- 这是最基础、最容易机械核对的一条规则：扫描每一条从权的引用部分，取出其中引用的权利要求编号，只要发现编号 ≥ 自身编号，就是格式错误，必须改。

正确示范：
```
权利要求5：根据权利要求1至4中任一项所述的装置，其特征在于，……
```
（引用的1～4均小于5，合规）

错误示范：
```
权利要求3：根据权利要求5所述的装置，其特征在于，……
```
（权利要求3引用了排在它后面的权利要求5，违反规则，必须改成引用编号更小的权利要求，或调整整体编号顺序）

### 规则二：多项从属权利要求只能"择一方式"引用在前权利要求

依据同一条款："引用两项以上权利要求的多项从属权利要求，只能以择一方式引用在前的权利要求。"

- 如果一条从权同时引用了两项以上的在前权利要求，引用部分必须使用"或""任一项"这种**择一（选择性）**表述，不能使用"和""及""与"这种要求同时满足多个引用对象的表述。
- 判断方法：读引用部分的连接词——"根据权利要求1或2所述"合规（择一）；"根据权利要求1和2所述"不合规（要求同时满足两者的限定，不是择一）。

正确示范：
```
根据权利要求1或权利要求2所述的装置，……
根据权利要求1至3中任一项所述的装置，……
```

错误示范：
```
根据权利要求1和权利要求2所述的装置，……
```
（这种写法在逻辑上要求同时依附两项权利要求的全部限定，不符合"择一"要求，必须改成"或"/"任一项"）

### 规则三：多项从属权利要求不得作为另一项多项从属权利要求的基础

依据同一条款："并不得作为另一项多项从属权利要求的基础。"

- 先判断一条从权是不是"多项从属权利要求"——只要它的引用部分包含两项以上权利要求（用了"或""任一项"这种择一表述），它就是多项从属权利要求。
- 判断规则：**任何一条多项从属权利要求，都不能被另一条多项从属权利要求引用**。也就是说，如果权利要求5是"根据权利要求1或2所述……"（多项从权），那么后面任何一条权利要求都不能写成"根据权利要求5或6所述……"这种同时以择一方式引用了权利要求5的多项从权。但是**单独、非择一地引用**权利要求5本身（即"根据权利要求5所述……"，只单独引用这一项）是允许的。

正确示范：
```
权利要求3：根据权利要求1或2所述的装置，其特征在于……（多项从权，合规，因为它引用的权利要求1、2都不是多项从权）
权利要求4：根据权利要求3所述的装置，其特征在于……（单独引用权利要求3这一项，不是"多项择一"引用，即使权利要求3本身是多项从权，这里也合规）
```

错误示范：
```
权利要求3：根据权利要求1或2所述的装置，其特征在于……（多项从权）
权利要求4：根据权利要求3或5所述的装置，其特征在于……
```
（权利要求4是多项从权，同时以择一方式引用了权利要求3（本身是多项从权）和权利要求5，属于"多项从权作为另一多项从权的基础"，违反规则。修改方式：可以把权利要求4拆成两条分别单独引用权利要求3、权利要求5的从权，或者把权利要求3改写成非多项从权）

### 规则四：从权引用部分应写明编号及主题名称

依据《专利法实施细则》第二十五条第一款：从属权利要求的引用部分应"写明引用的权利要求的编号**及其主题名称**"。

- 从权的引用部分不能只写编号，还应带上被引用权利要求的主题名称（即独权/上级从权保护的对象名称，比如"装置""方法""系统"）。
- 主题名称应当和独权的名称保持一致，不能中途变换措辞（比如独权是"一种XX装置"，从权引用时也应是"根据权利要求1所述的装置"，不能写成"根据权利要求1所述的设备"）。

正确示范：
```
权利要求1：一种XX装置，其特征在于，……
权利要求2：根据权利要求1所述的装置，其特征在于，……
```

错误示范：
```
权利要求2：根据权利要求1所述，其特征在于，……   （缺少主题名称"装置"）
权利要求2：根据权利要求1所述的设备，其特征在于，……   （主题名称和独权"装置"不一致，前后用词不统一）
```

### 规则五：编号连续性与固定句式格式

- **编号连续、无重复、无跳号**：权利要求书从1开始连续编号，不能跳号（比如从3直接跳到5）、不能有重复编号；调整、增删权利要求后必须重新核对全篇编号是否连续。
- **每项权利要求独立成段，以句号结尾**：每一项权利要求单独一段，最后以句号收尾，不能跟下一项权利要求粘连或漏掉句号。
- **固定引导句式**：
  - 独立权利要求：`一种/一个 XXX，其特征在于，……`（结构类/产品类）或按方法类固定句式（步骤类，以"包括以下步骤："引导）。
  - 从属权利要求：`根据权利要求X所述的XXX，其特征在于，……`（单项引用）或 `根据权利要求X至Y中任一项所述的XXX，其特征在于，……`（多项择一引用）。
  - 全篇权利要求书的引导句式应当统一，不要在"根据""按照""依据"这类近义表述之间来回切换。

### 检查方法（逐条机械核对）

对权利要求书从第一条独权开始，逐条向后核对每一条从权：
1. 提取该从权引用部分里的所有编号，检查是否都严格小于自身编号（规则一）。
2. 如果引用了两项以上编号，检查连接词是否为择一表述（规则二）。
3. 如果引用了两项以上编号，检查被引用的这些编号中，有没有任何一个本身也是"多项从属权利要求"（规则三）。
4. 检查引用部分是否同时写明了编号和主题名称，且主题名称与独权保持一致（规则四）。
5. 检查全篇编号是否连续、无跳号无重复；逐项检查句末是否有句号；引导句式是否统一（规则五）。

### 检查清单

- [ ] 是否存在从权引用了编号等于或大于自身的权利要求？
- [ ] 多项从权的引用部分是否都使用了"或"/"任一项"这种择一表述，而非"和"/"及"？
- [ ] 是否存在多项从权同时引用了另一条本身也是多项从权的权利要求？
- [ ] 每一条从权的引用部分是否都同时写明了编号和主题名称？主题名称是否与独权保持一致？
- [ ] 权利要求编号是否连续、无跳号、无重复？每项是否以句号结尾？引导句式是否全篇统一？

### 应用范围

本规则适用于任意技术方案类型（结构类/方法类/算法类）的权利要求书撰写与质检，是所有权利要求都必须遵守的形式底线，撰写从权时就应当直接遵守，而不是等质检阶段才发现问题。与 `权利要求质检总控` 编排的整份权要链路配合使用：质检时应优先核对本节的检查项。

## 二、依附编号／术语出处（原「权利要求依附编号与术语出处规范」）

### 适用场景

- **撰写从属权利要求时**（`从权撰写` 第3步门禁、单条交付前微型自检、第4步全文核对表）；
- **整份权利要求书质检时**（`权利要求书质检` 维度二第1点／输出项「依附编号错误」）；
- 单条审查中发现「所述××」可能无先行基础时按需加载。

**本节管什么：** 「所述／该」等回指用语所指向的名词，其**首次引入是否落在本条引用链上**——即依附编号与术语出处是否一致。

**不管什么：**

- 引用方向、多项择一、主题名称等**纯格式** → `本细则第一节（形式硬伤）`；
- 独立改进该平行、依赖该串联等**引用结构策略** → `权利要求引用结构检查`；
- 指代词是否应写全称、多对象消歧 → `权利要求表达清楚性规范第二节`（可与本节并行）。

---

### 核心规则（一句话）

**只要从权用到了某个须回指的词，而本条引用链上找不到该词的首次引入，就是依附编号／术语出处错误，必须改；禁止凭感觉写「所述有先行基础」。**

---

### 机械核对算法（撰写与质检同一套）

对每一条从属权利要求 \(N\)：

#### 1. 列词

列出本条正文中所有带「所述」（及同等回指如不当使用的「该」）的名词。

- 「所述锚固箱的底板」→ **分别**核对「锚固箱」与「底板」；
- 主题名称重复（如「所述……锚固结构」仅作引用套话）可不入表，但特征部分的部件／步骤名必须入表。

#### 2. 溯源

对每个词，在**本条之前的全部权利要求**（权1～权 \(N-1\)，**不是**只在当前引用链上）中查找**首次出现／首次引入**的权号。

- 本条以「包括／还包括／设有××」等**首次引入**、且未写成「所述××」的词 → 记为「本条新引入」，不要求上游出处。
- 公知且未当作本发明部件名回指的用语（如单独出现的「混凝土」作材料修饰）按案件判断；一旦写成「所述××」并当作已定义部件，必须溯源。

#### 3. 取最大号

在「须有出处」的词中，取其首次出现权号的**最大值** \(M\)（并保留每个词各自的首次权号，供逐词覆盖判定）。

#### 4. 覆盖判定

画出本条引用链：权 \(N\) → 直接引用对象 → … → 权1。

**通过条件：** 每个须出处的「所述××」，其首次出现权号都落在该引用链上的某一节点。

**失败条件：** 任一所述词的首次出现权号**不在**引用链上（典型：词在平行从权中引入，本条却只引权1）。

#### 5. 失败则三选一处置（禁止带病交付／带病出质检结论而不给改法）

| 代号 | 处置 | 适用 |
|------|------|------|
| **A. 改引用** | 改为引用（或经串联能覆盖）首次出现该词的权利要求 | 技术上本就依赖该上游从权 |
| **B. 本条首次引入** | 去掉不当「所述」，改为「所述母件设有／包括××」在本条给出 | 不欲串联、且本条可自足引入 |
| **C. 布局调整** | 先写／合并能提供出处的上游从权，或增加组合依赖后再写本条 | A/B 都不顺时 |

质检输出时：逐条写明「权 \(N\) → 问题词 → 首次出现于权 \(X\) → 当前链 → 建议 A/B/C」。

|--------|--------------|--------------------|------------------------|

### 正反例（锚固结构案型）

#### 反例1：平行从权引入的子件被下游误用（权6）

- 权2引入「顶板」；权4引入「底板」；权5引权1写螺栓连接；权6引权5写「所述锚固箱的底板与所述钢牛腿的顶板之间…」。
- 引用链 6→5→1 **不含**权2、权4 → **失败**。
- 处置：**B** 在权6写「所述锚固箱设有底板，所述钢牛腿设有顶板，所述底板与所述顶板之间…」；或 **A/C** 调整引用／组合布局使链覆盖权2与权4。

#### 反例2：侧板仅在权4出现，权7却引权1（权7）

- 权4引入「侧板」；权7引权1写「焊接固定于所述锚固箱的侧板外侧」。
- 链 7→1 无侧板 → **失败**。
- 处置：**A** 改为引权4；或 **B**「所述锚固箱设有侧板，…固定于所述侧板外侧」。

#### 正例

- 权2引入「塔壁钢板」；权3引权2写「所述塔壁钢板的内侧设有抗拔锚筋」→ 链 3→2→1 覆盖 → **通过**。

### 与其他 skill 的挂接

| Skill | 关系 |
|-------|------|
| `从权撰写` | **门禁必读**；第3步按本规范做微表；第4步按本规范做全文表；算法以本文件为准，从权撰写内仅保留短指引＋表格式 |
| `权利要求书质检` | **维度二第1点执行本规范**，不在质检 skill 内重写算法；输出格式仍用质检总控的「依附编号错误」栏 |
| `权利要求质检总控` | 整份链路中「依附编号」＝调度执行本规范 |
| `权利要求表达清楚性规范第三节` | 「引用编号与术语来源对应」专项指向本规范 |
| `本细则第一节（形式硬伤）` | 只做编号大小／多项格式；不做术语出处 |
| `权利要求引用结构检查` | 只做平行／串联策略；策略正确仍可能术语出处失败，两套都要过 |

### 检查清单

- [ ] 每条从权的「所述××」已列全（含「所述A的B」拆开）
- [ ] 首次出现权号是在**全文前序权利要求**中查的，不是只在引用链上查的
- [ ] 每个须出处词的首次权号都落在本条引用链上
- [ ] 失败项已选 A/B/C 之一并改稿（撰写）或写入质检意见（质检）
- [ ] 撰写已附单条微表；从权收束已附全文核对表

### 应用范围

任意技术方案类型（结构类／方法类／算法类）的从属权利要求撰写与质检。独立权利要求无「引用链」问题，但独权内部「所述」仍须在本条已出现特征中有先行基础（本条自洽），不适用「改引用」处置。
