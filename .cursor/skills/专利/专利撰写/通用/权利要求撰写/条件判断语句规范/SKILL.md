# 条件判断语句规范

方法/算法权利要求出现条件步骤时必读。正反例见同目录 `examples.md`。不写独权策略 plan。

## 先问范围，再选句式（硬性）

独权把 true / false **都写全**，等于要求侵权者实现**全部分支**才落入保护范围。发明点只在一个分支上时，写全会写窄。

| 情形 | 独权写法 | 从权 |
|------|----------|------|
| **发明点只在一个分支** | `在……的情况下，……`（不写另一分支） | 可补另一分支或细化阈值 |
| **两个分支都是必要控制逻辑**（如符合则解锁、否则保持锁定） | `判断是否……，若是，则……；若否，则……` | 细化条件或阈值 |
| 需要先取得判断结果再分支，且发明点仍只在一侧 | 可先「判断是否……」，再只写 `在……的情况下` 执行发明动作 | 另一侧 |

**独权默认采用第一行。** 不要为「句式完整」把未发明的 else 写进权 1。

## 允许的句式

**单分支（独权首选）：**
```
在所述检测值大于第一阈值的情况下，降低所述风机的转速。
```

**双分支（仅当两侧都必要）：**
```
判断所述触摸动作是否与预先设定的解锁触摸动作相同，若是，则将所述触摸屏设备切换到工作状态；若否，则保持所述触摸屏设备处于锁定状态。
```

多条件用「且 / 或 / 同时满足」写在「在……的情况下」或「判断是否」的条件里。嵌套判断拆成独立步骤，不要单步套娃。

## 禁止

- 「如果……那么……」「要是」「假如」「是的话」等口语。  
- 「当……时……」作条件步骤（易与时间点混淆；改「在……的情况下」或「判断是否」）。  
- 「检测是否……，是的话……」。  
- 独权发明点只在一侧，却写上「若否，则……」把另一侧锁进权 1。  
- 条件不可验证：「合适」「适当」「较好」。

「在……的情况下」**不是**禁止用语；它是单分支独权的规范写法。

## 检查清单

- [ ] 已判断：发明点在单侧还是两侧都必要  
- [ ] 单侧发明：独权用「在……的情况下」，未把 else 写进权 1  
- [ ] 两侧都必要：才用「判断是否……若是……；若否……」  
- [ ] 无「如果 / 当……时 / 是的话」  
- [ ] 条件可验证；嵌套已拆步
