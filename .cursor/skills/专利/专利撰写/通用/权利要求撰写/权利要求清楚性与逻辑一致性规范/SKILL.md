# 权利要求清楚性与逻辑一致性规范

## 适用场景

- 撰写权利要求时边写边自查；整份质检时由 `权利要求质检总控` → `权利要求书质检` 挂接。
- 查表达与逻辑清楚简要；形式引用硬伤见 `权利要求形式合规性规范`。

**执行时必须先 Read** `清楚性与逻辑一致性共用内核`，检查对象 = **权利要求文本**。本文件只补权要侧差异，不重复六条共性规则全文。

## 权要侧差异（相对内核）

### 规则二补充：定义写在哪里

识别自定义名词/非公知概念后，须在**权利要求内部**说清含义，见 `自定义名词就地定义`：**优先改自明名或在名称出现前白话描述**；「其中……」仅为兜底。不可只推给说明书，也不可默认堆砌「其中」。

### 规则四补充：反例的权要含义

反例常表现为：字面满足全部限定，却解决不了背景技术问题、或明显不是发明人想保护的方案（措辞过宽留漏洞）。

### 与参数/命名/依附的衔接（权要专有）

- 预设值/阈值等「先获取后使用」→ `预设值与参数来源检查`
- **同物多名**：同一特征须名称统一
- **同名多物（识别）**：不同对象不得共用裸名；改名落地 → `部件命名优化总控` **E 型** → `部件命名具体优化` 规则五（禁止绕过总控直触具体优化）
- **所述×× 术语出处** → `权利要求依附编号与术语出处规范`（不重写算法）

## 权要检查清单

先勾共用内核清单，再补：

- [ ] 同一技术特征全篇名称统一（无同物多名）？
- [ ] 有无同名多物？若有是否已交命名总控 E 型消歧？
- [ ] 从权「所述××」出处是否落在引用链上？

## 应用范围

适用于结构/方法/算法类权利要求的撰写与质检。质检链路：`质检总控` → `权利要求质检总控` → `权利要求书质检`。
