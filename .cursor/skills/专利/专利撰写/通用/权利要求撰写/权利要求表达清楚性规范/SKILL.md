## 一、主谓宾（原「权利要求主谓宾结构规范」）

> **规则卡。** 正反例与典型案例见同目录 [`examples.md`](examples.md)；从权默认走摘要自检，疑点或用户要举例时再 Read 示例。

### 核心规则

**权利要求中的每个动作、状态、关系描述都必须有明确的主语，避免因省略主语导致指代不明、执行者不清楚，从而造成权利要求不清楚。**

#### 基本原则

1. **动作必有执行者** — 每个动词前应有明确的主语（部件名称、模块名称、系统名称等）
2. **状态必有归属** — 每个状态描述应明确是哪个对象的状态
3. **关系必有双方** — 描述连接、配合等关系时，应明确关系的主体和客体
4. **允许省略的情况** — 仅当上下文中主语明确且唯一时，才可省略

### 问题类型（判定要点）

| 类型 | 判定 | 处置方向 |
|------|------|----------|
| 动作执行者不明确 | 动词找不到唯一主语 | 为每个动作补主语，或拆步 |
| 状态归属不明 | 「处于…」「温度…」等无归属对象 | 写明是谁的状态/哪处的量 |
| 关系主客体不明 | 「通过…连接」缺双方 | 写明 A 与 B 的关系 |
| 并列动作主语混淆 | 并列动词中途换执行者却未标出 | 换主体处重写主语，或拆句 |

### 检查方法（四步）

1. **标记**所有动词与状态词  
2. **为每个**动词/状态词寻找主语：当前句有无？省略时前文能否唯一确定？  
3. **盯易错句式**：动词开头；「通过…」开头；被动缺施动者；并列动作主语变化  
4. **修正**：补主语 → 调句式 → 拆复杂句（优先补充明确主语）

### 允许省略主语（须同时满足）

1. **唯一性** — 上下文只有一个可能主语  
2. **邻近性** — 主语在前文紧邻出现  
3. **结构性** — 如「用于…」已锚定主语  
4. **不引起歧义** — 读者无需推理  

典型允许：同一句内主语相同的并列动作；「所述X用于接收…、处理…并输出…」。

### 检查清单

#### 结构类
- [ ] 连接关系明确双方（A与B连接）
- [ ] 位置关系明确主体（A位于B的上方）
- [ ] 功能描述明确执行者（所述A用于…）
- [ ] 「其中/且/并」后动作主语明确
- [ ] 被动语态必要时补施动者

#### 方法类
- [ ] 每步动作执行者明确
- [ ] 判断/比较有操作主体
- [ ] 获取/接收有执行者
- [ ] 并列动作主语变化已标出
- [ ] 条件判断的判断主体明确

#### 算法类
- [ ] 计算/处理有执行主体（处理器、模块、系统）
- [ ] 数据流转各环节执行者明确
- [ ] 判断/比较/提取主体明确
- [ ] 输出/返回执行者明确

### 从权摘要自检（C 层，可不等同于全文 Read）

- [ ] 本条每个动作/状态能指出主语，或属于合法承前省略  
- [ ] 并列动作若换执行者，已重新写出主语  

### 修正建议格式

```
【问题句子】：…
【问题类型】：动作执行者不明确 / 状态归属不明 / …
【歧义分析】：…
【修正建议】：…
【修正理由】：明确各动作执行主体，避免不清楚
```

### 与其他技能的配合

1. `本细则第三节（清楚性）` — 清楚性的一个维度  
2. `结构类权利要求撰写` — 结构撰写时同步检查主语  
3. `方法步骤条件与参数规范第一节` — 判断主体须明确  
4. `本细则第二节（指代与参照）` — 主谓宾与指代互补  

推荐：撰写边写边查 → 自查用本卡 → 质检结合清楚性规范；需要示例时 Read `examples.md`。

### 注意事项

1. 不要过度重复主语；同句并列可承前省略  
2. 目标是清楚，不是冗长  
3. 说明书对执行主体的解释应与权利要求主语一致  
4. 技术领域习惯可不同，清楚性原则不变

## 二、指代与参照（原「权利要求指代与参照清晰性规范」）

> **规则卡。** 正反例与综合案例见同目录 [`examples.md`](examples.md)；从权默认走摘要自检，疑点或用户要举例时再 Read 示例。

### 核心规则

1. **指代词** — 优先「所述+部件名」；多同类对象必须消歧；代词链超过 2 层宜复述完整名称  
2. **方位词** — 周向/轴向/平行/垂直等凡依托参照系才有意义的词，必须在权利要求文字内写明参照物  

> **分工：** 左/右、上游/下游、迎水/背水、场景钉死语要不要放宽以扩围 → `权利要求命名细则第四节`。本节只保证**清楚**（有参照、无歧义），不负责上位扩围。

### 第一部分：指代词

#### 基本原则

1. 优先「所述+完整名称」，少用「该」「其」  
2. 多同类对象用序号/位置/功能等限定消歧  
3. 指代超过 2 层时复述完整名称  

#### 问题类型（判定要点）

| 类型 | 判定 |
|------|------|
| 用「该」而非「所述」 | 可改为「所述」更规范 |
| 多同类对象指代不明 | 「所述固定座」在第一/第二并存时有歧义 |
| 「其」对象不唯一 | 读者需猜测「其」指谁 |
| 代词链过长 | 跨多层从权仍用「其」 |
| 并列结构指代混淆 | 「其输出端」在 A 和 B 并列后不明指谁 |

#### 指代词检查清单

- [ ] 是否用了「该」而非「所述」（建议统一「所述」）
- [ ] 多同类时「所述XX」有无歧义
- [ ] 「其」的对象是否唯一
- [ ] 代词链是否过长（>2 层建议复述）
- [ ] 并列结构中指代是否清晰
- [ ] 每个指代词能否在前文找到明确对象

### 第二部分：方位词参照物

#### 基本原则

凡「周向、轴向、径向、转动、移动、平行、垂直、倾斜」等 → 追问「相对于什么？」  
权利要求文字本身能直接回答 → 清楚；需读者猜 → 不清楚。

#### 问题类型（判定要点）

| 类型 | 须明确 |
|------|--------|
| 周向/径向/轴向 | 参照轴线 |
| 转动/旋转/枢转/摆动 | 转动轴 |
| 移动/滑动/伸缩 | 方向或参照面 |
| 平行/垂直/倾斜 | 参照对象 |
| 螺旋状/弧形/弯曲 | 形状参照轴/面 |
| 上/下/左/右/前/后 | 参照对象或坐标系（清楚性；扩围见方位上位规范） |

#### 方位词检查清单

- [ ] 周向/径向/轴向 — 有参照轴线
- [ ] 转动类 — 有转动轴
- [ ] 移动类 — 有方向或参照面
- [ ] 平行/垂直/倾斜 — 有参照对象
- [ ] 螺旋/弧形 — 有参照轴/面
- [ ] 上/下/左/右/前/后 — 有参照对象
- [ ] 「该方向/该轴线」 — 前文已定义

### 从权摘要自检（C 层）

- [ ] 无「该/其」造成多对象歧义；优先「所述+完整名称」  
- [ ] 若出现周向/轴向/平行/上下等，文字内能回答「相对什么」  

### 修正建议格式

```
【问题句子】：…
【问题类型】：指代歧义 / 方位缺少参照物
【歧义分析】：…
【修正建议】：…
【修正理由】：…
```

### 与其他技能的配合

1. `本细则第三节（清楚性）`  
2. `本细则第一节（主谓宾）`  
3. `结构类权利要求撰写`  
4. `权利要求命名细则第四节`（扩围，非本卡）  

需要示例时 Read `examples.md`。

### 注意事项

1. 「所述」优先；全文已统一用「该」且无歧义也可接受  
2. 对象唯一时可适当用指代，避免过度复述  
3. 目标是消歧，不是堆砌全称  
4. 说明书与权利要求的指代/方位表达宜一致

## 三、权要侧清楚性（原「权利要求清楚性与逻辑一致性规范」）

### 适用场景

- 撰写权利要求时边写边自查；整份质检时由 `权利要求质检总控` → `权利要求书质检` 挂接。
- 查表达与逻辑清楚简要；形式引用硬伤见 `权利要求形式与依附规范第一节`。

**执行时必须先 Read** `清楚性与逻辑一致性共用内核`，检查对象 = **权利要求文本**。本文件只补权要侧差异，不重复六条共性规则全文。

### 权要侧差异（相对内核）

#### 规则二补充：定义写在哪里

识别自定义名词/非公知概念后，须在**权利要求内部**说清含义，见 `权利要求命名细则第五节`：**优先改自明名或在名称出现前白话描述**；「其中……」仅为兜底。不可只推给说明书，也不可默认堆砌「其中」。

#### 规则四补充：反例的权要含义

反例常表现为：字面满足全部限定，却解决不了背景技术问题、或明显不是发明人想保护的方案（措辞过宽留漏洞）。

#### 与参数/命名/依附的衔接（权要专有）

- 预设值/阈值等「先获取后使用」→ `方法步骤条件与参数规范第二节`
- **同物多名**：同一特征须名称统一
- **同名多物（识别）**：不同部件不得共用裸名；消歧改名 → `权利要求命名细则第二节` 规则五
- **所述×× 术语出处** → `权利要求形式与依附规范第二节`（不重写算法）

### 权要检查清单

先勾共用内核清单，再补：

- [ ] 同一技术特征全篇名称统一（无同物多名）？
- [ ] 有无同名多物？若有是否已转命名具体优化消歧？
- [ ] 从权「所述××」出处是否落在引用链上？

### 应用范围

适用于结构/方法/算法类权利要求的撰写与质检。质检链路：`质检总控` → `权利要求质检总控` → `权利要求书质检`。
