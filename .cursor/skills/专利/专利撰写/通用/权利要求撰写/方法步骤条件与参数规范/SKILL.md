# 方法步骤条件与参数规范

原 `条件判断语句规范`、`预设值与参数来源检查` 已收束于此。主要适用于方法/算法权要；结构案若有预设参数，第二节同样适用。句式正误扩展例见同目录 `examples.md`。

条件判断的**判断主体**须明确，见 `权利要求表达清楚性规范` 主谓宾节。参数**含义**是否说清见 `权利要求命名细则` 第五节；本节只管**来源**。

## 分节何时用

| 时机 | 节 |
|------|----|
| 出现条件分支 | 一、判断句式 |
| 出现阈值/预设/运行参数 | 二、参数来源 |

---

## 一、条件判断句式

固定句式：

```text
判断是否满足[条件]，若是，则[操作A]；若否，则[操作B]
```

仅 true 分支可省略「若否」。多条件用「同时满足…和…」或「满足…或…」；复杂组合可在条件部分用括号，仍保持「判断是否满足…」开头。

**禁止：** 「如果…那么…」「当…时…」「在…情况下」「是的话」「如检测到…则…」。true/false 固定用「若是」「若否」，不用「如果是」「要是」。

**嵌套：** 禁止单步骤内再套一层判断。拆成独立步骤，每步一套判断句式。

条件必须客观可验证，避免「合适」「适当」。结构类一般不涉及本节。

## 二、预设值与参数来源（机器人视角）

权要里每出现预设值、阈值、系数、比例、目标值等，须能从文字获得该数据。机器人没有常识补全：没写来源就拿不到。

对参数 X 三问：①前文是否已「预先设定／给定」？②是否本领域公认常量（如 g、水的密度）？③使用前是否已有获取／测量／采集／计算／读取步骤？三者皆否 → 必须补获取或标明预设，不得凭空使用。

| 类型 | 写法 |
|------|------|
| 已给定/预设 | 写明「预先设定／预设」；尽量交代依据或范围 |
| 公知常量 | 可直接用 |
| 运行时才能确定（温度、转速、置信度等） | **必须**先写获取/计算步骤，且排在使用之前 |

含义已用白话钉死的短名（如调节比），仍须交代该量从哪来。步骤顺序满足**先获取、后使用**。

---

## 最低自检

- [ ] 条件判断均以「判断是否…」起，若是/若否固定；无「如果／当…时」  
- [ ] 嵌套已拆步；条件可验证  
- [ ] 每个阈值/参数能回答「从哪来」；运行时量在使用前已获取  
- [ ] 预设值已写出「预设／预先设定／给定」
