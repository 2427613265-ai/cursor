# 权利要求命名细则

原 `部件命名优化总控`、`部件命名具体优化`、`交底口语名改写为自明结构名规范`、`方位与场景限定上位规范`、`自定义名词就地定义` 已收束于此。**规则全文保留**；点名旧名即读本页对应节。本页只改「打开哪一节」，不改判定标准与处置。

**间接校正仍外指：** 同物多名识别 → `权利要求表达清楚性规范` 第三节；同类件序数消歧 → 同上第二节；母子件层级 → `结构类权利要求撰写`；名称偷带功能 → `功能性限定使用边界规范`。

## 分节何时用

| 时机 | 必用节 |
|------|--------|
| 结构案各版独权正文前；方法案**仅第二版**正文前；每条从权新名 | 〇闸门与分型，再按型用二～五节 |
| 交底口语/图纸习惯名 | 三、口语改写 |
| 左/右、上/下、上游/下游、迎水/背水、内外、场景钉死语 | 四、方位与场景 |
| 非公知概念、自造词 | 五、就地定义（先问能否改名） |

---

## 〇、分型、闸门与交付（原「部件命名优化总控」）

### 适用场景

- 写独权之前：默认各版均可触发；**方法/算法案仅第二版触发**（第一版不优化命名，方法案无第三版，见 `方法类权利要求专有细则` 第六节 / `方法类独权撰写`）；
- 写独权第一版、第二版、第三版之前（结构案）；方法案见上例外；
- 写每一条从权之前；
- 审核权利要求中某个部件名是否要改名、上位、删定语、消歧、定义或调整母子件命名层级时。

**硬性规则：本节是命名入口。独权/从权应先走本节分型，再转本细则对应节（二～五节及间接校正）；不再打开已删除的旧叶目录。**

---

### 本节管什么

本节**不直接替代二～五节的具体命名规则**，而是先做三件事：

1. 识别当前部件名的问题类型；
2. 决定本轮要转本细则哪一节或哪几节（直接命名类 / 间接校正类）；
3. 给出本轮命名优化的最小交付要求。

---

### 一、挂接清单（完整版）

#### A. 直接命名类（必须挂接；命中即分流）

| 具体 skill | 管什么 |
|------------|--------|
| `本细则第二节（具体优化）` | 名称中的材料/性能/效果/用途/场景定语是否非必要；两档命名对照 |
| `本细则第三节（口语改写）` | 交底口语名、图纸习惯名、临时名能否改成自明结构名/功能结构名 |
| `本细则第四节（方位与场景）` | 名称中的左/右、上/下、上游/下游、内/外、防洪等方位/场景钉死语是否应上位 |
| `本细则第五节（就地定义）` | 改名后仍不自明的本案特有概念：优先在名称出现前白话写清，必要时才用「其中」兜底 |

#### B. 间接校正类（建议挂接；按条件分流）

| 具体 skill | 管什么 | 何时分流 |
|------------|--------|----------|
| `权利要求表达清楚性规范第三节` | 同物多名、同名多物、术语跳变（识别） | 同一对象出现多种叫法，或不同对象共用一名时；**同名多物的改名落地转 `本细则第二节（具体优化）` 规则五** |
| `权利要求表达清楚性规范第二节` | 第一/第二、所述××消歧；方位参照是否清楚 | 存在多个同类部件，或名称依赖序数/方位消歧时 |
| `结构类权利要求撰写` | 母件名与子件名层级；子件不得与母件同级并列 | 一次引入多个新部件，或展开某母件内部构成时 |
| `功能性限定使用边界规范` | 名称是否偷带功能/效果，是否应把功能从名称挪到句中限定 | 名称含调心、限位、防腐、抗拔、用于…等功能/效果色彩时 |

---

### 二、先识别问题类型

对每个拟入权部件名，按下表分型：

| 类型 | 典型表现 | 下一步调用 |
|------|----------|------------|
| A. 名称夹带材料/性能/效果/用途/场景定语 | 高强螺栓、防腐护套、上游锚固箱、专用支架 | **必须** `本细则第二节（具体优化）`；若定语偏功能效果，可并行 `功能性限定使用边界规范` |
| B. 名称是交底口语名/图纸习惯名/临时名 | 小板、连接块、那个支撑件、侧支结构 | **必须** `本细则第三节（口语改写）`；改后再回 `本细则第二节（具体优化）` |
| C. 名称中带左/右、上/下、上游/下游、内/外等方位或场景词 | 左侧板、下游支架、外侧孔 | **必须** `本细则第四节（方位与场景）`；之后再回 `本细则第二节（具体优化）` |
| D. 名称改不动仍不自明 | 本案特有词、自造词、缩略词 | **必须** `本细则第五节（就地定义）`（优先前置白话说清，少用「其中」） |
| E. 名称前后一致性可疑 | 同物多名、同名多物、术语跳变 | **同名多物：必须先 `本细则第二节（具体优化）`（规则五消歧改名）**；同物多名/术语跳变：`权利要求表达清楚性规范第三节` 识别收口 |
| F. 同类部件需要消歧命名 | 第一/第二锚固单元、所述锚下承压板指哪一块 | **按条件** `权利要求表达清楚性规范第二节` |
| G. 母件/子件命名层级可疑 | 把子板与母箱写成同级“还包括” | **按条件** `结构类权利要求撰写` |
| H. 名称偷带功能效果 | 调心垫板、限位挡块、防腐护套 | **按条件** `功能性限定使用边界规范` + **必须** `本细则第二节（具体优化）` |

---

### 三、调用顺序

默认按下列顺序分流（按需中止，不必五/八个全跑）：

#### 直接命名链路（优先）

1. **`本细则第二节（具体优化）`**  
   处理高强、钢、防腐、调心、限位、专用等非必要定语；
2. 若名称本身不是自明结构名，转  
   **`本细则第三节（口语改写）`**；
3. 若名称里含方位/场景词，转  
   **`本细则第四节（方位与场景）`**；
4. 若改名后仍不自明，转  
   **`本细则第五节（就地定义）`**。

#### 间接校正链路（命中条件时追加）

5. 名称含明显功能/效果色彩时，追加  
   **`功能性限定使用边界规范`**；
6. 一次引入多部件或展开母件内部构成时，追加  
   **`结构类权利要求撰写`**（核对命名层级）；
7. 存在多个同类件、需序数/方位消歧时，追加  
   **`权利要求表达清楚性规范第二节`**；
8. 落笔前若发现同物多名/术语跳变，追加  
   **`权利要求表达清楚性规范第三节`**；  
   若发现**同名多物**（不同件共用裸名），追加  
   **`本细则第二节（具体优化）`（规则五）** 做归属前缀等消歧改名。

> 说明：并非每个名称都要八个 skill 全跑一遍，而是先由本总控判型，再按需分流。

---

### 四、独权与从权的最低要求

#### ★ 独权硬性闸门（因命名直接影响保护范围）

**默认（结构类独权等）：** 每一版独权（第一版 / 第二版 / 第三版）在写出独权正文之前，必须先交付「部件命名优化对照表」供用户选择确认；未经用户确认，不得直接输出该版独权全文。

**方法/算法案例外（硬性，服从 `方法类独权撰写`）：**

| 版本 | 本总控 |
|------|--------|
| 第一版（第5步） | **不触发**命名优化；沿用交底原名即可写正文 |
| 第二版（第7步） | **唯一一次**触发本总控并交付对照表；确认前不得写第二版正文；关键名至少两档 |

方法案无第三版；第二版确认名即全书基准。

原因：独权中的名称直接框定保护范围；方法案第一版沿用交底原名保证可读，命名优化集中在对准重新核定问题的第二版一次做完。

对照表最低列（**方法案仅第二版适用**；结构案各版适用）：

| 部件原名（交底/上一版） | 分型 | 第一档优化 | 第二档优化 | 推荐采用名 | 对保护范围的影响（一句话） | 用户选择 |
|------------------------|------|------------|------------|------------|----------------------------|----------|
| … | A/B/… | … | … | … | 变宽/变窄/更清楚/需定义 | 待确认 |

规则：

1. 关键入权部件/术语（尤其是独权顶层对象与核心中间量）**逐一入表**，不得只口头说“已优化”；
2. 至少给出**两档**优化名（结构案第三版硬性；方法案第二版对关键名须两档，次要名可一档+保留说明；结构案第一、二版对关键名也须两档）；
3. 表中须标**推荐采用名**及**对保护范围的影响**；
4. 标注「**待确认：独权部件命名表**」；
5. **用户确认或改选采用名之后**，才允许进入**该次触发所对应版本**的独权正文撰写；
6. 若用户改选了更宽/更窄档，须按确认结果落笔，并在独权交付物中注明“命名已按用户确认表采用”。

#### 1. 独权第一版

- **结构案：** 必须触发本总控；至少完成明显口语名、明显非必要定语的筛选；**先出命名对照表 → 用户确认 → 再写第一版独权**；不要求本轮一定扩到最宽，但不能把明显错误名称直接带入。
- **方法/算法案：** **不触发**本总控；沿用交底原名写第一版（见 `方法类独权撰写`）。

#### 2. 独权第二版

- **结构案与方法/算法案均必须触发本总控**；
- 至少完成：去掉与重新核定技术问题无关的材料/性能/效果/场景定语（及方法案中的工具/算法钉死名等）；
- **先出命名对照表 → 用户确认 → 再写第二版独权**；
- 若当前名称仍夹带非必要缩限，应改或下放；
- **方法/算法案：本版为全案唯一一次命名优化。**

#### 3. 独权第三版

- **结构案：** 必须触发本总控；由本总控强制分流到 `本细则第二节（具体优化）`，完成至少两档命名对照；**先出命名对照表（含保护范围影响说明）→ 用户确认 → 再写第三版独权**；若名称涉及方位/场景词，再并行触发 `本细则第四节（方位与场景）`；若存在同类件消歧或术语跳变，追加指代清晰性 / 清楚性规范。
- **方法/算法案：** 无第三版；不在本档触发。

#### 4. 每条从权

- 必须触发本总控；
- 任何新增部件名称，至少要完成：
  - 是否口语名；
  - 是否带非必要定语；
  - 是否与前文术语冲突；
  - **新名是否与已入权部件同名异物（对照已用名表；冲突则先按 `本细则第二节（具体优化）` 规则五消歧改名）**；
- 新引入多个子部件时，须追加 `结构类权利要求撰写` 核对命名层级；
- 从权默认可在本条交付物中简记命名结论；**若该条命名会实质影响后续独权重写或保护范围理解，应升格为显式对照表请用户确认**。

### 五、最低交付物

#### 独权（硬性）

必须先交付命名对照表（见第四节表格），并得到用户确认后，才写独权正文。表内每个关键部件最终应对应下列处置之一：

1. **保留原名**；
2. **优化为更中性的结构名/功能结构名**；
3. **保留短名但优先前置白话说清**（必要时才「其中」兜底）；
4. **保留原名但把某些定语下放到更下位从权或说明书**；
5. **调整命名层级/消歧方式**。

#### 从权（默认）

使用本总控后，本轮至少简记：

- 分型（A～H，可多选）；
- 已调用具体 skill 清单；
- 采用名 + 理由。

### 六、典型示例

#### 示例1：高强螺栓

- 分型：A
- 调用：`本细则第二节（具体优化）`
- 处理：优先比较 `高强螺栓 → 螺栓 → 连接螺栓`

#### 示例2：左侧承压耳座

- 分型：A + C + F（若两侧都有）
- 调用：`本细则第二节（具体优化）` → `本细则第四节（方位与场景）` → 必要时 `权利要求表达清楚性规范第二节`
- 处理：判断是否优化为 `一侧承压耳座` 或 `第一承压耳座`

#### 示例3：锚下块

- 分型：B
- 调用：`本细则第三节（口语改写）` → 再回 `本细则第二节（具体优化）`
- 处理：先尝试改为承压板、支撑块、垫块等自明名称

#### 示例4：球面调心垫板

- 分型：A + H
- 调用：`本细则第二节（具体优化）` + `功能性限定使用边界规范`
- 处理：先问“球面”是否结构必要、“调心”是否效果偷渡；比较 `球面调心垫板 → 球面垫板 → 垫板`

#### 示例5：锚固箱包括底板、侧板……（从权展开）

- 分型：G
- 调用：`结构类权利要求撰写`（先总列子件名，再展开；子件名不得与锚固箱同级“还包括”）
- 可并行：`本细则第二节（具体优化）` 审查各子件名

#### 示例6：本案特有缩略词

- 分型：D
- 调用：`本细则第五节（就地定义）`

### 八、与具体 skill 的关系（收口）

- 本节 = **总控 / 分流入口**
- **直接命名类**
  - `本细则第二节（具体优化）` = 材料、性能、效果、用途、场景定语的具体执行；**兼管跨权利要求同名多物的消歧改名**
  - `本细则第三节（口语改写）` = 口语名、图纸习惯名
  - `本细则第四节（方位与场景）` = 方位、场景钉死语
  - `本细则第五节（就地定义）` = 改不动仍不自明的名称（优先前置白话，少用「其中」）
- **间接校正类**
  - `权利要求表达清楚性规范第三节` = 同物多名 / 同名多物的**识别**收口（改名回指 `本细则第二节（具体优化）`）
  - `权利要求表达清楚性规范第二节` = 同类件消歧命名与参照清楚
  - `结构类权利要求撰写` = 母件/子件命名层级
  - `功能性限定使用边界规范` = 名称中的功能/效果偷渡边界

## 二、去非必要定语、两档对照、同名多物（原「部件命名具体优化」）

### 适用场景

- 写独立权利要求第一版、第二版、第三版时；
- 写每一条从属权利要求时；
- 审核权利要求中的部件名称是否过窄、带有非必要效果/材料/性能定语、是否属于交底口语名或图纸习惯名时。

**定位：本节是具体执行层，通常由 `本细则〇节（分型与闸门）` 先判型后再调用。**

---

### 核心目标

对部件名称做三件事：

1. **去口语化**：把交底口语名、图纸习惯名、临时叫法改成自明结构名或功能结构名；
2. **去非必要缩限**：删除名称中不必写死的材料、性能、效果、用途、场景定语；
3. **保清楚、再扩围**：在不牺牲清楚性的前提下，把名称改到更宽、更稳妥的一档。

---

### 核心规则

#### 规则一：先问“这个名称是不是结构名本身”

先把名称拆开看：

- **真正的结构核心词**：板、杆、箱、套、座、块、孔、槽、肋、螺栓、螺母、垫板、支撑板等；
- **可能可删或可上位的修饰语**：钢、高强、防腐、调心、限位、锚下、上游、下游、左、右、专用、防洪等。

写权利要求时，优先保留真正限定结构边界的词，审查修饰语是否必须保留。

---

#### 规则二：部件名称中的材料/性能/效果词，不当然保留

凡名称中带下列定语时，必须单独追问是否属于必要限定：

| 类型 | 常见词 | 审查动作 |
|------|--------|----------|
| 材料 | 钢、橡胶、不锈钢、聚四氟乙烯 | 先问该材料是否解决当前问题所必需；不是则上位删除或下放从权 |
| 性能/强度 | 高强、高压、高精度 | 先改成中性结构名；性能要求另作从权或说明书 |
| 效果/功能 | 调心、限位、防尘、防腐、抗拔 | 先问该词是在命名结构，还是偷带效果；若仅是效果，优先改成更中性的结构名 |
| 场景/用途 | 上游、下游、防洪、专用、塔端 | 先判断是否为保护范围所必需；非必要则上位或下放 |

**典型示例：**

- `高强螺栓` → 默认先优化审查为 `螺栓`；只有当“高强”本身是区别点或不可替代时才保留。
- `防腐护套` → 先问是仅表示用途，还是本领域已固定成自明结构名；若只是用途，可考虑 `护套`。
- `球面调心垫板` → 先问“球面”是否是结构必要限定；“调心”若只是效果词，可考虑改写为带球面配合面的垫板，或保留为功能结构名并说明理由。

---

#### 规则三：优先改成“自明结构名 / 功能结构名”

命名优化优先级：

**自明结构名 > 功能结构名 > 原口语名 + 解释**

也就是说：

1. 能直接改成自明结构名，先改；
2. 纯结构名改不清楚时，可改成业内一看就懂的功能结构名；
3. 仍改不清楚时，再转 `本细则第三节（口语改写）` 与 `本细则第五节（就地定义）`。

---

#### 规则四：每次至少做“两档命名对照”

对拟入权的关键部件名，至少在心里或书面完成两档比较：

`原名 → 第一档优化名 → 第二档优化名`

并判断：

1. 哪一档**更清楚**；
2. 哪一档**更宽**；
3. 更宽那一档会不会把结构边界写糊。

若更宽档已不清楚，则退回上一档；不要为扩围而牺牲可读性。

**独权额外硬性：** 因独权部件名直接关系保护范围，两档对照必须做成表格交付用户选择确认；列至少包括：原名、第一档、第二档、推荐采用名、对保护范围的影响、用户选择。未经用户确认，不得据此直接写独权正文。

---

#### 规则五：跨权利要求「同名多物」必须消歧（硬性）

**问题类型：** 两个（或多个）**不同结构位置 / 不同功能归属** 的部件，在权利要求书中使用了**同一个裸名**（例如权4箱内「加劲板」、权7拉杆端「加劲板」）。

这与「同物多名」（同一件换了好几个叫法）相反，但同样导致「所述××」指向不清。

**自检句（写每个新部件名时必问）：**  
> 这个名字在本权利要求书**已出现的部件名**里，是否已经用来指过**另一个不同结构位置或功能归属**的件？

- 是 → 本条不得再使用该裸名，必须先消歧改名再落笔；
- 否 → 可通过。

**对照范围：**

- 写独权任一版：对照本版拟用全部部件名内部是否互撞，并对照交底/上一版已定名；
- 写每一条从权：对照**权1至本条之前（含平行从权已写正文）**已入权的全部部件名称。

**消歧优先级（改名，不是只加“所述”）：**

1. **加归属前缀（首选）**：`锚固箱加劲板` / `拉杆加劲板`；`拉索锚垫板` / `拉杆垫板`；
2. **加功能或位置结构定语**：`承压加劲板` / `箱内加劲板`；
3. **同条内多个同类件**：改用第一/第二，并转 `权利要求表达清楚性规范第二节`；
4. **禁止**：不同权利要求各写一个裸名「加劲板」「承压板」「垫板」，指望读者靠上下文猜。

**若冲突发生在已写正文之间：**  
优先改**后写/新引入**那一条的名称；若前条裸名过于泛化、后条改名仍易混，可将前条一并改为带归属前缀的名称，并保持全书统一。

**与清楚性规范的分工：**  
`权利要求表达清楚性规范第三节` 负责识别「同名多物 / 同物多名」；**改名落地**由本规则执行。

---

### 分阶段要求

#### 一、独权第一版

目标：最小特征集独权中，先去掉明显口语名、临时名（结构案须开对照表；方法案沿用交底原名，本版不优化命名）。  
此时允许保留部分较具体但清楚的名称，不追求最大扩围。

#### 二、独权第二版

目标：结合重新核定后的技术问题，去掉名称中的非必要缩限词。  
重点清理：

- 高强/专用/防腐/高水头/上游等非必要定语；
- 数量、场景、材料等可概括词；
- 名称里偷带效果的词。

#### 三、独权第三版（仅结构案）

目标：在清楚前提下，把名称优化到保护范围最大。  
必须显式比较至少两档命名方案。方法案无第三版，不走本档。

#### 四、每条从权

目标：凡新出现一个部件名，都要问一遍：

1. 这是自明结构名吗？
2. 这里是不是把材料、效果、性能偷偷写进名字里了？
3. 这个词应该保留在名称里，还是改成中性结构名，把限定内容留到句子后半段？
4. **它是否与已入权的其他部件同名异物？**（规则五）

---

### 操作步骤

对每个部件名依次做以下判断：

1. **先拆词**：找出核心结构词和修饰词；
2. **判必要性**：修饰词是否对当前权利要求解决的问题必需；
3. **尝试上位**：去掉修饰词后是否仍清楚；
4. **尝试改名**：若原名口语化，改成结构名或功能结构名；
5. **同名冲突审查（硬性）**：对照已入权部件名表，执行规则五；冲突则加归属前缀或功能/位置定语消歧；
6. **必要时转其他 skill**：
   - 名称像方位/场景钉死语 → `本细则第四节（方位与场景）`
   - 名称本身是交底口语 → `本细则第三节（口语改写）`
   - 改不动仍不自明 → `本细则第五节（就地定义）`
   - 同条内多个同类件需序数消歧 → `权利要求表达清楚性规范第二节`

---

### 典型判法

#### 例1：高强螺栓

- 原名：高强螺栓
- 第一档：螺栓
- 第二档：连接螺栓

判断：

- 若当前条仅想限定“通过螺栓连接”，则 `高强` 通常不是必要技术特征；
- 默认优先 `螺栓`；
- 若需要与销轴、焊缝等区分，可用 `连接螺栓`；
- `高强` 留到更下位从权或说明书。

#### 例2：防腐护套

- 原名：防腐护套
- 第一档：护套
- 第二档：密封护套 / 保护护套

判断：

- 若本条真正限定的是“外部套设一层套体”，通常 `护套` 已足够；
- `防腐` 多为用途/效果词，优先删除或下放。

#### 例3：横向限位挡块

- 原名：横向限位挡块
- 第一档：限位挡块
- 第二档：挡块

判断：

- 若“横向”对区别方向确有必要，可保留；
- 若仅在图上是横向，且从句子关系已可看出，则可上位成 `限位挡块`；
- 若再去掉 `限位` 后结构边界过空，则停在第一档。

#### 例4：两处「加劲板」（同名多物）

- 权4锚固箱内已有：`加劲板`
- 权7拉杆端拟再写：`加劲板`

判断：

- 自检句命中：裸名已被另一结构位置占用；
- 消歧：权4改为 `锚固箱加劲板`，权7改为 `拉杆加劲板`（或后写条单方加前缀，前条过泛时两边都改）；
- 禁止两条从权各留一个裸名「加劲板」。

### 与其他 skill 的分工

- `本细则〇节（分型与闸门）`：本节的总控入口，先分型再决定是否调用本节；
- `本细则第三节（口语改写）`：处理口语名、临时名能否直接改写；
- `本细则第四节（方位与场景）`：处理名称中的左/右、上游/下游、防洪等场景钉死语；
- `本细则第五节（就地定义）`：名称改不动时，负责在权利要求里说清含义（优先前置白话，少用「其中」）；
- `权利要求表达清楚性规范第三节`：识别同名多物/同物多名；**改名落地由本节规则五执行**；
- `权利要求表达清楚性规范第二节`：同条内多个同类件的第一/第二消歧；
- `结构类独权撰写`：第三版时强制做两档以上命名优化对照；
- `从权撰写`：每条从权新增部件名时，必须调用本节（含同名冲突审查）。

## 三、口语改写为自明名（原「交底口语名改写为自明结构名规范」）

### 核心规则

当交底书里出现“发明人自己叫的名字”时，**不要默认原词照抄进权利要求，再靠“其中，……”补解释**。应先做一层判断：

1. **能否直接改成更自明的结构名 / 功能结构名？**
   - 能：**优先改名**，让权利要求本身一眼可懂；
   - 不能：再保留短名，并转 `本细则第五节（就地定义）`——**优先在名称出现前白话写清**，勿默认「其中」。
2. 判断标准不是“说明书里能不能解释”，而是：**本领域技术人员不查说明书，单看权利要求文字，能否准确理解这个部件是什么。**

**优先级：改名清楚 > 前置白话说清 > 原名+其中兜底。**

对**布置／排列类口语**（如「对称错位」「上下左右错开」）同理：优先改写成**可核对的几何或位置关系**（错开相对谁、对称相对哪条中心线），不要只留黑话词；若必须保留原词，按 `本细则第五节（就地定义）` 先前置描述。

---

### 适用场景 / 触发词

- 交底中的称呼明显口语化、临时化：如“侧支孔”“小孔”“导流口”“底节专用门”等；
- 名称听起来像方位/习惯叫法，但读者不清楚它到底是孔、口、通道、件、段还是组件；
- **布置／排列口语**：如「对称错位」「花错布置」「上下左右错开」等——读者无法单凭该词判断错位方向、对称参照；
- 用户指出“其实它本质上就是某种更常见的结构名”；
- 撰写从权时，某个名称一上来就需要“其中，……”才能勉强读懂。

---

### 两步判断（硬性）

#### 第一步：先问能不能改名

把交底原名拿出来，问三件事：

1. **这个名称是否本身不自明？**
   例如“侧支孔”并不能让读者立刻知道它是“廊道对应的出水孔”还是“侧向支路通道”；“对称错位”并不能让读者立刻知道错的是哪一层、对称相对哪条线。
2. **是否存在本领域更常见、边界更清楚的名称（或可核对的几何／位置表述）？**
   例如把“侧支孔”改成“出水孔”；把“对称错位设置”改成“相邻层在水平投影上相互错开，并关于××中心线对称布置”。
3. **改名后是否不改变技术事实，只是把表达说清楚？**
   若只是从口语名改成规范结构名／可核对布置表述，则应改；若改名会改掉技术内涵，则不能硬改。

**三问结论：**
- 能改清楚 → 直接改名；
- 改名仍不清楚或会改错含义 → 保留原名，转 `本细则第五节（就地定义）`：**优先在名称出现前白话写清**，不要默认「其中」。

#### 第二步：改名后再判断要不要再解释

- 若改名后已经**客观清楚**（如“出水孔”“安装孔”“导流槽”，或已写明错开维度与对称参照），**一般不再需要**额外定义句。
- 若改名后仍需限定专属含义：优先把限定写进**名称出现前的句子**；仅当前置会极臃肿时，再补「其中」（见 `本细则第五节（就地定义）`）。

---

### 与 `本细则第五节（就地定义）` 的分工

| 情形 | 应用 |
|------|------|
| 原名只是交底口语，存在更自明的规范名 | **先用本节改名** |
| 布置类口语可改写成可核对几何／位置关系 | **先用本节改写**（通常不必再定义句） |
| 没有更好的现成名称，或改名会丢失发明特有含义 | **保留短名 + `本细则第五节（就地定义）`（先前置白话，其中兜底）** |
| 改名后仍有特殊边界需交代 | **先改名，再前置白话补足；仍不够才「其中」** |

**禁止的坏顺序：** 口语名原样进权利要求 → 每次都靠“其中”硬解释。  
**推荐顺序：** 先改自明名 → 真改不动则名称出现前白话说清 → 仍不行才「其中」。

---

### 示例

#### 示例1：本案“侧支孔”

```
原写法：
所述输水廊道包括阀门、出水口和侧支孔；
……其中，所述侧支孔为所述阀门所对应的、供鱼类由所述出水口进入所述船闸闸室的通道。
```

若发明人确认该“侧支孔”本质上就是与廊道出水口对应的**出水孔**，则优先改为：

```
所述输水廊道包括阀门、出水口和出水孔；
所述阀门控制所述出水口的通断；
所述出水口经所述出水孔与所述船闸闸室连通。
```

此时名称已自明，**一般不必再用“其中”解释**。

#### 示例2：改不动时才定义

```
……包括导稳组件；
其中，所述导稳组件包括……。
```

如果“导稳组件”没有更常见的可替代名，且该词概括了一组发明特有构成，则可以保留原词，并用“其中”或下位部件清单解释。

#### 示例3：布置类口语「对称错位」

```
原写法：
所述拉杆为多根，多根所述拉杆沿竖向分层布置，并对称错位设置。
```

问题：「对称错位」非自明——错位相对谁、对称相对哪条参照不清楚；交底「左右」属观察方位，不宜钉死。

优先改写为可核对表述（示意）：

```
所述拉杆为多根，多根所述拉杆沿竖向分层布置；
相邻层的所述拉杆在水平投影上相互错开，并关于索塔纵向中心线对称布置。
```

此时不必保留「对称错位」再靠“其中”解释。若用户坚持保留该词，则须按 `本细则第五节（就地定义）` **先前置白话写清**错开维度与对称参照（其中仅兜底），且观察方位仍宜按 `本细则第四节（方位与场景）` 处理。

---

### 反例（应避免）

#### 反例1：能改名却不改

```
……包括过鱼小孔；
其中，所述过鱼小孔为……。
```

若该“小孔”其实就是“进鱼孔”或“出水孔”，就不应继续使用“小孔”这种口语词。

#### 反例2：为求口语贴近而牺牲清楚性

```
……包括侧支孔；
```

若不解释读者根本不知其为何物，就不应仅因交底原词如此而照抄。

#### 反例3：布置黑话原样入权

```
……并对称错位设置。
```

未说明错开维度与对称参照，读者无法判断何种布置落入保护范围。

---

### 与其他 skill 的关系

- `本细则第五节（就地定义）`：本节在前，负责**先判断能否改名**；后者负责**改不动时如何说清**（先前置白话，其中兜底）。
- `权利要求表达清楚性规范第三节`：负责识别“名称不自明、突然出现”的问题；本节给出优先改名的处理路线。
- `本细则第四节（方位与场景）`：布置改写时若出现左／右等观察方位，按该规范上位（如改为中心线对称），与本节并行。
- `从权撰写`：从权中一旦出现交底口语名 / 非自明名 / 布置口语，先 Read 本节，再决定是改名、前置描述还是「其中」兜底。

- [ ] 该名称是不是发明人口语、图纸习惯称呼或临时叫法？
- [ ] 是否属于布置／排列口语（对称错位、花错等）？若是，能否改成可核对的几何／位置关系？
- [ ] 本领域有没有更常见、更自明的结构名/功能结构名可替换？
- [ ] 改名是否只改变表达清楚性，而不改变技术事实？
- [ ] 若已能用更自明名称说清楚，是否避免了不必要的“其中”句？
- [ ] 若仍保留原名，是否确实已无更好名称，且已按 `本细则第五节（就地定义）` 优先前置白话说清（其中仅兜底）？

## 四、方位与场景限定上位（原「方位与场景限定上位规范」）

### 适用场景 / 触发词

**应当加载本节的典型情形：**

- 撰写或改写**从属权利要求 / 独立权利要求**时，出现或拟写入：左侧/右侧、前/后、上/下、上游/下游、迎水侧/背水侧、内侧/外侧、防洪、高水头、工程专名等；
- 用户问「左右怎么上位」「上游下游要不要改第一第二」「背水侧能不能上位」「场景词怎么放宽」；
- 质检/单条审查发现权利要求被观察方位或场景语不必要钉死。

**不替代：**

- `权利要求表达清楚性规范第二节`——方位是否有参照物、是否清楚；
- `结构类独权撰写` 命名总规则——本节是其在**方位/场景定语**上的专条展开；
- `本细则第五节（就地定义）`——自定义结构名仍须就地定义（可与本节并行）。

---

### 核心规则（各类共用）

1. **先问：这个限定是解决技术问题所必需，还是交底图/实施例习惯？**  
   - 习惯标签 → 能上位则上位；  
   - 必要结构/功能关系 → 保留。  
2. **两步判断（不得跳步）：**  
   - ① 改掉或放宽后，是否仍清楚，且能多覆盖等同实施方式？能 → 上位；  
   - ② 不能扩围 → 不要为「看起来更上位」而改成第一/第二或空泛词。  
3. **实施例具体侧向/场景下沉**：交底图的左/右、某枢纽专名等，优先说明书或下游从权收回。  
4. **禁止误伤结构名中的字面「侧/向」**：如「侧支孔」「轴向」「径向」中的字，不是观察「左侧」。

---

### 一、观察方位对（左/右 · 前/后 · 上/下）

**特征：** 多相对于看图方向或安装习惯，左右/前后镜像后方案往往仍成立。

| 档 | 写法 | 适用 |
|----|------|------|
| **A** | **一侧**；**至少一侧**；**一端**；**一侧端部** | 对称或可互换，优先 |
| **B** | **第一侧 / 第二侧**；**第一端 / 第二端** | 两侧都要写入同一条且需消歧，且序数比左/右更能扩围 |
| **C** | **左侧 / 右侧**；**前部 / 后部**；**上部 / 下部** | 不对称且为必要区别时保留 |

**从权默认：** 用 A；交底「左侧」用下游从权或说明书收回。

```
❌ 所述左侧阀门……所述左侧出水口……
✅ 所述一侧阀门……所述一侧出水口……
（下游从权可选）所述一侧阀门为左侧阀门……
```

**前/后、上/下同理：** 若仅为相对图纸，可改为「一侧/另一侧」「一端/另一端」「靠近××的一侧」；若「上部开口、下部封闭」本身解决技术问题，保留上/下。

---

### 二、流程 / 流体方向（上游 / 下游）

**特征：** 通常锚定**水流、物流、工艺顺序**，比左/右稳定，**不要盲目改成第一/第二**。

| 情形 | 处理 |
|------|------|
| 「上游门—缓冲池—下游闸室」等流向关系是方案骨架 | **保留**上游/下游（或改为已定义的部件名，如「所述缓冲池上游侧」） |
| 仅因图面把两个同类件标成上游件/下游件，功能完全对称可互换 | 可考虑第一×× / 第二××（仍先做两步判断） |
| 想扩围但不想丢流向 | 用「沿水流方向的上游侧 / 下游侧」并点明参照（水体/闸室），**清楚优先于序数** |

**禁止：** 把所有「上游叠梁门」无脑改成「第一叠梁门」导致与流向关系变糊。

---

### 三、功能侧（迎水侧 / 背水侧 · 进水侧 / 出水侧 · 高压侧 / 低压侧）

**特征：** 往往描述**受力、过流、工艺功能面**，常有技术含义，不是纯看图左/右。

| 情形 | 处理 |
|------|------|
| 阀在背水侧、拦污在迎水侧等，是布置贡献或必要关系 | **保留**迎水侧/背水侧（参照物：门体/水流） |
| 交底写死「背水侧」但任意一侧安装阀均可 | 可上位为「设置于所述门体的一侧」或「设置于所述输水管上」；背水侧下沉从权/说明书 |
| 进水口/出水口 | 保留功能名；不要改成含糊的第一口/第二口，除非两侧同构成对 |

```
✅ 保留（常见）：所述流量调节阀设置于所述上游门体的背水侧。
✅ 可上位（若任一侧均可）：所述流量调节阀设置于所述输水管上。
   （从权）……且位于所述上游门体的背水侧。
```

---

### 四、内外侧（内侧 / 外侧 · 内壁 / 外壁 · 腔内 / 腔外）

| 情形 | 处理 |
|------|------|
| 「安装于内壁」「开口朝向外侧」是装配关系本身 | **保留**内外，并保证参照物清楚 |
| 内外仅实施例习惯、镜像外壳同样可装 | 可改为「一侧壁」「朝向远离××的一侧」等，仍须清楚 |

---

### 五、场景 / 用途 / 工程钉死语

**特征：** 防洪、高水头、某某枢纽、1000 吨级等，常把范围缩到交底场景。

| 档 | 处理 |
|----|------|
| 独权 / 较宽从权 | 能删则删，或上位为领域通用名（如「检修门」「船闸过鱼系统」） |
| 说明书 / 最下游从权 | 保留「高水头」「防洪检修」等实施例语境 |

与 `结构类独权撰写` 第三版「过窄材料/结构/用途定语能上位则上位」一致；本节负责提醒**从权也不要无必要重复钉死**。

---

### 六、易混：「侧」字不是「左侧」

| 用语 | 处理 |
|------|------|
| 侧支孔、侧向孔口、侧壁、旁通 | **结构/方向用语，保留**；用就地定义说清含义 |
| 左侧通道、右侧阀门 | **观察方位**；按第一节上位 |
| 轴向、径向、周向 | 属参照系方位 → 指代 skill 管清楚；本节一般不改名 |

---

### 从属权利要求专项（硬性）

1. 布局或正文一出现本节覆盖的限定语 → **先 Read 再写**。  
2. **观察方位对**默认 A 档；**功能侧 / 上下游**默认谨慎保留，仅当确认可互换才上位。  
3. 交付物写明：本条用了哪一类、选了哪一档、一句话理由。  
4. 同一条不要「一侧」上位后又无必要夹带「左侧」把范围缩回（除非本条职责就是实施例收回）。

## 五、自定义名词就地定义（原「自定义名词就地定义」）

### 核心规则（优先级硬性）

权利要求须**自足可读**。遇到非公知概念时，按下列顺序处理——**越靠前越优先**；不得一上来就堆「其中，……」：

| 优先级 | 做法 | 何时用 |
|--------|------|--------|
| **① 改自明名** | 换成领域一看就懂的结构名/功能结构名（或可核对几何表述） | 原词只是口语/习惯叫法 | 
| **② 名称出现前白话写清** | 在首次使用该简称/标签**之前**，用一两句普通技术话把含义说完，再自然引入短名 | 需要短名便于后文「所述××」回指，但含义可用前文说清 |
| **③ 「其中」兜底** | 仅当必须保留本案特有紧凑标签，且①②都做不到或会极臃肿时，再用「其中，所述××为……」 | 最后手段 |

**硬性禁止：**

- 禁止「先甩黑话名词 → 再靠一串『其中』补课」的默认写法。  
- 禁止同一独权/从权里为多个本可用①②说清的词连续堆「其中」。  
- 禁止「其中」句再引入新的未定义黑话（用未定义解释未定义）。  
- 禁止把定义只写在说明书里、权利要求里直接甩自定义词。

**可读性优先于形式习惯：** 若「其中」使句子更难读，而把定义挪到名称**前面**或改成自明名后更顺，必须改用①或②。

---

### 什么需要处理

- **公知术语 / 客观物理量**（通常不用定义）：如「螺栓」「电机」「压力」「温度」。  
- **非公知概念**（必须在权要内说清，但不等于必须用「其中」）：自造词、被赋予特殊含义的普通词、本案特有参数/集合/中间量，如「调节比」「信息盲区」「节点贡献度」。

**判断：** 本领域技术人员不看说明书，能否准确理解？不能 → 须在权要内说清（优先①②，必要时③）。

---

### 优先写法②：名称出现前白话描述（推荐）

把「定义」写成**引入句**，而不是名词后面的附录。

#### 模式

```text
[先用普通话交代构成/计算/作用] → 得到/形成/作为「短名」→ 后文用「所述短名」回指
```

#### 正确 / 错误

```
错误（黑话先行 + 其中补课，难读）：
  识别信息盲区；其中，所述信息盲区为对定位贡献高且当前无压力表覆盖的特征簇。
```

```
正确（先说清，再给短名，可不用其中）：
  将定位贡献高且当前缺乏压力表覆盖的特征簇，作为信息盲区；
  自所述信息盲区内选取候选节点……
```

```
错误：
  当所述调节比大于1.5时……；其中，所述调节比为伸出长度与壳体高度之比。
```

```
正确（参数也可先写清再命名）：
  以所述调节杆的伸出长度与所述壳体高度的比值为调节比，
  当所述调节比大于1.5时，锁定所述调节杆。
```

**要点：** 短名是**标签**，不是先扔标签再解释；前文已经把含义钉死的，**不要再加「其中」复述一遍**。

---

### 兜底写法③：何时才用「其中」

仅同时满足时才用：

1. 该短名需要在后文多次「所述××」回指，删掉短名会导致行文极冗长；且  
2. ①改自明名会丢失本案必要区分，或改后仍不自明；且  
3. ②前置白话会把本步句子撑到难以阅读（极少见），或该词在句中语法位置不便前置。

写法：紧接首次出现后，用「其中，所述××为……」一次说清；**同一词只定义一次**。

```
可用（兜底）：
  ……得到所述稳定系数；其中，所述稳定系数为相邻两采样周期内压力均方差之比。
```

若改成「以相邻两采样周期内压力均方差之比为稳定系数，得到所述稳定系数」同样清楚，**应优先改成前置描述，删掉其中**。

---

### 与其他规范的关系

- **先**走 `本细则第三节（口语改写）` / `本细则〇节（分型与闸门）`：能改名则改名（①），不要进本节就堆「其中」。  
- 本节是清楚性「人为定义词」的**落地写法**：负责**怎么说清**——①改名 → ②前置白话 → ③其中兜底；不是「凡自定义必加其中」。  
- 预设值/参数的**来源**（先获取后使用）见 `方法步骤条件与参数规范第二节`；本节只管**含义是否在权要内说清**。  
- 说明书仍应有更细记载；具体实施方式「先释义后展开」见 `具体实施方式名词先释义后展开`（说明书侧，不替代本节的权要自足要求）。

---

### 检查清单

- [ ] 非公知概念是否已在**权利要求内部**说清（不依赖说明书）？  
- [ ] 是否优先完成了**改自明名**或**名称出现前的白话描述**？  
- [ ] 「其中」是否仅为①②不可行时的兜底？有无多余、重复、可删的「其中」？  
- [ ] 有无「黑话先行 + 一串其中」导致比前置描述更难读？——有则必须改写。  
- [ ] 「其中」句是否只用已出现/已说清的特征，无新的未定义词？  
- [ ] 同一概念全文名称与含义是否一致？说清一次后，后文是否避免重复「其中」？

### 应用范围

适用于结构/方法/算法类权利要求的撰写与质检。撰写时默认走①②；质检时若见到大量「其中」，应优先建议改为前置描述或自明名，而不是要求「再补更多其中」。
