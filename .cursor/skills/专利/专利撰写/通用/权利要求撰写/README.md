# 通用·权利要求撰写

本分支用于存放**不区分结构类/方法类/算法类，所有案件类型通用**的权利要求撰写相关 skill（比如通用的用词规范、格式规范等，与具体案件类型无关）。

案件类型专属的权利要求撰写规范，请分别放到 `专利/专利撰写/结构类/权利要求撰写/`、`专利/专利撰写/方法类/权利要求撰写/`、`专利/专利撰写/算法类/权利要求撰写/` 对应目录下。

## 命名簇（子目录 `部件命名/`）

撰写时**唯一入口**是 `部件命名优化总控`（方法/算法案仅第二版）。目录多一层**不改变** `name` / 调用；流水线与「谁管什么」见 `部件命名/README.md`。

| skill | 简要说明 |
|-------|----------|
| `部件命名优化总控` | 分型、分流、对照表闸门；不替代叶子细则 |
| `交底口语名改写为自明结构名规范` | 第 1 闸：交底口语/布置黑话能否改成自明名 |
| `部件命名具体优化` | 第 0、3 闸：非必要定语、两档对照、同名多物改名落地 |

本簇挂接、正文仍在本目录（双用途，不搬进 `部件命名/`）：

| skill | 简要说明 |
|-------|----------|
| `方位与场景限定上位规范` | 第 2 闸（名称定语）+ 句中限定/质检可直触；观察方位、上下游、功能侧、内外、场景钉死语 |
| `自定义名词就地定义` | 第 4 闸（改完仍不自明）+ 方法参数/质检可直触；先前置白话，「其中」仅兜底 |

## 形式、清楚性与句式（本目录）

| skill | 简要说明 |
|-------|----------|
| `权利要求形式合规性规范` | 从权引用方向、多项从权择一引用、编号连续性等《专利法实施细则》硬性格式规则 |
| `权利要求依附编号与术语出处规范` | 「所述××」是否落在本条引用链上；失败则改引用/本条引入/调布局 |
| `权利要求清楚性与逻辑一致性规范` | 孤岛特征、人为定义术语、模糊用语、歧义与反例、物理/数学常识、术语一致性 |
| `独立权利要求必要技术特征检查` | 逐一检查独权各特征是否必要，重点排查数量词、排列方式、具体机构 |
| `权利要求主谓宾结构规范` | 每个动作/状态/关系是否有明确主语，避免省略主语导致指代不明 |
| `权利要求指代与参照清晰性规范` | 指代词（"该""其"）和方位词（周向、轴向等）的清晰性与参照物；不管方位是否过窄 |
| `条件判断语句规范` | 方法类/算法类权利要求中条件判断的固定句式（"判断是否…，若是，则…；若否，则…"） |
| `预设值与参数来源检查` | 机器人视角自查预设值/阈值/参数在使用前是否有明确来源，是否满足"先获取、后使用" |

独权/从权策略 skill 将 `部件命名优化总控` 列为硬性门禁。

## 与质检分支的关系

- 撰写阶段：边写边对照 `权利要求清楚性与逻辑一致性规范` 等自查；涉及部件名时先走 `部件命名优化总控`
- 定稿质检：由 `专利/质检总控` → `权利要求质检总控` 分流；整份权要链路再调用 `权利要求书质检`，按"必读/按需"分级加载。口语名、方位钉死语、非公知概念可**直读对应叶**，不必先经命名总控

后续新增：命名类放 `专利/专利撰写/通用/权利要求撰写/部件命名/<中文名称>/SKILL.md`；其余仍放 `专利/专利撰写/通用/权利要求撰写/<中文名称>/SKILL.md`。并更新本 README 与 `部件命名/README.md`。
