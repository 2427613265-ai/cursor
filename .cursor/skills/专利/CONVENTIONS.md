# 专利 Skill 编写约定

本约定自 Phase 0/1A 起生效。优化目标是**薄接口、瘦热路径、规则全集保留**——不压缩实质撰写规则，只调整装载与发现方式。

## description（公共 API）

- **上限约 150 字**（按去掉换行后的字符计）。
- **只写**：何时触发、管什么、不管什么、禁止误触/须经哪一总控。
- **不写**：完整门禁表、逐步算法、长挂接清单、大段模板（这些放正文）。

## 正文体量（后续 Phase 逐步达标）

| 类型 | 建议 |
|------|------|
| 规范类 `SKILL.md` | ≤约 150 行；正反例可外置同目录 `examples.md`，按需 Read |
| 总控/策略类 | ≤约 200 行：步骤、确认点、挂接、交付契约；细则外指子 skill |

## 硬门禁（不得借优化降级）

- 权利要求依附编号与术语出处（见 `权利要求形式与依附规范` 第二节）
- 权利要求命名细则（分型及去定语/口语/方位/就地定义）
- 权利要求形式合规性（见 `权利要求形式与依附规范` 第一节）
- 结构类「总列后逐件展开 / 列名未展不得交付」等已成文硬规则

「何时全文 Read」可以分层（硬必读 / 摘要自检 / 条件必读），但**判定标准与处置规则本身不删不弱化**。

## 度量

- 基线快照：`SKILL优化基线-Phase0.md`（及 `.json`）
- 每轮 description/行数优化后，应用脚本或手工回填对比

## 挂接命名

- 正文与总控表中引用其他 skill 时，优先用 frontmatter 的 `name` / 中文目录名，保持可 Grep 一致

## 顶层入口

| 意图 | 入口 |
|------|------|
| 质检/审核/检查 | `质检总控` |
| 写案子/未点名阶段 | `专利撰写总控` |
| 已点名阶段 | 直接进对应策略 skill（交底理解/独权/从权/说明书/创造性答复） |

## Golden cases 与 lint

- 样例：`golden-cases/`（依附编号、部件命名、形式合规）
- 检查脚本：在本目录执行 `python3 scripts/lint_skills.py`（description >150 为错误；正文超软上限为警告）
