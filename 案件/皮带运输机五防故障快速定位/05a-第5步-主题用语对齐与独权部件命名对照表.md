## 4. 新主题下这些特征还合适吗

换到「带式输送机上的保护装置故障定位」，问是否仍成立、是否把范围又钉回旧领域。

| 第一版特征 | 新主题下 | 处置 | 一句理由 |
|------------|----------|------|----------|
| 多只保护装置 | 合适 | 留 | 核定问题就是「哪一只」；主题含保护装置 |
| 信号输出端 | 合适 | 留 | 一对一接入的作用部位；不依赖烧结 / 五防名称 |
| 采集单元 | 合适 | 留 | 通道与对应关系的载体；一体或分设均可，不钉回隔离 PLC |
| 相互独立的输入通道 | 合适 | 留 | 机制骨架；不把范围钉回远程 IO / 数字量口 |
| 各信号输出端分别连接至不同输入通道 | 合适 | 留 | 离开它可改回串联，点位身份被抹掉 |
| 皮带标识 | 合适（相对主题） | 留（必要性留嵌套第 2 步再勾） | 把对象锚在带式输送机；不是烧结专有。核定问题字面未写「哪一条皮带」，是否非必要下一闸再问 |
| 点位标识（含前置白话：区分安装点） | 合适 | 留 | 直接对应「位于哪一安装点」 |
| 故障类型 | 合适 | 留 | 直接对应「属于哪类保护」；不把五种名称写进独权 |
| 对应关系配置于采集单元 | 合适 | 留 | 通道状态变成定位信息的绑定；不钉死组态表 |
| 根据状态变化的通道及对应关系给出含三项身份的定位信息 | 合适 | 留 | 产品配置闭环，不是使用过程 |
| 前序「五防」 | 不合适 | 删 | 把范围钉回五种保护齐套 |
| 前序「皮带运输机」 | 宜改称谓 | 概括为带式输送机 | 同一客体的规范名，覆盖冶金 / 矿山 / 港口 / 电力等交底领域 |

不因新主题把隔离加装、分布式 IO、消抖、HMI、分级联锁、预警写成独权特征。

## 5. 再一次删减 / 上位（本闸只预告，不写核对长表）

组集时考虑过的，本步仍要再问；对着的是**核定问题**，不是「方案能不能跑」。逐条勾选放在嵌套第 2 步，避免本回复与第二版全文叠在一起。

预告（供命名时心里有数，**不是本闸定稿**）：

- **多只 / 多条：** 问题依赖「哪一只」；单只装置不存在点位混淆。数量词宜留。
- **故障类型：** 第 2 步曾写「弱于点位标识」。核定问题已写明「属于哪类保护」，本版倾向保留。
- **皮带标识：** 相对核定问题字面偏软（问题没问哪一条皮带），相对审定主题和多皮带厂偏硬。默认保留，嵌套第 2 步可改选下放。
- **相互独立 / 分别连接至不同通道：** 机制本身，不是排列方式或螺栓级细节，不宜删。
- 具体机构（PLC、远程 IO、环网、消抖）组集时已拟删，本步无新发现要拉回。

### 6.4 就地定义（确认名之后写正文时用，本闸不写权 1）

- **点位标识：** 名称出现前保留白话：以用于区分各所述保护装置安装点的标识为点位标识。
- **对应关系：** 采集单元配置有各输入通道与皮带标识、点位标识及故障类型的对应关系（短名出现时含义已在句中）。
- **定位信息：** 给出包含皮带标识、点位标识及故障类型的定位信息（内容即定义）。
- 不用「其中」堆定义。

### 6.5 正文铺陈预告（确认采用名之后才写）

- 总列同级：保护装置、采集单元。
- 关系动词取宽档：连接、配置有、被配置为。
- 产品权禁止「使用时 / 然后 / 派人沿线」。
- 「被配置为根据状态发生变化的输入通道……给出定位信息」是产品能力，不是操作规程。
- 「以用于区分……为点位标识」是前置定义，不是效果收尾。
