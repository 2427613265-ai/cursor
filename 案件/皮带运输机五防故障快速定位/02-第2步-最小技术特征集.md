# 【第 2 步 / 共 9 步】最小技术特征集

阶段：结构类独权撰写。本案已明确为 **实用新型**，组集按产品（系统 / 装置）骨架；不把使用步骤、纯算法流程列入最小集。本步只组集，不写独权正文。

## 1. 已确认的一句话与机制三栏

**一句话：** 对各五防保护装置按点位独立采集动作信号，并按预先绑定的皮带标识、点位标识与故障类型输出定位信息。

| 技术问题 | 机制 | 技术效果 |
|----------|------|----------|
| 保护动作后只能得知“该皮带有保护动作”，不能得知是哪一只装置、在哪一点、属哪类保护；根因是多点共用串联回路，点位身份被抹掉 | 每只保护装置独占一条采集通道；通道与皮带标识、点位标识、故障类型预先绑定；装置动作使该通道状态变化后，系统按绑定关系生成指向该装置的定位信息 | 中控可直接指向具体保护装置，无需沿线逐点排查 |

实用新型口径：独权只能是产品。上表机制落到「通道独占接入 + 通道与身份的对应关系 + 采集单元给出定位信息」这三项结构 / 配置上，不写成「使用时先采集再显示」。

## 2. 一句话抽出的特征（含清楚化）

| 原词 | 入集用名 | 说明 |
|------|----------|------|
| 各五防保护装置 | 保护装置（多只） | 「各」要求多于一只；「五防」作主题用语，不把跑偏 / 打滑 / 撕裂 / 堵料 / 拉绳五种都钉进独权 |
| 按点位独立采集 | 相互独立的输入通道 | 权要能用的结构名；不钉死远程 IO、数字量口 |
| 动作信号 | （不单列部件） | 落入关系：保护装置的信号输出端接入输入通道 |
| 预先绑定 | 对应关系 | 各输入通道与皮带标识、点位标识及故障类型相对应；不钉死组态表、挂签本 |
| 皮带标识、点位标识、故障类型 | 同左 | 对应关系与定位信息的内容；「编号 / 位号」是实施例叫法 |
| 输出定位信息 | 定位信息 | 内容包含皮带标识、点位标识及故障类型 |

## 3. 完整方案支撑特征（一句话字面上没有）

| 特征 | 为何必不可少 |
|------|----------------|
| 采集单元 | 输入通道与对应关系的载体；没有它，独立采集和给出定位信息无处附着，无法实施 |
| 各保护装置的信号输出端分别连接至不同的输入通道 | 机制的关系 / 作用部位：独占接入。只写「有装置、有通道」仍可把多只装置串进同一通道，点位身份照样被抹掉，三栏效果出不来 |
| 对应关系配置于采集单元 | 绑定必须能为给出定位信息所用。仅现场挂签、采集单元不知道对应关系，系统给不出定位信息 |
| 采集单元被配置为根据发生状态变化的输入通道及所述对应关系给出定位信息 | 机制闭环。有独立通道和对应关系、但不给出定位信息，仍停留在「只知道有动作」，三栏效果出不来。这是产品能力 / 配置，不是操作规程 |

皮带运输机整机不列入最小集：它是应用对象，保护装置已是皮带机上的五防装置；是否把「皮带运输机」写进前序主题，留到第 4 步审定。

## 4. 入集表（含删一法）

| 特征 | 来源 | 入集理由 | 若不入如何下放 |
|------|------|----------|----------------|
| 保护装置（多只） | 抽出 | 去掉一句话接不上；无动作来源，效果无 | — |
| 采集单元 | 支撑 | 去掉则通道与对应关系无载体，无法实施 | — |
| 相互独立的输入通道 | 抽出 / 清楚化 | 去掉则回到公共回路，点位身份被抹掉，效果无 | — |
| 各保护装置的信号输出端分别连接至不同的输入通道 | 支撑（关系） | 去掉后装置与通道可以仍是串联接入，机制不成立 | — |
| 皮带标识 | 抽出 | 多皮带现场去掉后无法指向哪一条皮带，效果不完整 | 单皮带场景可从权再写「皮带标识为皮带编号」 |
| 点位标识 | 抽出 | 交底 150 m / 十余只拉绳的核心：去掉后只能知皮带、不知哪一只，效果无 | — |
| 故障类型 | 抽出 | 对齐已确认一句话的三项身份；与点位标识分工（点位指哪一只，类型指哪类保护） | 若点位标识已唯一含装置种类，第 5 步可再问是否删 |
| 对应关系（输入通道 ↔ 皮带标识、点位标识及故障类型） | 抽出 / 清楚化 | 去掉则通道状态变不成指向具体装置的信息，效果无 | 组态表、挂签对照、装置自带编码等实现进从权 |
| 定位信息（含上述三项身份） | 抽出 | 去掉则没有「给出定位」，仍要沿线查 | HMI 文句、三级树、颜色闪烁进从权 |
| 采集单元被配置为根据发生状态变化的输入通道及对应关系给出定位信息 | 支撑 | 闭环；无此配置则前序结构不产生三栏效果 | 显示屏 / 声光 / 推送等具体输出形式进从权 |

### 机制 → 载体 → 结构 → 关系（短表）

| 机制 | 载体 | 必须结构 | 必须关系（含作用部位） | 可下放的具体化 |
|------|------|----------|------------------------|----------------|
| 独占通道，点位身份不被串联抹掉 | 采集单元上的输入通道；保护装置 | 输入通道相互独立 | 各保护装置的信号输出端分别连接至不同输入通道（一对一接入，不是串入公共回路） | 远程 IO、数字量、独立屏蔽电缆、中继接线箱 |
| 通道与身份预先绑定 | 采集单元 | 持有对应关系（配置 / 存储 / 标识，不钉死形态） | 对应关系以输入通道为索引，指向皮带标识、点位标识及故障类型 | 组态地址表、接线箱挂签、装置编码 |
| 按绑定给出指向具体装置的定位信息 | 采集单元 | 被配置为根据状态变化的输入通道及对应关系给出定位信息 | 定位信息与发生状态变化的那条输入通道相对应 | HMI 三级树、声光柱、独立上位机 |

## 5. 同名检查

| 入集用名 | 不得混用的交底口语 / 实施例名 |
|----------|--------------------------------|
| 保护装置 | 传感器、检测装置、开关、执行元件（执行元件交底未展开，不入集） |
| 采集单元 | PLC、CPU、远程 IO、S7-1513、TBEN、主控 |
| 输入通道 | 数字量输入口、采集通道、测点 |
| 对应关系 | 对照表、组态表、挂签本 |
| 皮带标识 | 皮带编号、3# 皮带 |
| 点位标识 | 传感器位号 |
| 故障类型 | 五防名称的某一种 |
| 定位信息 | 报警画面、HMI 提示 |

一名一物：采集单元 ≠ 输入通道；保护装置 ≠ 采集单元；皮带标识 ≠ 点位标识 ≠ 故障类型；定位信息是给出的内容，不是一个另设部件名。

## 6. 未入集下放候选

**机制效果仍在、只是更好（从权种子）：**

- 采集系统与原生产主控隔离、不参与启停联锁（定位机制不依赖隔离；实用新型加装场景的保底点）
- 廊道就近远程 IO、手拉手 / 介质冗余环网
- 中继接线箱、编号挂签、弹簧端子、独立屏蔽电缆
- 通道侧消抖 / 边缘预处理
- 显示装置、HMI「皮带编号—传感器位号—故障类型」三级树、声光、颜色闪烁
- 输入通道限定为数字量开关量通道
- 跑偏、打滑、撕裂、堵料、拉绳五种保护装置分列
- 重 / 轻故障分级、检修临时解锁（交底与「不参与生产联锁」仍未说清，从权也先按监测侧配置写，不写成停机方法）
- 动作频次 / 持续时长趋势预警（预防性维护；实用新型从权尽量写成存储 / 显示配置，不单列方法）

**与定位效果无关（通常连从权都不占，说明书即可）：**

- 西门子 / 图尔克型号、IP67、M12 / M8、TIA Portal、GSDML、PNP、0.5 A、500 ms、造价与备件、360㎡ 烧结线、CS9 电气楼六楼

**不入集的方法步骤（实用新型独权不用）：** 使用时派人到现场、先停机再排查、模型训练等。

## 7. `[推定]` / 待确认（本组集）

1. **`[推定]`** 对应关系由采集单元持有（配置、存储或标识），不限定必须是一张名为对照表的文件。
2. **`[推定]`** 「给出定位信息」是采集单元的配置能力；具体可以是自身显示、送给显示装置或送给其他终端，独权不另强制一件上位机。
3. 故障类型：删一法上弱于点位标识（点位若已唯一，赶到现场的效果仍在）。现为对齐第 1 步一句话三项身份而入集；若确认点位标识已含装置种类，可在确认本步时删去故障类型。
4. 采集单元是否必须与生产主控分设：本组集按「不必分设」。若实用新型要强调「不停产加装」，把隔离升格入集须你明示（会收窄范围）。
