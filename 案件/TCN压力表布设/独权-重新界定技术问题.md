## 重新界定后的技术问题（上位定稿候选）

**如何使供水管网压力监测点的布设与漏损定位模型的信息需求相匹配，并缩小监测点优化的搜索范围，以避免因布设与定位脱节导致定位精度不足，以及因在全管网范围内选点优化而导致方案难以实施。**

---

## 界定考虑

### 点1：最核心的问题

交底场景中，压力监测服务于漏损定位。若不解决，方案整体失败的主矛盾是：

- **布点位置与定位模型真正需要的信息不对齐** → 数据冗余或缺关键特征 → 定位精度不足、监测系统支撑不住定位任务；
- 伴生尖锐工程矛盾是：若只能在全管网节点上做遍历式增量试探，城市级管网**算不动、落不了地**。

盘点后：经验主观、事前难评估、自动化降门槛等属入口表现或宣传效果，**不升格**为重新界定主问题。

### 点2：最具创造性手段所解决的问题（本步以点2为纲）

交底中区分度最高的一撮手段是：

1. 从全节点基准定位模型提取节点级高维响应特征并按相似响应划分特征组；
2. 据此识别高贡献却缺乏监测覆盖的区域，将候选点从全网收缩到该区域；
3. 在收缩后的候选域内，以定位误差减少量为目标做动态增量选点并重评。

反推其稳定解决的不良后果，正是上位后的两层缺口：

- **布设未对准定位模型的信息需求**（而非仅对准静态水力/经验规则）；
- **选点搜索范围过大导致优化难以实施**。

故主问题落在「匹配信息需求 + 缩小搜索范围／使优化可实施」，以便第二版把上述创造性骨架留在独权。

### 点3：好补强所解的问题

若创造性仍边缘，沿交底较易加深、无需另起炉灶的方向包括：盲区判定口径、盲区级切换／充分感知条件、加点后重评、冗余回退控制等——均服务于「更准对准信息缺口」与「更稳控制搜索与表数」。与点1、点2同层，可作为后续可选创造性补强抓手。

### 综合取舍

三点同向。默认以**点2**为纲，兼顾点1主矛盾与点3可补强性。  
表述遵守**手段不进问题**：不写入 TCN、谱聚类、特征簇、信息盲区、EPANET、边际贡献衰减率等手段名；场景保留「供水管网压力监测点布设」「漏损定位模型」。

### 操作检视

| 方法 | 结论 |
|------|------|
| 交底问题盘点 | 主问题取「匹配信息需求 + 优化可实施」；主观经验/自动化宣传不升格 |
| 特征反推 | 高贡献手段对准的正是信息需求错配与搜索范围过大 |
| 手段不进问题 | 已去掉 TCN／特征簇／盲区等钉死手段 |
| 区分度落点 | 宽于「只提高精度」空泛效果，窄于把具体算法写进问题；第二版可撑住创造性骨架 |
| 用户加权 | 用户要求「上位」一版 → 相对交底与常规重界定进一步去场景钉死、统一双缺陷表述 |
| 可检验 | 假定第二版只留：响应特征分组 → 高贡献缺覆盖区域识别与候选收缩 → 约束域内按误差减少量增量选点并重评，仍能回答本问题 |

## 上位处理相对交底书原问题的差异

| 项 | 说明 |
|----|------|
| 保留 | 「布设与定位／模型需求脱节」「工程难落地（计算规模／搜索过大）」两条主线 |
| 上位 | 「TCN」→「漏损定位模型」；「静态水力／全局增量」具体对标 →「信息需求不匹配／搜索范围过大」需求层表述 |
| 收窄后果 | 「工程实用性差」落到可检验后果：「定位精度不足」+「方案难以实施」 |
| 不升格 | 经验主观、自动化降门槛等不作为主问题 |

相对此前非上位重界定稿，本版进一步：去掉「端到端」钉死、将「感知需求」改为更中性的「信息需求」、将「盲目试探选点」改为后果层「全管网范围内选点优化难以实施」，并显式纳入「缩小搜索范围」作为与创造性贡献对齐的需求缺口。
